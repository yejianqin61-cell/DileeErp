# ERP_Map M0 建设计划：定义基线

> 类型：实施计划 · 日期：2026-10-28 · 状态：待执行 · 依据：[ERP_Map PRD](./PRD.md) 第 2、5、6、8 节

**M0 的完成标准**：用 Dilee ERP 的一条真实跨模块交接，证明“管线 → stage → 操作人 → 单据字段 → 交接”能准确描述业务；将术语、证据状态和 M1 验收边界写回 PRD。M0 只形成定义与核验材料，不开发 Skill、MCP 或 HTML 地图。最大风险是旧文档与当前实现不一致，因此先追一条真实链路，再定术语。

## 1. 需要满足哪些要求？

- **R-1 选出能检验模型的真实交接** — PRD §3、§8：样例须跨模块，并包含分叉或回退等非直线情形。
- **R-2 统一地图术语及归属** — PRD §2：操作人归属 stage；单据是字段集合；交接描述字段或推进结果的流向。
- **R-3 写出字段级交接样例** — PRD §2、§6：说明触发、来源字段、目标字段、门禁、失败或回退，以及谁操作。
- **R-4 建立依据与差异口径** — PRD §2、§3：关键结论可定位到当前代码或业务材料，区分已核验、待核验、与实现不符。
- **R-5 固定 M1 可执行的产品边界** — PRD §4–§6：明确 M1 需要的地图内容、HTML 交互和重复生成验收，不提前实现。

## 2. 每项要求怎样落地？

### R-1 选出能检验模型的真实交接

- **做法**：优先试追“到货批次 → 来料质检 / 应付来源”。若当前实现无法形成合适样例，按跨模块、分叉、字段变化和可查证四项标准改选。
- **涉及范围**：Dilee ERP 的采购、质检、财务业务链及现有业务材料。
- **检验入口**：从一个上游动作追到两个下游结果；逐项对照当前业务代码与材料。
- **验收**：选定一个具体交接；写清选择理由和未选候选；没有把旧设计当成当前实现。
- **难点**：应付来源时点在现有材料中有不同表述，必须核对当前代码。

### R-2 统一地图术语及归属

- **做法**：用样例定义管线、stage、操作人、单据、字段、交接和依据。每个词只表达一种含义，并给出易混淆情形的判定规则。
- **涉及范围**：ERP_Map 产品术语与 Dilee ERP 样例说明。
- **检验入口**：让不参与编写的人按术语表独立标注同一段业务流程。
- **验收**：操作人只挂在 stage；系统自动动作有明确标记；单据能还原为字段清单；同一业务环节不会同时被标成 stage 和单据。
- **难点**：业务角色、系统动作和实体状态容易被误写成管线或 stage。

### R-3 写出字段级交接样例

- **做法**：为选定交接列出单据字段、来源与目标、值如何变化、快照或引用关系、触发与阻塞条件，并覆盖一条异常路径。
- **涉及范围**：样例交接的上游 stage、下游 stage、字段和业务规则。
- **检验入口**：只看样例材料，能回答“谁在何处操作、哪些字段过去、何时不能推进、如何回退”。
- **验收**：每个目标字段都有来源或明确的人工/系统生成方式；分叉结果分别描述；至少一条异常路径可追溯。
- **难点**：不要把数据库字段名直接当成业务字段含义，也不要把单据画成独立于字段的对象。

### R-4 建立依据与差异口径

- **做法**：每条关键判断记录出处与核验状态。代码与文档冲突时并列记录两种说法，标出当前实现，不静默合并。
- **涉及范围**：样例交接的证据记录和内容核验规则。
- **检验入口**：从任一交接结论回到对应代码或材料，复查是否支持该结论。
- **验收**：关键结论有可定位依据；未证实内容标为待核验；冲突项有处理结论或明确待决人。
- **难点**：代码能证明当前行为，却不一定能证明业务意图；两者须分开记录。

### R-5 固定 M1 可执行的产品边界

- **做法**：依据样例修订 PRD 的术语、首版范围和验收项。把 HTML 交互与模板重复生成写成可演示的结果，不写实现方案。
- **涉及范围**：ERP_Map 产品基线及 M1 的输入清单。
- **检验入口**：按 PRD 的 M1 验收项模拟一次产品验收，检查是否还需临场解释。
- **验收**：M1 能据此开始；每个验收项可观察；M0 未遗留影响地图结构的未决问题。
- **难点**：避免把样例中的 Dilee ERP 特例误定为所有 ERP 的通用规则。

## 3. 按什么阶段建设？

### 阶段 1：真实交接能否被追清

**覆盖**：R-1 选出能检验模型的真实交接、R-3 写出字段级交接样例、R-4 建立依据与差异口径。

**目标**：选出一条跨模块交接，并能沿当前代码说明它的触发、字段去向和分叉结果。

**任务**

- 试追“到货批次 → 来料质检 / 应付来源”的一条实际调用路径。
- 对照业务材料，列出当前实现与设计说法的差异。
- 按跨模块、分叉、字段变化和证据完整性决定保留或更换样例。
- 记录上游动作、下游结果、关键字段及一条异常路径。

**证明**：样例选择有理由；每个关键判断可返回依据；旧文档与当前实现的差异有状态。

**本阶段不做**：确定全站管线清单或编写 HTML。

### 阶段 2：同一段业务只有一种读法

**覆盖**：R-2 统一地图术语及归属、R-3 写出字段级交接样例、R-4 建立依据与差异口径。

**目标**：产品、业务、开发按同一组术语阅读样例，能指出每个 stage 的操作人和单据字段流向。

**任务**

- 用选定样例写出管线、stage、单据字段和交接的最小示范。
- 定义操作人、系统自动动作、字段快照、字段引用和核验状态。
- 用分叉与异常路径检查术语是否产生歧义。
- 请产品、业务、开发分别按样例回答“谁操作、什么字段流向哪里、为何推进”。

**证明**：三种视角的回答一致；分歧记录为待决并修订术语。缺少相应评审人时保留待核验状态，不宣布阶段完成。

**本阶段不做**：穷举 Dilee ERP 的所有 stage 与字段。

### 阶段 3：M1 可以按基线开工

**覆盖**：R-4 建立依据与差异口径、R-5 固定 M1 可执行的产品边界。

**目标**：M1 的制作者能仅凭 PRD 和样例判断要录入什么、怎样验收、哪些内容仍待核验。

**任务**

- 把已验证术语、样例结论和差异处理写回产品基线。
- 明确 M1 的管线广度、字段深度与 stage 操作人验收项。
- 明确单文件 HTML 的交互验收和相同输入、相同模板版本的重复生成验收。
- 做一次按验收项的桌面演练，关闭会改变地图结构的未决问题。

**证明**：PRD、术语与样例没有相互矛盾；M1 每项验收都有可观察结果；剩余问题有状态和解决人。

**本阶段不做**：实现 Skill、MCP、模板或地图页面。
