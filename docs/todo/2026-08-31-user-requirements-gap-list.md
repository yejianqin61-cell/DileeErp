1. 财务页曾只有加载分支，没有主 JSX，加载结束后页面为空；本轮已补齐工作台渲染。

3. 多项历史需求存在“接口或局部代码已完成、业务入口/状态闭环未完成”的情况，不能按完成验收。

## 详细待办

### TODO-01：采购单整单批次工作区

**原始要求**：采购单直接登记到货，允许第一批、第二批等动态列，并同步对应应付；用户可增删改，业务可回退。

**代码证据**：`apps/web/app/procurement/page.tsx` 已有 `renderBatchWorkflow`、到货编辑/撤销按钮和批次字段；`apps/api/src/modules/procurement/purchase-orders.service.ts` 已有 receipt 新增、PATCH、cancel。

**缺口**：当前详情页按采购物料分别渲染批次表，主采购单列表没有显著的“批次工作区”入口，无法一眼比较整单各批次；动态“应付”没有以整单列矩阵展示。

**实现与验收**：点击采购单号打开至少 80% 宽度 Sheet；一张表固定采购物料行，批次成组列（到货数量、应付金额、质检状态、入库数量）；批次可新增、编辑、撤销；已产生质检/入库/过账事实时只能走受控回退或冲销。

### TODO-02：到货、质检、入库批次状态机

**原始要求**：有到货就自动出现质检项目；同一采购单可多批质检和多批入库，显示采购单号及第几批；质检完成后可入库，状态可回退。

**当前状态**：到货创建质检和应付来源的后端逻辑已存在，采购页也有质检/入库列表。

**缺口**：需验证前端是否始终按 receipt 批次过滤，质检/入库状态是否可回退且不破坏库存及财务事实；目前页面列表缺少明确的“采购单 / 第 N 批”组合展示和统一批次状态链。

**验收**：每次到货自动生成一条 pending 质检；同一 receipt 可多次维护但不重复生成；质检通过才能生成可入库动作；入库支持 draft、posted、reversed（或等价）回退；所有列表显示订单号、采购单号、批次号。

### TODO-03：财务批次应付闭环

**原始要求**：到货批次应付流转到财务；财务增加应付对账，上游是原料到库。

**当前状态**：财务页加载应付来源、应付条目、供应商应付对账数据；本轮已修复财务页空白渲染。

**缺口**：需确认每个到货批次只生成一个可追踪 payable source，接收/过账/冲销后状态与采购单批次同步；应付对账需按供应商、订单号、批次聚合，不能只按总额。

**验收**：批次到货后财务出现待接收来源；接收应付可编辑金额但差异需原因；过账可核销；冲销可回退；对账可定位到采购单和批次。

### TODO-04：工序员工日报

**原始要求**：按生产单、工序隔离；按日期切换；同一员工同一工序同一天累加为一行；计件不强制时长，计时不强制计件数量；显示计划数量、是否超单为表头；增加当日员工总薪资。

**当前状态**：后端已有累加事务和唯一性处理，页面已有生产单/工序/日期分组及工资列。

**缺口**：历史上出现过“业务记录的 production_order_operation_id 已存在”和保存无网络请求问题，需补端到端回归；计件/计时条件校验、重复提交幂等、日报与计划数量超单计算需在真实数据库验证。

**验收**：四种组合（计件/计时、单次/重复）均可保存；重复录入同一自然键只更新累加行；切换日期和工序不串数据；日报保存后工资明细立即可查。

### TODO-05：工资页面与结算

**原始要求**：工资由每日薪资累加；工资总览独立页面，表格 CRUD；员工类型固定“车间/非车间”；车间按计件/计时，非车间由财务填写；生成工资台账按姓名检索。

**当前状态**：`apps/web/app/finance/salary/page.tsx` 已有车间/非车间分区；按姓名检索已修复。

**缺口**：需确认日报保存是否自动写入工资结算，工资总览是否真正支持增删改查及月份/期间，员工创建是否只能选择两个固定类型且后端也拒绝自定义值。

**验收**：日报提交即产生工资明细；同员工同日汇总；车间计件/计时字段互斥校验；非车间允许财务人工维护；工资台账按姓名、期间查询并可编辑。

### TODO-06：全站确认后编辑

**原始要求**：所有表单支持编辑；confirm 后可调整回 draft。

**缺口**：目前各模块状态机不一致，部分模块只允许 draft 编辑，部分仅有冲销接口。需要建立统一规则：无下游事实可退 draft；有事实必须走冲销/更正，并保留审计记录。

**验收**：销售单、采购单、BOM、到货、质检、入库、生产单、领料、财务单据逐一具备编辑或受控更正入口，错误状态返回明确原因。

### TODO-07：全站新增类目返回与刷新

**原始要求**：任意页面点击新增类目，保存后回到原填写页，原内容不丢失，下拉立即出现新类目并选中。

**当前状态**：`ActionDialog` 提供新增类目按钮，部分页面已有父级草稿恢复逻辑。

**缺口**：联系人、员工类型、绩效、质检、送检等入口曾出现点击无反应或提示需去业务页面；各页面刷新策略不统一。

**验收**：覆盖客户联系人、供应商、物料、单位、部门、岗位、员工类型、绩效类目、质检项目、送检项目；新增后原表单值完整恢复，选项列表无刷新也立即更新。

### TODO-08：人事模块

**原始要求**：员工筛选；入职/离职时间；离职状态机；员工可编辑；员工类型只允许车间/非车间；考勤选择日期和时间；绩效支持快速新建类目。

**缺口**：需逐项验证 API DTO、数据库约束、页面字段和编辑动作，尤其是离职时间与状态转换是否原子保存，绩效类目是否真的可从登记弹窗创建。

### TODO-09：生产基础资料

**原始要求**：工序池和加工地点池收进二级页面；生产单可自由选择工序；工序员工日报按生产单/工序隔离。

**缺口**：需确认导航和生产单表单是否使用池中数据，是否能新建、编辑、停用并在表单即时刷新；不能把所有工序平铺到主生产页面。

### TODO-10：PWA 与部署缓存

**原始要求**：PWA 壳不可丢失，线上更新后浏览器不加载旧 chunk。

**缺口**：历史出现 manifest 404、ChunkLoadError 和构建覆盖 `.next` 的问题。需检查 `manifest.webmanifest`、图标、service worker、Next 运行方式和反向代理缓存头；部署必须先停服务、解包到正确目录、安装依赖、迁移、构建、启动并做健康检查。

### TODO-11：物料主数据与 BOM 隔离

**原始要求**：物料清单独立 CRUD；BOM 物料名称使用统一物料唯一 ID；销售产品不能出现在物料清单；BOM 一张订单只能一份但可编辑。

**缺口**：需增加数据库级类型/来源约束和服务层校验，防止用户误把销售产品写入物料；采购、库存、BOM 必须使用同一 materialId，不允许名称替代唯一标识。

### TODO-12：仓库库存与生产领料

**原始要求**：原料仓储情况独立页面 CRUD；生产领料绑定生产单，按物料核算库存，表格 UI。

**当前状态**：已有原料库存页面和生产领料 Sheet。

**缺口**：需验证库存余额是否由入库/领料/退料/报废统一账务计算，编辑和冲销是否幂等，领料是否阻止负库存或给出明确补料流程。

### TODO-13：环境与部署一致性

**原始要求**：本地前后端和 Docker 可启动；远程增量部署可重复。

**缺口**：历史部署包曾错误打包用户 home 目录，导致 `package.json`、schema 和 ecosystem 不在目标目录；服务器还出现 Prisma CLI 版本不一致、npm ci 无 lockfile、PM2 指向旧路径等问题。

**验收**：发布包根目录必须包含 `package.json`、锁文件、`apps/api`、`apps/web`、`ecosystem.config.cjs`；服务器使用项目唯一 `.env`；部署后 `curl /api/v1/health` 返回 database=ok，3000/3001 端口可达；浏览器强刷后无旧 chunk 和 manifest 404。
