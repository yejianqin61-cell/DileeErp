# 迪礼 ERP V1.0 模块说明

## 模块总览

六个业务模块共享订单主线、基础资料、权限、状态机、审计字段、附件、字典和 REST API 规范。模块之间通过明确的业务 ID 关联，不直接读写其他模块内部实现。

| 模块 | English key | 核心职责 | V1.0 边界 |
| --- | --- | --- | --- |
| 生产 | production | 生产订单、生产任务、工序进度 | 不预设工序和自动排产 |
| 采购 | procurement | 供应商、采购计划、采购单及到货 | 分批到货规则待确认 |
| 财务 | finance | 应收、应付、收付款和余额 | 不做总账、税务和会计凭证 |
| 仓库 | warehouse | 原料/成品/退料/不良品库存、出入库、盘点 | 成本、批次、库位待确认 |
| 人事 | hr | 员工、考勤、绩效、薪资台账 | 不自动计薪，不做社保 |
| 客户池 | customers | 客户基础资料和客户池 | 不含询盘、报价、合同和接单转化 |

## 共享模块边界

以下能力属于平台层，不归属某个业务模块：账号认证、模块权限、数据字典、状态机、附件、编号、审计字段、逻辑删除、导出、打印/PDF、备份和系统设置。

## 生产模块（production）

### 职责

- 创建和维护订单及生产单。
- 记录订单关联的生产任务和工序进度。
- 为报表提供订单推进状态和工序进度数据。

### 关键关系

订单是根对象；生产单、工序进度、领料和成品检验通过订单号或业务外键关联。

### 待模块确认

工序名称/顺序、进度计量方式、订单物料清单、生产外发、返工和生产成本字段。

## 采购模块（procurement）

### 职责

- 维护供应商。
- 根据生产/物控需求建立采购计划和采购单。
- 记录到货并触发来料检验和原料入库关联。

### 关键关系

采购单关联订单、供应商、物料和到货/检验记录；库存变更由仓库模块完成。

### 待模块确认

采购计划来源、分批到货、退货、价格与币种、采购单状态和字段。

## 财务模块（finance）

### 职责

- 维护订单关联应收、应付、收款、付款和未结余额。
- 支持任意配置币种、原币金额和操作员手工汇率。
- 提供应收应付报表和导出。

### 明确不做

会计凭证、总账、税务申报、自动计薪和完整财务核算。

### 待模块确认

应收/应付形成节点、部分收付款、退款、对账和金额精度。

## 仓库模块（warehouse）

### 职责

- 分开管理原料、成品、退料和不良品。
- 处理入库、出库、领料、退料和手工盘点。
- 接收质量模块的合格/不合格数量分流结果。

### 关键规则

检验允许部分合格；合格数量进入可用库存，不合格数量进入不良品库存。盘点确认后生成库存调整记录。

### 待模块确认

实体仓库边界、库位、批次/批号、库存成本、单位换算、调拨和库存冻结。

## 人事模块（hr）

### 职责

- 员工名册、在职状态和系统账号关联。
- 考勤、绩效记录。
- 按周期人工维护薪资台账、实发金额和发放状态。

### 明确不做

根据考勤/绩效自动计薪、社保和复杂人事审批。

### 待模块确认

考勤来源、绩效周期、薪资字段、发放状态和个人数据可见范围。

## 客户池模块（customers）

### 职责

- 维护客户基础资料、联系人和客户状态。
- 为订单和财务提供客户关联。

### 明确不做

询盘、报价、成本核算报价、打样、英文合同和接单转化。

### 待模块确认

客户字段、联系人结构、客户分类、状态和重复客户处理方式。

## 模块依赖

```text
客户池 ─────┐
            ├── 订单/生产 ── 采购 ── 质量 ── 仓库
供应商 ─────┘       │                         │
                    └──────── 财务（应收/应付）

人事为所有经办人、账号和权限提供基础资料。
```

## 模块开发约定

1. 先完成平台层规范和模块负责人访谈，再实现具体模块业务。
2. 模块只能通过公共领域类型、服务接口或 REST API 使用其他模块能力。
3. 每个模块必须提供自己的领域目录、API 控制器/路由、数据访问边界和测试目录。
4. 未确认的业务规则使用显式 TODO 或待确认文档记录，不以默认值偷偷固化。
