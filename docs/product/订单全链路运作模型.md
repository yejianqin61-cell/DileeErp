# 迪礼 ERP V1.0 订单全链路运作模型

> 文档类型：项目级业务总览。
>
> 目的：从订单确认到成品出库、应收对账结束，统一说明迪礼 ERP 的订单主线和模块交接。模块字段、API 和页面细节以各模块设计文档为准。

## 1. 总览

`order_no` 是迪礼 ERP 全流程唯一认可的业务身份证，由销售人员人工填写且必须唯一。客户 PO、外部合同号、采购单号、生产单号、QC 记录、出入库单号、应收应付单号和收付款单号都是派生业务标识，均不能替代订单号。

订单全链路覆盖：

```text
客户 -> 销售单/订单确认 -> BOM -> 采购 -> 来料 QC -> 原料入库
                                        │
                                        v
生产单 -> 原料领料 -> 厂内生产/外加工 -> 成品 QC -> 成品入库
                                                           │
                                                           v
客户发货/成品出库 -> 应收来源 -> 应收确认 -> 收款/核销 -> 应收对账结束
```

人事财务模块与主链路并行：车间员工日报产生薪资来源，月度汇总为薪资台账；采购原料 QC 合格入库产生应付来源，付款后形成应付结算闭环。

## 2. 全链路维度

下表按正常订单的时间顺序描述主链路。分批采购、分批入库、分批领料、分批成品入库、分批发货和分批收款都属于同一订单主线的多次业务事实。

| 阶段 | 主责模块/角色 | 前置输入 | 形成的核心业务事实 | 关键输出与下游交接 |
| --- | --- | --- | --- | --- |
| 1. 客户与订单确认 | 销售 | 客户资料、客户需求 | 客户池、销售单、人工 `order_no`、一款产品的规格/数量/交期/价格及客户要求 | 销售单确认后，物控可依据销售单建 BOM；可按版本化模板导出 Excel |
| 2. BOM 建立 | 物控 | 已确认销售单及其版本 | 订单 BOM、来源销售单版本、物料需求 | 采购文员手工参考 BOM 创建采购单；生产可读取产品/工艺要求 |
| 3. 采购下单 | 采购 | 销售单、BOM、供应商、物料池 | 采购单与采购明细，关联 `order_no`、供应商、数量、单价、预计到货日期 | 供应商分批到货；采购单跟踪部分到货/已到齐/超收 |
| 4. 到货与来料 QC | 仓库、QC、采购 | 采购单明细、实际到货物料 | 到货/送检事实、来料 QC：合格、不合格、让步接收 | 合格/让步接收数量可入库；不合格进入不良品或退供应商处置 |
| 5. 原料分批入库 | 仓库 | 采购单、QC 可入库数量 | 原料入库单/明细、原料库存单余额 | 实际 QC 合格入库数量产生应付来源草稿；原料可被厂内生产领用 |
| 6. 应付确认与付款 | 财务 | 原料入库、采购价格、供应商 | 应付来源、应付单、付款及核销记录 | 支持按入库来源汇总、分批/一次性付款；退供应商、价格差异等通过冲销/调整处理 |
| 7. 生产任务建立 | 生产、物控 | 销售单、订单 BOM、订单要求 | 生产单，关联订单号、计划伞数、执行方式、工序任务和地点 | 厂内生产进入领料/日报；外加工记录地点、工艺说明与物料直发/签收 |
| 8. 原料领料与退料 | 仓库、车间、物控 | 厂内生产单、可用原料库存、BOM 参考量 | 原料出库（领料）、退料、损耗/报废、超领告警 | 领料减少原料库存；退料回仓；生产单可查看累计领料追溯 |
| 9. 生产执行与员工日报 | 生产、车间、物控 | 生产单、工序池、员工目录 | 工序日报、员工计件/计时日报、工序进度、超单/日报差异告警 | 生产完成后送成品 QC；员工日报为月度薪资来源 |
| 10. 成品 QC | QC、生产、仓库 | 厂内生产完成品或外加工回厂成品 | 成品 QC：合格、不合格、让步接收 | 合格/让步接收数量可成品入库；不合格进入不良品；外加工成品也可选择直接装柜发货 |
| 11. 成品分批入库 | 仓库 | 生产单、成品 QC 可入库数量 | 成品入库单/明细、成品库存单余额、与生产完成数量的差异告警 | 成品可按订单分批发货；库存不足禁止出库 |
| 12. 成品分批出库/发货 | 仓库、销售 | 订单号、成品可用库存、发货资料 | 成品出库、物流/签收资料、发货附件 | 成品出库自动形成可追溯应收来源草稿；支持分批发货、超发告警 |
| 13. 应收确认与收款核销 | 财务、销售 | 成品出库、销售单价格、客户、签收/物流参考 | 应收来源、应收单、收款及核销记录 | 支持一笔应收多次收款、一笔收款核销多笔应收；余额与账龄持续更新 |
| 14. 应收对账与订单结束 | 财务、销售 | 应收、收款、发票、对账资料 | 已收清/已关闭应收、对账状态、订单收支追溯记录 | 订单满足业务完成条件后由操作员维护为已完成；V1.0 不以系统自动状态替代人工订单关闭判断 |

### 2.1 厂内生产路径

```text
原料库存 -> 领料 -> 生产单工序日报 + 员工日报 -> 成品 QC -> 成品库存 -> 成品出库 -> 应收
```

生产单默认一个订单一张，但允许补单、返工和拆分生产单。工序日报用于生产进度，员工日报用于计件/计时薪资来源；二者不相等时产生差异告警。

### 2.2 外加工路径

```text
采购单 -> 外加工直发/外加工点签收 -> 外加工生产单
                                           ├─ 回厂：成品 QC -> 成品入库 -> 成品出库
                                           └─ 直接装柜：成品信息 -> 成品出库/发货
```

外加工现场的日报、员工薪资和生产进度不进入 ERP。直发物料不先虚构厂内库存；外加工余料、退料、损耗与回厂的详细库存口径由后续跨模块设计继续细化。

## 3. 多模块维度

| 模块 | 在订单链路中的职责 | 接收的上游数据 | 输出给下游的数据/事实 |
| --- | --- | --- | --- |
| 销售 | 客户池、销售单、订单产品要求、模板导出 | 客户需求、客户资料 | `order_no`、销售单版本、产品规格/数量/交期/价格、客户要求，供 BOM、生产、应收使用 |
| 物控/BOM | 将销售要求转为订单物料需求，并维护生产工序与领料参考 | 已确认销售单、产品/工艺/包装要求 | 订单 BOM、工序选择、领料参考量，供采购与生产使用 |
| 采购 | 按订单 BOM 采购物料并管理供应商和价格 | 销售单、BOM、物料池、供应商 | 采购单、采购明细、到货进度、采购价格，供 QC/原料入库/应付使用 |
| QC | 控制来料和成品进入可用库存的质量门禁 | 到货物料、生产完成品、外加工回厂成品 | 合格、不合格、让步接收数量，供仓库入库与不良品处置使用 |
| 仓库 | 以动态表单记录收发退调，以静态库存单汇总余额 | QC 结果、采购单、生产单、订单、成品发货资料 | 原料/成品入出库、库存余额、退料/不良品、发货事实，供生产、应收应付使用 |
| 生产 | 将订单转化为厂内/外加工生产任务，记录工序和员工生产日报 | 销售单、BOM、物料领用、员工目录 | 生产单、工序日报、员工日报、完成量、告警、成品 QC 送检依据 |
| 人事 | 员工目录、考勤、绩效和月度薪资台账 | 员工资料、生产员工日报、考勤/绩效 | 薪资来源、月度薪资台账、工资付款记录 |
| 财务 | 应收、应付、收款、付款、薪资付款和对账 | 销售单价格、成品出库、原料 QC 合格入库、员工薪资来源 | 应收应付余额、核销状态、账龄、付款/收款/工资付款、订单收支追溯 |
| 平台层 | 权限、审计、附件、状态机、字典、表单定义、模板和导出 | 所有模块的公共规则 | 统一身份、操作留痕、版本快照、附件、可配置类目和影响预览能力 |

## 4. 关键数据关系

```text
customer
  └─ sales_order (order_no, version)
       ├─ order_bom (sales_order_version)
       │   └─ purchase_order -> incoming_qc -> raw_material_stock_in -> payable_source
       ├─ production_order
       │   ├─ raw_material_stock_out / material_return
       │   ├─ operation_daily_report
       │   ├─ employee_daily_report -> payroll_ledger
       │   └─ finished_goods_qc -> finished_goods_stock_in -> finished_goods_stock_out -> receivable_source
       └─ sales_export_record

receivable_source -> receivable -> receipt / reconciliation
payable_source    -> payable    -> payment / reconciliation
```

所有箭头关系在数据库实现中使用内部 UUID 外键；`order_no` 冗余保存在关联业务事实中，用于查询、导出、审计和跨模块人工核对。

## 5. 结束条件与异常回退

### 5.1 正常订单结束

业务操作员在以下信息均已核对后，手工维护订单推进状态为“已完成”：

1. 销售单已确认，销售单版本、客户要求和导出资料可追溯；
2. 对应生产单已完成或已关闭，成品已按实际路径入库或直接装柜发货；
3. 所需成品已出库，物流/签收及发货资料已记录；
4. 成品出库形成的应收已确认、收款已核销、应收余额为零或已按财务规则完成调整；
5. 未解决告警、退货、差异和财务对账事项已由业务人员确认或处理。

V1.0 以人工维护订单状态为主。系统提供“生产完成、已出库、应收余额、未解决告警、对账状态”等提示，不强制自动关闭订单。

### 5.2 进退皆可

错误和异常不通过改写历史消失，而通过独立的业务事实回退：

| 发生点 | 受控回退方式 | 联动结果 |
| --- | --- | --- |
| 销售单/BOM 变更 | 新版本、差异/复核提示 | 不改写已确认 BOM、采购、生产、库存或财务事实 |
| 采购/原料问题 | 采购变更、QC 不合格、不良品、退供应商、冲销 | 更新采购进度、库存、应付来源或产生复核提示 |
| 领料/生产问题 | 领料冲销、退料、损耗、返工生产单 | 更新库存、领料追溯、生产进度和告警 |
| 成品/发货问题 | 成品退库、不良品、客户退货、补发、出库冲销 | 更新库存、出库进度、应收来源或产生财务调整提示 |
| 财务问题 | 红字/冲销、退款、补收、补付、独立调整 | 更新未核销余额、状态、账龄和对账记录，不改写原收付款 |

每次影响上游或下游的编辑，系统必须先提供影响预览。操作员确认后，库存余额、进度、金额余额、状态、告警和报表在同一事务中同步重算；独立确认的下游事实保留来源并通过冲销、调整或复核处理。

## 6. V1.0 仍待深化的边界

- QC 检验单的字段、抽检规则和不良品处置细节；
- BOM 的详细字段、版本界面和物料损耗/替代料规则；
- 销售单价格来源、预收/预付、超额核销和最终会计口径；
- 外加工费、余料/退料/损耗、成品回厂与直接装柜的详细结算和库存口径；
- 订单关闭的审批规则、自动提示阈值及消息通知。

这些事项不影响当前全链路主关系，但在进入相关模块开发前必须形成对应开发规格。
