# 迪礼伞业定制 ERP V1.0 软件需求规格说明书（SRS）

## 1. 文档目的

本文档将 PRD 中的全局产品决策落实为可执行的软件系统约束。模块级业务字段、工序、成本算法和具体状态值仍由对应业务负责人在模块规格中确认。

## 2. 系统边界

- 系统为厂内局域网 Web 应用，数据、数据库、上传文件和备份均保存在厂内。
- 前后端分离：浏览器访问前端，前端通过 REST API 访问后端。
- V1.0 不支持手机端、离线操作或仁和云实时集成。
- 核心业务范围：生产、采购、仓库、质量、销售客户池、应收应付、员工考勤/绩效/薪资台账、固定报表。

## 3. 技术栈

### 3.1 前端

- React + Next.js + TypeScript。
- 表格：TanStack Table。
- UI 组件：shadcn/ui。
- 表单：React Hook Form。
- 前端组件、颜色、间距、字体、断点和交互状态必须使用统一 design token；业务模块不得自行引入平行组件规范。

### 3.2 后端与数据

- NestJS + TypeScript。
- RESTful API，所有业务接口返回 JSON。
- 数据库：PostgreSQL。
- 数据库访问层、迁移和约束必须集中管理；禁止模块绕过 API 直接修改业务数据。

## 4. 全局数据规范

### 4.1 主键与 ID

- 所有业务表主键字段统一命名为 `id`。
- `id` 使用 UUID，应用层生成；推荐 UUID v7，以获得时间有序性。数据库不得使用自增整数作为业务主键。
- 外键统一使用关联表名加 `_id` 命名，例如 `order_id`、`supplier_id`、`created_by`。
- 业务可读编号（订单号、采购单号等）与数据库 `id` 分离。编号必须唯一，但格式由单据编号规则确认后实现。
- API 路径、JSON 字段和数据库字段统一使用 `snake_case`；TypeScript 内部变量可按项目 lint 规则使用 `camelCase`，边界层负责转换。

### 4.2 审计字段

除纯关联表、数据库内部表和明确标记为只读快照的表外，所有业务表必须包含：

```text
created_at  timestamp with time zone not null
updated_at  timestamp with time zone not null
created_by  uuid not null
updated_by  uuid not null
```

- 时间统一存 UTC，API 以 ISO 8601 字符串传输；界面按厂内时区显示。
- `created_by`、`updated_by` 关联用户表，不允许使用姓名文本代替。
- 新增、修改和逻辑删除必须写入上述字段；备注字段按业务表需要保留。
- 系统初始化或迁移数据没有真实经办人时，使用专用系统用户，不使用空值或虚构员工。

### 4.3 逻辑删除

- 禁止物理删除业务数据。
- 业务表统一使用 `deleted_at`、`deleted_by` 标记逻辑删除；需要删除备注时使用 `delete_remark`。
- 常规查询默认过滤已删除记录；管理员或专用恢复接口可查询。
- 被其他业务数据引用的记录不得通过删除破坏引用完整性；应提示停用或改为逻辑删除。

### 4.4 字典与可配置项

状态、计量单位、币种等业务字典存储在数据库中，通过管理接口维护，不写死在前端或后端代码中。已被业务数据引用的字典项不可物理删除，只能停用或逻辑删除。

## 5. 状态机规范

- 需要流程状态的实体必须定义状态集合和合法转换，不允许在各模块中散落字符串判断。
- 状态机由三部分组成：`state_definitions`（状态）、`state_transitions`（允许的来源/目标转换）、实体当前状态字段。
- 每次状态变更必须经过统一状态机服务校验；非法转换返回业务错误，不写入数据。
- V1.0 订单状态允许管理员增删改，初始状态值由 PRD 提供；人工维护为主，不强制根据其他单据自动流转。
- 状态变更接口必须记录实体 ID、原状态、目标状态、操作人、操作时间和备注；不要求单独的审计查询页面，但记录应可供实体详情展示和问题排查。
- 状态定义的删除采用停用/逻辑删除；已有历史记录继续保留原状态文本或状态 ID。

## 6. 附件系统规范

- 文件上传统一使用 `attachment` 领域模型，业务表不得自行设计 `file1`、`image_url` 等重复字段。
- `attachments` 至少包含：`id`、`file_name`、`storage_key`、`mime_type`、`file_size`、`sha256`、`created_at`、`updated_at`、`created_by`、`updated_by`、`deleted_at`、`deleted_by`。
- 通过统一关联表将附件关联到任意业务实体，至少记录 `entity_type`、`entity_id` 和可选备注。
- 文件内容保存厂内文件存储，数据库只保存元数据和存储键；API 通过受控下载接口提供文件，不暴露物理路径。
- 上传必须校验文件大小、MIME 类型和扩展名；文件名按原名展示，存储键使用不可预测的 UUID/哈希，避免路径冲突和路径穿越。
- 删除附件采用逻辑删除；物理清理由后续受控维护任务处理，不影响业务记录追溯。

## 7. REST API 规范

### 7.1 URL 与方法

- URL 使用复数资源名和小写 `kebab-case`，例如 `/api/v1/orders`、`/api/v1/purchase-orders`。
- `GET` 查询，`POST` 创建，`PATCH` 局部修改，`DELETE` 逻辑删除。
- 所有接口使用 `/api/v1` 版本前缀；破坏性契约变更必须升级版本。
- 列表接口统一支持分页、排序和可组合筛选；具体字段由模块规格定义。

### 7.2 JSON 返回结构

成功响应统一为：

```json
{
  "data": {},
  "meta": {}
}
```

列表 `data` 为数组，`meta` 至少可包含 `page`、`page_size`、`total`。

失败响应统一为：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数校验失败",
    "details": []
  }
}
```

- HTTP 状态码表达通用结果，`error.code` 表达稳定的业务错误类型。
- 日期时间使用 ISO 8601；金额不使用浮点数，API 以十进制字符串传输并明确币种。
- 所有写接口必须执行 DTO 校验、权限校验、事务处理和审计字段写入。

## 8. 认证与权限

- 每位操作员使用独立账号。
- 采用管理员 + 按模块授权的操作员模型；V1.0 不做逐字段权限。
- 未登录请求返回 `401`，已登录但无模块权限返回 `403`。
- API 不信任客户端提交的 `created_by`、`updated_by`，由服务端从当前登录用户上下文写入。

## 9. 事务与一致性

- 影响库存、订单关联、检验分流和应收应付余额的写操作必须在数据库事务中完成。
- 部分合格检验必须在同一事务内分别形成合格库存和不良品数量。
- 逻辑删除、状态变更和关联单据写入必须保持外键和业务约束一致。
- 并发冲突返回明确业务错误，不静默覆盖他人已更新的数据。

### 9.1 进退皆可与可追溯更正

- ERP 遵循“进退皆可”原则：业务可在状态机和权限允许范围内前进、退回或更正，但不得以直接覆盖方式抹除既有事实。
- “退”包括不良品分流、退料、退供应商、客户退货、冲销和独立调整；每一种退回动作均必须保留来源、原因、操作人、时间、关联单据和变更前后值。
- 对会影响上下游的修改，保存前必须展示影响预览：受影响单据、库存/数量/金额/状态变化、告警和需人工复核风险。操作员确认后，相关派生数据必须在同一事务中重新计算或更新。
- 静态余额类数据不得人工直接修改；库存余额、进度、应付来源等必须由动态业务事实、冲销和调整记录推导。
- 已独立确认的下游事实不得被上游编辑静默改写。系统保留原始来源并创建差异/复核提示；必要时由对应模块创建退货、冲销或调整记录。各模块必须定义可编辑状态、联动范围、风险提示、告警、撤销/调整和恢复规则。

## 10. 非功能要求

- 在厂内 2-3 名操作员并发下，常规列表和详情请求目标响应时间不超过 1 秒，复杂报表目标不超过 3 秒；上线后以真实数据校准。
- PostgreSQL、应用服务和附件存储每日自动备份到厂内独立存储设备，并完成恢复演练。
- 系统不依赖公网运行；依赖厂内局域网和服务器可用。
- 前端页面仅提供中文界面，但业务字段允许录入英文。

## 11. 测试要求

- API 契约测试：JSON 返回结构、HTTP 状态码、错误码、分页和筛选。
- 数据规范测试：UUID 主键、审计字段、逻辑删除、外键和唯一约束。
- 状态机测试：合法/非法转换、停用状态、变更备注和操作人记录。
- 附件测试：类型/大小校验、下载授权、逻辑删除和路径安全。
- 事务测试：检验分流、库存变更、财务余额和并发更新的一致性。
- 前端测试：TanStack Table 列表、React Hook Form 校验、shadcn/ui 交互和关键业务流程。

## 12. 未决事项

生产工序、订单物料清单、库存成本算法、单位换算、批次管理、附件业务范围、批量导入、单据编号格式等仍以 [0818初定义待确认事项](../memo/0818初定义待确认事项.md) 为准，在对应模块规格阶段确认。
