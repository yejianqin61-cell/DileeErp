> 用途：统一前端菜单、业务人员认知、后端模块边界和测试范围。
>
> 约定：`已接入` 表示已有可调用的后端接口或页面入口；`待完整验收` 表示主流程已有实现，但仍需真实上游数据、权限和异常场景验证；`待开发` 表示已纳入产品范围但当前不应视为可用。

## 一、菜单层级

一级菜单只保留业务入口，避免把表、接口和技术对象直接暴露给操作员：

1. 工作台
2. 销售
3. 采购
4. 质检（来料质检 / 成品质检 / 质检合格待入库与次品登记；从采购页与仓库页拆出的独立模块，入口 `/qc`）
5. 仓库
6. 生产
7. 人事
8. 财务
9. 报表

> 实际渲染顺序与图标以 `apps/web/components/layout/app-shell.tsx` 的 `navigation` 为准（当前为 工作台 / 生产 / 采购 / 质检 / 财务 / 仓库 / 人事 / 客户与销售 / 报表与告警）。

告警中心是跨模块入口，可从工作台和各业务模块进入，不单独制造一条业务链。基础资料、单位池、工序池、表单模板等放在所属模块的“基础资料”功能组中。

所有业务单据默认支持：查询、详情、编辑草稿、软删除/停用（按实体规则）、审计记录、附件关联、按 `order_no` 追溯。已经过账的数据不直接覆盖事实，使用更正、冲销或反向单据保持上下游自洽。

## 三、销售与客户

### 3.0 板块结构（2026-09-30 起）

销售一级页（`/sales`）是**纯导航页**，三个板块各有一个二级页面，每页只拉自己那一个接口：

| 二级页 | 内容 |
|---|---|
| `/sales/finished-goods` | 成品出库总览（按产品 + 单位汇总全部销售单的成品存量） |
| `/sales/customers` | 客户池（与 `/customers` 同一个组件；`/customers` 属「客户」栏目自己的入口） |
| `/sales/orders` | 销售单列表（详情 Sheet、出库通知、工艺单导出、货号筛选） |

> 详见 [销售板块二级页与明细列名设计](../design/sales-order-subpages-and-detail-labels-2026-09-30.md)。

### 3.2 销售单

- 新建销售单，人工录入 `order_no`：**已接入**
- **订单号更正（改号）+ 全链联动改名**：**已接入**（2026-09-30）。
  编辑器里订单号那一格可改（**任何时候都行**，含已确认、已有 BOM/采购/生产/入库/应付的单）；
  保存前先弹一张影响面确认（「将同步更新 N 类下游单据共 M 条」+ 历史版本快照 + 别的单上的返单来源），
  **原因必填**。确认后**一个事务**里改完全链：38 张冗余 `order_no` 的表 + 别的销售单上的
  `reorder_from_order_no` + 本单全部版本快照，末尾做残留校验（并发建单时整事务回滚让用户重试）。
  审计里**保留旧号**并另记一条 `sales_order.rename_order_no`（from→to + 逐表条数）——
  按旧号反查靠它。影响面预览与执行共用同一份登记表（`sales-order-order-no.ts`），
  并由一条 schema 覆盖守卫测试钉住「带 `order_no` 的表一个不漏」。
  - 修的是两件事：① 改号**真的能改**（此前这一格可编辑但 `save()` 会 `delete payload.order_no`，
    点保存不报错、号还是旧的）；② 改号**不会改一半**（此前 38 张表各自留着旧号，
    而采购找 BOM、领料聚合、财务报表反查客户、对账单取范围都按 `order_no` join，会静默少数据）。
  - `customer_id` 仍不可改（客户快照不能换头）；`order_no` **不进核心字段锁**：改号不动任何一张单的
    数量与金额，不该逼用户先回退整条链。
  - 见 [订单号更正与全链联动设计](../design/sales-order-no-rename-2026-09-30.md)
- 关联客户、外部合同号、产品和数量：**已接入**
- 草稿编辑、详情、列表筛选：**已接入**
- 销售确认、关闭：**已接入**
- 订单影响预览、审计时间线：**已接入**
- 销售单模板字段维护：**已接入（表单定义能力）**
- **工艺单（生产单）导出**：**已接入**（2026-09-16；2026-09-24、2026-09-30 两轮增强）。
  按 `example/销售单` 两张样本的并集版式导出（材料 18 项 / 工艺要求 9 项 / 布量 5 格 / 正唛侧唛 /
  明细分组），空盘位自动省略、工艺要求重新编号。
  - **行高按内容自动算**：ExcelJS 不做自动行高，所以服务端按「显示宽度 ÷ 跨列可用宽度」估折行数
    （汉字算 2 个单位、留 1 个单位余量、显式换行各占一行、左右两栏取 max；下限 20 磅、上限 300 磅）——
    修「行高需要自己调，太扁了」；
  - **材料明细 18 项可引用物料清单的物料**：每格既能手打文字、也能从**可搜索**的下拉里选一个物料
    （选中会把「名称 规格型号 颜色」填进格子并显示物料图片；清除引用不动已写好的文字）；
    **引用下拉里过长的物料文字换行显示**（不再是横向滚出可视范围）——2026-09-30；
    **格子空但引用了物料时，导出用引用的物料兜底印出来**（编码 + 名称 + 规格 + 颜色）——
    修「引用了的资料在导出的 excel 中无法显示」；
  - **导出时可勾选把哪些物料的图片一并带上**：图片排在本表**底部的图片区**（一排 5 张，
    每张下面写着「序号 + 栏位名 + 物料编码/名称」），用 oneCellAnchor 锚定，用户在 Excel 里自行拖拽。
    转换在**浏览器**里做（WebP → JPEG，最长边 640）—— **Excel 不认 WebP**，
    而服务端转码需要解码器（用户的拍板是不引那个原生依赖）；
    导出走 `POST /sales-orders/:id/production-sheet.xlsx`（multipart，字段名 = 栏位键）；
  - **工艺要求每一点带标题**：落格是 `序号.栏位中文名：内容`（如 `1.样品要求：…`），
    改造前只有 `1.<内容>`，看纸上的人得自己猜是哪一项；
  - **细分明细的列名可按单改**：`sales_orders.spec_detail_labels`（JSONB，默认 `{}`），
    编辑器「修改列名」一次改 6 格（留空 = 恢复默认名），导出件跟着这张单印；
    进版本快照、返单沿用来源单。

  见 [销售单工艺单导出设计](../design/sales-order-spec-refinement-and-production-sheet-export-2026-09-16.md)、
  [物料图片与销售单材料引用设计](../design/material-images-and-sales-order-material-refs-2026-09-24.md) 与
  [销售板块二级页与明细列名设计](../design/sales-order-subpages-and-detail-labels-2026-09-30.md)

### 4.2 采购计划（2026-09-27）

- **一个销售单的一份 BOM 一份计划**，新建时自动带出该 BOM 全部明细行并预填 BOM 上标过的供应商
  （只预填启用中的）：**已接入**（2026-09-27）
- 计划明细 **14 列**：选择 / 名称 / 型号 / 下单状态 / 本次采购量 / 当前库存量 / 单位 / 单价 /
  **行总价** / 供应商 / **供应商地址** / **联系人（含电话）** / 预计到货 / 操作；列宽固定、
  一次性展示全部列、超长省略且悬停看全文：**已接入**（2026-09-27；2026-09-30 行高与行内控件加高：
  内边距 8px、控件 34px、字号 12px，并加「行总价」列）
- **金额口径**（2026-09-30，用户：「添加价格字段，单价，总价。不然财务没法付钱」）：
  行总价 = 数量 × 单价（只读派生、本地即时算、不落列）；表下方给**计划合计 + 其中未下单**，
  计划列表给「计划金额」列 —— **一律按币种分列，不跨币种相加**；一行价都没填时显示「未填价」
  而不是 0：**已接入**（2026-09-30）
- **币种按行记**（`purchase_plan_items.currency`，默认人民币）：币种的决策点仍在「收束下单」预览里
  按供应商组选，下单时**写回该组每一行**，因此已下单行的币种永远等于那张采购单的币种；
  退回采购计划不清它：**已接入**（2026-09-30）
- **单价为 0 的行不能下单**（BOM 带出来的行单价就是 0，必须由采购员按报价填）：
  计划侧逐行校验、采购单侧的下单门禁同步收紧，前端在下单前也先拦一次并指出是第几行 ——
  否则 0 单价会一路变成一条 **0 元应付**，而全链路不报错：**已接入**（2026-09-30）
- **物料/单位已不在池里（停用、软删、改成成品）时，那一格仍显示这一行的名字**（从快照兜回来），
  不会退化成「请选择物料」；补回来的选项是 disabled（显示得出、选不到别的行上）：**已接入**（2026-09-30）
- **按供应商收束下单后自动流转到采购单**：同一事务建单 + 回写计划行链接，状态落成
  **已下单**（`ordered`），因此一定出现在采购单列表里（列表范围 = 已下单及之后）：
  **已接入**（2026-09-27；2026-09-30 补回归断言，见 `purchase-plans-service.test.cjs`）
- 供应商下拉里可就地**快速新建**并自动选中；地址/联系人是选中那家的**只读派生**：**已接入**（2026-09-27）
- **按供应商收束下单**（一组一张采购单，币种在收束预览里按组各选；没勾的行留在计划里，可多波次下单）：**已接入**（2026-09-27）

## 十一、依赖关系总览

```text
客户
  -> 销售单（order_no）
  -> BOM
  -> 生产单
       -> 原料需求 -> 采购单 -> 到货/QC -> 原料入库 -> 应付
       -> 厂内领料/外加工直发
       -> 工序日报、员工日报、薪资来源
       -> 成品 QC -> 成品入库 -> 成品出库 -> 应收
  -> 收款/付款/对账
  -> 订单关闭
```

`order_no` 是跨模块的业务身份证；采购单号、生产单号、入库单号、出库单号、检验单号、收付款单号等都是围绕它产生的业务单据号。任何编辑、冲销和更正都必须保留原操作人、时间、原因和影响范围。
