# 财务「会计科目」三处不一致排查（2026-11-04）

> 用户报障：厦门纳益联合专利代理事务所这笔支出，应付确认时选的是「损益类 / 销售费 推广费」，
> 但凭证模块显示「负债类 / 应付账款」，凭证单据里面又变成「管理费用 服务费」——
> 「会计科目要求是跟着收入支出一条龙走下去的，不仅要做凭证，财务三大报表都要用这个统计。」
>
> 排查结论先说：**三个值来自三个不同的字段，其中两个是系统设计、一个是财务手工改单**；
> 同时暴露一个真正的报表缺陷：**现金流量表按凭证业务分录科目落行，已挂账的付款一律被归成
> 「购买商品、接受劳务支付的现金」**，没有使用业务科目（收支类目）。

## 1. 这笔的线上事实（只读查询，生产库 `dilee_erp`）

供应商标识：`a3cee69d…` = 厦门纳益联合专利代理事务所有限公司

| 单据 | 值 | 字段 |
| --- | --- | --- |
| 应付条目 `APO-20261104-AC4E1120`（其他应付，¥2700） | 损益类 / **销售费 推广费** | `supplier_payable_entries.subject_id` |
| 收支流水 `CF-20261104-0F8879E3` 的「会计科目」 | 负债类 / **应付账款** | `cash_flow_entries.subject_id`（销账对方科目） |
| 收支流水同一行的「收支类目」 | 损益类 / **销售费 推广费** | `cash_flow_entries.category_subject_id`（业务科目） |
| 付款单 `SPAY-20261104-6DEBAD5D` | 销售费 推广费 | `supplier_payments.subject_id` |
| 挂账凭证 `记-2026-11-0002` 现分录 | 借 销售费推广费 / 贷 **银行存款 中国银行（人民币）** | `voucher_lines` |
| 付款凭证 `记-2026-11-0003`（已红冲）现分录 | 借 **管理费用 服务费** / 贷 银行存款—中国银行…642A | `voucher_lines` |
| 红字 `记-2026-11-0005` | 冲 0003（借 管理费用 服务费 的反向） | `voucher_lines` |

**凭证分录是被人手工改过的，不是系统生成的**：

- `voucher_lines` 行时间戳：0003 = 06:59:53（凭证 06:50:47 生成），0002 = 07:37:07（凭证 06:49:58 生成）；
- `audit_events`：`voucher.update`（`line_edited: true`）今天共 12 条，全部是财务账号 `caiwu / 财务` 在改；
- 线上运行的 `dist` 与本地 HEAD 的 `voucher.service.js` / `supplier-payment.service.js` **哈希完全一致**，
  所以能确定系统原本会生成什么：
  - 挂账（确认应付）= 借 **条目科目（销售费 推广费）** / 贷 **应付账款**；
  - 付款（销账）= 借 **应付账款** / 贷 **银行存款**。

即：**系统自动生成的两张凭证都符合权责发生制，业务科目也传到了挂账凭证的借方**；
现在看到的「管理费用 服务费」「贷 银行存款」是财务在凭证编辑器里手改的结果。

## 2. 为什么同一笔支出会出现三个科目

系统里「会计科目」不是一个字段，而是四个落点，各自服务不同环节：

| 落点 | 字段 | 谁写 | 用在哪 |
| --- | --- | --- | --- |
| ① 业务科目 | `supplier_payable_entries.subject_id` | 建单/导入/确认弹窗（人工选） | 应付台账「会计科目」；挂账凭证借方；流水「收支类目」 |
| ② 记账对方科目 | `cash_flow_entries.subject_id` | 系统按销账规则定（已挂账付款 = 应付账款） | 凭证业务分录；凭证摘要；现金流量表落行 |
| ③ 收支类目 | `cash_flow_entries.category_subject_id` | 系统从①带过来 | **目前只有「收支明细表」一列在用** |
| ④ 凭证分录科目 | `voucher_lines.subject_label` | 生成时取②；手工改后就是人工值 | 凭证纸；利润表/资产负债表/现金流量表取数 |

问题出在：界面把 ② 也叫「会计科目」，而 ③（真正的业务科目）**收支流水接口根本不返回、凭证模块不显示**。
财务在凭证模块看到「应付账款」→ 认为分类错了 → 直接去凭证编辑器改分录（④）→ 越改越乱。
今天 12 次 `line_edited`、这笔的 0002/0003 都是这么来的。

## 3. 真正的报表缺陷（用户要求里最硬的一条）

`finance-three-statements.ts` 的 `buildCashFlowStatement` 落行规则：
**按凭证里非资金分录（业务分录）的科目分类**。

权责发生制下，已挂账付款的付款凭证业务分录是「应付账款」，
而 `CASH_FLOW_STATEMENT` 里「应付账款」被归到第 5 行
**「购买商品、接受劳务支付的现金」**（`finance-three-statements.ts:317`）。
于是：

- 专利代理费 / 推广费 / 房租这类**已挂账的其他应付付款**，在现金流量表里全被算成「采购付款」；
- 它们本应按业务科目（销售费 推广费 → 第 8 行「支付其他与经营活动有关的现金」）；
- 业务科目明明存在（`category_subject_id`），但现金流量表取数链路里**完全没有用它**。

利润表/资产负债表按凭证分录科目统计，所以在凭证不被手改的前提下是对的（销售费推广费进「销售费用」）；
**现金流量表是错的**，这与「三大报表都用科目统计」的要求直接冲突。

## 4. 放大因素（代码缺口）

1. **改单不留痕**：`voucher.update` 的审计只记 `{ line_edited: true }`，不记改前/改后科目
   —— 本次排查只能靠行时间戳和代码反推。财务改错后没人说得清原来是什么。
2. **自动凭证可任意改**：没有「这是系统自动生成的凭证，改科目会与来源单据不一致」的提示，
   也不要求原因；改完不回写来源单据。
3. **挂账凭证没有「按来源重算」**：`regenerate` 只支持收支流水来源的凭证，挂账凭证改错只能红冲/删除。
4. **摘要把对方科目当类型**：`voucherSummaryFor` 用流水主科目拼摘要，
   付款凭证摘要就是「厦门纳益… · 应付账款（自动生成：supplier_payment / …）」——这正是用户说的「类型变成负债类」。

## 5. 修复建议

### P0 报表口径（需确认后执行，会改变历史报表数字）

- 现金流量表落行改为：**有收支类目就用类目**（业务科目），没有才退回凭证业务分录科目。
  这样纳益这笔会落「支付其他与经营活动有关的现金」，与利润表「销售费用」同口径。
- 取数链路：`slice()` 查凭证时带上 `cash_flow_entries.category_subject_id` 的科目名，
  `buildCashFlowStatement` 对现金凭证优先用类目匹配。
- 同步补测试：其他应付（已挂账）付款 → 落第 8 行；采购付款 → 仍落第 5 行。

### P1 展示打通（不改记账）

- `cash-flow.service` 的 `ENTRY_INCLUDE` 增加 `categorySubject`，接口返回收支类目；
- 凭证模块「收支流水」表加「收支类目」列；凭证详情显示来源流水的业务科目；
- 凭证摘要用收支类目（有则用）而不是主科目；文案把 ② 改叫「记账对方科目」。

### P2 护栏

- `voucher.update` 审计记 **before/after 分录科目**；
- 编辑自动生成的凭证时提示来源与影响、要求填原因（是否禁止改自动凭证的业务科目需拍板）；
- 挂账凭证补「按来源重算」（草稿状态）。

### P3 线上数据（写操作，需授权）

- 这笔：0002（已过账）贷方被改成银行存款；0003 已红冲、0005 是红字。
  建议按系统口径重做（红冲 0002 → 重开 借 销售费推广费/贷 应付账款；付款凭证重新按 借 应付账款/贷 银行存款 生成），
  具体动作必须财务确认后执行。

## 6. 统计口径现状（三大报表）

| 报表 | 取数 | 现状 |
| --- | --- | --- |
| 利润表 | 凭证分录科目（损益类） | 正确（挂账凭证借方 = 业务科目） |
| 资产负债表 | 凭证分录科目 | 正确（应付账款/银行存款按凭证） |
| 现金流量表 | 凭证业务分录科目 | **修复前错误**：第 5 行「购买商品支付的现金」把「应付账款/应付票据」写在「资产类」分支里，负债类一条都匹配不上 —— 已挂账的付款整笔落进 `unmapped`，现金流量表里钱凭空消失、期末现金与资产负债表勾稽不上（本轮已修，见 §7） |
| 收支明细表 | 主科目 + 收支类目两列 | 正确（类目已有） |
| 三大报表的凭证口径 | 只取 `posted` 凭证 | 手改后的凭证会原样进表（本次 0002 就是） |

## 7. 本轮已修（2026-11-04，按用户拍板）

用户拍板：**修现金流量表（有收支类目就按类目落行）**、**线上数据先不动**、凭证要支持**重新生成**。

### 7.1 现金流量表：按「收支类目」落行，并修掉第 5 行的分类 bug

- `finance-three-statements.ts`：
  - `StatementVoucher` 增加 `categorySubject`（来源流水的收支类目）；`buildCashFlowStatement`
    对每张凭证**优先按类目**匹配报表行，没有类目才退回凭证业务分录科目。
  - 第 5 行「购买商品、接受劳务支付的现金」的匹配条件拆开：
    `资产类（存货类 + 预付账款）` 与 `负债类（应付账款、应付票据）` 两个分支。
    修复前「应付账款」在资产类分支里永远匹配不上，已挂账付款整笔落进 `unmapped`。
- `finance-three-statements.service.ts`：取凭证时带 `sourceType/sourceId`，批量查
  `cash_flow_entries.category_subject_id` 并挂到本期/上期两张表的 `StatementVoucher` 上。
- 测试：
  - 内核：`categorySubject=损益类/销售费 推广费` 的付款凭证落第 8 行、第 5 行为 0；无类目时退回分录科目（应付账款 → 第 5 行）。
  - 取数：`cash_flow_entry` 来源的凭证带上类目，报表按类目落行。

### 7.2 凭证支持「重新生成」挂账凭证

- `voucher.service.ts`：
  - `regenerate` 对 `source_type = supplier_payable` 的草稿凭证走 `regenerateAccrual`：
    按来源应付单**现在的内容**重建「借 业务科目 / 贷 应付账款」。
  - 抽出 `accrualDraft` 供 `createAccrual` 与重新生成共用 —— 重新生成的结果与第一次生成**逐字一致**。
  - 边界：只对草稿开放；资金搬运类应付（科目是资金科目）拒绝并提示删除草稿；
    审计 `voucher.regenerate` 记改前/改后科目。
  - 应收挂账暂不开：它的对方科目是候选链推的，财务当初若选过别的收入科目，重算会把它换掉
    （等应收侧也有科目快照再开）。
- 前端 `voucher-workspace.tsx`：草稿的收支流水凭证、应付挂账凭证出现「重新生成」按钮；
  弹窗按来源说明重建规则（挂账凭证写明「借 业务科目 / 贷 应付账款」），成功提示区分来源。
- 测试：API 单测「挂账凭证重新生成：按来源应付单重建借业务科目/贷应付账款、覆盖手改分录、审计记改前/改后」；
  web 行为测试「挂账凭证也能重新生成」。

### 7.3 没做（用户口径）

- **线上这批已乱的凭证不动**（0002 贷方被改成银行存款、0003 已红冲、0005 红字），只修代码与以后的数据。
- 不阻止财务手工改分录（本轮只提供「重新生成」这条回退路径）；是否禁止改自动凭证的业务分录，待后续拍板。
- 收支流水接口仍未返回「收支类目」、凭证模块仍不显示它 —— 那是下一步的展示打通（P1），不在本轮范围。

## 8. 后续：P1「展示打通」已于 2026-11-05 完成

用户次日再次报障（同一笔链：确认应付 `APO-20261027-CE78BFBC` / 流水 `CF-20261105-9CFB412B`）：
「每一笔确认应付中选择的会计科目，到了收支流水中都是错的，但凭证里的会计科目又是对的」。
查库确认与 §1 完全同形（主科目 = 应付账款、收支类目 = 管理费用、挂账凭证借方 = 管理费用），

- 收支流水页 / 收支明细表 / 收支汇总表 / 凭证模块的流水表：「分类 / 项目」= 业务科目
  （`category_subject_id`，手工流水退回主科目）；
- 主科目（记账对方科目）退到明细表独立一列与流水页悬停提示，**生成凭证仍用它**；
- 筛选（`subject_id` / `category`）与显示同一口径，改类目走 `PATCH category_subject_id`。
