# 0821-05-04 原料流转冲销、审计与附件

## 状态

已完成

## 目标

让操作员能以严格反向事实更正已过账的领料、退料或报废，完整保留原始记录、库存变化、原因、审计与可选凭据，而不静默改写任何历史业务数据。

## 关联决策

- `raw-material-issue-return-scrap-inventory-chain-implementation-design.md` 的 4.3、4.4、4.6 节
- `warehouse-module-design.md` 的进退皆可和跨模块联动规则
- 编码路线图 A3、A6、D4

## 范围

- 提供已过账原料流转单的影响预览和整体冲销操作；冲销单逐明细生成严格反向库存/持有量影响，原单标记已冲销但继续可查；
- 在冲销后会造成可用库存负数，或会使后续退料/报废失去有效来源时拒绝操作；
- 固化“冲销原单 -> 新建正确草稿 -> 过账”的更正流程，禁止已过账单据直接修改、删除或局部冲销；
- 接入统一审计和 `attachment`，提供按 `order_no`、生产单、单据与对象查询的历史；
- 完成原料流转权限边界和冲销错误码的稳定测试。

## 非范围

- 审批流、全局告警中心和跨模块自动重算；
- 供应商退货、采购入库冲销逻辑重构或成品库存更正；
- 前端原料流转表单。

## 验收与验证

1. 已过账领料、退料和报废不能直接编辑或删除，只能整体冲销；原单、冲销单及其原因均可追溯。
2. 安全冲销准确还原库存或车间持有数量；不安全冲销因库存不足或下游事实存在而被拒绝。
3. 冲销与附件操作遵守既有权限和审计规则，且审计关联 `order_no`、生产单号、原单和冲销单。
4. API、独立 PostgreSQL 测试覆盖纠错主路径、下游门禁、无权限及重复冲销。
5. D4 后续数据不被静默回写，正确业务数据可通过新草稿重新过账。
