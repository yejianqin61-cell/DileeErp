# 0821-05-01 通用库存事实扩展与原料入库回归

## 状态

已完成

## 目标

在不改变既有采购来料 QC 入库可观察行为的前提下，将库存事实扩展为可承载后续生产领料、退料和冲销来源的追加式账本，为 D4 提供唯一可信的库存写入边界。

## 关联决策

- `raw-material-issue-return-scrap-inventory-chain-implementation-design.md` 的 4.2、4.3 节
- `warehouse-module-design.md` 的库存余额、进退皆可与审计规则
- 编码路线图 C4、D4

## 范围

- 演进库存事实的数据模型，使其保留既有原料入库来源关系，同时支持来源类型、来源记录、订单号、生产单和单位的通用追溯；
- 保持库存事实只追加、不直接编辑余额的规则，并提供按库存分类、物料和单位聚合有效余额的唯一服务边界；
- 迁移既有原料入库写入与查询逻辑，使入库、入库冲销和应付来源链路保持原有行为；
- 增加真实 PostgreSQL 回归，证明既有原料入库仍能形成正确库存事实与余额。

## 非范围

- 新建领料、退料、报废或冲销业务表单；
- 修改采购、QC、应付来源或生产单的业务规则；
- 仓位、批次成本、单位换算和盘点。

## 验收与验证

1. 原料入库与其既有冲销仍能以可追溯库存事实正确增减可用原料余额。
2. 库存事实可保留原料入库来源，并预留通用来源、订单号、生产单和原料流转明细关联，不破坏已存在记录。
3. 任意库存余额仍只能从有效事实聚合得出，业务 API 不存在直接修改余额的入口。
4. 数据库迁移可在独立 PostgreSQL 测试库执行；既有采购入库链路的单元、集成和 API 回归通过。
5. 审计、认证与统一 API 契约不回归，且 `verify:quick` 保持通过。
