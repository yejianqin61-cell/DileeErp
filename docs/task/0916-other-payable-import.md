# 任务：其他应付批量导入（模板 + 上传 → 应付草稿 → 对账/确认）

## 状态
已完成

## 认领
负责人：全栈 Agent
开始日期：2026-09-16

## 来源需求（用户原话）

「财务模块，应付管理，因为有一些非原料类的支出。也就是其他应付现在要支持批量导入这类应付对账条目。
我们提供模板，用户填写上传。直接进入应付对账。然后再流转到确认应付。」

用户选择：**只生成应付草稿**（不自动生成对账单）；供应商池里没有的对方**自动建档**；
模板七列（供应商编码 / 供应商名称 / 应付金额 / 币种 / 费用说明 / 确认日期 / 备注）。

设计见 [其他应付批量导入](../../design/other-payable-batch-import-2026-09-16.md)。

## 目标

- 财务能下载模板、填一批非原料支出（运费/房租/水电…）、上传，得到一批**应付草稿**；
- 这些草稿立刻出现在【应付对账 → 待创建对账】，也可以在【确认应付】勾选批量确认；
- 逐行错误可读、可定位；整批写库原子（不出现「半个文件进去了」）。

## 关联决策

- 导入产出**草稿**而不是对账单：确认应付本来就能直接批量确认草稿，两条下游路径都通；
- **按表头名认列**、行级错误不连坐、整批失败只有三种（找不到表头 / 缺必需列 / 没有数据行）——
  与员工花名册导入同一套纪律（操作员面对的是同一件事）；
- **同一份文件里的重复行直接拒绝**（同供应商+金额+币种+日期+说明）：重复入账等于重复付款；
- 供应商匹配顺序 **编码 → 名称 → 自动建档**，忽略大小写与空格；自动建档写审计；
- **写库一个事务**（与花名册导入的分批降级刻意不同）：宁可不写，也不要写一半让用户重传变重复；
- 入口放在「新建其他应付」旁边，权限与它一致（不额外要求管理员）。

## 范围与非范围

**做**：模板接口、导入接口（multipart）、解析口径纯函数、服务层导入编排（供应商匹配/建档 +
事务写库 + 审计）、前端「批量导入其他应付」弹窗（模板下载 / 上传 / 逐行结果 / 去应付对账入口）。

**不做**：导入批次号与幂等去重、撤销整次导入、附件列、按币种字典校验币种、并发换号重试。

## 决策记录

- **七列而不是六列**：提问时的选项标题写成了「六列」，实际列出并实现的是七列（含备注）。
- **金额与币种的容错只做「归一化」不做「猜测」**：千分位/货币符号/全角数字认得出就归一化；
  币种认不出就报错，绝不静默按 CNY —— 币种错了，账就错了。
- **自动建档写 `supplier.create_from_payable_import` 审计**：财务的导入会改动采购模块的主数据，
  这件事必须在审计里看得见。
- **结果面板不做成 toast**：「第 7 行金额不合法」这类信息必须逐条可读；
  文案只留数据与去处（遵守财务页 2026-09-16 第①条「说明性语句全部去掉」）。
- **`import-template.xlsx` 必须排在 `payable-entries/:id` 之前**：否则会被当成一个 id 匹配掉。
