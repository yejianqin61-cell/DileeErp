**本轮：9 项变更，8 项完成，1 项放弃。查询工具调用失败率从 11.5% 降到 1.4%。**

## 2. 这意味着什么

**方向没变，但排序依据换了。**P0 猜「失败多发生在模型选错工具」，实测证明是工具目录缺动作；于是 P1 按缺陷补入口，没有做那场会改掉模型 schema、执行器与 33 条断言的大重构。

代价要说清：剩下的 1.4% 是设计意图，不是缺陷 —— 伪造句柄必须被拒。而 `model_steps` 中位数 3 才是下一个真正压用户的地方，它对应时延，而降它要改上下文形状，不是砍工具。

## 3. 仍开放

- 上下文只有最近 8 轮问答、工具事实全丢，所以长追问链会越来越慢。
- 流式渲染无节流与手写 markdown，长答案必然卡；KaTeX、Mermaid、代码高亮都没有。
- 前端仍是自建会话页，自动标题、分支、编辑重发、草稿、附件都没做。
- 注释全量清除还没动手；白名单已在设计稿定好，但代码没扫过。
- `finance_positive` 只验到「读得到」，金额数值的正确性口径没定，所以没断言。
