# 0821-06-04 日报差异、超单告警与审计

## 状态

已完成（2026-08-22）

## 目标

在日报变化时自动、可审计地维护超单和工序日报/员工日报差异告警，不阻止真实生产事实保存。

## 关联决策

- D5 设计 4.4、4.5、4.8 节
- 编码路线图 D5、G3

## 范围

- 实现告警重算服务：超单按生产单工序累计量触发，差异按生产单/工序/日期两套日报件数触发；
- 实现告警列表、详情、确认、审计查询和按订单/生产单/工序/日期/状态筛选 API；
- 固定 `pending -> confirmed/recovered`，恢复后异常复回 `pending` 的状态规则；
- 将日报写入、累计重算、告警更新和审计放入同一数据库事务。

## 非范围

- 全局告警中心、消息推送、处理人指派、审批流和告警忽略状态；
- 成品、库存或应收应付告警。

## 验收与验证

1. 超过目标量生成单一持续 `over_order` 告警，后续继续报工更新同一告警而非重复创建。
2. 同日两套日报数量不等生成 `daily_discrepancy`；相等时自动恢复并保留历史数量和时间。
3. 告警确认必须填写备注；已确认告警再次异常自动回到待处理并写审计。
4. 任一日报变更失败时，累计进度、告警和审计不得部分提交。

## 完成记录

- 新增生产日报告警列表、详情、确认和审计查询 API；
- 告警统一使用 `pending`、`confirmed`、`recovered` 生命周期，确认必须填写备注；
- 超单与日报差异按复合业务键持续更新，避免重复告警；数量恢复一致时自动恢复，已确认告警在数量变化后回到待处理；
- 日报变更事务内写入告警重算审计事件，告警确认事务内写入确认审计事件；
- 验证：`npm run build --workspace=@dilee/api` 通过，事务及接口场景由 task 07 统一回归。
