# T10 期初余额写入校验科目

## 1. 这份任务在哪

- **Phase 2 报表不再靠名字认科目**，目标是财务新增一个科目时三张报表都点名它没归位。
- **本任务把期初余额的写入从「自由文本」变成「必须指向真实科目」**：T3 已经落了主键并回未归位清单，但写入时不存在的科目仍然照收——报表随后就少一块。
- **开始于**：T3 已落科目主键。**后续等它**：无（Phase 2 收尾任务之一）。

## 2. 开发前需要知道什么

**先读**

- `apps/api/src/modules/finance/opening-balance.service.ts` — `normalize`、`replaceAll` 与 T3 新加的 `resolveOpeningSubjectIds`。
- `apps/api/src/modules/finance/opening-balance.controller.ts` — 请求体字段与长度限制。
- `apps/api/test/unit/opening-balance-service.test.cjs` — T3 新加的那六条用例，判据与它们一致。

**已定**

- 新建科目不存在 → **422 拒绝**，并给出可选科目。期初是建账的起点，收一笔不存在的科目等于让它从报表里消失。
- 同名跨分类且没写分类 → **不拒绝**，留空并进未归位清单（T3 的口径，沿用不动）。两者区别：前者是「写错了」，后者是「写得不够」，一个该拦一个该提示。
- 已停用的科目：允许，因为它可能正是历史账上的科目，但要计数提示。

**边界与缝**

- 触及期初余额的写入校验与响应。不碰报表侧。
- 缝：既有期初余额服务测试入口。不新增缝。

**运行**

- `npm run build --workspace=@dilee/api`
- `node --test apps/api/test/unit/opening-balance-service.test.cjs`
- `npx tsc -p apps/api/tsconfig.json --noEmit`

**未知**

- 拒绝会让「历史期初一次性导入」变难：导入件里的科目名可能全是旧名。若如此，需要一个「忽略校验」的显式开关，并写进未知项而不是悄悄放开。

## 3. 流程

1. 读上面三个文件，用一句话复述本任务。
2. 写一条会失败的测试：填一个不存在的科目 → 422，且不落库。
3. 在 `replaceAll` 里区分「不存在」与「归不上」两种情形。
4. 停用科目放行但计入提示。
5. 跑构建、类型检查与测试。
6. 提交。
