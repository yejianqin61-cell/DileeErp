# T8 报表行与科目的对应关系落成数据

## 1. 这份任务在哪

- **Phase 2 报表不再靠名字认科目**，目标是财务新增一个科目时三张报表都点名它没归位。
- **本任务把「哪个科目进哪一行」从代码里的字符串比对搬成数据**：今天 63 处 `named()` / `prefixed()` 写在行定义里，财务改名或新增科目时它们全部失配。
- **开始于**：T6 补了资产负债表缺口出口、T7 补齐了成本类归属。**后续等它**：报表取数按科目身份归集。

## 2. 开发前需要知道什么

**先读**

- `apps/api/src/modules/finance/finance-three-statements.ts` — 三张表的行定义、`named/prefixed/only/anyOf` 四个匹配器、`checkStatementCoverage`。
- `apps/api/src/modules/finance/accounting-subject-catalog.ts` — 122 条科目的分类与名称，映射的初始数据来源于此。
- `apps/api/prisma/schema.prisma` 的 `AccountingSubject` — 映射要能指向它（主键或编码）。

**已定**

- 映射的键是**科目主键**，不是名字也不是编码的字符串派生。名字只是显示文案，编码是身份，映射必须认身份。
- 初始映射由现有规则**生成**，不手工抄 122 行：写一个只跑一次的脚本/迁移，按今天的 `named/prefixed` 逐条算出，产物进库。
- 代码里的行定义保留 `named/prefixed` 作为**回退**：历史行没有主键时仍要靠文本。两者并存，不是二选一。
- 未映射的科目一律留空，由 T6 的缺口出口点名。

**边界与缝**

- 触及报表内核、行定义、一条数据迁移。不碰凭证与流水的写入路径。
- 缝：既有报表内核测试入口，加一条「映射覆盖度」断言。不新增缝。

**运行**

- `npm run build --workspace=@dilee/api`
- `node --test apps/api/test/unit/finance-three-statements.test.cjs apps/api/test/unit/accounting-subject-catalog.test.cjs`
- `npx tsc -p apps/api/tsconfig.json --noEmit`
- `npx prisma migrate status`

**未知**

- 生成初始映射时，`prefixed(...)` 会命中多条科目；一条科目落两行是错的。若发现今天存在重叠，先在这里停下来说明，不要顺手改口径。

## 3. 流程

1. 读上面三个文件，用一句话复述本任务。
2. 先写一条会失败的测试：给定一份科目主键，报表行按映射落行（而不是按名字）。
3. 把映射落成数据（新列或新表），并写生成初始映射的迁移。
4. 报表内核接受「按主键查到的行号」，`named/prefixed` 降为回退。
5. 加一条守卫：122 条科目每条最多只能映射到一行。
6. 跑构建、类型检查、测试与迁移状态。
7. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 缝 |
| --- | --- | --- | --- |
| 1 | 一条带主键、名字改成「运费」的科目 | 按映射仍落「销售费用」行 | 报表内核 |
| 2 | 一条带主键、名字改成任意文本的科目 | 落行结果与改名前一模一样 | 报表内核 |
| 3 | 一条没有主键、名字是旧名的历史行 | 走 `named/prefixed` 回退，落同一行 | 报表内核 |
| 4 | 122 条科目的初始映射 | 无科目被两行认领 | 内核守卫 |
| 5 | 迁移前后同一批凭证 | 三张报表每一格逐格相等 | 内核 + 迁移 |
