## 目标

实现销售单草稿、订单号校验、版本、确认和影响预览 API，建立后续全部订单模块可复用的上游事实。

## 范围

- 销售单列表、详情、创建、草稿编辑、逻辑删除和订单号可用性检查；
- 固定核心字段、客户/联系人快照、表单定义版本和扩展字段结构化值的校验与保存；
- `draft -> confirmed -> closed` 状态机配置和确认业务动作；
- 确认前必填校验、订单号唯一性、数量/单位/金额十进制传输和销售权限校验；
- 编辑影响预览：本任务至少识别 BOM 是否存在，并返回不可自动改写下游的复核提示；
- 销售单版本、审计日志、状态变化和稳定错误码。

## 非范围

- 采购、生产、库存、应收来源；
- Excel 模板、导出、打印和配色/花色详细业务规则；
- BOM 创建本身。

## 验收与验证

1. 手工输入的重复订单号返回 `409 ORDER_NO_CONFLICT`，数据库中不会出现重复有效订单。
2. 草稿可编辑；确认只允许在所有核心必填项完整时执行。
3. 非法状态跳转返回 `422 INVALID_STATE_TRANSITION`，并且不写入状态记录。
4. 确认事务中同时写入当前状态、状态变更和审计事实。
5. 已关联 BOM 的销售编辑返回影响预览；BOM 不会被静默修改。
6. API 的成功、校验、权限、冲突和业务规则错误均符合全局契约。
