# 编码阶段全链路待办清单

## 用途

本清单是迪礼 ERP V1.0 后续编码的唯一总待办。每一项完成后才可进入依赖它的项；实施时仍需在对应目录创建可认领的细化任务，并在完成后更新本清单、每日开发日志和测试记录。

状态说明：`已完成` 表示代码、构建与静态/运行态检查已完成；`后置验证` 表示 PostgreSQL 真实环境验收留待部署前执行；`待开发` 表示尚未开始。

## 依赖总览

```text
平台运行基线
  -> 销售订单主身份
  -> BOM 明细 / 基础资料
  -> 采购 -> 来料 QC -> 原料入库 -> 应付
                          -> 生产单 -> 领退料 -> 生产日报 -> 成品 QC -> 成品入库 -> 发货 -> 应收
                                              -> 薪资来源 -> 月度薪资 -> 工资支付
  -> 报表、导出、预警、部署验收
```

`order_no` 始终贯穿所有订单相关事实；采购单号、生产单号、QC 单号、出入库单号和收付款单号均为派生编号，不能替代订单号。

## 推荐实施顺序

1. 完成 A4-A7，尤其是 PostgreSQL 实测、版本化表单、影响预览和基础资料。
2. 完成 B3-B4，使 BOM 真正成为采购与生产可用的物控清单。
3. 交付 C1-C6，先得到“采购 -> 来料 QC -> 原料入库 -> 应付”的第一个中游闭环。
4. 交付 D1-D7，建立生产、领料和员工日报/薪资来源事实。
5. 交付 E1-E5，完成从成品检验到应收对账的订单主链闭环。
6. 交付 F1-F3，完成员工考勤、绩效、薪资及工资支付闭环。
7. 最后交付 G1-G5，完成运营可见性、报表、厂内上线和历史数据导入。

## 不在本清单内

- 询盘、报价、打样、英文合同、审批流、移动端、离线操作、仁和云实时对接；
- 未经业务负责人确认的新字段、成本算法、外加工结算口径或会计总账规则。

新增业务规则必须先更新对应模块设计或 memo，再新增本清单条目或细化开发任务。
