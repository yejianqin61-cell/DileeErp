# 编码阶段全链路待办清单

## 用途

本清单是迪礼 ERP V1.0 后续编码的唯一总待办。每一项完成后才可进入依赖它的项；实施时仍需在对应目录创建可认领的细化任务，并在完成后更新本清单、每日开发日志和测试记录。

状态说明：`已完成` 表示该项范围内的代码与真实测试环境验收均已完成；`部分完成` 表示已有可用的上游能力或子范围，但不得把未实现的后续事实混入已交付范围；`后置验证` 表示部署前必须执行、尚未完成的现场验证；`待开发` 表示尚未开始。

## 当前链路快照

| 链路 | 当前状态 | 已验证范围 | 后续缺口 |

现有链路的完整用户旅程测试应随相关表单补齐，但不阻塞下一个纵向业务切片；每个新切片必须在完成时纳入 `verify:chain`。

## 依赖总览

```text
平台运行基线
  -> 销售订单主身份
  -> BOM 明细 / 基础资料
  -> 采购 -> 来料 QC -> 原料入库 -> 应付
                          -> 生产单 -> 领退料 -> 生产日报 -> 成品 QC -> 成品入库 -> 发货 -> 应收
                                              -> 薪资来源 -> 月度薪资 -> 工资支付
  -> 报表、导出、预警、部署验收
```

`order_no` 始终贯穿所有订单相关事实；采购单号、生产单号、QC 单号、出入库单号和收付款单号均为派生编号，不能替代订单号。

## 推荐实施顺序

1. 已完成 D1-D3：部门/岗位/员工目录、工序池与工序计价，以及基于已发布 BOM 的厂内/外加工生产单均已通过真实数据库、API 与浏览器验收。它们是后续生产事实的共同来源。
2. D4 已完成：原料领料、退料、报废及库存联动已形成可追溯闭环，并通过真实数据库、API 和浏览器验收。
3. D5 已完成并形成可供 F2/D7 复用的生产日报与告警事实；D6 已完成外加工物料直发、签收、余料回厂、成品回厂和直装柜来源事实；D7 已完成生产进度、生产计量、订单状态、阻塞建议和工作台。D6/D7 的真实 PostgreSQL/API/浏览器回归仍是部署前验证项。
4. 交付 E1-E5，完成从成品检验到应收对账的订单主链闭环。
5. 回到 C6，完成应付确认、付款和核销；它只依赖已有应付来源，适合作为独立财务切片推进。
6. 交付 F1-F3，完成员工考勤、绩效、薪资及工资支付闭环。
7. 最后交付 G1-G5，完成运营可见性、报表、厂内上线和历史数据导入。

## 当前下一步建议（E1）

下一条链路建议实施 E1：成品送检与成品 QC。D7 已关闭开发任务；D7 仅保留真实环境回归验证。

选择理由：

1. E1 可直接消费 D7 的生产单完成条件、订单推进状态和外加工成品回厂来源。
2. 成品 QC 是成品入库、成品出库、发货资料和应收链路的必要门禁，依赖关系清晰且不会重复建设生产事实。
3. E1 应继续按合格/条件接收/不合格分流，保留 `order_no`、生产单、来源批次、操作人、时间和审计记录。
4. D7 的真实环境回归可与 E1 集成测试一起执行，但不能用 E1 的代码替代 D7 的后置验证。

建议实施顺序：先维护日报字段/状态机和差异规则设计，再拆 API/数据库、前端工作台、真实 PostgreSQL/API/Playwright 验收任务；每次日报过账都必须保留 `order_no`、生产单号、工序、员工、操作时间和审计记录。

## 不在本清单内

- 询盘、报价、打样、英文合同、审批流、移动端、离线操作、仁和云实时对接；
- 未经业务负责人确认的新字段、成本算法、外加工结算口径或会计总账规则。

新增业务规则必须先更新对应模块设计或 memo，再新增本清单条目或细化开发任务。
