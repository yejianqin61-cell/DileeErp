# 0821-04-01 组织、员工与生产执行地点

## 状态

已完成

## 目标

让管理员和物控员通过真实 API 与页面维护部门、岗位、员工及厂内车间/外加工点，为生产单提供可追溯且可停用的人员与地点来源。

## 关联决策

- `employee-operation-production-order-chain-implementation-design.md` 的 4.1、4.3、4.5 节
- `production-module-design.md` 的生产执行地点与审计规则
- 编码路线图 D1、A7

## 范围

- 建立部门、岗位、员工和生产执行地点的持久化模型、REST API、权限和基础资料页面；
- 员工包含工号、姓名、部门、岗位、员工类型、在职状态、可选系统账号、入离职日期与备注；不保存身份证或银行卡；
- 地点区分 `workshop` 与 `outsource_site`；外加工点维护联系人、联系方式和地址；
- 新建时只能选择启用的部门、岗位和地点；停用保留历史引用，不做物理删除；
- 创建、编辑、停用和恢复均使用统一审计日志。

## 非范围

- 考勤、绩效、生产日报、薪资和工资支付；
- 工序、工序计价和生产单；
- 外加工直发、余料回收或加工费结算。

## 验收与验证

1. 管理员可完成部门、岗位、员工、车间和外加工点的创建、查询、编辑、停用与恢复。
2. 停用的岗位和地点不可用于新员工或新生产单来源选择，已关联历史仍可查看。
3. 员工工号、部门/岗位有效关系和地点类型字段有服务端校验；无权限请求返回统一 403 错误。
4. 每次变更具备四个审计字段及操作审计事件。
5. 增加规则、HTTP/API、真实 PostgreSQL 与浏览器基础资料验收用例，并纳入现有测试入口。
