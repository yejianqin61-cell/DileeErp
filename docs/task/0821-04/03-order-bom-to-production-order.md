# 0821-04-03 已确认订单和 BOM 到草稿生产单

## 状态

已完成

## 目标

让物控员以已确认销售订单和已发布 BOM 创建厂内或外加工草稿生产单，使订单的 `order_no`、BOM 版本与执行地点成为不可混淆的生产任务来源。

## 关联决策

- `employee-operation-production-order-chain-implementation-design.md` 的 2、4.2、4.3 节
- 编码路线图 D3、B4

## 范围

- 生产单持久化模型、派生生产单号、列表/详情/创建/编辑/草稿删除 API；
- 创建时由服务端以 `order_no` 解析已确认订单，并保存订单 UUID、`order_no`、已发布 BOM UUID 和版本快照；
- 支持 `standard`、`supplement`、`rework`、`split`；非标准单必须关联同订单父生产单并填写原因；
- 区分 `in_house` 与 `outsourced`，校验地点类型、计划数量、单位、产品规格与工艺说明预留字段；
- 同订单不施加一个生产单的数据库唯一限制，但新建标准单时展示已有生产单提示；
- 草稿生产单可逻辑删除并记录原因及审计。

## 非范围

- 生产单工序、生产状态动作、日报、领料、外加工直发；
- BOM 自动展开为固定工艺路线；
- 销售单或 BOM 的编辑语义变更。

## 验收与验证

1. 已确认订单与已发布 BOM 可创建草稿生产单，详情完整显示 `order_no`、BOM 版本、生产单号和地点。
2. 未确认订单、未发布 BOM、订单号与客户端来源不一致、无效地点类型、零或负计划数均被拒绝。
3. 同订单允许标准单之外的补单/返工/拆分单，但父单跨订单或缺少原因被拒绝。
4. 草稿逻辑删除后不再参与正常列表，审计仍可追溯；已进入后续状态的删除限制由 04 实施。
5. 增加真实 PostgreSQL 原子性测试，断言订单 UUID、冗余 `order_no` 和 BOM 快照始终一致。
