## 目标

把采购单页现有的**草稿工作区整套搬到计划详情 Sheet**：13 列一次展示完（固定宽度、不横向滚动）、
供应商那一格可下拉可选可**快速新建**、勾选本次要下的行后**按供应商收束预览**（每组选币种）→ 下单。

这是本批次的**主界面**，也是"原来在采购单页干的活"的新家。

## 口径与决策（依据设计文档）

- **口径 9**：13 列（选择/名称/型号/下单状态/本次采购量/当前库存量/单位/单价/**供应商**/**供应商地址**/
  **联系人（含电话）**/预计到货/操作）；「需求量」→「本次采购量」；`contact_name` + `phone` 合并一列。
- **口径 3**：供应商来自计划行（新建计划时已从 BOM 预填），采购员只处理例外。
- **口径 4**：供应商 = 下拉 + 下拉里快速新建；**地址/联系人是只读派生**（不可改）。
- **口径 5**：编辑表只保证"列不超出容器"（编辑格里是输入框/下拉框，不做省略号）。
- **口径 6**：勾选本次要下的行（默认全选）→ 收束下单；**下过的行留在计划里**并显示 PO 号。
- **口径 10**：**每个供应商分组各选一个币种**（默认 CNY）。
- **§6.2**：13 列的宽度表（百分比，和为 100）。
- **§6.1**：结构照搬 `orders/page.tsx` 现有的草稿工作区（它整套搬过来）。

## 实施要点

### 1. 13 列的固定宽度（§6.2，逐列抄）

| 列 | 宽 | 列 | 宽 |
| --- | --- | --- | --- |
| 选择 | 3% | 单价 | 7% |
| 名称 | 11% | 供应商 | 11% |
| 型号 | 8% | 供应商地址 | 12% |
| 下单状态 | 9% | 联系人 | 9% |
| 本次采购量 | 7% | 预计到货 | 7% |
| 当前库存量 | 7% | 操作 | 4% |
| 单位 | 5% | | |

- 和必须为 100；**故意**没有横向滚动（口径 5）：编辑表用固定布局把 13 列压在容器内。
- 编辑格里**不**加 `cell-ellipsis`（对输入框做省略没有意义）。
- 地址/联系人两格是**只读文本**（口径 4）：显示选中供应商的地址与「联系人 / 电话」；
  供应商没选时显示 `-`。

### 2. 供应商格（口径 3/4）

- 直接用现成组件 `apps/web/components/bom/supplier-select.tsx`（下拉 + 「＋ 新建供应商「xxx」」）；
  **不要**复制一份到 procurement 目录 —— 两个副本一定会漂移。
- 选完把 `supplier_id` 写进行状态；地址/联系人**不写**（它们是从供应商关系/快照派生的）。
- 快速新建成功后，把新供应商并进本页的供应商池（`onCreated`），并**自动选中**该行。

### 3. 行状态与保存

- 行状态：`id`（既有行）/ `material_id` + `material_snapshot` / `unit_id` + `unit_snapshot` /
  `bom_item_id` / `supplier_id` / `model` / `quantity` / `unit_price` / `expected_date`。
- 保存 = `PATCH /purchase-plans/:id`（整体替换行）+ `expected_updated_at`（打开时拿到的）。
- 冲突（422）时**照 BOM 工作区的写法**：显示提示、**保留本地改动**、给"重新加载（放弃本次修改）"入口，
  **不静默覆盖**。
- **已下单行**（`purchase_order_item_id` 非空）在界面上：显示 PO 号、**禁用删除**、
  **内容列一律只读**（物料/单位/数量/单价/供应商，下拉与输入框都 `disabled` 或改成只读文本），
  **两个例外**：**行序（`sequence`）允许拖动**、**预计到货允许改**
  （设计文档 §4.1 的两个例外：序号是展示、预计到货是"预期"而非既成事实，且口径 7 关掉了采购单页的
  明细编辑，这里是它唯一的通路）—— 见 [T03](./03-plan-save-and-delete.md) 的规则。
  预计到货改完保存后服务端会同步进那张采购明细。要改**其它**内容必须**先退回采购计划**，
  所以禁用态的 `title` 里要写清这一句；
  被服务端 422（`PURCHASE_PLAN_ORDERED_LINE_LOCKED` / `_REMOVED`）拒绝时把原因原样显示出来。

### 4. 收束预览与下单（口径 6/10）

- 勾选默认**全选未下单行**（已下单行不参与本次下单）。
- 按 `supplier_id` 分组；**没选供应商的行单独一组并明确标红**（不能下单，要给指路文案）。
- 每组一个**币种下拉**（默认 `CNY`），来自既有币种字典（`lib/currency-catalogue`）。
- 预览每组显示：供应商 / 行数 / 金额合计（按该组币种）/ 币种选择。
- 下单 → `POST /purchase-plans/:id/order` → 成功后**刷新详情**（行上出现 PO 号）并提示
  "已下单 N 张"；失败把服务端原因原样显示。
- 下单后**已下单行仍留在表里**（口径 6）——不要在前端把它们过滤掉。

### 5. 当前库存量（口径 9 的第 6 列）

- 该列是**物料当前库存**（原料仓），数据来自既有库存读侧（`GET /materials` 或库存接口里已有的字段）。
  **不要**在本任务里新写库存汇总逻辑；找不到现成来源就按既有采购单草稿表那一列的做法取值
  （它已经有一列"当前库存"，照它取）。

### 6. 新建计划的落地路径

- [T09](./09-web-plans-list-page.md) 的新建流程建完 → 直接打开本 Sheet（`?plan_id=`），
  行已带好 BOM 明细与预填供应商（口径 2/3）。

## 决策记录

- **复用 `components/bom/supplier-select.tsx` 而不是新建一个**：同一份下拉 + 快速新建逻辑，
  抄一份出来的两个副本会在"新建失败怎么办""同名怎么办"这些细节上慢慢分叉。
- **已下单行留在表里**（不折叠、不移到另一个 tab）：口径 6 的理由是"已下单行离开工作面 =
  没人再想得起来还差什么"。
- **币种按组而不是按计划**：口径 10——一张采购单一个币种，而一张采购单=一个供应商。
