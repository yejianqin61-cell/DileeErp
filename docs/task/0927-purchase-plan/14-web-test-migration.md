## 目标

让前端测试与**新的界面结构**一致：原来压在采购单页上的 4 个测试文件，其覆盖点已经被搬到计划页
（或已经不再是页面行为），逐个搬迁/重写；并补上计划页自己的新用例（列表、详情 Sheet、收束下单）。

**不要**为了让测试变绿而放宽断言：这一批的界面改动很大，放宽断言等于把"改错了"藏起来。

## 口径与决策（依据设计文档）

- **§6.1**：计划详情/编辑的结构照搬 `orders/page.tsx` 的草稿工作区（**整套搬过来**）——
  所以那 4 个文件里针对草稿工作区的断言，语义仍然成立，只是**渲染目标换成了计划页**。
- **§6.3**：采购单页保留"列表（已下单及之后）、导出、到货跟踪、关闭到货、打印字段填写" ——
  这几块的断言**留在采购单页**。
- **§6.5 / §9 第 6 条**：jsdom **不排版**，所以列宽/省略号的"生效与否"**不能**用组件测试证明，
  只能断言类名与 `title`；真正的观感靠部署后目测。这条要写进完成记录，免得下一个人以为测过了。

## 实施要点

### 1. 搬迁边界（本任务最容易做错的地方）

| 覆盖点 | 去哪 | 依据 |
| --- | --- | --- |
| 草稿工作区：添加/删除行、保存草稿、按供应商收束、下单 | **计划页** | §6.1（整套搬过来） |
| 「下单状态」列（累计口径 + 本行 PO 号） | **计划页** | 口径 13（数据源改为计划行） |
| 按 BOM 编辑明细 | **计划页** | 口径 7 |
| `?order_no=` 深链预置筛选 | **计划页列表** | 口径 14（列表列含订单号/货号） |
| 打印字段填写（付款方式/交期条款/交货地址/回签） | **采购单页（留下，文件不搬）** | §6.3 保留清单 |
| 导出、到货跟踪、关闭到货 | **采购单页（留下，文件不搬）** | §6.3 保留清单 |
| 「退回采购计划」 | **采购单页（新增断言）** | §6.3 + 口径 15 ③ |
| 「新建采购单」「草稿 tab」「编辑」「下单」入口 | **删掉断言**（入口不存在了） | §6.3 删除清单 |

- 所以**实际被搬迁的是 3 个文件**（draft / collapse / deeplink），
  `procurement-order-print.test.tsx` **原地保留**，只改它断言的按钮集合。
- 搬过去的文件要**同时更新**：`vi.mock("next/navigation")` 的 pathname、`api-stub` 里的 URL 前缀
  （`/purchase-plans…`）、以及"页面根 testid"。
- **不要** copy 一份旧文件再改：那会留下两个断言同一件事的文件，其中一个会随代码漂移。

### 3. jsdom 不能证明的事（写进完成记录）

- 列宽是否真的生效、省略号是否出现、有没有横向滚动条 —— **组件测试证明不了**（jsdom 不排版）。
  能断言的只有：类名（`data-table-fixed` / `cell-ellipsis`）与 `title`（hover 全文的来源）。
- 所以完成记录里要写清"哪些断言是行为、哪些只是结构"，并在部署后按设计文档 §9 第 3 条目测。

### 4. 迁移时的纪律

- 被搬走的 3 个文件，搬完之后**旧文件必须消失**（不是留着"以防万一"）；
  `procurement-order-print.test.tsx` **原地不动**，只在按钮集合变化时改那几条断言。
- 断言要按**新行为**重写，不要为了让旧断言通过而给页面加兼容分支。
- 全量跑：`cd apps/web; npm run test:unit`（`test:lib` + `test:components` 都要绿）。
