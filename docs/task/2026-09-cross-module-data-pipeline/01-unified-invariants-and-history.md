# 01 — 统一业务约束与历史日报清理

**What to build:** 建立跨模块共享的物料、库存和日报数据约束，并在唯一性约束上线前安全处理历史重复日报。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

## 当前执行记录（2026-09-03）

- 已存在并纳入迁移 `20260903100000_unified_daily_report_invariants`：同工序同日工序日报、同工序/员工/日期/计薪方式员工日报建立有效记录唯一索引；历史同键记录合并数量、时长、金额并软删除，多计薪方式记录进入异常表。
- BOM、采购和原料入库/领料入口已校验 `raw_material` 边界；库存共享余额入口也拒绝成品物料事实。
- 当前仍未勾选本任务验收项：历史迁移守恒、异常清单处置和 PostgreSQL 并发/迁移执行需要真实测试数据库验证。

- [ ] BOM 和采购明细后端只接受启用的 `raw_material`，成品只能进入成品链路；BOM 外采购物料必须记录新增原因。
- [ ] 原料入库接口强制使用 `raw_material` 库存类别，非法类别被拒绝。
- [ ] 盘点工序日报和员工日报重复业务键，保证数量、时长、金额合并后守恒。
- [ ] 同一员工同工序同日同时存在计件和计时的数据不自动合并，形成可处理异常清单。
- [ ] 合并后的旧记录软删除并保留合并关系、操作人、时间和原因。
- [ ] 清理完成后增加并验证防重复约束或等效事务门禁。
- [ ] 提供重复请求、并发写入、非法物料类型和非法库存分类的 API/数据库测试。
