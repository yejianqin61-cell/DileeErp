# 07 — 工资台账刷新与跨模块编辑治理

**What to build:** 让生产工资来源可靠进入工资台账，并统一销售、采购、质检、入库、财务单据的草稿编辑、受控回退和快照治理。

**Blocked by:** 02 — 采购与应付管线；04 — 生产日报与工资来源；05 — 生产完工；06 — 成品与应收管线

**Status:** in-progress

## 本次增量实现记录（2026-09-03）

- 已完成工资台账回退状态收紧：仅 `confirmed`（已确认）和 `expired`（已过期）允许回到 `draft`（草稿）。
- `partially_paid`、`paid`、`closed` 台账拒绝直接回退，并返回“请使用工资调整单”的明确错误。
- 回退成功写入 `payroll_ledger.reopen` 审计事件，记录回退前后状态。
- 已完成日报工资来源刷新：日报新增、修改、删除及非车间清理会在同一事务中重算覆盖日期范围内的草稿台账；已确认/支付台账只转为 `expired`，不改写已支付事实。
- 已新增领域规则测试，覆盖可回退与不可回退状态；API 构建通过。
- 已完成采购单受控回退校验：`ordered` 回退 `draft` 必须提交原因；有到货事实仍禁止回退，原因写入审计详情。
- 已完成工资台账前端入口对齐：新建台账按员工工号 UUID 提交，避免同名歧义；仅 `confirmed`/`expired` 展示回退和编辑，确认台账编辑要求填写原因，已支付/关闭不展示直接编辑入口。
- 已完成销售单确认后编辑入口治理：确认销售单编辑对话框要求填写修改原因，与后端受控编辑规则一致。
- 已完成销售单受控回退：仅无 BOM、采购或生产下游事实的已确认销售单可回到草稿，必须填写原因并记录审计；销售页已提供对应入口。
- 已完成同名员工生成台账的候选返回：按姓名命中多人时，API 在错误详情中返回员工 UUID、工号、姓名和员工类型，调用方可据此选择具体工号。
- 已修正 HR 综合页工资台账入口：只有 `paid` 状态显示“关闭”，避免对 `confirmed` 台账提供后端不允许的操作。
- 工资台账回退现统一要求填写原因；财务工资页通过原因对话框提交，HR 综合页不再提供无法填写原因的快捷入口。
