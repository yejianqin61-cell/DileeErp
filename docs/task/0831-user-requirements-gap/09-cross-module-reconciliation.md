# 09 — 库存边界、订单对账与业务身份回归验收

**What to build:** 以订单号完成采购、库存、质检、生产、成品和财务的最终对账视图，收紧原料/成品边界和库存维度，并完成最低业务链路真实回归。

**Blocked by:** 03、04、05、06、07、08

**Status:** ready-for-agent

- [ ] 库存余额只由有效库存事实派生，按物料 ID、物料名称/编码、单位、类别和订单号展示，禁止跨单位聚合。
- [ ] 销售成品不会进入原料物料池、BOM、采购或生产领料候选；领料负库存有明确补料流程。
- [ ] 订单工作台显示采购需求、到货、QC、入库、待/已确认应付、付款及生产/成品数量金额差异。
- [ ] 业务页面使用姓名、编号、供应商/客户、单据号和订单号定位，不向用户暴露 UUID。
- [ ] 真实环境完成“销售单 -> BOM -> 采购 -> 到货 -> QC -> 入库 -> 应付 -> 付款对账”链路。
- [ ] 真实环境完成“生产单 -> 日报 -> 工资 -> 成品质检 -> 入库 -> 出库 -> 应收 -> 收款”链路。
- [ ] 两条链路均验证幂等、权限、审计、冲销、数量金额快照和无负库存。
