# T2 编码对外只读

## 1. 这份任务在哪

- **Phase 1 科目有了身份证**，目标是改一个科目名之后所有报表数字一个都不变。
- **本任务把 R-1 科目有不可变编码 的第二半落到写入口**：新建科目自动拿编码，改科目改不动编码。
- **开始于**：T1 给科目加不可变编码。**后续等它**：期初余额落主键。

## 2. 开发前需要知道什么

**先读**

- `apps/api/src/modules/finance/accounting-subject.service.ts` — 新建与修改的校验顺序，`nextSortOrder` 怎么取下一个排序号。
- `apps/api/src/modules/finance/accounting-subject.controller.ts` — 请求体字段与长度限制，哪些字段对外暴露。
- `apps/api/test/unit/accounting-subject-service.test.cjs` — 服务层测试用的替身是怎么搭的。

**已定**

- 编码由服务端生成，请求体里不接收 `code`。客户端传了也忽略，不报错。
- 生成规则与 T1 相同：由 `sortOrder` 推出，因此新建科目的编码唯一性继承排序号的唯一性。
- 修改接口不接受 `code` 字段，且不提供「重算编码」的入口。

**边界与缝**

- 触及科目主数据的服务与控制器。不碰迁移、凭证、报表。
- 缝：既有科目主数据服务单元测试入口。不新增缝。

**运行**

- `npm run build --workspace=@dilee/api`
- `node --test apps/api/test/unit/accounting-subject-service.test.cjs`
- `npx tsc -p apps/api/tsconfig.json --noEmit`

**未知**

- 若服务层测试用的是真实 Prisma 而不是替身，本任务需要先补替身。遇到就停下来说明，不自行造一套测试基建。

## 3. 流程

1. 读上面三个文件，用一句话复述本任务。
2. 让新建路径在落库前算出编码。
3. 让修改路径的字段白名单排除编码。
4. 让查询接口把编码带出去，且不能被写回。
5. 补用例：新建拿到编码、修改改不动编码、传了编码被忽略。
6. 跑构建、类型检查与测试。
7. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 缝 |
| --- | --- | --- | --- |
| 1 | 在空分类下新建科目 | 返回体带编码，格式 `S` 加 4 位数字 | 科目服务 |
| 2 | 修改请求里带一个不同的 `code` | 库里编码不变，接口仍成功 | 科目服务 |
| 3 | 新建请求里带一个自定义 `code` | 忽略传入值，用服务端生成的 | 科目服务 |
| 4 | 修改科目名称 | 编码不变，名称已改 | 科目服务 |
| 5 | 修改科目 `sortOrder` | 编码不变 | 科目服务 |
