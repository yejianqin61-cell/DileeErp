# T5 改名回归用例

## 1. 这份任务在哪

- **Phase 1 科目有了身份证**，目标是改一个科目名之后所有报表数字一个都不变。
- **本任务把这句话钉成一条会失败的测试**：今天没有这条用例，所以「改名就错」只能靠人记得。
- **开始于**：T1 给科目加不可变编码。**后续等它**：Phase 2 报表不再靠名字认科目 会复用这条用例。

## 2. 开发前需要知道什么

**先读**

- `apps/api/src/modules/finance/finance-three-statements.ts` — 报表内核怎么把凭证行归集成借贷累计，`subjectKeyOfLine` 怎么取键。
- `apps/api/test/unit/finance-three-statements.test.cjs` — 既有报表用例怎么造凭证行、怎么断言金额。
- `apps/api/src/modules/finance/finance-three-statements.service.ts` 的科目索引段 — 主键键与文本键怎么并存。

**已定**

- 这条用例断言的是「有主键时改名字不影响金额」，不涉及只存文本的历史行。历史行的行为由 T4 的回填处理。
- 用例放在既有报表内核测试文件里，不新建测试文件、不新增缝。
- 用例必须能在今天失败一次（先红），再靠 T1 的编码落位转绿。

**边界与缝**

- 触及报表内核测试。不碰业务代码（本任务只加测试）。
- 缝：既有报表内核测试入口。不新增缝。

**运行**

- `npm run build --workspace=@dilee/api`
- `node --test apps/api/test/unit/finance-three-statements.test.cjs`
- `npx tsc -p apps/api/tsconfig.json --noEmit`

**未知**

- 如果报表内核今天对「同一主键、不同文本」的行会拆成两个桶，这条用例会先红后需要改内核。若如此，停下来说明，因为这已超出「只加测试」的范围。

## 3. 流程

1. 读上面三个文件，用一句话复述本任务。
2. 造一批凭证行，每行都带科目主键与当时的科目文本。
3. 用改名前的文本跑一次利润表，记下金额。
4. 换一批同样主键、但文本改成新名字的行，再跑一次。
5. 断言两次金额相等。
6. 再断言「只改了文本、主键不同」时金额会变，证明这条用例真的在测主键而不是在测常量。
7. 跑构建、类型检查与测试。
8. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 缝 |
| --- | --- | --- | --- |
| 1 | 同一主键，文本由旧名换新名 | 利润表该行金额不变 | 报表内核 |
| 2 | 同一主键，文本由旧名换新名 | 资产负债表该行金额不变 | 报表内核 |
| 3 | 不同主键，文本相同 | 两张报表金额都变化 | 报表内核 |
| 4 | 主键为空，文本是旧名 | 金额落在旧名对应的行 | 报表内核 |
| 5 | 主键存在但科目已停用 | 金额仍按主键归集，不落空 | 报表内核 |
