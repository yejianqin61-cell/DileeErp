# T3 期初余额落科目主键

## 1. 这份任务在哪

- **Phase 1 科目有了身份证**，目标是改一个科目名之后所有报表数字一个都不变。
- **本任务把期初余额从「只认科目文本」改成「认科目主键」**：期初是唯一一张连科目外键都没有的业务表。
- **开始于**：T1 给科目加不可变编码。**后续等它**：历史快照回填。

## 2. 开发前需要知道什么

**先读**

- `apps/api/src/modules/finance/opening-balance.service.ts` — 整批替换的三条口径，以及 `normalize` 现在只校验文本。
- `apps/api/prisma/schema.prisma` 的 `AccountingOpeningBalance` — 唯一键是哪三列，为什么没有 `subject_id`。
- `apps/api/src/modules/finance/finance-three-statements.service.ts` 的期初合并段 — 报表怎么把期初的文本键解析成科目。

**已定**

- 加可空 `subject_id` 外键，指向科目主键。可空是因为历史行可能归不上。
- 唯一键保持原样，不改成按主键。理由：软删行的唯一键占位依赖现有三列，改了会让「删掉一行再加回来」撞索引。
- 写入时先按科目解析出主键，再落库；解析不到就不阻断，留空并回给调用方一条提示。

**边界与缝**

- 触及期初余额的 schema、服务、报表取数的期初合并。不碰凭证与流水。
- 缝：既有期初余额服务单元测试入口。不新增缝。

**运行**

- `npm run build --workspace=@dilee/api`
- `node --test apps/api/test/unit/finance-three-statements-service.test.cjs`
- `npx tsc -p apps/api/tsconfig.json --noEmit`

**未知**

- 报表侧现在按「唯一同名」把文本键解析成主键。加了外键之后有两条解析路径，要确认不会同一条期初被算两次。

## 3. 流程

1. 读上面三个文件，用一句话复述本任务。
2. 给期初余额加可空科目外键与关系。
3. 写迁移：加列、按唯一同名回填、建索引。
4. 让写入路径解析科目主键并落库。
5. 让报表取数优先用主键，文本键只作历史兜底。
6. 补用例：期初落主键、归不上时留空并提示、两条解析路径不重复计数。
7. 跑构建、类型检查与测试。
8. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 缝 |
| --- | --- | --- | --- |
