# 任务 2：后端按指定轮次组上下文

<task-brief>

## 1. 在哪里

- **阶段 7 会话能像样地用**。
- **本任务推进 R-9**：编辑重发后，模型只看当前分支上的历史。
- **开工前提**：无。**后续**：任务 5。

## 2. 要知道的

**先读**

- 模块内 `context-manager.ts`：现在取哪 8 轮、过滤什么。
- `business-query-agent.dto.ts` 与控制器 `createRun`：请求体与幂等。
- `agent-orchestrator.ts` 的 `run`：上下文在哪里取。
- `apps/api/test/unit/agent-context-manager.test.cjs`：现有行为。

**已定**

- `CreateRunDto` 加可选 `context_run_ids`：UUID 数组，最多 200 项。
- 不传：行为与现在完全一样。传空数组：不带任何历史。
- 任一号不属于本人本会话：400 `AGENT_CONTEXT_INVALID`，不建轮次、不占并发许可。
- 传入的轮次仍按现有规则过滤（只要已完成、当前档位可读），按创建时间排序后取最后 8 轮。
- **不落库**：只经内存传给编排器。幂等命中时返回原轮次，忽略本次的数组。

**边界与接缝**

- 动 DTO、控制器、编排器、上下文管理器。接缝：控制器与 `AgentContextManager.history`。不改表。

**运行**

- `npm run test:unit:api`，`npm run typecheck`

**可能卡住**

- 编排器 `run` 的现有调用方（含回放脚本）需要同步改签名才能编译：新参数必须可省略；做不到就停下上报。

## 4. 用例

会话里有完成轮次甲、乙、丙（按时间）。

| # | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 不传 | 上下文含甲乙丙三对问答 | `history` |
| 2 | 传 `[丙, 甲]`；传 `[]` | 依次甲、丙；空 | `history` |
| 3 | 普通档位传入一个 full 轮次与一个未完成轮次 | 两者都不进上下文 | `history` |
| 4 | 传入他人会话的轮次号 | 400，轮次数不增，随后能正常提问 | 控制器 |
| 5 | 传 `[甲]` 提问 | 模型收到的历史只有甲；轮次表与事件表不含这份数组 | 控制器与脚本模型 |
