## 2. What it means

目录让「该用列表入口」的问法直接走对了，但整体时延没有改善：平均步数从 2.83 升到 3.04，工具调用次数没有增加。
步数多出来的部分与缺口声明、目录展开同时出现（带缺口声明的平均 3.70 步，不带的 2.96 步），这是相关，没有做对照实验。

失败码超限的 4 项里 3 项是伪造句柄用例按设计被拒，三轮各一次；判据按「1/70」写时没有为它单列。

漂移率不能直接当基线：缺口题用普通账号提问，10 题里 5 题标注的是财务工具，该账号看不到。
只算工具可见的 5 题，是 15 条声明 3 条不一致（20%），全部落在同一题。

最需要知道的一条：普通账号问财务数据，15 次全部报了缺口且被放行，答复说系统查不到。实际是没有权限。
按现在的门槛，三个会话问同一类问题就会生成一张「缺工具」候选。

过程：首次全量在第 3 轮中途因模型账户余额耗尽中断，充值后只补跑 54 项，其余原样保留。

验证：全套 `npm run test` 退出码 0（部署门禁 122、API 3260、实验装置 35、web lib 457、web 组件 1537）。
评测环境是一次性数据库加模拟数据，跑完已删除。

## 3. Still open

- 步数中位数目标未达成，没有做任何针对性改动。
- 无权限的财务问题仍会生成缺口声明与候选，线上用户也会看到「查不到」而非「没有权限」。
- 缺口题的账号档位与标注不匹配，漂移率没有可用的干净基线。
- 通过率只看终态、来源、调用与少量数字断言，答案其余数值没有核对。
- 缺口题没有断言「应该声明」，通过只代表问答正常结束。
- 模型费用没有记录。
- P2 八个阶段的代码都未推送、未部署；阶段 4、7 的两条迁移与缺口表授权上线时要处理。
