# P2 施工计划：工具目录、缺口判定、前端换装

日期：2026-11-24｜状态：待施工｜类型：施工计划

设计：[迪礼顾问 P2 设计](../design/dilee-consultant-p2-tool-catalog-2026-11-24.md)。
基线：[P1 报告](../review/agent-golden-p1-2026-11-23.md)。

## 0. 结论

**七个阶段，按「最可能推翻计划的东西先做」排序。**先让模型看见目录，再让缺口可被证明，
然后才把它变成工单；前端换装排在后面，因为它是唯一不会推翻其余决策的一块。

最贵的假设只有一条：**闭合矩阵能让模型不试错就报缺口**。它排在第二阶段，验证不过就停在观测层，
不动前端。

## 2. 做法，逐条

### R-1 L1 模块目录常驻 prompt

- **Approach**：六个模块各一段声明，含「管什么、四轴取值、不支持什么」。生成而非手写，随能力表变化。
- **Touches**：查询编排层，工具注册表。
- **Test seam**：现有 provider 的 plan 调用，检查系统指令文本。不新增接缝。
- **Acceptance**：
  - [ ] prompt 里六模块各一段，每段含四轴与否定清单
  - [ ] 增删一条 capability 后 prompt 自动跟随，不需手改文案
  - [ ] 财务档不可见时，prompt 里没有财务模块
- **Hard part**：文案长度。六段声明若超 400 token，会挤掉历史轮次。

### R-2 L2 operation 按需展开

- **Approach**：新增一个查询工具，模型按模块名取该模块全部 operation 的五字段条目。
- **Touches**：查询编排层，工具注册表。
- **Test seam**：工具执行器入口，既有的 operation 分发路径。不新增接缝。
- **Acceptance**：
  - [ ] 取一个模块返回五字段齐全的条目
  - [ ] 未知模块名返回可读错误并列出可用模块
  - [ ] 返回值与注册表逐字一致
- **Hard part**：模型可能每次都想展开全部模块，把「按需」用成「每次」。需要观测调用次数。

### R-3 闭合矩阵声明

- **Approach**：每个 capability 声明四条轴坐标；模块声明自己的取值集合。空格子由集合差算出，不手工标注。
- **Touches**：工具注册表。
- **Test seam**：注册表导出的纯函数，直接读坐标。不新增接缝。
- **Acceptance**：
  - [ ] 35 条 capability 全部有坐标，无一遗漏
  - [ ] 模块取值集合可从坐标聚合得出，无需第二处维护
  - [ ] 已知空洞可被算出来：趋势为 0、科目为 0
- **Hard part**：坐标是域语义，需用户逐行审。审错则缺口判断整体偏移。

### R-4 缺口声明工具

- **Approach**：模型把坐标填进结构化参数提交；编排层校验格式后交给复核。
- **Touches**：查询编排层，工具注册表。
- **Test seam**：工具执行器入口。
- **Acceptance**：
  - [ ] 合法坐标声明被接收，写入内部事件
  - [ ] 缺任一轴或轴值非穷举内值时被拒，并列出合法值
  - [ ] 用户原话不出现在声明参数里
- **Hard part**：模型倾向把「试了一次没结果」当缺口。要在工具描述里写死判据。

### R-5 缺口声明可被代码复核

- **Approach**：拿坐标查注册表；命中覆盖条目则驳回，并把条目原文回给模型。
- **Touches**：查询编排层。
- **Test seam**：编排层现有单测入口，用假 provider 驱动两轮。
- **Acceptance**：
  - [ ] 坐标被现有条目覆盖时驳回，模型收到该条目原文
  - [ ] 确实无覆盖时放行，进入工单路径
  - [ ] 误报不计入失败预算，不把 run 打成 failed
- **Hard part**：判断「覆盖」的严格度。过松则误报放行，过紧则真缺口被挡。

### R-6 缺口转工单并去重

- **Approach**：放行的坐标按「模块 + 四轴」归并成一张工单，需求字段结构化填好，交给既有建单通道。
- **Touches**：查询编排层，工单桥接的建单入口。
- **Test seam**：建单入口。桥接尚未存在，先用注入的假建单器，接真通道留到 P3。
- **Acceptance**：
  - [ ] 同一坐标两次声明只产生一张工单
  - [ ] 不同坐标产生不同工单
  - [ ] 工单里没有用户原话，只有坐标与问句形状
- **Hard part**：桥接未建，本阶段只能到「落库为候选」，不能真开 run。

### R-7 目录单一真源与双向对账

- **Approach**：catalog 由能力表生成；加一条测试双向核对，少一边即红。
- **Touches**：工具注册表。
- **Test seam**：注册表单测，沿用 P1 盯前端标签的同一模式。
- **Acceptance**：
  - [ ] 每条 capability 都有 catalog 条目
  - [ ] 每条 catalog 条目都有 capability
  - [ ] 故意删一侧，测试变红
- **Hard part**：无。

### R-8 `/agent` 接管 `/business-query`

- **Approach**：新页面接管路径，旧路径 301 到新路径；信封与 reducer 不变。
- **Touches**：Web 应用路由，顾问页面。
- **Test seam**：现有浏览器端到端用例，路径改一处。
- **Acceptance**：
  - [ ] 访问旧路径落到新页面
  - [ ] 现有断线续接用例在新路径下仍绿
  - [ ] 会话、取消、历史切换功能等价
- **Hard part**：两条路径并存期间的状态不可分叉。直接切，不做灰度。

### R-9 chat-demo 会话体验移植

- **Approach**：移植纯模块与行为，组件按现有设计系统重画；只取行为不取视觉。
- **Touches**：Web 顾问模块。
- **Test seam**：移植模块的单测，与现有 reducer 单测并存。
- **Acceptance**：
  - [ ] 自动标题、重命名、删除可用
  - [ ] 编辑重发产生分支，可切换
  - [ ] 草稿按会话保存，刷新不丢
  - [ ] 中英切换与明暗主题跟随设置
- **Hard part**：分支与「服务端权威」的接缝。分支只能存在本地缓存，不能写进服务端事件表。

### R-10 流式节流与 markdown 全家桶

- **Approach**：渲染按节流刷新；Markdown 改走成熟解析器，接 KaTeX、Mermaid、高亮。
- **Touches**：Web 顾问模块。
- **Test seam**：渲染组件的现有测试入口。
- **Acceptance**：
  - [ ] 万字答案流式期间单帧渲染耗时在上限内
  - [ ] 公式、图表、代码块渲染正确
  - [ ] 流式光标贴在正文末尾，不单独占行
- **Hard part**：节流与「最后一个增量必须显示」的取舍。

### R-11 服务端权威 + 本地缓存

- **Approach**：首屏读本地缓存立即渲染，同时按游标向服务端补差量；本地只缓存，不回写。
- **Touches**：Web 顾问模块。
- **Test seam**：缓存读写函数，纯函数可直接测。
- **Acceptance**：
  - [ ] 冷启动先出本地内容，再补差量
  - [ ] 降权后本地旧 full 轮次不再展示
  - [ ] 本地缓存损坏时退回纯服务端路径，不白屏
- **Hard part**：降权拦截要在本地缓存读取处也生效，不能只在服务端。

### R-12 model_steps 中位数下降

- **Approach**：目录与索引到位后重跑同一黄金集，对比中位数；这是唯一的改进判据。
- **Touches**：评测脚本，黄金集用例。
- **Test seam**：现有评测入口。
- **Acceptance**：
  - [ ] 黄金集通过率不低于 100%
  - [ ] model_steps 中位数低于 3
  - [ ] 工具调用失败率不回升
- **Hard part**：中位数可能被少数长追问链拉高。要按组看，不能只看总体。

## 3. 阶段

### 阶段 1 — 模型能看见目录

**Covers**：R-1 L1 模块目录常驻 prompt、R-2 L2 operation 按需展开、R-7 目录单一真源与双向对账。

**Goal**：prompt 里出现六段模块声明，模型需要细节时能展开该模块的 operation 条目，选工具不再靠猜。

**Tasks**

- 建能力到目录的生成器，六模块六段声明
- 把目录接进系统指令，替换现在那段话
- 加展开工具：按模块名取该模块的五字段条目
- 加未知模块名的可读错误，列出可用模块
- 加双向对账测试，两侧任一缺失即红
- 铺一条端到端：一句话提问命中正确模块，无需试错

**Proof**：端到端跑通，且 prompt 文本里六段声明齐全、展开返回与注册表逐字一致。
**Not here**：坐标、缺口声明。

### 阶段 2 — 缺口能被证明

**Covers**：R-3 闭合矩阵声明、R-4 缺口声明工具、R-5 缺口声明可被代码复核。

**Goal**：模型对一条确实无入口的问法，报出坐标而不是报「查不到」；对已被覆盖的问法，被驳回并改用既有工具。

**Tasks**

- 给 35 条能力标四轴坐标，产出模块取值集合
- 算空格子，输出一份空洞清单供人审
- 加缺口声明工具，校验坐标格式
- 加代码复核，命中覆盖条目则驳回并回传条目原文
- 用假 provider 跑两种情形：真缺口放行、误报驳回

**Proof**：两条相反情形的单测都绿，且空洞清单已人工审过。
**Not here**：把缺口变成工单。

**这是最贵的一步。**若模型在矩阵已写明的情况下仍然报不准，就停在观测层，不前移。

### 阶段 3 — 缺口变成候选

**Covers**：R-6 缺口转工单并去重。

**Goal**：同一坐标反复出现只攒一条候选，候选里只有坐标与问句形状，没有用户原话。

**Tasks**

- 按坐标归并，落一张候选表
- 加门槛：同坐标出现三次才升为待开工
- 接一个可注入的建单器，真通道留到桥接阶段
- 覆盖同坐标两次只一条、异坐标两条

**Proof**：去重与门槛两条测试绿。
**Not here**：真的启动 harness run。

### 阶段 4 — 顾问换外壳

**Covers**：R-8 `/agent` 接管 `/business-query`、R-11 服务端权威 + 本地缓存。

**Goal**：从旧路径进入即到新页面，断线续接与历史切换行为等价。

**Tasks**

- 在新路径铺一条端到端细线：提问、流式、完成
- 旧路径 301 到新路径
- 接本地缓存读与游标补差量
- 降权拦截在本地缓存读取处生效
- 迁移现有断线续接用例到新路径

**Proof**：旧路径访问落到新页面，续接用例在新路径下绿。
**Not here**：新体验特性。

### 阶段 5 — 长答案不卡

**Covers**：R-10 流式节流与 markdown 全家桶。

**Goal**：万字答案流式期间不卡，公式、图表、代码块显示正确。

**Tasks**

- 接节流渲染，定单帧耗时上限
- 换成熟 markdown 解析器，接公式与图表
- 接代码高亮
- 加一条长答案渲染用例，断言帧耗上限

**Proof**：长答案用例通过，帧耗在限内。
**Not here**：会话体验特性。

### 阶段 6 — 会话能像样地用

**Covers**：R-9 chat-demo 会话体验移植。

**Goal**：标题、重命名、删除、编辑重发产生分支、草稿、主题与中英切换全部可用。

**Tasks**

- 接自动标题与重命名、删除
- 接编辑重发与分支切换，分支只落本地
- 接草稿按会话保存
- 接主题与中英切换
- 覆盖：刷新后草稿仍在、分支可切

**Proof**：五条体验各一条用例绿。
**Not here**：附件与朗读。

### 阶段 7 — 时延有数

**Covers**：R-12 model_steps 中位数下降。

**Goal**：同一黄金集重跑，中位数低于 3，通过率与失败率都不退。

**Tasks**

- 在黄金集里加一条针对目录的问法，覆盖「该用列表入口」的一类
- 重跑全量，按组出中位数
- 与 P1 快照对比，写报告

**Proof**：报告里中位数低于 3 且失败率不回升。
**Not here**：任何未在此列出的改进。
