# P2 施工计划：工具目录、缺口判定、前端换装

日期：2026-11-24｜版本：1.7｜状态：施工中（阶段 1–6 已完成）｜类型：施工计划

设计：[迪礼顾问 P2 设计](../../design/dilee-consultant-p2-tool-catalog-2026-11-24.md)（v1.7）。
基线：[P1 报告](../../review/agent-golden-p1-2026-11-23.md)。

## 0. 结论

**八个阶段，按「最可能推翻计划的东西先做」排序。**先让模型看见目录，再用一次离线实验定缺口判定的方案，
然后才写缺口代码、攒候选；前端换装排在后面，因为它是唯一不会推翻其余决策的一块。

最贵的假设只有一条：**模型能在具体候选里认出最近邻工具，并说准还差什么**。
它在第二阶段用实验验证，写缺口代码之前就有结论；验证不过就停在观测层，不写缺口代码，前端照常推进。

v1.0 → v1.1 的改动：闭合矩阵从「要实现的需求」改成「实验里的对照组」；缺口声明改为最近邻差异；
新增候选集接口（RAG 预留）；阶段从七个拆成八个，实验单独成段。

## 2. 做法，逐条

### R-1 L1 模块目录常驻 prompt

- **Approach**：六个模块各一段声明，含「管什么、operation 数、不支持什么」。生成而非手写，随能力表变化。
- **Touches**：查询编排层，工具注册表。
- **Test seam**：现有 provider 的 plan 调用，检查系统指令文本。不新增接缝。
- **Acceptance**：
  - [ ] prompt 里六模块各一段，每段含「管什么」与否定清单
  - [ ] 增删一条 capability 后 prompt 自动跟随，不需手改文案
  - [ ] 财务档不可见时，prompt 里没有财务模块
- **Hard part**：文案长度。六段声明目标 150 token，若超 400 token 会挤掉历史轮次。

### R-2 L2 operation 按需展开

- **Approach**：新增一个查询工具，模型按模块名取该模块全部 operation 的五字段条目；
  注册表同时收进每个 operation 的机器可读参数清单 `accepts`。
- **Touches**：查询编排层，工具注册表，各执行器的参数校验。
- **Test seam**：工具执行器入口，既有的 operation 分发路径。不新增接缝。
- **Acceptance**：
  - [ ] 取一个模块返回五字段齐全的条目
  - [ ] 未知模块名返回可读错误并列出可用模块
  - [ ] 返回值与注册表逐字一致
  - [ ] 35 条都有 `accepts`，且与执行器实际接受的参数一致（以测试比对，不靠人工）
  - [ ] 每条「边界」字段已按四轴检查清单过一遍
- **Hard part**：`accepts` 现在散在各执行器的校验里，收拢时不能和执行器分叉。模型也可能把「按需」
  用成「每次」全展开，需要观测调用次数。

### R-3 缺口判定方案对照实验

- **Approach**：离线跑 A/B/C 三组（设计 §2.7），用假 `report_gap` 只记录不放行，按判据定方案。
- **Touches**：评测脚本，新增缺口题集。
- **Test seam**：现有黄金集评测入口 `scripts/agent/golden-eval.mjs` 的调用模型部分；题集放在黄金集用例旁边。
- **Acceptance**：
  - [ ] 题集约 30 题，四类齐全，每题有期望判定与期望最近邻，**标注经用户审过**
  - [ ] 三组各跑 3 次，报告给出六项指标（设计 §2.7）
  - [ ] 按判据写出结论：采用 C / 重开矩阵 / 停在观测层，三选一
  - [ ] 报告进 `docs/review/`，原始快照一并入库
- **Hard part**：题集的标注是域语义，标错则结论偏移。B 组的四轴坐标只为实验标注，不入注册表。

### R-4 缺口声明工具 `report_gap`

- **Approach**：模型提交最近邻 operation、差异类型（封闭枚举）、差异短语、可选缺失参数名与所需字段；编排层校验格式后交给核对。
  工具描述写明所需字段的格式 `<Prisma 模型>.<字段>` 并给一个例子。
- **Touches**：查询编排层，工具注册表。
- **Test seam**：工具执行器入口。
- **Acceptance**：
  - [ ] 合法声明被接收，写入内部事件
  - [ ] 缺必填字段或 `missing` 不在枚举内时被拒，并列出合法值
  - [ ] 工具描述含所需字段的格式与例子；字段格式不对不导致拒收
  - [ ] 用户原话不出现在声明参数里
- **Hard part**：模型倾向把「试了一次没结果」当缺口。工具描述里写死判据，R-5 再用规则兜一道。

### R-5 缺口声明可被代码核对

- **Approach**：按设计 §2.3 核对。operation 存在且可见、声明的缺失参数其实被接受、最近邻本轮全是 0 行判为缺数据，
  这三条不过即驳回并回传原文；所需字段对照 schema 只做标注，分成已核对与未核对两组。
- **Touches**：查询编排层，工具注册表，Prisma DMMF 读取。
- **Test seam**：编排层现有单测入口，用假 provider 驱动两轮。
- **Acceptance**：
  - [ ] 三条驳回核对各有一条用例，驳回时模型收到对应条目原文或合法值
  - [ ] 不存在或格式不对的字段进 `unverified_fields`，声明照常放行
  - [ ] 确实无覆盖时放行，进入候选路径
  - [ ] 最近邻本轮全是 0 行时声明被判为缺数据，不进候选；别的 operation 落空不影响
  - [ ] 驳回不计入失败预算，不把 run 打成 failed
- **Hard part**：第 2 条依赖 `accepts` 的完整性；`accepts` 漏写会把真缺口放行，多写会把真缺口挡住。

### R-6 缺口归并为候选并设门槛

- **Approach**：放行的声明按「最近邻 + 差异类型」归并成一条候选，历次差异短语原样追加，记次数；
  达门槛升为待开工，交给可注入的建单器。
- **Touches**：查询编排层，工单桥接的建单入口。
- **Test seam**：建单入口。桥接尚未存在，先用注入的假建单器，接真通道与可行性探针留到 P3。
- **Acceptance**：
  - [ ] 同一归并键两次声明只产生一条候选，短语不同也一样
  - [ ] 候选保留历次差异短语
  - [ ] 不同归并键产生不同候选
  - [ ] 候选里没有用户原话，只有最近邻、差异类型、历次短语与两组字段
  - [ ] 按不同会话计数；未达门槛不调建单器，达门槛恰好调一次
- **Hard part**：归并键偏粗，同一最近邻、同一差异类型下的不同缺口会并成一条（设计 §2.4）；
  门槛为 3 个不同会话（设计 §10-2）。

### R-7 目录单一真源与双向对账

- **Approach**：catalog 由能力表生成；加一条测试双向核对，少一边即红。
- **Touches**：工具注册表。
- **Test seam**：注册表单测，沿用 P1 盯前端标签的同一模式。
- **Acceptance**：
  - [ ] 每条 capability 都有 catalog 条目
  - [ ] 每条 catalog 条目都有 capability
  - [ ] 故意删一侧，测试变红
- **Hard part**：无。

### R-8 `/agent` 接管 `/business-query`

- **Approach**：新页面接管路径，旧路径永久重定向到新路径；信封与 reducer 不变。
- **Touches**：Web 应用路由，顾问页面。
- **Test seam**：现有浏览器端到端用例，路径改一处。
- **Acceptance**：
  - [ ] 访问旧路径返回 308 并落到新页面（Next `permanent: true` 的实际状态码）
  - [ ] 现有断线续接用例在新路径下仍绿
  - [ ] 会话、取消、历史切换功能等价
- **Hard part**：两条路径并存期间的状态不可分叉。直接切，不做灰度。

### R-9 chat-demo 会话体验移植

- **Approach**：移植纯模块与行为，组件按现有设计系统重画；只取行为不取视觉。
- **Touches**：Web 顾问模块。
- **Test seam**：移植模块的单测，与现有 reducer 单测并存。
- **Acceptance**：
  - [ ] 自动标题、重命名、删除可用
  - [ ] 编辑重发产生分支，可切换
  - [ ] 草稿按会话保存，刷新不丢
  - [ ] 中英切换与明暗主题跟随设置
  - [ ] 移植文件保留 MIT 许可头
- **Hard part**：分支与「服务端权威」的接缝。分支只能存在本地缓存，不能写进服务端事件表。

### R-10 流式节流与 markdown 全家桶

- **Approach**：渲染按节流刷新；Markdown 改走成熟解析器，接 KaTeX、Mermaid、高亮。
- **Touches**：Web 顾问模块。
- **Test seam**：渲染组件的现有测试入口。
- **Acceptance**：
  - [ ] 万字答案流式期间单帧渲染耗时在上限内
  - [ ] 公式、图表、代码块渲染正确
  - [ ] 流式光标贴在正文末尾，不单独占行
- **Hard part**：节流与「最后一个增量必须显示」的取舍。

### R-11 服务端权威 + 本地缓存

- **Approach**：首屏读本地缓存立即渲染，同时拉服务端会话快照覆盖对账，进行中的轮次从快照游标续接；
  本地只缓存，不回写；财务档轮次不写本地。后端不改。
- **Touches**：Web 顾问模块。
- **Test seam**：缓存读写函数，纯函数可直接测。
- **Acceptance**：
  - [ ] 冷启动先出本地内容，再以服务端快照覆盖
  - [ ] 财务档轮次不写本地
  - [ ] 降权后本地旧 full 轮次不再展示
  - [ ] 本地缓存损坏时退回纯服务端路径，不白屏
- **Hard part**：降权拦截要在本地缓存读取处也生效，不能只在服务端。

### R-12 model_steps 中位数下降

- **Approach**：目录与索引到位后重跑同一黄金集，对比中位数；这是唯一的改进判据。
- **Touches**：评测脚本，黄金集用例。
- **Test seam**：现有评测入口。
- **Acceptance**：
  - [ ] 黄金集保持全部通过
  - [ ] model_steps 中位数低于 3（步数为整数，即降到 2 或以下）
  - [ ] 工具调用失败率不回升
- **Hard part**：中位数可能被少数长追问链拉高。要按组看，不能只看总体。

### R-13 候选集接口与漂移观测

- **Approach**：把「给模型哪些候选工具」收成一个函数，现在按档位过滤后返回全部；`describe_module`、
  `report_gap` 核对与实验脚本都经由它。另记一项漂移率：声明的最近邻与核定应用工具不一致的比例。
- **Touches**：工具注册表，查询编排层，评测报告。
- **Test seam**：注册表单测；评测报告的指标计算。
- **Acceptance**：
  - [ ] 候选只有这一个出口，编排层与实验脚本不另行拼装候选
  - [ ] 财务档不可见时候选里没有财务条目
  - [ ] 评测报告输出漂移率，黄金集里的缺口题可直接算出
- **Hard part**：线上漂移率要靠 P3 之后的可行性探针回填，P2 只能在评测里算。

## 3. 阶段

### 阶段 1 — 模型能看见目录

**Covers**：R-1 L1 模块目录常驻 prompt、R-2 L2 operation 按需展开、R-7 目录单一真源与双向对账、
R-13 候选集接口与漂移观测（接口部分）。

**Goal**：prompt 里出现六段模块声明，模型需要细节时能展开该模块的 operation 条目，选工具不再靠猜。

**Tasks**

- 建能力到目录的生成器，经候选集接口输出，六模块六段声明
- 收拢 35 条的 `accepts`，加与执行器的一致性测试
- 把目录接进系统指令，替换现在那段话
- 加展开工具与未知模块名的可读错误
- 加双向对账测试，两侧任一缺失即红
- 铺一条端到端：一句话提问命中正确模块，无需试错

**Proof**：端到端跑通，且 prompt 文本里六段声明齐全、展开返回与注册表逐字一致。
**Not here**：缺口声明与核对。

### 阶段 2 — 方案用数据定

**Covers**：R-3 缺口判定方案对照实验。

**Goal**：在写任何缺口代码之前，用数据回答「最近邻差异是否足够好、闭合矩阵是否值得重开」。

**Tasks**

- 起草约 30 题的缺口题集与标注，交用户审
- 写 A/B/C 三组的提示与假 `report_gap`
- 每组每题跑 3 次，算六项指标
- 按判据写结论报告，快照入库

**Proof**：报告给出三选一结论，题集标注有用户审过的记录。
**Not here**：任何编排层改动。

**这是最贵的一步。**结论是「停在观测层」时，阶段 3、4 改为只记日志，不做候选与建单；阶段 5 起照常推进。
结论是「重开矩阵」时，阶段 3 改按设计 v1.0 §2 施工，先补用户审坐标。

### 阶段 3 — 缺口能被核对

**Covers**：R-4 缺口声明工具 `report_gap`、R-5 缺口声明可被代码核对。

**Goal**：模型对一条确实无入口的问法报出最近邻与差异，而不是报「查不到」；对已被覆盖的问法被驳回并改用既有工具。

**Tasks**

- 加 `report_gap`，校验格式与枚举
- 加三条驳回核对，驳回时回传条目原文或合法值
- 接 Prisma DMMF 读取，把所需字段分成已核对与未核对
- 用假 provider 跑三种情形：真缺口放行、误报驳回、0 行判缺数据

**Proof**：三种情形的单测都绿，驳回不计失败预算。
**Not here**：把缺口变成候选。

### 阶段 4 — 缺口变成候选

**Covers**：R-6 缺口归并为候选并设门槛。

**Goal**：同一差异反复出现只攒一条候选，达门槛才交给建单器；候选里只有最近邻、差异与所需字段，没有用户原话。

**Tasks**

- 按归并键归并，落一张候选表
- 加门槛，数值按用户拍板
- 接一个可注入的建单器，真通道与探针留到桥接阶段
- 覆盖同键两次只一条、异键两条、门槛前后各一次

**Proof**：去重与门槛的测试绿。
**Not here**：真的启动 harness run，可行性探针。

### 阶段 5 — 顾问换外壳

**Covers**：R-8 `/agent` 接管 `/business-query`、R-11 服务端权威 + 本地缓存。

**Goal**：从旧路径进入即到新页面，断线续接与历史切换行为等价。

**Tasks**

- 在新路径铺一条端到端细线：提问、流式、完成
- 旧路径永久重定向到新路径，用例按 308 断言
- 接本地缓存读与服务端快照对账
- 降权拦截在本地缓存读取处生效
- 迁移现有断线续接用例到新路径

**Proof**：旧路径访问落到新页面，续接用例在新路径下绿。
**Not here**：新体验特性。

### 阶段 6 — 长答案不卡

**Covers**：R-10 流式节流与 markdown 全家桶。

**Goal**：万字答案流式期间不卡，公式、图表、代码块显示正确。

**Tasks**

- 接节流渲染，定单帧耗时上限
- 换成熟 markdown 解析器，接公式与图表
- 接代码高亮
- 加一条长答案渲染用例，断言帧耗上限

**Proof**：长答案用例通过，帧耗在限内。
**Not here**：会话体验特性。

### 阶段 7 — 会话能像样地用

**Covers**：R-9 chat-demo 会话体验移植。

**Goal**：标题、重命名、删除、编辑重发产生分支、草稿、主题与中英切换全部可用。

**Tasks**

- 接自动标题与重命名、删除
- 接编辑重发与分支切换，分支只落本地
- 接草稿按会话保存
- 接主题与中英切换
- 覆盖：刷新后草稿仍在、分支可切

**Proof**：五条体验各一条用例绿。
**Not here**：附件与朗读。

### 阶段 8 — 时延有数

**Covers**：R-12 model_steps 中位数下降、R-13 候选集接口与漂移观测（漂移率部分）。

**Goal**：同一黄金集重跑，中位数低于 3，通过率与失败率都不退，漂移率有基线。

**Tasks**

- 在黄金集里加一条针对目录的问法，覆盖「该用列表入口」的一类
- 把阶段 2 的缺口题并入黄金集，报告输出漂移率
- 重跑全量，按组出中位数
- 与 P1 快照对比，写报告
