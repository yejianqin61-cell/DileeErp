# Task 03：供应商应付对账闭环

## 目标

让财务可以按供应商、采购单、订单号、批次和期间核对系统应付与供应商外部账单，并解释待处理来源、正式应付、付款、冲销、调整和差异。

## 后端要求

- 使用 `SupplierPayableReconciliation` 作为独立应付对账对象，不复用客户应收对账表。
- 创建对账时按供应商、期间、币种和可选订单号/采购单汇总快照：待处理来源金额、正式应付金额、已付款金额、冲销/调整金额和系统余额。
- 支持采购单级和入库/签收批次级明细；默认批次明细、采购单和供应商汇总。
- 记录外部余额、差异、状态、处理说明、附件、创建人和时间。
- 只有待处理/差异状态可以处理；已处理记录需要受控修改并记录原因。
- 对账快照不可因后续业务变化而漂移；重新对账应生成新快照。
- 查询支持供应商、订单号、采购单号、期间、币种和状态。

## 前端要求

- 财务页将“供应商应付对账”作为独立工作区，不与普通应收对账混标题或混操作。
- 创建表单使用供应商选择、可选订单号/采购单、期间、币种和外部余额。
- 列表显示对账单号、供应商、订单号/采购单、期间、系统应付、外部余额、差异和状态。
- 提供详情 Sheet，展示来源批次、正式应付、付款、冲销/调整的组成明细。
- 差异处理必须填写处理说明，可上传或关联附件。

## 不做

- 不实现银行自动对账、供应商门户或电子发票验真。
- 不改变正式应付和付款的原始金额；对账只保存快照和差异处理结果。

## 验收标准

1. 可按供应商和期间创建应付对账，系统余额等于快照中的应付减付款并考虑冲销/调整。
2. 可按采购单和批次展开对账明细，能够回溯到原料入库或外加工签收来源。
3. 待处理来源不会被误计为正式应付，但会单独显示待接收金额。
4. 外部余额和系统余额不同会产生差异状态；处理说明为空时不能结案。
5. 后续付款或来源变化不会修改既有对账快照。
6. 所有创建、处理和受控修改均有审计记录。

## 测试

- 服务测试：快照计算、冲销/调整影响、状态转换和差异规则。
- PostgreSQL 集成测试：采购和外加工混合来源、付款、来源作废、重复创建。
- HTTP 测试：筛选、创建、详情、处理和权限。
- Playwright：财务 -> 创建应付对账 -> 查看批次明细 -> 处理差异。

- 交付对账服务/API、财务工作区、详情视图、测试及必要迁移。
