# Task 02：采购与外加工应付来源人工接收闭环

## 目标

建立统一的“待处理应付来源 -> 财务人工接收 -> 应付草稿 -> 应付确认 -> 付款核销”流程。人工接收是必经的财务职责边界，不自动跳过来源层直接生成已确认应付。

## 来源范围

- 采购到货批次 `purchase_receipt`：按实际到货数量和采购单价产生待处理来源。
- 原料入库过账 `raw_material_inbound`：在对应来源不存在时补建待处理来源；库存和来源必须同事务提交。
- 外加工实际签收 `outsource_receipt`：按实际签收数量产生待处理来源；直发数量本身不形成应付。

## 后端要求

- 提供统一待处理来源查询，支持来源类型、订单号、采购单号、供应商、批次和期间筛选。
- 正式接收接口根据来源类型创建 `SupplierPayableEntry` 草稿，保留来源编号、数量、单价、税率、币种、金额和订单快照。
- 来源与正式应付保持唯一关联；重复接收返回已有条目，不重复记账。
- 已作废、已冲销或已接收来源不得再次接收；上游来源冲销只能作废尚未接收的来源。
- 应付草稿可编辑金额、确认日期和备注；金额改变必须填写差异原因并留下审计快照。
- 只有正式应付 `confirmed` 才可被供应商付款核销；支持部分付款、未分配付款和冲销恢复。
- 支持采购和外加工两种来源类型，禁止前端写死为原料入库类型。

## 前端要求

- 财务页提供“待处理应付来源”独立工作区，区分采购到货、原料入库和外加工签收。
- 每行显示供应商、订单号、采购单号、来源批次、数量、单价、金额、币种和来源状态。
- “接收应付”打开结构化表单，默认带入来源金额，差异金额必须填写原因。
- 接收后显示正式应付单号和草稿状态；正式应付列表支持编辑、确认和查看来源。
- 付款核销选择项显示可用余额，不允许选择已取消、已冲销或未确认条目。

## 不做

- 不把待处理来源自动升级为已确认应付。
- 不实现供应商外部系统直连、发票验真或自动付款审批。

## 验收标准

1. 采购到货、原料入库过账、外加工签收分别能看到正确类型的待处理来源。
2. 同一来源重复点击接收只产生一个正式应付草稿。
3. 原料入库过账时库存事实和待处理来源要么同时成功，要么同时回滚。
4. 上游来源冲销后，未接收来源变为 `voided`，无法接收；已接收应付不会被静默删除。
5. 应付金额修改必须要求差异原因，并保留来源原始金额。
6. 只有确认应付可以付款核销；超额、重复和币种不一致均被拒绝。
7. 付款部分核销、足额核销和冲销后的余额均正确。
8. 采购与外加工来源在同一财务工作区可追踪到正式应付和付款。

## 测试

- 服务/领域测试：来源类型映射、幂等、作废和金额差异。
- PostgreSQL 集成测试：三类来源接收、事务一致性、并发重复接收、付款余额。
- HTTP 测试：筛选、接收、确认、付款核销、冲销和权限。
- Playwright：采购到货 -> 来源列表 -> 接收应付 -> 确认 -> 付款核销；外加工签收走同样旅程。

## 依赖与交付物

- 依赖采购到货、原料入库、外加工签收现有来源模型和审计能力。
- 交付统一来源 API、正式应付接收 API、财务页面、测试和必要的关系/索引迁移。
