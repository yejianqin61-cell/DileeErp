# 2026-09-02 财务模块 P0/P1 开发任务

来源：[财务模块 P0/P1 改进规格](../../design/finance-module-improvement-spec-2026-09-02.md)

本批任务遵循统一设计原则：上游先产生业务事实和待处理来源，财务人员再人工接收、确认和支付；工资仅自动导入车间员工生产日报收入，其他收入来源全部人工填写。

| --- | --- | --- | --- |
| 01 | [应收草稿确认与收款核销修复](01-receivable-draft-confirmation.md) | P0 | 成品出库应收来源 |
| 02 | [采购与外加工应付来源人工接收闭环](02-payable-source-acceptance.md) | P0 | 采购到货、原料入库、外加工签收 |
| 03 | [供应商应付对账闭环](03-supplier-payable-reconciliation.md) | P0/P1 | 02 |
| 04 | [限定范围的生产工资来源与工资台账](04-limited-payroll-chain.md) | P1 | 车间员工日报、HR 工资台账 |

## 共同完成标准

- 真实 PostgreSQL 集成测试覆盖事务、幂等、状态和余额；不得仅以 TypeScript 构建通过作为完成依据。
- 页面以订单号、来源编号、采购单/入库/签收批次、客户/供应商姓名展示，UUID 只作内部关联。
- 所有写操作记录操作人、时间、原因、来源和前后关键值；上游冲销不得静默删除已确认财务事实。
