# Task 04：限定范围的生产工资来源与工资台账

## 目标

保留低自动化工资策略：仅车间员工的工序生产日报收入自动形成生产工资来源；车间员工其他收入、非车间员工所有收入以及考勤/绩效/社保/个税等均由人工填写或人工调整。

## 自动化边界

### 自动生成

- 车间员工工序日报，计件模式：件数 × 当日人工单价。
- 车间员工工序日报，计时模式：时长 × 当日人工单价；件数可填写并用于生产统计，但不参与计时工资金额计算。
- 日报新增、修改、删除在同一事务中刷新 `ProductionPayrollSource`，并同步日报差异告警和生产进度。

### 必须人工填写

- 车间员工基本工资、津贴、奖金、补贴和其他非生产收入。
- 非车间员工的基本工资、收入、津贴、奖金和全部其他收入。
- 加班金额、考勤扣款、绩效金额、社保、个税和其他调整。
- 工资台账的确认、支付和关闭。

## 后端要求

- 生产工资来源唯一粒度为员工、生产单、日期和计薪方式；日报重复提交按既有累加规则处理，不产生重复来源。
- 工资台账生成时只收集车间生产日报来源，写入来源快照；不读取考勤/绩效记录自动计算金额。
- 工资台账保留人工金额字段和调整记录，计算净应付时明确展示生产来源、人工输入和调整组成。
- 草稿可编辑和删除；确认后保护核心字段；部分支付、已付清、关闭状态按余额流转。
- 工资付款只能核销已确认或部分支付的台账，不得超过未付余额；冲销后恢复余额。
- 生产日报修改/删除后，相关工资来源和未确认台账的来源快照可刷新；已确认/已支付台账不得静默改写。

## 前端要求

- 生产日报页面继续展示计件/计时、件数、时长、单价和计算金额；计时模式允许填写件数并标注其用于统计。
- 工资台账页面按员工姓名+编号、期间和车间/非车间筛选。
- 台账详情分区显示：生产日报自动来源、人工收入、人工扣款、调整、应付、已付和未付。
- 页面不得提供从考勤或绩效“一键自动计薪”的入口；人工字段必须可编辑并有备注/原因。
- 工资付款支持草稿、分配、过账、冲销和余额查看。

## 不做

- 不自动把考勤、绩效、加班记录转换成工资金额。
- 不自动生成非车间员工或车间非生产收入来源。
- 不实现税费政策引擎、银行代发文件或完整薪资审批流。

## 验收标准

1. 车间员工计件日报保存后自动产生/刷新生产工资来源，金额等于件数乘单价。
2. 车间员工计时日报保存后自动产生/刷新生产工资来源，金额等于时长乘单价；填写的件数可被统计但不改变计时金额。
3. 同一员工、生产单、日期、计薪方式重复提交按规则累加，不产生重复工资来源。
4. 修改或删除日报会同步来源；已有确认/支付事实时不允许静默覆盖。
5. 车间员工其他收入和非车间员工收入只能通过人工工资台账字段/调整记录进入。
6. 考勤、绩效、社保和个税不会被系统自动带入金额；人工字段可追溯。
7. 工资台账确认、部分支付、足额支付、冲销和关闭的余额正确。
8. 工资来源、台账和付款操作均有审计记录。

## 测试

- 服务测试：计件/计时金额、来源唯一性、人工字段边界和状态流转。
- PostgreSQL 集成测试：日报并发累加、修改/删除同步、台账快照和工资付款核销。
- HTTP 测试：车间/非车间员工、工资来源、台账和支付权限。
- Playwright：生产日报 -> 工资台账 -> 查看自动生产来源 -> 填写人工收入 -> 确认 -> 工资付款。

## 依赖与交付物

- 依赖生产员工日报、员工主数据和现有 HR 工资台账/工资付款服务。
- 交付工资来源边界修正、台账详情和表单、支付动作、测试及必要迁移。
