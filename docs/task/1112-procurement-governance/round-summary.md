## 2. 这意味着什么

审计把三条抱怨追到了四处实现，而它们其实是同一件事的三面：**规则写死在 SQL 和状态枚举里，于是既拦住了本不该拦的，也拒绝解释自己**。

所以本轮没有拆表、没有加状态、没有放开口径 7。改法是把"什么能建计划"从 `where` 里搬到纯函数，把"退回"从整单降到行，再把这些结论摆回用户本来就站着的三个位置（新建弹窗、物料块头、计划编号的 title）。**已完成的计划仍然删不掉** —— 那是刻意的；现在界面会告诉用户去哪加一行，而不是让他在空下拉前面猜。

代价写在明处：候选查询从"数据库过滤"变成"取回后内存分类"（量级与销售单同阶），行级退回没有行锁（与整单退回一致，不为新入口单独引入锁协议）。

## 3. 仍然开着的

- **行级退回无行锁**：两人同时退同一行只靠自然幂等；整单退回本来也没有，本轮选择对齐而非单独立规矩。
- **部分到货的单重新下单会新建一张**：`findMergeTarget()` 要求整单零到货，所以那种单退完一行再下单，单号仍然会变 —— 这条口径没动，只是现在能被解释。
- **被拦原因最多三条**，超出只写「还有 N 张」，没有展开全部。
- **BOM 工作台改 BOM 对已下单明细的影响**仍只有摊回逻辑兜底，界面无提示（不在 R1 范围）。
- **真实数据库与 e2e 未跑**（本地无库）：迁移未验证，`test:api` / `test:integration` / `test:e2e` 全部未执行。
