## 目标

让采购员基于已确认销售单和指定 BOM 版本手工建立采购单，并让仓库按采购明细登记分批到货，始终以 `order_no` 追溯订单来源。

## 范围

- 实现物料、供应商、单位池的列表、创建、编辑、停用接口及权限、审计和引用后保护；
- 实现采购单列表、详情、草稿创建/编辑、影响预览、下单、取消和采购单号系统生成；
- 创建时服务端验证 `order_no`、确认销售单、BOM ID/版本和供应商/物料/单位有效性，保存 BOM 与价格快照；
- 实现采购明细的十进制数量、价格、税率、费用和金额校验；采购数量由采购员手工填写，不从 BOM 自动生成；
- 实现按采购明细分批登记到货、送检和进度汇总；到货不得增加可用库存；
- 应用 `procurement` 与 `warehouse` RBAC，写入统一审计事件和稳定错误码。

## 非范围

- 来料 QC 结果、原料入库和应付来源；
- 自动采购、采购计划单、供应商比价和结算；
- 采购退货及已过账事实冲销。

## 验收与验证

1. 草稿销售单或无效 BOM 版本不能创建采购单，返回契约化业务错误。
2. 每张采购单只关联一个 `order_no`，系统生成采购单号；BOM 变更不修改已保存采购快照。
3. 草稿可编辑；下单后状态动作受控，存在受保护下游事实时不可直接取消。
4. 同一采购明细允许多次到货；累计到货、采购数量差异与超收告警可查询，但不改变库存。
5. 基础资料被引用后优先停用，不能物理删除或使历史快照失效。
6. API 集成测试覆盖权限、来源校验、采购状态、分批到货、金额/数量校验与审计。

## 决策记录

采购单是 BOM 的人工消费结果，不是 BOM 明细的自动副本；来源快照用于解释当时的采购依据。
