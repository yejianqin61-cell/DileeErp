## 目标

把可入库的来料 QC 数量分批过账为原料库存动态事实，并在同一业务事务中更新派生进度和生成财务可接收的幂等应付来源草稿。

## 范围

- 实现原料入库草稿、详情、查询、过账和冲销 API；入库必须关联采购明细、到货、QC、物料、供应商和 `order_no`；
- 在过账前校验累计入库数量不超过 QC 允许入库数量，条件接收须保留仓库确认关系；
- 在单一数据库事务中写入入库动态事实、库存读模型/派生汇总、采购明细进度、审计事件及应付来源草稿；
- 区分可用原料和不良品库存分类；禁止直接编辑库存余额；
- 以入库明细与来源 QC 明细建立幂等键，确保重试不重复增加库存或应付来源；
- 应付来源保存数量、单位、采购价格/税率/币种快照、金额、供应商、订单号、来源关系和待财务接收状态。

## 非范围

- 财务应付确认、付款、核销、对账和总账；
- 生产领料、外加工直发、实体仓库/库位和单位换算；
- 退供应商和价格变更差异处理。

## 验收与验证

1. 未完成 QC、QC 不允许入库或超过允许数量的入库过账被拒绝，库存和应付来源均不产生。
2. 过账成功后可按 `order_no` 从入库追溯采购、到货、QC 和应付来源；库存余额只能由有效动态事实汇总。
3. 同一过账请求重试不会重复写入库存或应付来源；重复来源返回稳定冲突或幂等成功结果。
4. 应付来源金额使用实际可计价入库数量和采购价格快照，不使用原采购下单数量。
5. 入库冲销使用反向事实且保留原记录、操作人、时间、原因和关联风险；无法造成负库存。
6. 数据库集成测试覆盖事务回滚、并发冲突、幂等、库存门禁及应付来源生成。

## 决策记录

`POST /raw-material-inbounds/{id}/post` 是本链路的关键一致性缝隙，库存事实与应付来源不得拆为异步且不可追溯的两次写入。
