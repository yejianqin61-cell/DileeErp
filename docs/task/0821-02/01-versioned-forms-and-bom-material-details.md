## 目标

在既有 BOM 来源版本之上建立最小版本化表单定义和 BOM 物料明细能力，使采购能取得稳定、可追溯的物料需求快照，但不提前固化未经物控确认的字段。

## 范围

- 实现版本化表单定义、字段定义和结构化字段值的最小通用能力，记录定义版本并保留历史解释能力；
- 为 BOM 建立物料明细：物料引用/快照、需求数量、单位、可选损耗数量或损耗率、可扩展字段值；
- 支持物控在已确认销售单对应 BOM 上创建、编辑、发布新版本和读取指定版本；
- 采购读取 BOM 时返回固定核心字段和稳定快照；BOM 后续变更不自动修改采购事实；
- 复用既有 `sales` 权限、审计、软删除、UUID 与 JSON API 契约。

## 非范围

- BOM 工艺、损耗和物料属性的最终业务字段清单；
- 采购单、自动采购建议、生产领料；
- 独立物控权限模型和 Excel 导出。

## 验收与验证

1. 已确认销售单可拥有带物料明细的 BOM 版本；草稿销售单不能创建或发布可采购 BOM。
2. 每条 BOM 明细保存物料来源、数量、单位与扩展字段定义版本；数量和单位不可仅存于自由文本。
3. 新版本不会改写已发布版本；采购读取指定版本时始终得到相同快照。
4. 已被采购引用的 BOM 版本不能被物理删除，修改必须走新版本或受控更正并写入审计。
5. API/领域测试覆盖版本递增、物料明细校验、来源追溯和下游引用保护。

## 决策记录

未确认的 BOM 明细采用版本化扩展字段；订单号、来源版本、物料、数量和单位为受保护核心。
