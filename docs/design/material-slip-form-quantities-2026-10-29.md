# 领料单表单补齐打印件上的四个数量（2026-10-29）

## 1. 需求原话

> 领料单这边，系统中的领料单表单还要多一些字段，和领料单导出件保持一致。
> 增加配料数量、已领数量、本次领料量和余下数量

结论先说：**打印件早就有这四列，缺的是系统表单**，而且表单里原本有 3 个近义列，其中 2 个口径与打印件**不一致**
（差一个「本次领料量」）。这次不是简单加列，而是把两边统一到同一组数字。

## 2. 改之前的实际情况

### 2.1 三处名字不一样

| 打印件（Excel 领料单） | 全屏编辑页（新建/编辑领料单） | 生产单面板里的草稿表格 |
|---|---|---|
| 配料数量 | 核定用量 | BOM 核定用量 |
| 已领数量 | 生产领用数量（**含**本单） | 生产已领累计（**含**本单） |
| 本次领料量 | 领料数量 | 本次领料数量 |
| 余下数量 | 生产未领用数量（**不含**本单） | 生产未领用（**不含**本单） |

### 2.2 两处数字其实对不上

打印件的口径（`material-slip-export.service.ts` 原有实现）：

- 已领数量 = 净领料（领料 − 退料）**扣掉本单自己**（只有已过账的单据自己在库存事实里）；
- 余下数量 = 配料数量 − 已领数量 − **本次领料量**。

而页面上的「生产领用数量」是 `cumulative_issued_after`（已领 **+** 本次），
「生产未领用数量」是 `配料 − 已领`（**没减**本次）。也就是说：

> 同一个格子，页面比打印件多算或少算一个「本次领料量」。

车间拿打印件核对系统时，只要本次领料量不是 0 就对不上。上一轮采购单导出出错也是同一类根因
（纸面与页面各算一套），所以这次不再各处补公式，而是把口径收到一个模块里。

## 3. 口径：只写一处

新增 `apps/api/src/modules/production/material-slip-quantity.ts`：

```ts
issuedBeforeQuantity(netIssued, ownQuantity, ownPosted) // 已领数量（不含本单）
remainingQuantity(bomQuantity, issuedBefore, current)    // 余下数量（已减本次，可为负）
```

- 草稿 / 待仓库出库：单据还没写库存事实，净领料本身就是「本单之前」；已过账：扣掉本单自身。
- 余下数量为负 = 超领，**原样返回负数**（打印件上也是负数），页面也不抹成 0。
- 配料数量为空（非 BOM 物料且无领料快照）时余下数量返回 `null`（显示「-」），不假装是 0。
- 返回前统一 `toFixed(4)`（对齐 `numeric(18,4)`），避免 `0.30000000000000004` 漏到页面。

调用方两个，都只有这一份实现：

1. `material-slip-export.service.ts`（打印件）
2. `raw-material-movements.service.ts` 的 `previewLines()`（页面预估）

## 4. 接口字段（页面用它，不再自己换算）

`POST /production/material-movements/issue-preview` 的每一行新增：

| 字段 | 含义 | 打印件对应列 |
|---|---|---|
| `material_quantity` | 配料数量（BOM 核定用量，无则需求量） | 配料数量 |
| `issued_quantity` | 已领数量（不含本次） | 已领数量 |
| `current_quantity` | 本次领料量 | 本次领料量 |
| `remaining_quantity` | 余下数量（配料 − 已领 − 本次，可负、可 null） | 余下数量 |

原有字段（`bom_reference_quantity`、`available_before`、`cumulative_issued_after` 等）**全部保留**：
提交/过账/退料影响预览也在用同一个 `previewLines()`，删字段会牵连库存校验。

`previewLines()` 里的这四个字段按「草稿」换算（预估接口只服务草稿编辑）。已过账单据的
`impactPreview`（退料/报废）虽然也走这个函数，但它只读库存与风险字段，不读这四个 —— 已在代码里注明。

## 5. 页面改动

### 5.1 全屏编辑页（`material-slip-editor.tsx`）

列序（领料单 14 列，补料单 10 列）：

```
物料 / 物料代码 / 型号 / 颜色 / 单位 /
配料数量 · 已领数量 · 本次领料量 · 余下数量 /     ← 与打印件一一对应，连续排在一起
当前库存量 / 采购入库数量 / 采购未入库数量 / 备注 / 操作
```

- 删掉「生产领用数量」「生产未领用数量」：它们就是「已领数量 + 本次」与「余下数量 + 本次」，
  留着等于同一件事显示两遍，而且名字与打印件不同，正是这次对不上的来源。
- 新增「单位」列：打印件有单位，页面原来只在物料下拉文案里带；四个数量没有单位容易读错
  （取 BOM 明细的单位，非 BOM 物料显示「-」）。
- 「本次领料量」仍是可输入框（打印件这一列就是它的值）。
- 余下数量为负时标红（`status-danger`），数字本身照打印件显示负数。
- 补料单打印件只有「补领数量」，所以补料单**不显示**已领/余下两列（与打印件一致）。
- 表格 `min-width` 1180px → 1260px（13 列 → 14 列）。

### 5.2 生产单面板里的草稿表格（`material-issues-panel.tsx`）

```
物料 / 配料数量 / 已领数量 / 本次领料量 / 余下数量 / 当前库存 / 风险 / 操作
```

同样去掉「生产已领累计」「生产未领用」，余下数量为负标红。列数与原来相同（8 列），
只是把三个近义列换成打印件的四个名字。

## 6. 单据详情弹窗（老板确认后追加，同一轮完成）

需求原话是「表单」，但保存后的单据在列表里只能双击看详情，而详情原来只有「物料 + 数量」，
即**系统里看不到余下数量**。老板确认后补上，做法与表单同一思路：

### 6.1 接口

新增 `GET production/material-movements/:id/slip-document`（`MaterialSlipExportController`），
直接返回 `MaterialSlipExportService.buildSlipDocument()` 的组装结果：

```json
{ "document_type": "issue", "document": { ...与打印件同一份数据 } }
```

- **与导出件同一份数据**：页面不再另查 BOM 与库存事实，四个数量与 Excel 里那四个格子逐项相等
  （有测试直接对比同一张单的 JSON 与 xlsx 单元格）。
- **不要求管理员**（与两个 xlsx 导出不同）：详情弹窗是只读页面，生产/仓库普通操作员都要看；
  真正下载导出仍仅管理员。
- 路由比 `GET .../:id` 多一段（`/slip-document`），不会被当成单据 id 匹配。
- 退料/报废/冲销单没有领料单版式，直接 404（不让它们按领料单口径解释数量）。
- 明细行补了 `remark`（打印件不印、详情要看），补料单把 `reason`（补料原因）也带出来。

### 6.2 页面

新增共用组件 `apps/web/components/production/material-slip-lines-table.tsx`：
领料单列表页与生产单面板都用它，列名/列宽/数量口径只有一份。

| 单据类型 | 列（合计宽度 100%） |
|---|---|
| 领料单 | 物料编码 12 / 物料名称 17 / 规格型号 13 / 颜色 7 / 单位 5 / 配料数量 10 / 已领数量 9 / 本次领料量 10 / 余下数量 9 / 备注 8 |
| 补料单 | 物料编码 16 / 物料名称 24 / 规格型号 20 / 颜色 10 / 单位 8 / 补领数量 12 / 备注 10 |

余下数量为负标红。弹窗头部的「单号/状态/提交时间/创建人/最后修改人」仍取自 `GET .../:id`
（审计两列走 `auditDetailFields`），与明细互补。

`lib/audit-columns-coverage.test.mjs` 的豁免清单里为这张明细表写了理由：一行是物料明细而不是单据，
没有「谁创建了这一行」，单据级操作人在弹窗头部字段里。

## 7. 测试

- `apps/api/test/unit/material-slip-quantity.test.cjs`（新增 5 条）
  - 口径函数：草稿不扣本单 / 已过账扣本单 / 净领料 0 时不出现负数 / 超领 -1 / 无配料数量返回 null / 浮点 0.1+0.2。
  - **跨服务一致性**：同一个业务状态（配料 5、已领 4、本次 2）下，导出件的
    `[bomQuantity, issuedQuantity, currentQuantity, remainingQuantity]` 必须与预估接口的
    `[material_quantity, issued_quantity, current_quantity, remaining_quantity]` **逐项相等**。
  - 草稿与已过账两条路径的已领数量、余下数量相等（证明「含不含本单」不是靠调用方自觉）。
  - 源码守卫：两个服务都必须从 `./material-slip-quantity` 引入并调用 `issuedBeforeQuantity`。
- `apps/api/test/material-slip-export.test.cjs`（新增 3 条）：`buildSlipDocument` 的领料单版式、
  补料单版式、其他单据类型 404；并直接对比「同一张单的 JSON 四个数」与「xlsx 第 7 行第 7~10 列」。
- `apps/web/test/material-slip-editor.test.tsx`：列名/取值断言改为四个打印件列名 + 单位；
  新增「改本次领料量后余下数量跟随后端返回」→ 输入 15 时余下显示 **-5**（证明前端不自算、超领不抹 0）。
- `apps/web/test/material-issues-panel.test.tsx`：新增按表头定位取值的 `draftColumn()` 助手
  （不再靠 `toHaveTextContent("2")` 这类会撞车的断言），并断言旧列名不得再出现；
  详情弹窗用例改为断言 10 个打印件列名与四个数量（含超领 -6）。
- `apps/web/test/material-issues-page.test.tsx`：同上，并断言 slip-document 只请求一次。

## 8. 非目标（这次没动）

- 打印件本身：列、列宽、行高、合计公式一律未改（上一轮刚按老板要求调过宽窄）。
- 库存校验、提交/过账/冲销状态机、BOM 数据、权限（xlsx 导出仍仅管理员）均未改动。
- 退料单/报废单/冲销单没有打印版式，也不在领料单详情里展示四个数量。
