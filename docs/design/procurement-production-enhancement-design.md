# 采购与生产增强开发设计

## 1. 目标与范围

本设计覆盖三类能力：

1. BOM 表增加规格、颜色、生产配料基数和核定用量，并明确核定用量的计算口径。
2. 物料主数据支持默认单位快速新增、物料编码自动生成或人工填写。
3. 生产模块增加生产领料单、生产工序池，并将工序员工日报改为一次多选员工。

采购单、BOM 表、生产单、生产领料单、员工日报继续使用现有 UI 组件库、表格组件和居中悬浮页面，不引入浏览器原生弹窗或原生选择控件。

## 2. 领域术语与数据关系

### 2.1 BOM 表

BOM 表属于采购模块，且绑定唯一订单号。一个订单号最多一份有效 BOM 表，BOM 行引用物料清单中的物料唯一 ID。

BOM 行字段：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 物料 | 物料清单中的物料 ID | 必须是启用的原料物料；禁止引用销售成品 |
| 物料名称 | 物料快照名称 | 保存时写入快照，展示以物料主数据为准 |
| 规格型号 | 该订单 BOM 使用的规格型号 | 可为空但建议填写 |
| 颜色 | 该订单 BOM 使用的颜色 | 可为空但建议填写 |
| 生产配料基数 | 该物料对应的基准产量 | 必须为正数 |
| 核定用量 | 订单生产所需用量 | 由生产配料基数、订单数量和基准用量计算 |
| 单位 | 物料使用单位 | 默认带入物料默认单位，允许在 BOM 行确认 |

“生产配料基数”不是库存数量，也不是订单数量；它表示这条物料配方对应的基准产量。建议补充一个明确的“基准用量”字段，否则仅凭生产配料基数和订单数量无法计算核定用量。推荐模型为：

```text
核定用量 = 订单数量 / 生产配料基数 × 基准用量
```

若业务确认“生产配料基数”本身就是基准用量，则采用：

```text
核定用量 = 订单数量 × 生产配料基数
```

第一种口径更符合“基数”和“用量”是两个不同概念，开发前必须在产品确认中锁定，避免数据库字段含义漂移。金额和数量全部使用 Decimal，前端展示按单位精度格式化，禁止 JavaScript 浮点累加。

### 2.2 物料

物料是采购和仓库共同使用的主数据。销售单产品不得自动写入物料清单；只有 `material_type = raw_material` 的物料可进入 BOM 和生产领料。成品物料与原料物料在 API 层强制隔离。

物料编码提供两种模式：

- 自动生成：服务端按固定前缀、日期或序列生成，并在数据库唯一约束下重试冲突。
- 手动填写：用户输入编码，服务端校验唯一性、长度和允许字符。

建议新增 `code_mode`（`auto`/`manual`）仅作为创建请求字段，不必持久化；持久化的唯一事实仍是 `materialCode`。编辑时默认不允许修改已被 BOM、采购单或库存事实引用的编码，避免历史快照与主数据失配。

默认单位选择器必须支持“新增类目”：在当前表单上打开子弹窗创建单位，创建成功后关闭子弹窗、回到物料表单、保留原填写内容，并立即把新单位加入选择项且自动选中。该流程复用全站类目创建返回机制。

## 3. 生产领料单

### 3.1 入口与绑定

生产领料单从生产模块进入，创建时先选择一个状态为生产中的厂内生产单。系统读取该生产单绑定的 BOM 表，按 BOM 行生成领料明细。用户可以调整申请补料数量，但不能改变物料身份；新增非 BOM 物料必须明确显示风险并记录原因，默认不允许。

### 3.2 全量表格字段

领料单使用居中悬浮大页面，目标宽度至少为原页面可视区域的 80%，表格一次性展示全部字段，不使用横向滚动隐藏字段：

| 字段 | 数据来源/计算 |
| --- | --- |
| 物料名称 | BOM 物料快照 |
| 物料代码 | 物料主数据编码 |
| 型号 | BOM 规格型号 |
| 颜色 | BOM 颜色 |
| 核定用量 | BOM 核定用量 |
| 库存数量 | 原料库存事实汇总 |
| 采购入库数量 | 绑定订单号下已过账原料入库 |
| 采购未入库数量 | 采购明细数量 - 已过账入库数量 |
| 生产领用数量 | 当前生产单已过账领料累计 |
| 生产未领用数量 | 核定用量 - 生产领用数量 |
| 申请补料数量 | 用户填写，默认 0 |

颜色规则：库存不足、生产未领用量大于 0 或申请补料大于 0 时使用警示样式；库存足够使用成功样式。计算结果必须由服务端返回，前端只负责展示，防止并发领料下的错误判断。

### 3.3 状态与接口

沿用现有单据状态：`draft -> posted -> reversed`。建议接口：

- `GET /production/material-movements?production_order_id=`：列表
- `GET /production/material-movements/:id`：详情及计算列
- `POST /production/material-movements/preview`：按生产单和行预览库存、采购、领用差额
- `POST /production/material-movements`：创建草稿
- `PATCH /production/material-movements/:id`：编辑草稿
- `DELETE /production/material-movements/:id`：删除草稿
- `POST /production/material-movements/:id/post`：锁定库存并过账
- `POST /production/material-movements/:id/reverse`：冲销

过账必须在事务内重新读取库存并校验，不能信任创建时的预览值。生产领料单必须绑定 `production_order_id`，明细物料必须引用物料清单唯一 ID。

## 4. 生产工序池

生产工序池是生产模块的基础资料页面，支持启用工序的增删改查、停用和恢复。生产单新增工序只能从工序池选择，生产单保存的是工序快照，后续修改工序池名称不改写历史生产单。

首次部署预置以下工序，使用幂等 seed，重复迁移不得重复创建：

```text
大裁、拉边、小裁、验片、合片、剪线头、打顶打带、打珠尾、缝伞、品检、折伞、外发加工、其他、包装
```

预置工序默认启用；“其他”允许使用，但不能绕过工序池直接输入自由文本。删除采用停用，已有生产单仍可展示历史快照。

## 5. 工序员工日报

### 5.1 交互

在生产单 -> 工序的日报悬浮页面内，员工字段改为一次多选。选择结果在表格中展开为多行，每行仍可单独填写：

- 计薪方式：计件或计时
- 计件数量：计件必填，计时可为空
- 时长：计时必填（单位小时，最多 4 位小数），计件可为空
- 当日人工单价：两种方式均必填，由用户人工填写（计时为 元/小时，计件为 元/件）

批量选择只负责生成行，不绕过每行校验。**同一员工在同一生产单、工序、日期下允许重复选择**（每次加入生成一条独立日报，各自计薪），因此批量选择不去重。

### 5.2 工资累计

日报保存后在同一事务内更新/重建该员工、生产单、日期、计薪方式的工资来源汇总。工资台账按周期汇总每日来源金额，不再读取工序标准计价，也不要求填写覆盖原因。

## 6. 页面与组件要求

1. BOM、采购单、生产领料单、工序员工日报均使用现有 `Dialog/Sheet`、`DataTable`、`Button`、`Select`、`Input` 组件。
2. 生产领料单和日报悬浮页使用宽屏布局，在桌面端占原页面至少 80%；移动端允许纵向折叠，但桌面端字段必须全量可见。
3. 新增单位、物料、工序等类目后，回到调用页面，恢复原表单值，刷新选择项并自动选中新建项。
4. 所有数量、库存和差额列使用统一格式化函数，空值显示 `-`，不把 `undefined` 暴露给用户。

## 7. 数据库改造建议

### BOM Item

新增：`specification_model`、`production_batch_base`、`base_usage`（若采用推荐公式）、`approved_usage`。保留 `model` 作为兼容读取字段，迁移完成后统一 API 输出为“规格型号”。

### Material

确认 `material_code` 唯一约束；创建 API 增加自动/手动编码模式，默认单位继续使用 `default_unit_id`，并强制原料/成品类型校验。

### Production Material Movement

复用现有领料单和明细模型，补充用于审计的 BOM 行引用、核定用量快照、库存预览快照和申请补料数量。历史单据不能因 BOM 或物料主数据编辑而改变。

## 8. 实施顺序

1. 先确认核定用量公式和字段命名，补 Prisma 模型与迁移。
2. 完成物料编码模式、默认单位新增类目返回和物料类型隔离。
3. 完成 BOM 表格字段、计算和编辑保存。
4. 完成工序池 seed、CRUD，并让生产单从工序池选择。
5. 完成生产领料单预览、全量字段悬浮页面和事务过账。
6. 完成员工日报多选员工、逐行计薪校验和工资来源累计。
7. 执行 API 单元/集成测试、前端构建、Playwright 页面验收和部署包验收。

## 9. 验收标准

- 同一订单号只能创建一份 BOM，BOM 可编辑，核定用量按确认公式计算且保存后可复现。
- 新建物料可自动生成编码或人工填写编码；默认单位可在当前表单内新增并立即可选。
- 销售成品不会出现在原料物料清单、BOM 或生产领料候选中。
- 生产工序池首次部署包含 14 个预置工序，支持增删改查和停用。
- 生产领料单绑定生产单和 BOM，桌面端一次显示全部 11 个业务列，库存/采购/领用差额与服务端一致。
- 日报可一次多选员工；计件不要求时长、计时不要求件数，但人工单价始终必填。
- 每次日报保存后，工资总览和周期台账能看到对应累计金额。
- 所有新增类目流程返回原页面并保留已填写内容，选择项立即刷新。
