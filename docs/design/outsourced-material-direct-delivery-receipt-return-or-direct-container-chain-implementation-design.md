# D6 外加工物料直发、签收、回厂/直装柜链路实施设计

> 文档类型：链路实施设计文档。
>
> 状态：待开发。本文件只定义 D6 的业务事实、联动边界和验收口径；不替代采购、仓库、生产或财务模块的领域设计。

## 1. 问题说明

迪礼的外加工订单需要将采购原料直接发送到外加工点。原料不进入厂内可用库存，但采购、生产、仓库和后续财务仍需依据同一个 `order_no` 追溯其去向。外加工完成后，成品可能回厂验收、入库，也可能直接装柜发货；外加工余料也可能回厂。

现有 D2 已覆盖采购来料 QC、原料入库和应付来源，D3-D5 已覆盖厂内生产、领料与生产日报。它们不能表达“采购直发外加工点”“外加工点签收”“成品回厂或直装柜”这些不经过厂内原料库存的事实。如果只通过备注记录，采购到货、外加工生产单、仓库库存和订单状态会失去可追溯关系；如果把直发原料错误记入厂内库存，又会造成库存虚增。

## 2. 方案与范围

本链路以 `order_no` 为业务主线，以外加工生产单为生产归属，以一个可分批的“外加工物流批次”记录原料直发、外加工点签收、成品回厂、余料回厂或成品直装柜的实际发生。

外加工现场的工序日报、员工报工、薪资和进度继续不进入 ERP。D6 只管理物料/成品的交接与物流事实，不将外加工过程伪装为厂内生产。

### 2.1 上下游关系

```text
销售单 / BOM / 订单
       |
       | order_no
       v
外加工生产单 + 外加工点
       |
       +-- 采购单明细 -- 原料直发批次 -- 外加工点签收
       |                                      |
       |                                      +-- 余料回厂 -- 原料 QC / 入库
       |
       +-- 外加工完工成品 --------------------+-- 成品回厂 -- 成品 QC -- 成品入库
                                              |
                                              +-- 直装柜发货 -- 销售/财务后续链路
```

### 2.2 D6 包含

- 以采购单明细为来源，创建可分批的外加工原料直发批次。
- 记录发出数量、物流/交接资料、外加工生产单、外加工点及签收结果。
- 将“已签收的外加工直发数量”作为采购到货事实之一，供 D2 应付来源复用；不形成厂内原料可用库存。
- 记录外加工余料回厂；实际入厂时复用原料 QC 与原料入库能力，形成厂内库存。
- 记录外加工成品回厂；实际入厂时复用成品 QC 与成品入库能力。
- 记录外加工成品直装柜发货事实，保留订单、生产单、数量、装柜/物流资料和附件；为销售成品出库、应收和报关资料链路预留来源。
- 支持草稿修改、已发生事实的更正/冲销、影响预览、附件和完整审计。

### 2.3 D6 不包含

- 外加工点现场生产日报、工序进度、员工档案、计件/计时薪资和加工费核算。
- 采购付款、外加工加工费应付、供应商对账、应收确认和收款。
- 成品 QC 检验项目、成品入库、成品出库、报关单、装箱单的完整领域实现；D6 只提供可被后续链路消费的来源事实。
- 客户签收、物流追踪、移动端、离线操作、自动库存成本、自动 MRP 和审批流。

## 3. 用户故事

1. 作为采购操作员，我要从采购单明细创建外加工原料直发批次，以便原料不经厂内仓库也能追溯到订单和外加工点。
2. 作为采购操作员，我要将一张采购单明细分多次直发，以便反映供应商分批到货和分批发货的实际情况。
3. 作为仓库操作员，我要看到直发原料不增加厂内原料可用库存，以便库存余额不被虚增。
4. 作为外加工对接人，我要登记外加工点实际签收的数量、日期和凭据，以便区分已发出、已签收、短收和未签收物料。
5. 作为采购或财务操作员，我要基于已签收的合格直发数量查看应付来源，以便不因未进入厂内仓库而遗漏采购应付。
6. 作为物控员，我要查看外加工生产单累计签收原料和回厂/直装柜成品数量，以便掌握订单外加工交接状态。
7. 作为仓库操作员，我要登记外加工余料回厂并衔接原料 QC、入库，以便只有实际回厂且检验合格的余料进入厂内库存。
8. 作为仓库操作员，我要登记外加工成品回厂并衔接成品 QC、入库，以便成品库存只反映已实际回厂且验收合格的数量。
9. 作为销售/仓库操作员，我要登记外加工成品直接装柜发货，以便后续销售、应收和报关资料可以使用同一来源事实。
10. 作为操作员，我要在录入错误时预览更正或冲销的下游影响，以便不会误改库存、应付来源或发货来源。
11. 作为审计人员，我要追溯每次直发、签收、回厂、直装柜、更正和冲销的操作人、时间、原因、前后值与附件，以便所有业务变化可解释。
12. 作为管理员，我要阻止已停用外加工点、非外加工生产单、不匹配订单或已关闭生产单的新建交接，以便错误不能绕过前端校验写入系统。

## 4. 实施决策

### 4.1 核心业务对象

| 对象 | 核心字段 | 规则 |
| --- | --- | --- |
| 外加工物流批次 | 批次号、`order_id/order_no`、外加工生产单、外加工点、来源采购单明细、物料、单位、计划/发出数量、状态 | 一批次只对应一张外加工生产单、一条采购单明细和一种物料；同一采购明细可产生多批次。 |
| 外加工点签收 | 物流批次、签收日期、签收数量、签收人、签收凭据、差异原因 | 可分批签收；累计签收不得超过未冲销的发出数量。短收允许保存但必须填写原因并生成业务告警。 |
| 外加工回厂交接 | 类型、外加工生产单、`order_no`、数量、单位、交接日期、来源批次、后续 QC/入库来源 | 类型固定为 `material_return`（余料回厂）或 `finished_goods_return`（成品回厂）；交接本身不直接增加库存。 |
| 外加工直装柜 | 外加工生产单、`order_no`、成品名称快照、数量、单位、装柜/发货日期、物流资料 | 只记录实际发出事实，不形成厂内成品库存；后续 E 链路将其转为销售出库、应收和报关资料来源。 |
| 外加工交接更正 | 原业务事实、方式、原因、影响快照、执行人 | 已发生事实不直接覆盖；通过冲销或补充事实更正。草稿才允许原位修改或逻辑删除。 |

所有新对象均使用 UUID 主键和统一审计字段：`created_at`、`updated_at`、`created_by`、`updated_by`、`deleted_at`、`deleted_by`、`remark`。金额、数量通过 API 使用十进制字符串传输；表单关联统一复用 `attachment` 与 `attachment_link`。

### 4.2 状态机

外加工物流批次状态：

```text
draft -> dispatched -> partially_received -> received
  |          |                 |                |
  +--------> cancelled <-------+----------------+
```

- `draft`：未发生直发，可编辑或逻辑删除。
- `dispatched`：已记录发出，允许继续录入签收或以冲销方式纠正。
- `partially_received`：累计签收大于零且小于发出数量。
- `received`：累计签收等于发出数量。
- `cancelled`：只表示草稿取消或已发生直发被完整冲销后的终态；不得直接抹除历史事实。

回厂交接状态：`draft -> pending_qc -> qc_passed -> inbound_completed`，或 `pending_qc -> qc_failed/cancelled`。

直装柜状态：`draft -> dispatched -> corrected`。直装柜一旦发出，数量和日期的错误必须由冲销/补充发货事实处理；`corrected` 仅表达原事实已被后续更正，不删除原记录。

### 4.3 直发与采购应付口径

- 创建直发批次时，服务端从采购单明细取得采购单、物料、单位、单价/税率快照与 `order_no`，客户端不得直接覆盖这些关联快照。
- 直发数量必须大于零，累计未冲销直发数量不得超过采购单可履约数量；超过时拒绝并提示回到采购单调整，而不是绕过采购数量约束。
- 已发出不代表到货或应付来源。只有外加工点签收的有效数量才可作为 D2 应付来源候选；D2 的后续实现需要将来源类型扩展为 `warehouse_inbound` 与 `outsource_direct_receipt`。
- 外加工点签收不走厂内原料 QC 和入库，不增加 `raw_material_inventory`；签收凭据为必填附件或必填备注二选一，实际规则由界面强制执行。
- 签收短少、超收或更正都会重新计算采购单的已履约/可应付数量；若已被财务确认或付款，只允许产生待处理风险提示，具体财务冲销由后续 F 链路处理。

### 4.4 回厂与库存口径

- 外加工余料回厂创建后只表示“在途回厂”或“待验收”，不得直接增加原料库存；完成原料 QC 合格和原料入库后才增加可用原料库存。
- 外加工成品回厂创建后只表示“待验收成品”，不得直接增加成品库存；完成成品 QC 合格和成品入库后才增加成品库存。
- 回厂数量允许大于单个直发批次的签收数量，因为一个外加工生产单可对应多个直发批次，且成品数量与原料计量单位可能不同；D6 只做非负数和生产单一致性校验，不做单位换算或配比反推。
- 在后续 QC/入库链路拒绝或撤销时，回厂交接状态应同步反映，不能保留“已入库”的虚假状态。

### 4.5 直装柜口径

- 直装柜必须关联有效、未关闭的外加工生产单和同一 `order_no`，并填写成品描述、数量、单位、发货日期及至少一项物流/装柜资料。
- D6 不新增厂内库存变动，也不直接创建应收；它提供稳定的“外加工直装柜发货来源”，供销售 E 链路创建成品出库、发货资料、应收和报关资料。
- 直装柜数量默认不与厂内成品库存核销。若未来需要以外加工完工数量或销售单数量做上限门禁，应在 E 链路确认来源数量与补发规则后再增加，避免错误地将生产计划当作实物库存。

### 4.6 更正、冲销与风险提示

- 所有表单保存前提供影响预览，至少显示采购可履约/应付数量、厂内库存影响、回厂待验收数量、直装柜来源数量及将要变化的告警。
- 草稿状态允许修改和逻辑删除。已发出、已签收、已回厂或已直装柜的记录禁止原位删除。
- 更正已发生事实时，创建引用原记录的冲销事实或补充事实；冲销数量不能超过原记录尚未被冲销的数量，且必须填写更正原因。
- 若签收、回厂或直装柜已经被下游 QC、入库、销售出库、应付或应收来源引用，服务端返回影响预览与风险提示。D6 不自行改写下游单据；可自动联动的状态更新与必须人工处理的下游事实应明确区分。
- 所有创建、修改、冲销、状态流转、拒绝和影响预览确认写入审计事件，记录操作者、操作时间、`order_no`、关联单据、原因和前后值。

### 4.7 API、权限与前端工作流

API 复用全局 `/api/v1`、REST、JSON、`snake_case`、请求 ID、十进制字符串和稳定错误码规范。建议资源：

- `GET/POST /outsource-logistics-batches`
- `GET/PATCH /outsource-logistics-batches/:id`
- `POST /outsource-logistics-batches/:id/dispatch`
- `POST /outsource-logistics-batches/:id/receipts`
- `POST /outsource-logistics-batches/:id/reversals`
- `GET/POST /outsource-return-transfers`
- `GET/PATCH /outsource-return-transfers/:id`
- `POST /outsource-return-transfers/:id/submit-for-qc`
- `GET/POST /outsource-direct-shipments`
- `GET/PATCH /outsource-direct-shipments/:id`
- `POST /outsource-direct-shipments/:id/reversals`
- `GET /outsource-logistics-batches/:id/impact-preview`
- `GET /outsource-logistics-batches/:id/audit-events`

前端在采购、生产单详情和仓库入口展示同一外加工交接工作流：先选择外加工生产单及采购单明细，再录入直发与签收；余料/成品回厂和直装柜从生产单上下文发起。所有下拉选项由服务端返回，前端不自行拼接 `order_no`、库存余额或应付金额。

权限先复用现有 RBAC：管理员拥有完整权限；采购可维护直发和签收；仓库可维护回厂交接与查看直装柜；物控可查看并维护与生产单相关的交接；财务可读取应付来源；销售可读取直装柜来源。审批人/批准人字段只预留，不在 D6 建立审批流。

## 5. 测试决策

最高测试缝隙为 D6 REST API 加真实 PostgreSQL 事务；浏览器验收覆盖采购/仓库操作员按外加工生产单完成可见的交接流程。沿用现有 `node:test`、HTTP/API 契约测试、独立 PostgreSQL 测试库、质量门禁和 Playwright，不断言 Prisma 内部调用。

至少覆盖：

1. 只能为有效外加工生产单和启用外加工点创建直发批次；厂内生产单、订单不匹配、停用地点和已关闭生产单被拒绝。
2. 同一采购单明细支持多批直发和多次签收；签收累计正确改变批次状态，签收超出有效直发量被拒绝。
3. 直发和签收不增加厂内原料库存；有效签收可生成 D2 应付来源，未签收或被冲销数量不可生成。
4. 短收可保存但必须有原因并产生可追溯风险提示；已确认短收再补收后正确恢复或更新。
5. 余料回厂与成品回厂在 QC/入库完成前不增加库存；QC 合格并入库后才形成正确库存影响。
6. 直装柜不增加或减少厂内成品库存，但可被后续销售出库来源查询稳定读取。
7. 草稿可编辑/逻辑删除；已发生直发、签收、回厂和直装柜不能直接删除，冲销不得超过剩余可冲数量。
8. 更正预览正确指出受影响的采购应付来源、QC/入库来源、直装柜来源和需要人工处理的下游单据；事务失败时不留下部分事实。
9. 未认证返回 401、越权返回 403、非法状态/数量/关联返回全局约定的 422 或 409；幂等键重复提交不产生重复交接事实。
10. Playwright 覆盖登录、外加工生产单选择、分批直发、签收、回厂待 QC、直装柜、影响预览和审计查看。

## 6. 交付门槛

- 数据库迁移、Prisma 校验/生成、API 与 Web build 通过。
- D6 集成、HTTP/API、既有 D1-D5 回归和 Playwright 验收全部通过。
- 测试报告包含直发不入库、签收形成应付来源、回厂经 QC/入库后才影响库存、直装柜不影响厂内库存四项证据。
- 所有状态变更、更正和冲销均能从审计记录追溯到操作人、时间、原因和原始业务事实。

## 7. 后续衔接

- D2/D6：采购应付来源增加外加工直发签收来源，财务应付确认、付款和加工费结算由 F 链路定义。
- E1：成品 QC 和成品入库消费外加工成品回厂交接。
- E2-E5：销售发货、装箱/报关、应收和收款消费外加工直装柜来源。
- D7：订单工作台可聚合外加工直发、签收、回厂和直装柜状态，但不反推外加工现场生产进度。

## 8. 待后续确认的规则

- 外加工直发签收是否必须经过独立来料 QC，以及直发采购应付究竟以签收数量、签收后抽检合格数量还是其他数量为准。
- 外加工余料回厂的来源校验与处置：是否需要强制关联具体直发批次、是否允许直接报废、如何处理外加工点库存余额。
- 外加工成品回厂与直装柜的 QC 门禁：直装柜前是否必须检验、让步接收如何表达。
- 外加工成品数量的业务上限、补发/返工及客户退货规则。
- 直装柜是否在 D6 仅登记物流事实，或在 E 链路创建时才允许确认最终发货；本设计默认前者。
