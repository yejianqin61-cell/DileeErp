# 原料领料、退料、报废与库存联动链路实现设计

> 文档类型：跨模块纵向链路开发设计
>
> 链路：厂内生产单 -> 原料领料 -> 生产退料/报废 -> 原料库存事实与告警
>
> 对应路线图：D4；依赖 C4、D3
>
> 状态：待开发

## 1. 问题陈述

原料已经可以由采购来料 QC 合格后入库，厂内生产单及其工序也已经可建立和启动，但系统尚未记录某张生产单实际消耗了哪些原料。仓库操作员目前无法依据生产单领料、退回余料或登记报废，库存余额也无法解释为何减少。因此，后续的工序日报、生产进度、成品 QC 和订单工作台缺少可信的物料消耗事实。

本链路要在不直接编辑库存余额、不改变外加工边界的前提下，让每一笔厂内领料都可追溯至 `order_no`、生产单、物料和执行人，并允许用可审计的反向业务事实纠正录入错误。

## 2. 方案与边界

本批交付下列闭环：

```text
已入库可用原料 + 厂内生产中的生产单
  -> 创建原料领料草稿
  -> 影响预览：可用库存、BOM 参考量、累计领料和风险
  -> 过账领料：写入负向库存事实
  -> 原领料的余料退回：写入正向库存事实
  -> 原领料的报废：仅形成消耗/报废事实，不回到可用库存
  -> 冲销已过账业务事实：写入严格反向事实
```

`order_no` 是所有表单和库存事实的跨模块追溯身份；UUID 仅用于关系约束。领料、退料和报废均为厂内生产的物料流转，不等同于工序日报、员工计件/计时、生产完工或成品入库。

外加工物料直发、外加工余料、外加工点签收、回厂及加工费不在本批实现，继续由 D6 处理。采购原料入库、供应商退货、盘点和成品库存也不在本批重写。

## 3. 用户故事

1. 作为仓库操作员，我要选择一张有效的厂内生产单领料，以便原料库存和生产单的物料消耗能够同步追溯。
2. 作为仓库操作员，我要在领料前看到当前可用库存，以便系统阻止负库存出库。
3. 作为仓库操作员，我要看到 BOM 参考用量与该生产单的累计领料量，以便识别超领风险。
4. 作为仓库操作员，我要在超领或领用非 BOM 物料时填写原因并继续过账，以便真实现场情况不会因系统而遗漏。
5. 作为车间操作员，我要将未用余料退回仓库，并关联原领料明细，以便库存回补且退料不超过可退数量。
6. 作为车间操作员，我要登记已领物料的报废数量和原因，以便损耗有记录但不会虚增可用库存。
7. 作为操作员，我要以冲销单纠正已过账的领料、退料或报废，而不是修改历史数量，以便库存和审计历史保持自洽。
8. 作为物控员，我要按订单号、生产单号、物料及日期查询领退料和报废明细，以便核对生产物料消耗。
9. 作为管理员，我要查看每次过账、冲销和风险确认的操作人、时间、原因及前后数量，以便完成审计追溯。
10. 作为后续日报与进度功能，我要获得稳定且不可静默改写的生产物料消耗事实，以便与生产数量及异常告警交叉核对。

## 4. 实现决策

### 4.1 适用生产单与来源口径

- 仅 `execution_mode = in_house` 且状态为 `in_progress` 的生产单可创建并过账新的领料、退料和报废单。草稿、暂停、已完成、已关闭、已逻辑删除生产单不得新增物料流转；已过账历史始终可查询。
- 所有生产物料表单由服务端从 `production_order_id` 取得 `order_no`、销售订单、BOM 版本快照、厂内车间和计划数量，客户端不得重复传入并覆盖这些来源。
- 每个表单明细必须关联一个现有、启用物料及其固定单位。V1.0 不支持单位换算；明细单位必须等于物料默认单位和库存事实单位。
- BOM 仅作为领料参考，不自动生成领料需求，也不禁止非 BOM 物料或超出 BOM 数量的真实领用。系统必须对此给出风险提示并要求原因。

### 4.2 领域对象与字段

新增生产原料流转单头和明细。可使用单一业务表单模型，以 `document_type` 区分 `issue`（领料）、`return`（退料）、`scrap`（报废）和 `reversal`（冲销）；明细保留原单/原明细关联。实现可以拆表，但 API 和审计语义必须保持一致。

| 对象 | 核心字段 | 约束 |
| --- | --- | --- |
| 原料流转单头 | 单号、类型、生产单、`order_no`、生产地点快照、业务日期、状态、原因、备注、冲销来源 | 单号系统生成；状态为 `draft`、`posted`、`reversed`；已过账不直接编辑或删除。 |
| 原料流转明细 | 表单、物料、单位、数量、BOM 参考数量快照、原领料明细、备注 | 数量为正十进制字符串；退料和报废必须关联同一生产单下的原领料明细。 |
| 库存事实 | 库存分类、物料、单位、数量增减、来源类型/ID/版本、`order_no`、生产单、表单明细 | 仅追加，不修改或删除；可通过来源定位所有影响库存的业务记录。 |
| 风险确认 | 风险类型、表单/明细、风险上下文快照、操作原因、确认人及时间 | 本批至少覆盖超领、非 BOM 物料与冲销后负库存风险。 |

所有新业务表使用 UUID 主键及统一的 `created_at`、`updated_at`、`created_by`、`updated_by`、`deleted_at`、`deleted_by`、`remark` 字段。确认过账、冲销、逻辑删除尝试和状态变更均写入统一审计日志，审计内容包括操作人、时间、`order_no`、关联单号、原因、前后值和对象快照。

现有 `InventoryFact` 仅能关联原料入库，不足以表达生产领退料。D4 需要将其演进为保留既有入库关联兼容性的通用、追加式库存事实：新增通用来源字段和可选生产单/原料流转明细关联；原料入库继续作为一种来源。库存余额仍按 `inventory_category + material_id + unit_id` 聚合有效事实，业务服务不得手工更新余额。

### 4.3 数量、库存与状态规则

- 领料单草稿可创建、编辑和逻辑删除；过账时每个明细向 `raw_material` 可用库存写入负向库存事实。任一明细导致可用库存小于零时，整个事务拒绝，不得出现部分过账。
- 同一生产单和物料支持多次、分批领料。累计净领料量为已过账领料减已过账领料冲销，再减已过账退料及其冲销影响；报废不改变“已从仓库领出”的事实。
- 退料必须关联原领料明细，退料数量不得超过该原领料明细的可退数量。可退数量为原领料已生效数量减已生效退料、已生效报废及各自冲销影响；过账退料向可用原料库存写入正向事实。
- 报废必须关联原领料明细，数量不得超过该原领料明细在退料后仍由车间持有的数量。过账报废不向可用原料库存写入数量，但记录不可删除的报废消耗事实，以免系统把报废误解为可退余料。
- 领料、退料、报废均允许多物料明细；每张已过账表单只能整体冲销，冲销单生成逐明细严格相反的库存或持有数量影响。被冲销的原单保留且标记 `reversed`。
- 已过账表单的录错更正流程固定为“冲销原单 -> 新建正确草稿 -> 过账”。禁止修改已过账数量、来源生产单或物料，禁止物理删除。

### 4.4 超领预览、告警与风险门禁

领料草稿及过账前必须返回影响预览。逐明细至少展示：当前可用原料库存、过账后可用库存、该生产单 BOM 参考量、当前累计净领料、拟领数量、过账后累计净领料、已退料、已报废及未解决风险。

- 过账后库存为负是硬性门禁，返回 `422 INSUFFICIENT_INVENTORY`。
- 过账后累计净领料超过 BOM 参考量，是可继续的 `OVER_ISSUE_WARNING`；必须填写原因、写审计及风险确认。
- 领用 BOM 中不存在的物料，是可继续的 `MATERIAL_NOT_IN_BOM_WARNING`；必须填写原因、写审计及风险确认。
- 退料或报废超过原领料可处分数量，是硬性门禁，分别返回 `RETURN_QUANTITY_EXCEEDED`、`SCRAP_QUANTITY_EXCEEDED`。
- 冲销若会使库存为负或令下游退料/报废失去有效来源，则拒绝，返回 `INSUFFICIENT_INVENTORY` 或 `DOWNSTREAM_RECORD_EXISTS`。本批只显示单据内风险，不建设全局告警中心。

### 4.5 REST API、权限与前端工作流

API 复用 `/api/v1`、JSON 信封、`snake_case`、十进制字符串、请求 ID、统一异常及乐观并发校验。资源采用复数 kebab-case；状态动作不得以 `PATCH` 直接写入。

- 提供厂内生产单的可领料上下文/影响预览，以及原料流转单的列表、详情、草稿创建、草稿编辑、草稿删除、过账、冲销和审计查询接口。
- 过账与冲销必须在单一数据库事务中完成：校验生产单/来源/数量，写入表单状态、库存事实、风险确认和审计日志。过账请求使用幂等键，重复请求不得重复扣减或回补库存。
- 列表支持按 `order_no`、生产单号、单据号、物料、类型、状态、业务日期查询；结果同时返回来源生产单和库存影响摘要，避免前端自行拼接跨模块数据。
- 管理员拥有完整权限；仓库操作员可维护并过账物料流转；物控员可查看、创建草稿和确认风险，但最终权限复用现有 RBAC 配置，不引入审批流。未登录为 401，越权为 403。
- 前端在生产工作台或仓库工作台提供同一条工作流：选择生产单、录入明细、查看影响预览、填写必要原因、过账、查询/冲销历史。使用既定 TanStack Table、shadcn/ui、React Hook Form，不显示伪造库存或生产数据。

### 4.6 附件与可追溯性

领料、退料、报废及冲销表单复用统一 `attachment`，附件非必传，可附领料凭据、退料凭据、报废照片或说明。每条业务记录均可按 `order_no`、生产单号和物料回查至采购入库事实；库存余额查询可继续下钻到产生该余额的入库、领料、退料和冲销记录。

## 5. 测试决策

最高自动化测试缝隙为生产原料流转 REST API，使用独立 PostgreSQL 测试库验证可观察的业务结果；不对 Prisma 调用或前端内部实现断言。库存余额查询和审计查询是同一缝隙的结果验证。

- 领域/集成测试：可用库存入库后分批领料扣减；重复过账幂等；负库存全单失败且不遗留部分事实；退料回补；报废不回补；退料和报废均不得超出可处分数量。
- 风险测试：超领和非 BOM 物料在有原因时可过账并留下风险确认；缺少原因被拒绝；库存不足、生产单非厂内或非生产中均被拒绝。
- 回退测试：已过账领料不可直接修改；冲销后库存恢复；存在已退料/报废时阻止不安全冲销；新建正确领料可在冲销后完成。
- API/权限测试：未登录 401、无权限 403、非法状态/数量 422、版本冲突 409；所有响应遵守全局 JSON 契约。
- 浏览器验收：登录后选择已启动厂内生产单，领料并过账，库存余额变化；退料或报废后确认对应变化与历史可见。测试复用现有 `verify:chain`、独立 PostgreSQL、HTTP/API 和 Playwright 基础设施。

## 6. 不在本链路范围

- 工序日报、员工计件/计时日报、薪资计算、超单生产量和生产进度；这些属于 D5、D7。
- 成品 QC、成品入库、成品出库、应收和收款；这些属于 E1-E5。
- 外加工直发、外加工余料/回厂、外加工点签收、加工费和结算；这些属于 D6 与采购/财务后续设计。
- 采购退货、盘点、仓位、单位换算、库存成本、全局告警中心与审批流。
- BOM 自动 MRP、自动领料建议、自动排产及移动端/离线操作。

## 7. 交付门槛与后续衔接

1. 先完成通用库存事实迁移与可用库存聚合兼容性，确保既有原料入库链路不回归。
2. 完成厂内生产单领料、退料、报废、冲销及风险预览的 API 和审计闭环。
3. 完成前端真实工作流，不以占位数据替代库存或生产单结果。
4. 将 PostgreSQL、API 和浏览器验收纳入 `verify:chain`，并记录测试证据。
5. D4 验收后，D5 才可基于稳定的生产单、工序与物料消耗事实设计工序日报、员工日报和差异/超单告警。
