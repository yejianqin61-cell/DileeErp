# 财务三大报表：在本系统怎么实现（2026-09-24）

财务 2026-09-24 交付 `example/财务/财务三大报表（标准格式）(2).xlsx`，要求「需要财务三大报表」。
这份文档是**先看清楚、再回答怎么实现**的结论：模板口径 / 系统现状 / 差距 / 分期方案 / 需要她拍板的三件事。

结论先说：**模板可以照抄，但不能直接套**。系统当前的记账口径是「确认即收付」（一笔业务 = 一笔资金动作），
凭证又只能由收支流水生成 —— 现在就把三张表算出来，得到的是一张「只有货币资金 + 未分配利润」的表，
而应收账款 / 应付账款 / 存货 / 固定资产恒为 0。要让它们有数，必须补分录层，而那会改动她熟悉的确认流程，
所以这一期先出**映射表 + 取数方案 + 缺口清单**，等她定口径。

---

## 一、模板里有什么（逐张表）

`财务三大报表（标准格式）(2).xlsx` 四个工作表，是**财政部一般企业财务报表格式（2019 修订）**：

| 工作表 | 规模 | 结构要点 |
|---|---|---|
| 资产负债表 | A1:H41，左侧资产（行次 1–34）、右侧负债和所有者权益（行次 1–34） | 两栏对照；「期末余额 / 年初余额」；C18/C38/C40 与 G18/G28/G29/G39/G40 是公式行；**G41 = C40−G40 勾稽核对**，H41 = `IF(G41=0,"✓ 平衡","✗ 不平衡")` |
| 利润表 | A1:D27，行次 1–23 | 「本期金额 / 上期金额」；C17 营业利润 / C20 利润总额 / C22 净利润 / C24 综合收益总额 是公式行；末尾「每股收益（基本 / 稀释）」 |
| 现金流量表 | A1:D41，行次 1–35 | 经营 / 投资 / 筹资 三段，各段「流入小计 → 流出小计 → 净额」；C39 现金及现金等价物净增加额、C41 期末余额 是公式行 |
| 填表说明 | A1:D22 | 报表口径 / 填写方法 / 报表间勾稽关系 / 增删科目 |

模板自己写明了两件对我们很关键的事：

1. **口径**：「本表按《企业会计准则——财务报表列报》及财政部一般企业财务报表格式编制，
   适用于一般企业（制造业）对外报送」；并且「如贵司适用《小企业会计准则》，科目与格式可进一步精简，
   可另行索取简化版」。
2. **勾稽**：① 资产负债表「货币资金」期末 ≈ 现金流量表「期末现金及现金等价物余额」；
   ② 资产负债表「未分配利润」期末 − 年初 ≈ 利润表「净利润」；③ 资产总计 = 负债和所有者权益总计。

还有一条填写纪律值得照抄到我们的导出件里：**「合计/小计/总计」行由公式算，财务只填白色科目行**，
以及**亏损/流出/减项用负数填列**。

## 二、本系统的现状（四条事实，都能在代码里指到）

| 事实 | 位置 | 对三大报表意味着什么 |
|---|---|---|
| ① 科目表是**小企业准则式**的 121 条 + 1 条补充（分类 = 资产类/负债类/成本类/所有者权益类/损益类，项目 = 科目名） | `accounting-subject-catalog.ts` | 与模板的「一般企业」行**不是一一对应**：模板有交易性金融资产、合同资产、使用权资产、商誉、递延所得税…我们一条都没有；我们有「银行存款 阿里账户（美元）」这类明细科目要并进「货币资金」 |
| ② 凭证**只能由收支流水生成**（`POST /finance/vouchers/from-cash-flow/:entryId`），没有「手工新增凭证」入口 | `voucher.controller.ts` | 折旧、摊销、计提工资、结转成本这些**非现金分录在系统里没有落点** → 报表不可能完整；买了设备也没法记成固定资产（只能把某笔流水的分录改成固定资产） |
| ③ **确认即收付**：确认应收 = 借银行存款/贷主营业务收入；确认应付 = 借主营业务成本等/贷银行存款 | `receivable.service.ts:149`（`subjectNames: RECEIVABLE_CONFIRM_SUBJECT_NAMES`）、`supplier-payable.service.ts` | **应收账款与应付账款永远是 0**（钱与收入/成本同时发生，中间没有债权债务那一层）；资产负债表里资产只剩货币资金 |
| ④ 凭证有 `draft / posted / reversed` 三态；红冲是「另开一张反向凭证 + 原凭证置 reversed」 | `voucher.service.ts` | 取数只认 `posted`（红冲件本身是 posted，反向分录自带负数效果），草稿与已红冲都不进表 —— 但**必须把「本期有 N 条已生效流水还没生成凭证」显式提示**，否则表是不完整的而看的人不知道 |

**所以现在直接算，会算出什么？** 把全部已过账凭证按科目累计：

- 资产 = 货币资金（银行存款 + 库存现金）——银行账户的期初余额不在凭证里，还得从 `banks.opening_balance` 补；
- 负债 = 0（除非用过「应交税费-*」这类科目）；
- 所有者权益 = 未分配利润 = 收入 − 支出；
- **资产合计 = 权益合计**，G41 会显示「✓ 平衡」——一张形式上完美、内容上空心的表。

这正是「不能直接套」的原因：平衡不等于完整。

## 三、分期方案

### 一期（本轮之后紧接着可做，不改任何业务流程）

> **进度（2026-09-24）**：一期**已全部落地**——
> 口径内核 `apps/api/src/modules/finance/finance-three-statements.ts`（映射 + 聚合 + 公式 + 守卫）、
> 取数 `finance-three-statements.service.ts`（只取已过账凭证；一次取到期末再切四个切片）、
> 版式 `finance-three-statements.tables.ts`（8 列两栏对照 / 4 列本期上期）、
> 路由 6 条（`GET /finance/reports/{balance-sheet,income-statement,cash-flow-statement}[.xlsx]`，
> 与既有 8 张对账报表共用预览与导出出口）、以及「财务报表」板块的三个页签（`scope: "period"`，
> 筛选条只留期间与币种）。金额口径同时抽成 `money.ts`（全模块一份实现）。
> 测试：内核 16 条 + 取数 5 条 + 版式 5 条 + 接口 3 条 + 页面 1 条。
> **二期**（需要改业务流程或加表，用户 2026-09-24 已确认「都要」）见本文档 §8.4 / §8.5 与 §3 二期。

目标：出一份**能核对的管理口径**三大报表，并且**把缺口写在表上**，而不是让财务以为这就是对外那份。

1. **科目 → 报表行映射表**（下面第六节就是它的初稿），做成**代码里的数据**（不是 if 分支），
   并把「未映射到任何报表行的科目，期末余额非零」逐条列进表尾 —— 与报表导出「缺采购价物料必须显式列出」
   同一条纪律（`finance-report.tables.ts` 的先例）。
2. **取数**：`ReportTable` 复用现有的报表基建（`finance-report.types.ts` / `finance-report-workbook.ts` /
   `finance-report.controller.ts` 的预览 + xlsx 双出口），新增三个 key：
   `balance-sheet` / `income-statement` / `cash-flow-statement`，与现有 8 张报表同一套预览与导出。
3. **公式行照模板算**（合计/小计由我们算，不让财务手填），**保留模板的「勾稽核对」行**：
   资产负债表的 `G41 = C40 − G40` 与 `✓ 平衡 / ✗ 不平衡`，逐字照抄。
4. **表尾缺口清单**（每期都要有）：
   - 本期已生效但**未生成凭证**的收支流水条数与金额（按方向分）；
   - 草稿凭证条数（没进表）；
   - 未映射科目及其余额；
   - 外币折人民币的口径（见 8.2）。
5. 页面：加在「财务报表」板块的三个页签（`FINANCE_REPORT_TABS`），筛选条用一个**期间（月/年）**
   而不是现有的起止日期（报表口径是期间），期间控件单独一种 `scope: "period"`。

一期的产物是**真数**（有凭证就对得上），但会有大片空白行 —— 空白的原因写在表尾，不是猜的。

### 二期（需要财务确认业务口径后才能做）

> **进度（2026-09-24）**：**① 手工新增凭证已落地** —— 迁移
> `20260924100000_voucher_manual_source`（`source_id` 放宽为可空：手工凭证没有来源单据，
> 唯一索引不动，NULL 不受唯一约束）、`VoucherService.createManual`（借贷校验 / 期间与编号 /
> 科目快照 / 银行账户校验）、`POST /finance/vouchers`、以及凭证页的「新建凭证」
> （与编辑分录共用同一个编辑器的新建态：日期/币种在这里填）。**②③④ 待做**。

要把应收账款 / 应付账款 / 存货 / 固定资产这些行填上，必须补分录层：

1. **加「手工新增凭证」入口**（`POST /finance/vouchers`）：没有它，折旧/摊销/计提/结转永远进不来。
   分录编辑器（`voucher-line-editor.tsx`）已经能编多借多贷，缺的只是一个「新建」入口。
2. **权责发生制化**（这一步会改她熟悉的流程，必须她拍板）：
   - 确认应收 = 借 应收账款 / 贷 主营业务收入（+应交税费-销项税）；实际收款 = 借 银行存款 / 贷 应收账款；
   - 采购入库 = 借 原材料（或库存商品）/ 应交税费-进项税 / 贷 应付账款；付款 = 借 应付账款 / 贷 银行存款；
   - 工资：计提 借 生产成本/管理费用 / 贷 应付职工薪酬；发放 借 应付职工薪酬 / 贷 银行存款；
   - 期末：结转成本（借 主营业务成本 / 贷 库存商品）、折旧摊销、结转损益到本年利润。
   代价：她现在的「勾选 → 批量确认 → 钱就出去了」要变成「确认（挂账）→ 付款/收款（销账）」两步 ——
   系统里其实已经有这两步的雏形（`supplier_payments` / `customer_payments` 核销），
   但 2026-09-16 的既定口径是「不要又是登记付款又是确认应付」，所以**不能我们自己改**。

### 三期（口径稳定后）

现金流量表的**项目映射维护**（财务可改「哪个科目 / 哪类业务进哪一行」）、上期与年初累计口径、
导出件里的打印版式（模板的灰色合计行样式）、以及「报表锁定/归档」（结账后不再变）。

## 四、取数口径与公式

- **余额类（资产负债表）**：某科目在 `[期初, 期末]` 的累计 `借−贷`。
  - 「期末余额」= 建账以来到期末的累计；
  - 「年初余额」= 到上年 12-31 的累计；
  - 建账前的余额只有一个来源：**银行账户档案的 `opening_balance`**（它不在凭证里）——
    货币资金行必须把它加上，否则「货币资金期末」对不上银行余额表（`GET /finance/banks/balances`）。
    ⚠️ **只加资产侧会让勾稽不平**：期初余额在会计上是两侧同时存在的（钱有期初，对应的权益/负债也有期初）。
    内核因此把期初留成两个口子（`opening.money` / `opening.retained`），只填前者时把差额作为
    `openingDifference` 返回并要求写进表尾。**系统目前没有「科目期初余额表」**，所以一期的资产负债表
    会一直差一个「期初余额」的差额 —— 要消掉它就得让财务录一次全科目的期初（见 §8.4）；
  - 资产类科目取借方余额、负债与权益类取贷方余额；备抵科目（累计折旧 / 累计摊销）按同一方向算出来
    天然是负数，直接与主科目相加即净额（不要写成「减：累计折旧」，财务按准则记账时会算成正的）；
  - **损益类科目期末不结转到本年利润**（系统没有结转凭证），所以「未分配利润」=
    `利润分配 + 本年利润 + Σ 损益类科目贷方余额 + Σ 当期费用性质的成本类科目贷方余额`，
    这样 G40 的资产 = 负债 + 权益 才成立。
- **发生额类（利润表 / 现金流量表）**：期间 `[from, to]` 内的借贷发生额，收入类取 `贷−借`，
  费用类取 `借−贷`（模板要求：亏损/损失/流出用负数填列，后端算出来的符号就按这个给）。
  - 「本期金额」= 所选期间；「上期金额」= **整月期间取上一个自然月**（8 月对 7 月，天数不同也对），
    非整月期间（自定义起止、半月）取紧邻之前**等长**的一段 —— 一律按等长天数会让 9 月对到 8/2–8/31、
    3 月对到 1/29–2/28，财务对不上「上月」这个数。
- **现金流量表**：按**每张已过账凭证**里的资金类分录（`subject_key ∈ {银行存款, 库存现金}`）
  定方向（借 = 流入、贷 = 流出），用它**同一张凭证里的业务分录科目**决定落在哪一行。
  银行互转（`bank_transfers`）本来就不写凭证、不进收支流水，所以**自动被排除在现金流量表之外**——
  这正好是准则要求的（内部划转不影响现金及现金等价物总额）。
- **红冲**：原凭证 `reversed` 不进表，红冲件（`posted`，反方向）进表 → 净额正确。
- **币种**：凭证有 `currency`。人民币报表要把外币折成人民币，凭证上没有汇率（只有金额与币种）。
  一期口径建议：**按币种分行/分列不折算**（与全站「不跨币种相加」一致），并在表尾写明；
  要折算就得先有「期末汇率」这张表（这是 8.2 那个问题）。

## 五、页面与导出长什么样

- 位置：`/finance/reports?tab=balance-sheet | income-statement | cash-flow-statement`；
- 预览：直接用现有 `DataTable` 渲染 `ReportTable`（列头 / 数值格式 / 合计 / 表尾脚注都已经支持），
  两侧对照的资产负债表按「资产侧 4 列 + 负债权益侧 4 列」一次给 8 列；
- 导出：`POST`/`GET` 走同一个 `ReportTable` → xlsx（全站纪律：金额必须是数值单元格），
  表尾附 `makerStamp`（谁、什么时候生成的）——报表是对外文件，落款必须能答「这份文件从哪来」。

## 八、需要财务拍板的三件事（决定报表能填到什么程度）

**8.1 成本类科目的归属**：`临时工资 / 加工费 / 水电费 / 房租费 / 生产用品 / 机台维修费 / 顺丰快递 /
货拉拉 物流费 / 印刷费 / 工资支付 / 研发支出` 这一批，系统里是「当月付出去的支出」，
但按会计准则它们先是制造费用（期末在制品 → 存货），结转后才进营业成本。放在哪一侧，
直接决定「存货」与「营业成本」两行的数字。

**8.2 外币折算**：凭证上有币种但没有汇率。三大报表是人民币报表 —— 要按期末汇率折算吗？
（要折算就需要「期末汇率」这张表，并由财务每月维护；不折算则按币种分列，表尾写明。）

> **已落地（2026-09-24，用户回复「1,3,4 都要」的第 ④ 件）**：建 `exchange_rates`（期间 `YYYY-MM` + 币种 + `1 外币 = rate 人民币`，
> 精度 `DECIMAL(18,8)`），`PUT /finance/exchange-rates` 按期间整批替换，界面挂在会计科目页（`ExchangeRatePanel`）。
> 取数口径（`finance-three-statements.service.ts`）：
> - **折算点在分录层**：非本币凭证逐行折成人民币后才进内核/版式 —— 行匹配、勾稽、公式全都不用知道汇率的存在。
>   本币报表（`CNY`）取**全部**币种；报表币种换成外币时不折算（「1 外币 = X 人民币」的方向就反了），退回「不跨币种相加 + 表尾说明」。
> - **三个时点各用自己那个月的汇率**：期末存量与本期流量用**期末月**、年初存量用**上年 12 月**、期初现金与上期流量用**上期期末月**；
>   某月没维护就回退到「不晚于它的最近一个月」，并在表尾写明用的是哪一期（`gap.otherCurrencies[].period`）。
> - **汇率变动对现金的影响（行次 32）** = 期末资金（按期末汇率）− 期初资金（按期初汇率）− 本期资金净流量（按期末汇率）。
>   由取数层算好传给内核（内核只看凭证，看不到「资金余额折成多少」，硬算会算错），本币业务下恒为 0。
> - **折算不了的外币不许静默丢**：一条汇率都没有的币种，其凭证与期初都**不折进本表**（钱少了、两侧都少所以勾稽照样平，
>   这是最难发现的一类错），因此单独进 `gap.unconverted` 并要求在表尾点名 + 引导去维护汇率。
> - 银行账户期初兜底（只有货币资金）仍按报表币种取，且只在「本币科目期初表缺失或里面没有货币资金」时生效。

**8.3 「收到的税费返还 / 支付的各项税费」的口径**：科目表里退税挂在「营业外收入」
（见 `LEGACY_CASH_FLOW_ITEM_SUBJECTS` 的「国家退税」注释），而准则要求退税进「收到的税费返还」。
要不要为退税单独立一个科目（例如「应交税费-出口退税」）？否则这一行会与「收到其他与经营活动有关的现金」混在一起。

**8.4（连带）要不要补分录层**：也就是第二节事实②③那两条 —— 加「手工新增凭证」入口、
把确认应收/应付改成「挂账 → 销账」两步。不加，报表就永远只有货币资金与未分配利润；
加了，她现在的「确认即记账」流程要变。这一条是她必须明确点头的事，我们不自己改。

> **进展（2026-09-24）**：「手工新增凭证」已落地（二期 ①）。「挂账 → 销账」两步的完整方案见
> [`finance-accrual-two-step-2026-09-24.md`](./finance-accrual-two-step-2026-09-24.md) ——
> 方案里写清了现状事实、改成两步后的分录与报表影响、文件级改动点、要补的 7 条测试，
> 以及需要她拍板的三件事（要不要改 / 挂账落草稿还是直接过账 / 历史数据保持原样还是逐条重挂）。
> **同日进展：应收侧已按该方案落地**（确认应收 = 挂账、收款过账 = 销账；历史数据不动、测试已补），

**8.5 要不要录一次「科目期初余额」（建账期初）**：银行账户档案里有期初余额，其它科目没有。
只把银行期初加进货币资金、不给对应的权益/负债期初，资产负债表就会一直差一个「期初余额」的差额
（内核把这笔差额显式返回并要求写进表尾，不是算错）。要让勾稽真正为 0，需要财务录一次全科目的期初余额
—— 这需要一张新表（`accounting_opening_balances`）与一个录入界面，是她要拍板的工作量。
