> 状态：已确认，可进入开发拆解  
> 适用范围：采购、来料 QC、原料入库、应付、供应商付款、批次工作区

## 1. 已确认的最终业务口径

### 1.1 应付来源生成时点

**只有原料入库过账，才生成应付来源。**

```text
采购单
  → 到货批次
  → 来料 QC
  → 原料入库草稿
  → 原料入库过账
  → 应付来源
  → 应付确认
  → 供应商付款
  → 付款核销
```

以下环节不生成有效应付：

```text
采购下单
到货登记
QC 检验
QC 拒收
原料入库草稿
```

原因：到货物料可能 QC 不合格并退货，未实际入库的数量不形成付款义务。

### 1.2 QC 结果只有三种

| QC 结果 | 原料入库 | 应付 | 财务处理 |
|---|---|---|---|
| 全部入库 | 全部合格/可接收数量入库 | 按全部实际入库数量 × 采购单价 | 系统按采购单价计算应付 |
| 拒收 | 0 | 0 | 不产生应付，不进入付款链；拒收/退货由采购和仓库处理 |
| 部分入库 | 用户填写实际入库数量 | 用户填写实际入库数量、单价、总价 | 以用户确认的入库和金额作为应付来源 |

部分入库时，财务相关数据以用户明确填写的结算结果为准：

```text
实际入库数量
+ 实际结算单价
+ 实际结算总价
+ 金额差异原因
+ 币种/税率/费用
```

其中：

- 实际入库数量不得超过 QC 允许入库数量；
- 实际结算总价必须大于零；
- 单价、总价、币种、税率的计算和覆盖规则必须在同一张入库/应付来源中留痕；
- 用户填写的总价不是普通备注，而是正式财务来源字段。

### 1.3 “冲销”的定义

冲销只适用于已经过账、已经产生库存或财务影响的事实。

```text
草稿未过账 → 可以编辑或删除
已过账事实 → 不删除，新增反向事实进行抵消
```

示例：

```text
原料入库过账 +100
→ 发现数量错误
→ 生成原料入库冲销 -100
→ 库存恢复
```

如果原入库已经形成应付或已经付款，不能只冲库存，还必须按下游事实依次处理：

```text
付款核销冲销
→ 应付处理/冲销或调整
→ 原料入库事实冲销
→ QC/到货更正
```

冲销必须保留：

- 原事实 ID；
- 冲销原因；
- 冲销操作人；
- 冲销时间；
- 冲销前后状态；
- 数量、金额和余额变化；
- 关联订单号、采购单号、批次号。

## 2. 目标统一批次矩阵

采购单详情必须提供整单级批次工作区，而不是仅按单个采购物料分块展示。

### 2.1 推荐视图

行维度固定为采购物料，列维度按批次分组：

| 采购物料 | 计划量 | 累计到货 | 未到货 | 第1批到货 | 第1批QC | 第1批入库 | 第1批应付 | 第1批已付 | 第1批余额 | 第2批到货 | 第2批QC | 第2批入库 | 第2批应付 | 第2批已付 | 第2批余额 |
|---|---:|---:|---:|---|---|---|---|---|---|---|---|---|---|---|---|
| 原料 A | 100 | 100 | 0 | 60 | 全部入库 | 60 | 600 | 300 | 300 | 40 | 部分入库 | 20 | 240 | 0 | 240 |

### 2.2 批次分组字段

每个批次至少展开以下信息：

```text
批次序号
到货单号
到货日期
到货数量
QC结果
QC检验数量
QC可入库数量
实际入库数量
入库单号
入库状态
应付来源单号
应付数量
应付单价
应付总价
应付状态
已付款金额
未付款余额
批次风险/差异
```

### 2.3 视图入口

目标页面：

```text
apps/web/app/procurement/page.tsx
  → 采购单列表
  → 点击采购单号
  → 整单批次工作区 Sheet/Workbench
```

工作区要求：

- 宽度至少占原页面 80%；
- 横向滚动支持任意批次数量；
- 固定物料列；
- 批次列动态增加；
- 同一批次的到货、QC、入库、应付、付款必须视觉上成组；
- 所有行保留订单号、采购单号、批次号；
- 点击批次单元格可进入对应详情或操作表单；
- 批次状态变化后整单矩阵立即刷新。

## 3. 已完成能力清单

按照本次确认的判定标准，以下能力已经实现，即使尚未完成真实端到端验收，也不再列为开发缺口：

- 到货批次编号和批次序号；
- 累计到货、剩余到货和超单状态计算；
- 到货关闭后禁止新增到货；
- 到货批次幂等创建；
- 到货批次草稿编辑、撤销及状态恢复；
- 关闭、修改、撤销的事务锁和状态复核。

### 3.2 来料 QC

- 每批到货自动关联唯一 QC 记录；
- 同一批次支持分次检验累计；
- QC 合格、条件接收、不合格数量字段已存在；
- QC 数量不得超过到货数量；
- QC 与到货批次关联展示。

> 本计划将历史的“合格/条件接收/不合格”实现字段统一收敛为业务结果“全部入库/部分入库/拒收”。原有合格、条件接收、不合格数量可以作为检验明细，但最终入库结果必须落到这三个业务结果之一。

### 3.3 原料入库

- QC 可入库量门禁；
- 原料入库草稿；
- 入库草稿编辑；
- 入库过账写入库存事实；
- 入库冲销生成反向库存事实；
- 入库过账并发保护；
- 原料/成品物料边界校验。

### 3.4 应付和付款

- 应付来源、应付确认、供应商付款和付款分配接口；
- 一笔付款核销多笔应付；
- 一笔应付由多笔付款核销；
- 应付余额、付款余额和状态计算；
- 付款金额和核销金额门禁；
- 付款冲销；
- 供应商应付对账；
- 财务草稿编辑和已过账事实保护；
- 审计事件、原因字段和权限控制。

这些能力的真实 PostgreSQL/HTTP/Playwright 验收仍可继续补充，但不作为本计划的功能开发缺口。

#### U-04：全部入库场景

```text

→ 实际入库数量 = QC 可入库数量
→ 实际单价 = 采购单价

→ 生成应付来源
```

当前状态：**部分完成，2/4**。

- 需要在原料入库表单显示和确认“全部入库”；
- 应付来源必须以实际入库数量生成；
- 应付来源不能在到货或 QC 阶段提前生效。

- 拒收和未过账入库的零应付规则。

依赖：M2。

### M4：入库冲销与付款后回退治理

范围：U-10、U-11、U-12。

交付：

- 草稿删除；
- 已过账入库冲销；
- 应付/付款下游影响预览；
- 已付款回退阻断和处理指引；
- 反向事实、审计、状态恢复。

依赖：M3。

## 6. 端到端验收场景

> 本节是业务验收用例，不把“测试环境暂缺”视为功能未实现；代码/页面完成后即可标记开发完成，环境验收另行记录。

### Case A：一次性全部入库

```text
采购 100
→ 到货 100
→ QC：全部入库
→ 入库 100
→ 应付来源 100 × 采购单价
→ 应付确认
→ 付款 100%
→ 应付 paid
```

### Case B：分批到货、分批入库、分批付款

```text
采购 100
→ 第1批到货 60
→ 第1批 QC：全部入库
→ 第1批入库 60
→ 应付来源 60
→ 第1批付款 30
→ 应付 partially_paid
→ 第2批到货 40
→ 第2批 QC：全部入库
→ 第2批入库 40
→ 应付来源 40
→ 再付款并分别核销
```

### Case C：QC 拒收

```text
采购 100
→ 到货 100
→ QC：拒收
→ 入库 0
→ 有效应付 0
→ 不进入付款核销
→ 采购/仓库处理退货
```

### Case D：QC 部分入库

```text
采购 100
→ 到货 100
→ QC：部分入库
→ 用户填写实际入库 60
→ 用户填写结算单价/总价
→ 入库 60
→ 只对 60 生成应付来源
→ 剩余 40 作为未入库/待处理数量
```

### Case E：同一 QC 分批入库

```text
QC 可入库 100
→ 第1批入库 40 → 应付 40
→ 第2批入库 60 → 应付 60
→ 累计入库 100
→ 不得继续入库
```

### Case F：已付款后发现入库错误

```text
入库 100
→ 应付确认 100
→ 付款核销 100
→ 发现入库错误
→ 系统拒绝直接删除/修改
→ 先冲销付款
→ 再处理应付
→ 再冲销入库
→ 保留全量审计
```

## 7. 非本计划范围

- 总账、会计凭证、科目余额；
- 税务申报、自动税费计算、发票自动验真；
- 银行自动对账；
- 自动采购建议；
- 无审批盘盈盘亏；
- 复杂批号成本、库位成本；
- 将 QC 拒收自动转化为完整供应商退货业务单据；拒收后的采购/仓库退货仍需另行定义。

## 8. 最终自评结论

当前采购财务管线已经拥有大部分后端服务、状态机、草稿/过账/付款和审计能力。按照“已实现即完成”的新判定，真正需要开发的重点集中为：

1. **采购单整单统一批次矩阵视图；**
2. **财务页面按入库批次展示应付和付款余额；**
3. **QC 三结果统一为全部入库、拒收、部分入库；**
4. **部分入库时让用户填写实际入库数量、单价和总价；**
5. **把应付来源严格收敛到原料入库过账；**
6. **补齐入库冲销和已付款后上游回退的受控处理路径。**

最关键的数据原则是：

```text
到货是物流事实
QC 是质量判断
入库是库存和付款义务的财务触发点
应付是实际入库结算事实
付款是应付的资金结算事实
```
