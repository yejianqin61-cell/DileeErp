# 业务查询 Agent V0 全盘开发计划

> 类型：开发实施计划｜版本：V0｜日期：2026-10-25｜状态：待评审

建议分六个可验收阶段实施。先证明模型可达路径只能读业务数据，且普通员工看不到财务事实；再接入 DeepSeek、补齐 31 个查询能力，最后验证并发、恢复和发布。每阶段都交付可演示的问答链路。

本文安排施工顺序与证据。接口、字段口径和状态定义以[工程布局](business-query-agent-v0-architecture-2026-10-23.md)和[模块细化设计](business-query-agent-v0-module-design-2026-10-25.md)为准。

**范围**：NestJS API、Next.js 查询页、Agent 自有数据表、数据库权限、测试和部署配置。V0 只允许业务查询；Agent 没有业务写入、文件或代码操作能力。计划不包含多副本、队列、长期记忆或自主任务。

**待定条件**：接真实客户资料前确认联系人电话、地址的可见范围；接生产订单到 DeepSeek 前确认公有 API 或内网端点。两项不妨碍先用脱敏样例完成只读链路与模块测试。

## 1. 需求清单

- **R-1 只读业务边界** — 工程布局“决定”“会话、成本”；模块设计“工具注册”。
- **R-2 两档数据权限** — 用户指定老板、财务与其他员工的范围；工程布局“两档权限”。
- **R-3 用户会话隔离** — 用户指定按 `userId` 隔离；模块设计“API 权限与数据表”。
- **R-4 DeepSeek 查询编排** — 用户指定 DeepSeek 和复用方针；工程布局“为什么采用这个形态”。
- **R-5 完整只读工具集** — 用户指定工具尽可能多而全；工程布局“工具如何做到广覆盖”；模块设计 operation 映射。
- **R-6 八轮上下文与输入** — 用户明确输入 token 不设限；模块设计“LLM provider 与 orchestrator”。
- **R-7 持久状态与幂等** — 用户要求前后端状态机；模块设计“API 权限与数据表”“并发控制”。
- **R-8 小规模并发控制** — 用户要求先完善并发且不过度设计；模块设计“并发控制”。
- **R-9 JSON 与 SSE 协议** — 用户指定 JSON、SSE；模块设计“SSE 与前后端状态机”。
- **R-10 查询页状态机** — 用户要求前后端都有状态机；工程布局“前后端状态机”。
- **R-11 可观测性与成本** — 用户要求上下文控制成本；工程布局“会话、成本”；模块设计“怎样观察问题”。
- **R-12 数据口径与来源** — 模块设计“每个 operation 怎样复用现有查询”“最小验收集”。
- **R-13 可发布与可回退** — 工程布局“如何验收与回退”；模块设计“范围外与待定项”。

## 2. 逐项实施方法

### R-1 只读业务边界

- **做法**：业务查询只用独立只读数据库账号。Agent 状态只写自有表；注册表不提供通用 SQL、HTTP、文件或代码工具。
- **涉及**：数据库权限、查询执行、工具注册。
- **测试入口**：现有 HTTP 集成测试入口，穿过新查询路由；再用只读账号做一次数据库拒写检查。
- **验收**：[ ] 所有注册工具在只读账号下完成查询；[ ] 业务写入被数据库拒绝；[ ] 提示注入找不到可执行写操作。
- **难点**：现有领域服务混合读写，不能因为复用而注入其高权限连接。

### R-2 两档数据权限

- **做法**：服务端按当前有效角色判 `full` 或 `operational`。API、工具、SSE 和历史读取各自校验；输出使用显式字段投影。
- **涉及**：认证授权、工具执行、会话读取、流式发送。
- **测试入口**：同一订单的 HTTP 问答与 SSE 重放，再覆盖工具执行 Interface。
- **验收**：[ ] 老板和财务可查订单财务事实；[ ] 其他员工和人事只得非财务事实；[ ] 降权后旧财务 run 不再可读。
- **难点**：工作台综合状态、审计详情和自由 JSON 可间接泄露财务信息。

### R-3 用户会话隔离

- **做法**：所有 session、run、事件查询都以当前用户及资源 ID 为条件。幂等结果也需通过当前权限检查。
- **涉及**：会话存储、权限守卫、SSE 订阅。
- **测试入口**：现有 HTTP 集成测试入口，用两个账号交叉读、续接和取消。
- **验收**：[ ] 用户 B 不能读、续接或取消用户 A 的 run；[ ] 列表与快照只出现本人当前可见内容。
- **难点**：断线重放与幂等返回容易绕过初次请求的归属检查。

### R-4 DeepSeek 查询编排

- **做法**：复用 AI SDK 和 DeepSeek provider 处理模型协议与工具调用。编排器只开放固定工具，并在查询结束后关闭工具再流式回答。
- **涉及**：模型调用、编排、工具注册与执行。
- **测试入口**：编排 Interface 配假 provider；真实 DeepSeek 用脱敏订单做一次端到端试运行。
- **验收**：[ ] 模型只调用当前角色可见的工具；[ ] 多步查询有上限；[ ] 答案只引用本轮取得的来源。
- **难点**：模型工具参数、未知 operation 和中途取消都必须由本项目校验。

### R-5 完整只读工具集

- **做法**：按六个领域工具承载 31 个固定 operation。先沿用现有查询口径，再以只读连接构造窄 DTO。
- **涉及**：订单、销售、采购、生产、仓库、质检和财务查询。
- **测试入口**：工具执行 Interface；每个领域另以真实样例对照现有页面或报表。
- **验收**：[ ] 31 个 operation 均可按 schema 调用；[ ] 24 个非财务 operation 对 `operational` 安全；[ ] 7 个财务 operation 只对 `full` 开放。
- **难点**：原服务常返回价格、金额或宽关联对象，不能直接交给模型。

### R-6 八轮上下文与输入

- **做法**：只取本人当前有权读取的最近八个完成轮次，不带旧工具原始结果。不设应用层输入 token 配额。
- **涉及**：上下文管理、模型错误映射。
- **测试入口**：上下文管理 Interface 与完整问答入口。
- **验收**：[ ] 第九轮不带第一轮；[ ] 不按应用层 token 预算截断问题；[ ] 模型窗口超限返回明确错误。
- **难点**：旧 `full` 轮次在降权后不能进入新模型上下文。

### R-7 持久状态与幂等

- **做法**：持久化 session、run、事件；状态迁移与事件同事务提交。用幂等键和单用户活动 run 唯一约束挡住竞态。
- **涉及**：Agent 数据表、状态管理、编排。
- **测试入口**：HTTP 创建 run、状态管理 Interface 和进程重启恢复检查。
- **验收**：[ ] 相同键只启动一次模型；[ ] 取消后迟到结果不能写终态；[ ] 重启遗留 run 变为 `INTERRUPTED`。
- **难点**：并发创建、取消与模型回调可能同时写同一 run。

### R-8 小规模并发控制

- **做法**：单进程许可最多四个 run，每用户最多一个；无许可即返回 429，不建队列。
- **涉及**：并发许可、run 创建和结束。
- **测试入口**：HTTP 并发请求与许可释放检查。
- **验收**：[ ] 同用户第二个问题返回 409；[ ] 五个不同用户同时请求时最多四个运行；[ ] 失败与取消释放许可。
- **难点**：数据库活动 run 约束与进程许可必须同时正确，且不得泄漏许可。

### R-9 JSON 与 SSE 协议

- **做法**：JSON 建立和读取 run；SSE 发送版本化 JSON 事件。事件落库后按序发送，断线只重放，不重执行查询。
- **涉及**：控制器、事件存储、流式传输。
- **测试入口**：现有 HTTP 集成测试入口，读取分块 SSE 并断线续接。
- **验收**：[ ] 事件序号单调且可去重；[ ] 完成、失败和取消均有终态事件；[ ] 重连不重复工具调用。
- **难点**：重放与实时轮询之间不能丢事件；降权时不得重放旧财务片段。

### R-10 查询页状态机

- **做法**：前端 reducer 按后端快照和 SSE 事件更新页面。提供提问、进度、答案、来源、取消和恢复。
- **涉及**：页面、前端状态、权限栏目。
- **测试入口**：前端 reducer 测试与浏览器用户流程。
- **验收**：[ ] 四类表面角色能进入查询页；[ ] 刷新或断线可恢复当前 run；[ ] 权限撤销会清掉财务片段。
- **难点**：快照的答案与重放的 `answer_delta` 不能重复拼接。

### R-11 可观测性与成本

- **做法**：复用结构化日志，记录模型、工具、用量、耗时和稳定错误码。限制查询行数、字节数、工具步骤与运行时间。
- **涉及**：编排、工具执行、日志与配置。
- **测试入口**：编排 Interface 的错误路径及日志断言。
- **验收**：[ ] 每个 run 可按 ID 追踪工具与用量；[ ] 默认日志无问题全文和业务结果；[ ] 超时和超量有稳定错误码。
- **难点**：业务值可能藏在异常文本、工具参数或模型原始响应里。

### R-12 数据口径与来源

- **做法**：每个工具结果带业务来源和查询时间。数量、库存、成本与状态沿用现有领域规则，并与同单据结果对照。
- **涉及**：领域查询、DTO、答案来源。
- **测试入口**：工具执行 Interface 加真实业务样例的对照检查。
- **验收**：[ ] 库存余额与库存流水不混称；[ ] 软删、状态、单位和金额口径一致；[ ] 答案来源均可追到本轮事实。
- **难点**：原工作台状态混入财务事实；原料库存是全局实存量，不是订单专属余额。

### R-13 可发布与可回退

- **做法**：发布前检查数据库授权、模型端点、真实角色样例与开关。回退关闭 Agent 入口，保留自有会话数据待保留期处理。
- **涉及**：部署配置、数据库迁移、验收与回退。
- **测试入口**：预发布环境的双角色端到端流程和回退演练。
- **验收**：[ ] 只读账号无业务写权限；[ ] 两档真实账号通过验收；[ ] 关闭入口后业务系统原功能继续可用。
- **难点**：真实数据外发路径与联系人资料范围尚需按企业口径确认。

## 3. 分阶段施工与证据

### 阶段 1 — 一条安全的订单问答链路

**覆盖**：R-1 只读业务边界、R-2 两档数据权限、R-3 用户会话隔离、R-5 完整只读工具集、R-7 持久状态与幂等、R-9 JSON 与 SSE 协议、R-10 查询页状态机。

**目标**：登录员工能在查询页问一张订单；假 provider 经一个只读工具返回非财务事实，页面收到答案。另一个用户无法读取这次运行。

**任务**

- 打通登录、提问、只读订单搜索、假 provider 回答和 SSE 展示的最薄链路。
- 建立 Agent 自有表及单用户活动 run 约束，并分配只读和状态写入账号。
- 固定工具注册、输入校验和窄 DTO；禁止原 Prisma 对象进入模型。
- 接入 API 归属校验和当前角色档位校验。
- 用只读账号证明业务写入被拒绝，并用双账号证明会话隔离。

**证据**：端到端示例可演示；数据库拒写、跨用户拒绝和普通员工财务字段缺失检查通过。

**本阶段不做**：真实 DeepSeek、其余 30 个 operation 和完整视觉打磨。

### 阶段 2 — DeepSeek、上下文与运行控制

**覆盖**：R-4 DeepSeek 查询编排、R-6 八轮上下文与输入、R-7 持久状态与幂等、R-8 小规模并发控制、R-9 JSON 与 SSE 协议、R-11 可观测性与成本。

**目标**：同一订单问题由 DeepSeek 调用固定工具并流式回答；重复提交、超窗、取消及并发请求都有可预测结果。

**任务**

- 用脱敏订单把 DeepSeek 工具调用接到阶段 1 链路，并流式输出最终答案。
- 实现最近八轮上下文、来源约束和模型错误映射。
- 加入 run 合法迁移、幂等复用、取消和重启中断处理。
- 加入每用户一个、进程四个 run 的许可控制。
- 记录模型与工具用量，验证日志不含订单原始内容。
- 覆盖五用户并发、同键重试和超窗失败的可运行检查。

**证据**：脱敏样例得到带来源的流式答案；竞态、取消、重启与并发检查通过。

**本阶段不做**：扩展业务工具目录或引入分布式队列。

### 阶段 3 — 非财务订单全链路

**覆盖**：R-1 只读业务边界、R-2 两档数据权限、R-5 完整只读工具集、R-12 数据口径与来源。

**目标**：普通员工能问订单、采购、生产、质检和仓库进度；24 个非财务 operation 不泄露财务事实。

**任务**

- 先贯通一张订单的采购到货、质检、生产与库存查询并核对页面结果。
- 补齐订单与销售领域的非财务 operation。
- 补齐采购、生产及外加工领域的非财务 operation。
- 补齐仓库、成品质检和附件元数据 operation。
- 逐项检查宽对象、审计 JSON、文件名、价格和受财务影响的状态。
- 用真实订单样例对照数量、单位、库存余额及流水。

**证据**：24 个 operation 均有调用和字段检查；五类真实业务样例与现有页面口径一致。

**本阶段不做**：财务 operation 或业务写操作。

### 阶段 4 — 财务档位完整查询

**覆盖**：R-2 两档数据权限、R-5 完整只读工具集、R-12 数据口径与来源。

**目标**：老板和财务能查询同一订单的应收、应付、付款、对账、成本与人工；其他角色无法调用或重放这些结果。

**任务**

- 先让同一订单的应收问答在 `full` 成功、在 `operational` 被拒绝。
- 补齐收付款、应付和双向对账 operation。
- 补齐成本利润和订单关联人工日报 operation。
- 对照现有财务报表核验币种、出货、分摊与脚注口径。
- 演练运行中降权、历史重放拒绝和前端财务片段清除。

**证据**：7 个财务 operation 的双角色对照通过；降权后工具、SSE 和历史上下文均不再暴露财务事实。

**本阶段不做**：全员薪资台账、非订单财务分析或自动财务操作。

### 阶段 5 — 用户恢复体验与异常闭环

**覆盖**：R-3 用户会话隔离、R-7 持久状态与幂等、R-8 小规模并发控制、R-9 JSON 与 SSE 协议、R-10 查询页状态机、R-11 可观测性与成本。

**目标**：用户刷新、断线或取消时能看懂当前状态；重连不重复查询，忙碌或失败不会丢掉提问草稿。

**任务**

- 先贯通“回答中刷新页面、恢复快照、续接 SSE”用户流程。
- 完成前端 reducer 的合法迁移、去重和终态呈现。
- 完成 SSE 心跳、重放、取消与权限撤销处理。
- 呈现来源、工具进度、稳定错误和重试入口。
- 检查键盘操作、状态提示和长答案的可读性。
- 复核超时、结果大小与日志脱敏的异常路径。

**证据**：刷新、断线、取消、429、409 和权限撤销的浏览器流程通过；同一 run 的工具只执行一次。

**本阶段不做**：跨设备实时同步或后台队列。

### 阶段 6 — 发布验收与回退演练

**覆盖**：R-1 只读业务边界、R-2 两档数据权限、R-4 DeepSeek 查询编排、R-5 完整只读工具集、R-11 可观测性与成本、R-12 数据口径与来源、R-13 可发布与可回退。

**目标**：预发布环境用真实角色和代表性订单走通完整链路；关闭 Agent 后原业务系统仍正常。

**任务**

- 先在预发布环境从登录到 DeepSeek 回答跑通一条双角色订单链路。
- 核对只读与状态账号授权、密钥、模型端点和单进程部署假设。
- 对 31 个 operation 做目录审计及关键订单对照。
- 运行权限、并发、状态、SSE 和提示注入验收集。
- 记录用量和耗时基线，并确认会话保留与清理安排。
- 演练关闭入口、停止模型调用和保留 Agent 自有数据的回退路径。

**证据**：预发布验收记录、数据库权限证明、模型用量记录和回退演练结果齐备。

**本阶段不做**：多副本扩容、自动业务操作或超出 V0 的新工具。
