# 供应商编码自动生成 + 采购单库存粒度 + 应付台账/付款的区别（2026-09-15）

## 1. 新建供应商的编码：支持自动生成与手动填写

**排查结论：后端本来就支持，只有「应付管理里顺手新建供应商」这个入口没接上。**

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| `procurement-master-data.service.ts#createSupplier` | `code_mode === "auto" ? nextSupplierCode() : supplier_code` —— 两种模式都在 | 不变 |
| `SupplierDto` | `code_mode?: "auto" \| "manual"` + `supplier_code?` 可选 | 不变 |
| 采购 → 供应商页 `app/procurement/suppliers/page.tsx` | 已有「编码方式：自动生成 / 手动填写」下拉，手动留空时前端先拦，成功后提示生成的编码 | 不变 |
| **应付管理里的「新增类目 → 新建供应商」** | **`supplier_code` 标成必填、也不传 `code_mode`** → 走手动分支，留空直接 422 | 加「编码方式」下拉（默认自动生成），自动时留空并由服务端顺延 `SUP-…`，成功提示里带上生成的编码；手动留空在本地先拦下 |

顺带修掉同一处的另一个缺陷：`createSupplier` 失败时只 toast 不抛错，而 `ActionDialog` 靠
「onSubmit 是否 reject」决定关不关弹窗 —— 结果是**保存失败弹窗照样关闭**，用户只看到「点了没反应」。
现在校验失败与接口失败都 `throw`，弹窗留在原地显示原因。同一个文件里其它弹窗动作也统一改成
`submitAction()`（同样抛错），因为这是整页共用的行为。

## 2. 新建采购单时的库存判断粒度：**按物料（名称+规格+颜色）**，但「当前库存量」列曾跨单位相加

用户问的是「判断库存数只查名称，还是加上规格型号、颜色的粒度」。逐条查证：

- 库存查询走 `GET /inventory/raw-material-balances?material_ids=…`，**按 `material_id` 取数**；
- 而物料主数据是「名称 + 规格型号 + 颜色」唯一（`materials` 建了组合唯一索引），
  所以**规格型号与颜色在粒度上是分开的**，前提是主数据里它们是不同物料行；
- BOM 带入采购明细用的是 `bom.items[].materialId`（\*不是\*按名称匹配），
  服务端还会校验「明细必须引用当前 BOM 表中对应物料」（`PURCHASE_BOM_ITEM_MISMATCH`）与
  「物料/单位必须存在且启用」（`PURCHASE_REFERENCE_NOT_FOUND`）—— 后端这一层没有按名称拍的逻辑。

**但发现一个真缺陷**：草稿表的「当前库存量」列读的是 `stockByMaterial[materialId]`，
而那个键是 `refreshMaterialStock()` 里**把该物料所有单位的余额加起来**建的
（同一物料既有「米」又有「卷」是常态）。于是：

1. 显示的数量是跨单位之和（不可比的量相加）；
2. 绿/红的「够不够」比较（`>= 需求量`）也建立在这个错值上；
3. 同页的 `stockFor(materialId, unitId)`（按物料+单位）本来是对的，只有渲染那一格没用它。

修复：改为按「物料 + 单位」取值；同一物料在**其它单位**的余额作为提示文字与 `title` 一并给出
（「本行单位库存 5；另有 2 卷（单位不同，未相加）」），并删掉那个跨单位汇总键，避免以后再被误用。

## 3. 应付管理里「应付台账」和「付款」有什么区别

两张表放在同一个「确认应付」子栏目里，一个是**负债事实**，一个是**资金事实**：

| | 应付台账 | 付款 |
| --- | --- | --- |
| 一行是什么 | 一笔应付：一个来源批次（原料入库 / 外加工签收 / 其他应付） | 一次付款行为（日期 / 金额 / 方式 / 银行） |
| 关键字段 | 来源批次、订单号、采购单号、物料、应付金额、已付、未付 | 付款单号、日期、供应商、金额、已核销、方式、支付银行 |
| 状态机 | 草稿 → 确认 → 部分支付 → 已付清（另有冲销/作废） | 草稿 → 已过账 → 已冲销 |
| 谁决定余额 | 确认后才成为生效负债 | 只有**过账**才真的核销到应付台账 |
| 与收支流水 | 无直接关系（负债不产生现金流） | 过账自动写一笔支出；冲销自动回冲 |

关系：`应付台账（负债） ←核销— 付款（资金）`，一笔应付可被多张付款分批核销，
一张付款也可核销多笔应付。界面文案已按这个口径改写（见 `payable-workspace.tsx` 的两个 `panel-note`），
免得财务把「付款」当成第二本应付账。
