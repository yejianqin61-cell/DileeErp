# 迪礼 ERP V1.0 仓库模块设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：V1.0 领域规则已确认。QC 检验字段、具体 API 与数据库迁移在后续质量/仓库开发设计中继续拆解。

## 1. 设计目标与哲学

仓库模块以 `order_no` 为跨模块追溯主线，处理原料入库、原料领料、成品入库、成品出库，以及不良品、退料、退货和盘点调整。原料与成品均支持分批操作。

模块采用两层结构：

```text
动态层：入库/出库操作表单（业务事实）
  └─ 原料入库、领料、退料、退供应商、成品入库、成品出库、客户退货、冲销、盘点调整
                           │ 有效动态记录汇总
                           ▼
静态层：库存单（当前库存余额）
  └─ 原料、成品、退料、不良品四类库存
```

“进退皆可”是本模块固定设计哲学：

- 不良品可回退：来料与成品经 QC 后，合格、让步接收、不合格分别进入对应库存或处置路径；不合格可退供应商，生产余料可退仓，客户退货可回库或进入不良品。
- 录错可更正：动态表单的错误通过冲销、退料、退货、调整等可追溯动作纠正，不能直接篡改静态库存余额。
- 上下游自洽：编辑前必须展示采购、QC、生产、库存、应付/应收及后续出库影响；确认后，所有可派生余额、进度和告警在同一事务中联动更新。已确认的下游业务事实不被静默改写，改以差异提示、冲销或调整处理。

## 2. 固定原则

- 原料、成品、退料、不良品按库存分类分表管理；V1.0 不建设实体仓库、分仓、库位或货架管理。
- 库存单是静态汇总数据，按“库存分类 + 物料/成品”维护当前数量；订单、采购单、生产单、供应商、QC 等追溯信息保留在动态表单明细中，不拆分为订单专属可用库存。
- 每种物料或成品只有一个计量单位，不支持单位换算。
- 所有入库均必须经过 QC 检验。原料与成品的可用库存入库数量不得超过对应 QC 的合格数量与让步接收数量之和。
- 库存成本不由仓库模块自动计算；财务可人工维护相关数字，具体财务口径由财务模块设计。
- 库存余额由有效操作表单、冲销和盘点调整重算；禁止直接手工修改余额。
- 所有表统一具备 `created_at`、`updated_at`、`created_by`、`updated_by`、逻辑删除和完整操作审计；业务数据禁止物理删除。

## 3. 业务场景与上下游交接

| 场景 | 上游 | 仓库动态表单 | 结果/下游 |
| --- | --- | --- | --- |
| 采购来料 | 采购单、供应商到货 | 来料 QC 后原料入库 | 增加原料库存；实际入库量报送采购应付 |
| 来料不合格 | 来料 QC 不合格 | 不良品记录、原料退供应商出库 | 不进入可用原料库存；退货回冲对应应付来源 |
| 厂内领料 | 厂内生产单、BOM 参考 | 原料出库（领料） | 减少原料库存；生产单保留累计领料追溯 |
| 车间退料 | 原领料明细、生产单 | 生产退料入库 | 回到可用原料库存；不得超过可退数量 |
| 领料损耗/报废 | 生产单、物料 | 损耗/报废记录 | 不回到可用库存；记录数量和原因供追溯 |
| 厂内成品完工 | 生产单、成品 QC | 成品入库 | 增加成品库存；与生产计划/完工数差异告警联动 |
| 成品发货 | 订单号、销售发货资料预留 | 成品出库 | 减少成品库存；物流/签收资料预留，应收触发点由销售/财务定义 |
| 客户退货/返工 | 原成品出库、订单 | 成品退库/不良品/返工记录 | 不直接改原出库或应收来源；按实际状态回库或转不良品 |
| 外加工直发 | 采购单、外加工生产单、外加工点 | 外加工点签收记录 | 不进入厂内原料库存 |
| 外加工成品 | 外加工生产单 | 成品信息记录；QC 后入库或直接装柜发货 | 提供“回厂入库”与“直接装柜发货”选项 |
| 盘点 | 库存单 | 盘点单、库存调整记录 | 账实差异经确认后形成独立调整，不改写历史操作表单 |

## 4. 动态操作表单

### 4.1 原料入库

- 流程：供应商到货 -> QC -> 仓库按 QC 合格/让步接收数量分批入库。
- 关联采购单明细、QC 记录、`order_no`；可多次分批入库。
- 入库状态：`草稿 -> 已入库 -> 已关闭`。草稿可修改或逻辑删除；已入库后不得直接改数量或删除，只能通过冲销或退供应商更正。
- 累计合格入库超过采购数量时允许保存，但强提示采购超收，仓库操作员必须填写原因；采购单显示“已到齐/超收”。

### 4.2 原料领料、退料与损耗

- 原料领料必须关联厂内生产单、订单号、领料车间、领料人和领料日期；外加工直发不走厂内领料。
- 同一生产单支持分批领料；禁止负库存。
- 显示 BOM 参考量和累计领料量。超过参考量允许出库，但必须产生超领告警、填写原因并审计。
- 已出库领料录错时，使用领料冲销单后重新领料；草稿阶段才允许修改或逻辑删除。
- 生产退料必须关联原领料明细和生产单，退料数量不得超过可退数量，退回可用原料库存。
- 损耗/报废记录数量、原因、生产单和物料，不作为退料，不回到可用库存。

### 4.3 成品入库

- 流程：生产完成/送检 -> 成品 QC -> 仓库按 QC 合格/让步接收数量分批入库。
- 必须关联生产单、QC 记录、订单号和产品名称/规格快照；V1.0 不建立通用成品池。
- 累计入库数量不得超过 QC 可入库数量；与生产单计划量或已确认完成量不一致时允许保存并触发差异告警，不自动修改生产日报。
- 支持多次分批入库，状态为 `草稿 -> 已入库 -> 已关闭`；已入库后只可通过冲销或退库更正。
- QC 不合格成品进入不良品分类。

### 4.4 成品出库与退库

- 成品出库必须关联订单号，支持分批出库；销售出货指令、装箱单和发货单的强制门禁在销售模块继续定义，仓库表单预留关联字段。
- 禁止负库存。累计出库超过订单计划数量时允许保存，但强提示成品超发、填写原因并审计。
- 记录并预留承运/物流、发货日期、签收日期和 `attachment`；仓库出库先表达实物发出，应收触发点由销售和财务模块定义。
- 未签收的错发允许冲销出库；已签收后的客户退货通过独立客户退货入库处理，错发漏发通过补发出库处理，均不得直接修改原出库或应收来源。

### 4.5 不良品与外加工

- QC 结果固定支持合格、不合格、让步接收。让步接收进入可用库存但必须特殊标记并可追溯；不合格进入不良品分类，后续可退供应商或按报废规则处置。
- 外加工原料直发只记录采购单、生产单、外加工点和签收凭据，不进入厂内原料库存。
- 外加工余料、退料和损耗先在相关表单记录字段，不自动形成厂内库存变化；回厂余料必须走原料入库。
- 外加工成品必须记录成品信息，可选“回厂入库”或“直接装柜发货”。回厂入库必须经 QC；直接装柜发货仍保留成品信息和订单追溯。

## 5. 静态库存单

库存单只保存当前可查询的汇总余额，至少按库存分类和物料/成品维度查询。它不是操作入口，也不允许手工编辑数量。

| 库存分类 | 数量增加来源 | 数量减少来源 |
| --- | --- | --- |
| 原料 | QC 合格/让步接收原料入库、生产退料、盘盈调整 | 生产领料、退供应商、冲销、盘亏调整 |
| 成品 | QC 合格/让步接收的成品入库、客户退货入库、盘盈调整 | 成品出库、退库/转不良、冲销、盘亏调整 |
| 退料 | 生产退料记录及其暂存信息 | 回到可用原料库存或后续处置，具体字段按开发设计落实 |
| 不良品 | QC 不合格原料/成品、仓库发现不良 | 退供应商、报废、返工或其他已确认处置 |

动态表单的每次确认、冲销、退货和盘点调整都必须联动重算对应库存单。修改已确认动态记录时，影响预览应展示库存单变动、关联单据和风险；保存后系统保持所有库存分类余额自洽。

## 6. 盘点、告警、附件与权限

- 盘点单记录账面数、实盘数、差异、原因和附件；确认后生成独立库存调整记录，不直接编辑库存单。确认人/审批规则暂预留。
- 统一告警：库存不足、采购超收、领料超领、成品入库差异、成品超发、QC 未入库/重复入库。统一状态为“待处理、已确认、已恢复”；告警不阻塞保存，但关键风险必须强提示、填写原因并保留历史。
- 原料收发存、原料入库/领料/退料明细、成品收发存、成品入库/出库明细、库存余额、不良品、盘点差异、库存告警是 V1.0 固定报表。均支持按日期、订单号、采购单号、生产单号、物料/成品、状态筛选及 Excel/CSV 导出。
- 出入库表单统一支持非必传 `attachment`，包括送货单、QC 报告、领料单、物流/签收资料、退货凭据、盘点照片和其他。
- 新增“仓库”和“QC”操作员类型，保留物控、采购、财务、销售、管理员；按模块授权，审批人字段预留，不先实现审批流。

## 7. 审计与跨模块联动

所有新增、修改、逻辑删除、状态变更、冲销、退货、盘点调整、告警确认和恢复，记录操作类型、对象、订单号、关联单据、执行人、时间、结果、原因、对象快照及变更前后值。

编辑前必须提供影响预览，至少覆盖库存单余额、采购到货进度与应付来源、生产领料/完工数量、QC 可入库数量、成品发货与应收来源、后续关联操作单和未解决告警。可派生数据同步重算；独立下游事实通过差异提示、冲销、退货或调整处理，不可静默改写。

## 8. 与开发文档的边界

本文定义领域模型、业务表单、数量口径和跨模块规则，不定义最终数据库列、NestJS 模块、REST 路由、页面组件或任务拆分。后续先完成质量 QC 门禁的联合设计，再形成仓库模块的开发规格和任务文档。
