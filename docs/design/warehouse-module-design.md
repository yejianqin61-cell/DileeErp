# 迪礼 ERP V1.0 仓库模块初步设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：访谈中。本文仅记录已确认业务事实；待确认规则见 [仓库模块集中待确认事项](../memo/0820-仓库模块集中待确认事项.md)。

## 1. 设计目标

仓库模块以 `order_no` 为跨模块追溯主线，记录原料入库、原料出库（生产领料）、成品入库和成品出库的业务事实及库存变化。原料和成品均支持分批操作；所有出入库记录必须能够追溯至来源单据、业务订单和操作人。

V1.0 固定原则：

- 原料、成品、退料、不良品分开建表和管理，避免库存性质混淆。
- 原料入库承接采购与 QC：采购来料须经 QC 合格后，合格数量才可进入可用原料库存；该入库数量也是采购应付报送依据。
- 原料出库承接厂内生产单的领料；成品入库承接生产完成后的 QC；成品出库承接发货，具体门禁待确认。
- 原料入库、原料出库、成品入库、成品出库均支持同一业务单据的多次分批操作。
- 库存余额是由有效出入库事实汇总出的派生数据，不允许直接手工篡改余额。
- 所有记录统一保留 `created_at`、`updated_at`、`created_by`、`updated_by`，并支持逻辑删除与全量操作审计；禁止物理删除。
- 遵循“提供后悔药”原则：更正前展示关联采购单、生产单、QC、应付/应收、库存及下游出货影响；确认后联动重算派生数据或提示人工复核，不得静默改写已确认的下游事实。

## 2. 已确认业务范围

### 2.1 包含

- 原料入库，支持分批。
- 原料出库（生产领料）。
- 成品入库，支持分批。
- 成品出库，支持分批。
- 原料、成品、退料、不良品的分表库存管理。
- 订单号、采购单、生产单、QC 记录与出入库记录的可追溯关联。
- 手工盘点单与盘点确认后的库存调整记录。

### 2.2 需本轮确认

- 入库/出库单、收货、QC 和签收的先后与职责。
- 物料/成品库存粒度、库位、批号、单位换算和库存成本。
- 领料、退料、不良品、超领、缺料与生产单联动。
- 成品 QC、分批入库、成品出库、客户发货与销售/财务交接。
- 外加工直发、余料、退料、损耗和成品回厂的库存口径。
- 单据状态机、可编辑范围、撤销/冲销、告警、报表和附件。

## 3. 业务链路（已知部分）

```text
采购单 -> 供应商分批到货 -> QC 来料检验 -> 原料入库 -> 财务应付依据
                                            |
                                            v
生产单 <- 原料出库（领料）                  厂内生产
                                            |
                                            v
                                  QC 成品检验 -> 成品入库 -> 成品出库/发货
```

库存单据均需展示 `order_no`。一笔出入库操作可关联采购单明细、生产单、检验记录或后续销售/发货资料，具体必填组合由本轮确认。

## 4. 核心对象（初步）

| 对象 | 业务职责 | 已确认关系 |
| --- | --- | --- |
| 原料入库单/明细 | 将 QC 合格的采购原料记入可用原料库存 | 关联采购单明细、QC 和 `order_no`；支持分批 |
| 原料出库单/明细 | 车间从原料库存领料生产 | 关联厂内生产单和 `order_no` |
| 成品入库单/明细 | 将 QC 合格的生产成品记入可用成品库存 | 关联生产单、QC 和 `order_no`；支持分批 |
| 成品出库单/明细 | 将成品库存发出用于订单交付 | 关联订单号；支持分批 |
| 退料记录 | 将生产现场未使用原料退回仓库 | 独立库存分类，具体来源/可用性待确认 |
| 不良品记录 | 记录检验不合格的原料或成品 | 独立库存分类，处置方式待确认 |
| 库存余额 | 按库存分类、物料/成品维度汇总有效出入库数量 | 派生数据，可重新计算 |
| 盘点单/调整记录 | 核对账面与实际数量并记录经确认的差异调整 | 不直接改写历史出入库事实 |

## 5. 跨模块边界

- 采购模块维护采购单、供应商、采购价格与应付来源；仓库模块以 QC 合格后的原料实际入库量为应付依据。
- 质量模块定义来料和成品的 QC 检验、合格/不合格/让步接收口径及入库门禁。
- 生产模块维护生产单和工序进度；仓库模块以生产单为原料领料和成品入库的业务关联主线。
- 销售模块维护订单和后续发货资料；仓库模块以订单号关联成品出库，是否要求销售出货指令待确认。
- 财务模块消费采购原料入库形成的应付依据，并在销售出库/发货规则确认后承接应收依据。

## 6. 编辑与风险联动原则

1. 修改、取消或逻辑删除出入库单前，系统必须展示受影响库存余额、采购到货进度、生产领料/完工数量、QC 记录、应付/应收来源及后续出入库单。
2. 可由出入库事实重新汇总的库存余额、采购/生产进度和告警必须在同一事务中同步更新。
3. 已确认的 QC、应付报送、发货和财务记录是独立事实，不得被仓库单据编辑静默改写；系统应提示差异，并通过退货、冲销、调整或复核流程修正。
4. 所有编辑、取消、逻辑删除、盘点调整和冲销都必须记录原因、操作人、时间、对象快照与前后值。
