# 会计科目改进规划：从「名字即科目」到「编码即科目」

> 版本 1.0 ｜ 2026-11-11 ｜ 依据：[会计科目病灶诊断](../audit/accounting-subject-diagnosis-2026-11-11.md)（31 条病灶，P0 4 条、P1 15 条）

## 结论

本期 4 条 P0 全部由同一个根因派生：**会计科目没有不可变编码**。

老表的科目代码整列被丢弃，于是「分类 + 名称」这段人可读文本同时充当了身份、编码、快照与匹配依据。
财务改一个科目名不会报错，只会让某张报表的某一格悄悄变小，报表依然平、勾稽依然通过。

本规划用 6 个阶段、13 条需求处理这批病灶。

**第一步的代价最大，收益也最大**：先让科目有身份证（Phase 1 科目有了身份证）。
它是一次数据库迁移，做完之后，「改名即错」这一类事故链整体消失，后面五个阶段才有立足点。

先做止血再做结构：Phase 2 报表不再靠名字认科目 的第一件事是补资产负债表缺口出口，一天内可上线。

## 2. 逐条需求的解法

### R-1 科目有不可变编码

- **做法**：给科目加一列稳定编码，一次回填后终身不变。名称降级为可改的显示文案，编码成为唯一身份。
- **触及**：财务科目主数据、凭证与流水上的科目快照、期初余额、迁移与种子脚本。
- **测试缝**：既有科目主数据单元测试入口。不新增缝。
- **验收**：
  - [ ] 改一个科目名后，三张报表与所有导出件数字逐格不变
  - [ ] 编码唯一、非空、创建后不可改
  - [ ] 迁移可重复执行，第二次不产生任何变化
  - [ ] 历史快照能全部归到主键，归不上的行有清单
- **难点**：历史快照里存的是文本，同一个科目可能因改名而留下两个旧名，回填时要把它们认成同一个。

### R-2 报表按数据认科目，不按名字

- **做法**：把"哪个科目进哪张报表的哪一行"从代码里的名字比对，搬成一张数据映射。取数改按科目身份归集。
- **触及**：三大报表的口径内核、报表取数服务、科目主数据。
- **测试缝**：报表内核已有的纯函数入口。不新增缝。
- **验收**：
  - [ ] 迁移后三张报表的每一格与迁移前逐格相等
  - [ ] 财务新增一个科目，不需要改代码就能给它指定报表行
  - [ ] 没有指定报表行的科目出现在表尾点名单里
- **难点**：现有匹配规则里既有精确名单也有前缀规则，要能把两者都翻译成显式映射，且一格不差。

### R-3 报表缺口在页面上看得见

- **做法**：让三张报表都显示"未归位科目"，并把现金流量表缺的成本类科目归属补齐。缺口必须出现在财务看得见的地方。
- **触及**：三张报表的表构建器、现金流量表行定义。
- **测试缝**：既有报表导出与表尾文案测试入口。不新增缝。
- **验收**：
  - [ ] 资产负债表在存在未归位科目时也有提示
  - [ ] 六条成本类科目在现金流量表里有归属
  - [ ] 勾稽不平衡时不再一律归因为"期初没录"
- **难点**：这六条成本类科目该进哪一行是会计口径问题，需要财务确认。

### R-4 期初余额校验科目

- **做法**：期初余额写入时校验科目存在且唯一，并按科目身份落库。今天它只是自由文本。
- **触及**：期初余额的写入与读取、报表取数的期初合并。
- **测试缝**：既有期初余额服务单元测试入口。不新增缝。
- **验收**：
  - [ ] 填写不存在的科目被拒绝，并给出可选项
  - [ ] 同名跨分类的科目被要求指定分类
  - [ ] 历史裸名期初有一次性归位清单
- **难点**：已有数据里混着裸名、错名与正确写法的期初行，归位规则要能解释每一条。

### R-5 一张凭证的科目口径唯一可解释

- **做法**：明确现金流量表落行该用哪一个科目，写进口径文档，并让缺失时回落到凭证分录上的科目。对不上时页面说明原因。
- **触及**：收支流水与凭证之间的科目衔接、现金流量表取数、科目键写法。
- **测试缝**：既有报表口径内核的纯函数入口，配一条端到端用例。不新增缝。
- **验收**：
  - [ ] 同一张凭证在三张报表里都能解释到同一个科目
  - [ ] 收支类目缺失时不再整列空白，而是回落并注明
  - [ ] 口径文档里写明两个字段各自的职责
- **难点**：这是一条产品口径决定，不是纯技术修复，需要财务与实施一起定。

### R-6 科目性质由数据决定，不由名字决定

- **做法**：给科目标注结构化性质（是否资金、资金种类、自然余额方向），把散落的名字前后缀判断收敛到属性上。
- **触及**：科目主数据、报表的资金科目判定、凭证的资金分录判定、结算方式字典。
- **测试缝**：既有凭证领域纯函数入口与报表内核入口。不新增缝。
- **验收**：
  - [ ] 十五处名字前缀判断全部消失或改为读属性
  - [ ] 把「销售费 运费」改名成「运费」后，销售费用行金额不变
  - [ ] 全部资金科目在科目表里真实存在
- **难点**：结算方式靠"含现金"二字猜资金科目的那处，需要一次字典治理，否则改不动。

### R-7 科目变更不制造孤儿

- **做法**：删除前的引用统计补全到全部引用方；停用与删除分开语义；变更前给出影响面。
- **触及**：科目主数据的写入口、凭证分录、收支类目、期初余额。
- **测试缝**：既有科目主数据服务单元测试入口。不新增缝。
- **验收**：
  - [ ] 删除被凭证或类目引用的科目被拒绝，并列出引用处数量
  - [ ] 停用科目后历史单据仍可重算
  - [ ] 改名后历史文本快照仍能归到该科目
- **难点**：「停用」现在既表示"不再新用"又表示"不能再算"，两个语义要拆开且不破坏现有单据状态。

### R-8 重跑 seed 不覆盖财务的编辑

- **做法**：种子只负责"不存在则创建"，不再把启用状态与排序写回。
- **触及**：种子脚本、科目类目与科目清单。
- **测试缝**：既有种子脚本测试入口。不新增缝。
- **验收**：
  - [ ] 重跑种子不复活已停用的科目
  - [ ] 重跑种子不覆盖财务改过的排序
  - [ ] 新增科目仍能被种子补齐
- **难点**：新库初始化与老库升级共用一份种子，两种场景的要求相反。

### R-9 余额方向正确且被守卫

- **做法**：先修数据里写反的方向，再加一条守卫测试钉住规律。
- **触及**：科目主数据、守卫测试。
- **测试缝**：既有科目清单守卫测试入口。不新增缝。
- **验收**：
  - [ ] 损益类收入性质科目为贷方
  - [ ] 备抵科目与销项税为贷方
  - [ ] 守卫测试能在方向写错时失败
- **难点**：这一列今天无人消费，所以没有回归网兜住修改，只能靠人工核对会计准则。

### R-10 科目键只有一种写法

- **做法**：资金分录也写完整科目键，裸名只在读历史数据时兼容。
- **触及**：凭证分录的写入、报表取数、期初余额。
- **测试缝**：既有凭证领域单元测试入口。不新增缝。
- **验收**：
  - [ ] 新写入的分录键一律带分类
  - [ ] 历史裸名键仍能被正确读取
  - [ ] 有一条守卫禁止新写入裸名
- **难点**：读兼容层要保留多久、什么时候可以删，需要一个明确的下线条件。

### R-11 导出件的科目列只有一种口径

- **做法**：定一条导出件科目列约定并落成公共实现，所有导出件照抄。
- **触及**：全部报表导出件、台账导出、凭证打印。
- **测试缝**：既有导出件生成入口。不新增缝。
- **验收**：
  - [ ] 任意两份导出件并排，同一科目写法一致
  - [ ] 停用标记不再拼进科目名
  - [ ] 空值写空单元格，不写空字符串
- **难点**：九个导出面已有既有格式，改变会牵动财务现有的对账习惯，需要一次确认。

### R-12 科目以引用出现，不以文本出现

- **做法**：台账不再替财务"编"一个科目；收付款单的科目接回科目表；接口字段按语义拆名。
- **触及**：应付台账、对账明细、收付款单、报表接口字段。
- **测试缝**：既有台账导出与单据校验测试入口。不新增缝。
- **验收**：
  - [ ] 台账不再显示财务没选过的科目
  - [ ] 单据上不存在的科目被拒绝保存
  - [ ] 同一个字段名只有一种含义
- **难点**：台账现在"编"科目是为了让报表好看，去掉之后会出现空白，需要一句表尾说明接住。

### R-13 自动归类的失败行为确定

- **做法**：候选链统一按唯一同名解析，落空与歧义都给出明确错误，不再静默换成别的科目。
- **触及**：凭证生成、收付款过账、应付确认。
- **测试缝**：既有凭证生成单元测试入口。不新增缝。
- **验收**：
  - [ ] 候选全部不存在时返回明确错误而不是换一个
  - [ ] 同名跨分类时要求指定，不取第一个
  - [ ] 每一条业务链的失败都有可读提示
- **难点**：今天"静默换成主营业务成本"是能被业务接受的降级，改成报错可能阻断现有操作。

## 3. 阶段

### Phase 1 — 科目有了身份证

**Covers**：R-1 科目有不可变编码。

**Goal**：每个科目有一个终身不变的编码。改一个科目名之后，所有报表与导出件数字一个都不变。

**Tasks**

- 给科目加编码列，用现有分类与顺序回填出一组稳定编码
- 让科目录入与查询按编码解析，编码对外只读
- 把记录科目文本快照的地方改为落科目主键，编码只作展示
- 写一条迁移，把历史快照归到主键并输出归不上的清单
- 用回归用例钉住改名前后报表数字一致

**Proof**：那条回归用例通过；迁移清单里"归不上"的行数为 0，或每一行都有说明。
**Not here**：报表映射改数据驱动；任何界面改动。

### Phase 2 — 报表不再靠名字认科目

**Covers**：R-2 报表按数据认科目，不按名字；R-3 报表缺口在页面上看得见；R-4 期初余额校验科目。

**Goal**：财务新增一个科目，三张报表都在表尾点名"这个科目没有归位"。改名之后数字不变。

**Tasks**

- 先补资产负债表的缺口出口，让人当天看见现状
- 把报表行与科目的对应关系落成数据，用现有规则生成初始映射
- 报表取数改为按科目身份归集
- 补齐现金流量表缺的六条成本类科目归属
- 期初余额写入时校验科目存在且唯一
- 把覆盖度检查从测试挪到运行时，并扩到库里的全部科目

**Proof**：迁移后三张报表逐格与迁移前一致；新增科目后三张表都点名它未归位。
**Not here**：财务自助维护映射的界面；跨币种折算口径。

### Phase 3 — 科目性质写进数据

**Covers**：R-6 科目性质由数据决定，不由名字决定；R-9 余额方向正确且被守卫。

**Goal**：把「销售费 运费」改名成「运费」后，利润表销售费用行金额与改名前一模一样。
证明"名字不再承担业务语义"。

**Tasks**

- 给科目标注资金性质与自然余额方向，回填现有全部科目
- 把报表侧的资金科目判定改为读属性
- 把凭证侧的资金科目族判定改为读属性
- 收敛结算方式里"含现金"的文本猜测，改为显式选择或字典属性
- 补一个真实存在的现金科目，或让资金常量指向已有科目
- 修数据里写反的方向，并加一条守卫钉住规律

**Proof**：改名回归用例通过；资金科目清单与今天的结果逐一相同。
**Not here**：银行账户池与流水的关系；多币种资金科目。

### Phase 4 — 科目变更与缺科目都不再静默

**Covers**：R-7 科目变更不制造孤儿；R-8 重跑 seed 不覆盖财务的编辑；R-13 自动归类的失败行为确定。

**Goal**：删一个被引用的科目被拒绝并列出引用处。停用一个科目，历史单据仍能重算。
一条该归类的支出找不到候选时，系统明确报错。

**Tasks**

- 把删除守卫的引用统计补全到漏掉的四类地方
- 拆开停用与删除的语义，停用不影响历史重算
- 科目变更前给出影响面预览
- 改种子为只创建不覆盖
- 候选链统一按唯一同名解析，落空报明确错误

**Proof**：删被引用科目被拒并列出引用数；重跑种子不复活停用科目；候选全落空时报错而非换科目。
**Not here**：科目合并与拆分工具。

### Phase 5 — 一张凭证一套科目口径

**Covers**：R-5 一张凭证的科目口径唯一可解释；R-10 科目键只有一种写法。

**Goal**：同一张凭证在现金流量表、利润表、资产负债表里能解释到同一个科目。
解释不了的地方，页面写出原因。

**Tasks**

- 先写一条用例，钉住今天"同凭证两套科目"的实际表现
- 定下现金流量表落行用哪一个科目，写进口径文档
- 收支类目缺失时回落到凭证分录上的科目，并注明
- 科目键只保留完整写法，资金分录也带分类
- 为读历史裸名保留兼容层，并给新写入加守卫

**Proof**：那条用例覆盖三种报表并全部通过；同一张凭证的科目在三处可以互相解释。
**Not here**：权责发生制的二期分录与结转损益凭证。

### Phase 6 — 财务看到的就是一套口径

**Covers**：R-11 导出件的科目列只有一种口径；R-12 科目以引用出现，不以文本出现。

**Goal**：任意两份导出件并排看，同一个科目的写法一致。台账不再显示财务没选过的科目。

**Tasks**

- 定一条导出件科目列约定，落成公共实现
- 统一全部导出件的科目列
- 拆开一个字段两种含义的接口字段
- 台账与对账明细统一为不编科目，缺科目在表尾说明
- 收付款单的科目接回科目表，方向不一致给提示

**Proof**：两份导出件并排比对，同一科目写法一致；台账里不再出现未确认科目。
**Not here**：查询代理补科目维度；导出件版式与列宽调整。

## 5. 不在本规划内的

这些病灶已诊断但本规划不处理，留待下一轮：

- 查询代理（业务问答）没有科目维度，回答不了"上个月管理费用花了多少"
