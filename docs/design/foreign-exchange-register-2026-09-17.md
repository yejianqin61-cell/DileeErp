# 外汇一览表（收束统计）设计

- 日期：2026-09-17
- 需求：用户交付 `example/财务/外汇一览表.xlsx`，要求「这个表单导出……按照客户进行按照月份，年份或者任意时间跨度的收束统计」
- 关联：[任务记录](./0917-finance-round2.md) · [字段映射备忘](../memo/0917-外汇一览表字段映射.md) · [日志](../log/2026-09-17.md)
- 报表 key：`forex-receipts`（预览 `GET /finance/reports/forex-receipts`，导出 `…/forex-receipts.xlsx`）

## 1. 老表长什么样

`Sheet1` 是**两层表头 + 手写分组**的一张宽表（19 列 A–S，160 行）：

| 列 | 表头 | 说明 |
| --- | --- | --- |
| A | 客户 | 手写，同一客户连续若干行后换下一个 |
| B | 订单号 | `DL260001` 起顺延 |
| C | 订单数量 | 有的行是 `1000pcs` / `辅料` / `80A&80J` 这类自由文本 |
| D | 跟单 | 小陈 / 小罗 |
| E–I | 出货日期 / 单位 / 出货数量 / 单价 / 货款金额 | 未出货的行全空 |
| J–M | 定金（日期 + 金额）/ 货款（日期 + 金额） | 第二层表头合并单元格 |
| N | 汇入总金额 | 老表自己的合计列 |
| O | 银行手续费 | 大面积为空 |
| P | 实到账金额 | `N − O` |
| Q | 欠尾款 | 只有表头，样本里从没填过 |
| R | 是否完结 | `结清` / `完结` / 空 |
| S | 备注 | `出完货` / `库存伞架` / `铭牌开模费` |
| T | （无表头） | 样本里出现 `转刘总卡` |

## 2. 老表自带的三个问题（不能照抄）

1. **跨币种相加**：`I24` 是 `￥14,647.00`，同一行的 `N24` 却是 `$14,647.00`；`I37` 是 `$0.00`、`K37` 是裸的 `4707`。老表把美元与人民币写在同一条列里，求和出来的数没有会计意义。本仓库对这类问题的既有结论是 R7：**绝不跨币种相加**。
2. **同一笔收款被重复计算**：`DL260002` 有两次出库（R5、R6），两行的定金都写 `$620`（J5/J6 与 K5/K6 相同）。按老表求「定金合计」会把同一笔定金算两遍。老表自己的 `N` 列也不自洽：`N5 = $6,200` 是整单合计，`N6 = $3,100` 又只是本行金额。
3. **「货款」列混了两种东西**：既有出货后收的尾款，也有一次性付清的全款；事后完全分不出来。

## 3. 系统里的数据从哪来

**关键事实：「客户付款单」在 2026-09-16 已从界面撤掉**（改为「确认即记账」，见 `receivable-workspace.tsx` 顶部注释）。所以系统里「钱进来」只有两条路，两条最终都落在 `cash_flow_entries`：

| 路径 | 写入的流水 | 能自动挂到订单吗 |
| --- | --- | --- |
| 【确认应收】逐条 / 勾选批量 | `source_type = receivable_source`，`source_id` = 应收来源 | 能（来源 → 出库 → 订单） |
| 【确认应收】按对账单一键 | `source_type = receivable_reconciliation`，`source_id` = 对账单 | **不能**（一条流水覆盖 N 张出库单） |
| 【收支流水】手工录入 | `source_type` 为空 | 只能靠财务手填的 `order_no` |

**定金去哪录**：定金在**出货之前**就收到了，而应收来源是成品出库过账时才生成的 —— 那一刻系统里没有任何来源可挂。因此定金只能作为**手工收入流水**录入，并靠新加的 `cash_flow_entries.order_no` 挂到订单上。这就是 2026-09-17 给收支流水加「款项性质 + 订单号」两列的原因（用户选定：**加在【收支流水】上，并给收入流水加一个可选订单号**）。

| --- | --- | --- | --- |
| 1 | 客户 | `receivable_sources.customer.name` | |
| 2 | 币种 | `receivable_sources.currency` | **老表没有这一列，本期新增** |
| 3 | 订单号 | `receivable_sources.order_no` | |
| 4 | 订单数量 | `sales_orders.quantity` | |
| 5 | 跟单 | — | **系统无此字段，恒空**（用户 2026-09-17 确认） |
| 6 | 出货日期 | `finished_goods_outbounds.shipment_date` | |
| 7 | 单位 | `receivable_sources.unit` | |
| 8 | 出货数量 | `finished_goods_outbounds.quantity` | |
| 9 | 单价 | `receivable_sources.unit_price` | |

| 11–12 | 定金日期 / 定金金额 | 归属到该出库、`payment_nature = deposit` 且在期间内的收款 | 日期取期间内最后一笔 |
| 13–14 | 货款日期 / 货款金额 | 同上，`payment_nature ∈ {balance, final}` | 老表的「货款」列就是这两者合起来 |

| 19 | 欠尾款 | 货款金额 − **截至期间末的累计已收** | 时点余额，不能跨期间相加 |
| 20 | 是否完结 | 未收款 / 结清 / 未结清 | 老表只有两种写法，这里拆成三种 |
| 21 | 备注 | `receivable_sources.remark` | |

汇总工作表「客户汇总」，**一行 = 客户 × 币种**，每个币种段末给该币种的合计：

`客户 | 币种 | 订单数 | 出库数 | 定金合计 | 货款合计 | 其他到账 | 汇入总金额 | 银行手续费 | 实到账金额 | 欠尾款 | 已完结订单数 | 未完结订单数`

## 5. 归属规则（本设计的核心）

要回答的唯一问题是：**一笔到账属于哪一次出库？** 规则按优先级：

1. `source_type = receivable_source` → 用 `source_id` 精确指向那次出库。
   *不能*退化成「订单里最早的那次出库」：一张订单多次出库时，那样会把每笔货款都堆到第一次出货上，那一行的欠尾款变成负数、后面几行虚高。
2. 有订单号（流水自己的 `order_no`，或从来源/对账单反查出来的）→ 归到该订单**出货日期最早**的那次出库（同日按出库单号，顺序必须确定，否则两次导出结果不同）。
3. 归不到的**不塞进任何一行**，按原因分类写进表尾，带笔数与金额：
   - `reconciliation`：按对账单一键确认的流水，一条覆盖多张出库单，拆不出来；
   - `no_outbound`：订单还没有成品出库（多为出货前收到的定金）；
   - `no_order`：流水上没有订单号；
   - `currency_mismatch`：收款币种与出库应收币种不一致（加进同一行就是跨币种相加）。

**不变量：一笔收款在整张表里只出现一次。** 老表把同一笔定金抄在每个出库行上，按它求和会重复计算。

## 6. 期间口径

用户选定**按收款（实际到账）日期**筛选 —— 老表标题就是「外汇入款一览表」，看的是钱什么时候进来。

由此推出两条必须写清的规则：

- **准入条件**：一行出库出现在本期表里，当且仅当它**在期间内**至少收到一笔钱。只看累计的话，一笔 4 月收到的定金会让那一行出现在之后每一个月的表里。
- **欠尾款**用**截至期间末的累计已收**（含期间外的收款）。所以它是时点余额：跨期间相加没有意义，表尾写明了这一点。

副作用（已在表尾说明）：出货在 3 月、尾款 7 月到账的单子，会出现在 **7 月**那一段里，而不是 3 月。

## 7. 审计与行数上限

- 取数沿用 `MAX_REPORT_ROWS = 20000`，超出报 `REPORT_TOO_LARGE`，不静默截断。
- 候选收款集合 = 「截至期间末、同一批订单/来源的收款」∪「期间内的全部收入流水」。后者不能省：既没有订单号也没有来源的手工收入流水（房租那类）天然不在前者的范围内，而它们恰恰是表尾「流水上没有订单号」要报出来的东西 —— 少了这一步，这几笔钱会被静默丢掉，表里的汇入总金额小于银行流水，财务却看不出少在哪。

## 8. 多工作表能力

`tableFor()` 返回 `ReportTable[]`（第一个是主表），`sendWorkbook()` 接受数组。**约定**：第一个是主表，页面预览与文件名里的行数都用它。

为什么两张表必须在同一个文件里：分成两个下载文件，财务很容易只发出去一张，而「汇总和明细分开传」正是对账对不上的经典原因。

页面上只渲染主表，但会用 `extra_sheets` 明确写出「导出文件还包含：客户汇总（N 行）」——不提示的话财务会把导出的文件当成只有明细一张表。

## 9. 明确不做（以及代价）

| 不做的事 | 代价 |
| --- | --- |
| 银行手续费字段 | 该列恒空；「实到账金额」= 汇入总金额（未扣手续费）。加字段后只需改 `finance-report-forex.tables.ts` 里的一行算式 |
| 跟单字段 | 该列恒空。销售订单与出库单都没有业务员/跟单字段（全库搜过） |
| 把对账确认的流水拆到出库行 | 该类流水整笔进表尾。硬拆（按金额比例摊）会让明细行的欠尾款变成编出来的数 |
| 按出货日期再出一版 | 需要另一张表或一个「期间基准」开关；本期只做用户选定的收款日期口径 |
| 老表的「转刘总卡」备注列 | 未采纳（老表里它连表头都没有）。若财务确实要记，用「备注」 |
