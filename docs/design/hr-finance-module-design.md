# 迪礼 ERP V1.0 人事财务模块初步设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：访谈中。本文仅记录已确认事实；待确认规则见 [人事财务模块集中待确认事项](../memo/0820-人事财务模块集中待确认事项.md)。

## 1. 设计目标

人事财务模块合并管理员工目录、薪资台账、应收和应付。`order_no` 是业务应收应付的主追溯线；人员薪资以员工目录为基础，并承接生产模块的计件/计时日报金额。

固定原则：

- 员工目录是工资计算、考勤、绩效和薪资台账的共同基础资料。
- 成品出库及其他业务事项可形成应收；采购原料入库及其他业务事项可形成应付。
- 应收、应付、收款和付款均支持一次性结清与多次分批处理。
- 每笔业务应收/应付必须可追溯至 `order_no` 或标识为其他事项；不得用其他事项掩盖本应关联订单的业务。
- 生产模块只提供车间员工计件/计时薪资来源及参考金额；薪资台账可由财务独立调整，但不得反写生产日报。
- 遵循“进退皆可”：更正前展示影响预览；确认后更新可派生余额、核销进度和报表，独立财务事实以调整、冲销或复核记录处理，不静默改写。

## 2. 初步业务链路

```text
员工目录 -> 考勤/绩效/生产日报薪资来源 -> 薪资台账 -> 工资付款

成品出库/其他事项 -> 应收 -> 分批或一次性收款 -> 应收余额

采购原料入库/其他事项 -> 应付 -> 分批或一次性付款 -> 应付余额
```

成品出库、采购原料入库、收款、付款、薪资台账及其调整记录均需保留业务来源、操作人、时间和关联订单号（适用时）。

## 3. 核心对象（初步）

| 对象 | 职责 | 已确认关系 |
| --- | --- | --- |
| 员工目录 | 员工基础档案及薪资计算基础 | 供生产日报、考勤、绩效、薪资台账引用 |
| 考勤记录 | 记录员工出勤事实 | 是否参与薪资计算待确认 |
| 绩效记录 | 记录员工绩效事实 | 是否参与薪资计算待确认 |
| 薪资台账 | 按周期汇总生产薪资来源及人工调整 | 与员工目录关联；生产来源不得被反写 |
| 应收单/明细 | 对客户的待收业务款项 | 来源为成品出库或其他事项；关联订单号或其他事项说明 |
| 收款记录 | 客户实际付款事实 | 可分批核销一笔或多笔应收，规则待确认 |
| 应付单/明细 | 对供应商或其他对象的待付款项 | 来源为采购原料入库或其他事项；关联订单号或其他事项说明 |
| 付款记录 | 公司实际付款事实 | 可分批核销一笔或多笔应付，规则待确认 |
| 调整/冲销记录 | 对已确认薪资、应收、应付、收付款的可追溯纠错 | 保留来源、原因、前后值和影响 |

## 4. 跨模块边界

- 人事模块维护员工目录、考勤、绩效和薪资台账；生产模块提供车间员工计件/计时薪资来源。
- 仓库成品出库提供应收业务来源；应收生成时点、金额口径和客户签收门禁由本模块与销售模块共同确认。
- 仓库原料入库提供应付业务来源；采购模块提供供应商、单价与采购单，仓库 QC 合格入库量是应付数量依据。
- 销售模块维护客户；采购模块维护供应商；财务模块消费其基础资料，不复制主数据。
- 其他应收/应付必须说明业务类型、相对方、金额、发生日期和原因；是否可不关联订单需本轮确认。

## 5. 编辑与联动原则

1. 编辑来源单据、应收/应付、收付款或薪资台账前，系统展示受影响订单、来源单据、未核销余额、已核销金额、员工薪资、库存/出库或入库事实、状态和风险。
2. 确认后，应收应付余额、核销进度、逾期/差异告警和报表必须在同一事务中更新。
3. 已确认收款、付款、工资付款及仓库出入库是独立事实；更正通过冲销、退款、补收、补付或独立调整处理，不直接改写原始事实。
4. 所有操作保留操作人、时间、备注、原因、对象快照与前后值；禁止物理删除。
