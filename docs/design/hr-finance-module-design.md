# 迪礼 ERP V1.0 人事财务模块设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：V1.0 领域规则已确认。销售单价格细节、外加工费计量和最终财务会计口径在对应模块继续细化。

## 1. 设计目标与哲学

人事财务模块合并管理员工目录、考勤、绩效、薪资台账、应收、应付、收款和付款。`order_no` 是订单业务的财务身份证；无订单的合法杂项须明确标识为其他事项并填写业务类型、相对方和原因。

模块遵循两条固定设计哲学：

- **进退皆可**：对已确认的工资、应收应付及收付款，通过调整、冲销、退款、补收、补付等独立记录更正；不覆盖原始业务事实。
- **灵活为上**：表单类型、其他应收应付类型、薪资构成、部门、岗位、员工类型和考勤类型均为管理员可维护类目，支持增删改。已被业务数据引用的类目保留历史快照，默认停用而非物理删除。

固定边界不因类目可配置而改变：订单关联、来源单据、金额/核销余额、状态机、审计和影响预览必须严格校验。

## 2. 已确认业务链路

```text
员工目录 -> 月度考勤/绩效 + 生产日报薪资来源 -> 月度薪资台账 -> 分批/一次性工资付款

成品出库 -> 应收来源草稿 -> 财务确认应收 -> 分批/一次性收款 -> 应收余额
其他事项 -> 手工应收 -> 分批/一次性收款 -> 应收余额

采购原料 QC 合格入库 -> 应付来源草稿 -> 财务确认应付 -> 分批/一次性付款 -> 应付余额
其他事项 -> 手工应付 -> 分批/一次性付款 -> 应付余额
```

应收应付来源、收付款、薪资台账与支付记录均记录来源、操作人、时间、订单号（适用时）和审计信息。

## 3. 员工目录、考勤与绩效

### 3.1 员工目录

员工目录是工资计算、考勤、绩效和生产日报的共同基础资料。V1.0 至少维护：系统生成且唯一的员工编号、姓名、部门、岗位、员工类型、入职日期、在职状态、联系电话和备注；不存储身份证和银行卡信息。

部门、岗位和员工类型均为可维护类目。员工离职采用离职/停用，不得物理删除，历史生产日报、考勤、绩效和薪资台账继续保留；离职生效后禁止新建生产日报和薪资来源。

### 3.2 考勤与绩效

- 考勤按员工和日期人工录入，支持出勤、请假、加班、迟到早退、缺勤、工时及备注等可维护考勤类型；V1.0 不对接考勤机、不做排班或自动导入。
- 绩效按员工和自然月人工录入，支持评分、等级、奖惩金额和评语。
- 考勤与绩效在 V1.0 只作为薪资调整参考，不自动计薪。

## 4. 月度薪资台账与工资付款

### 4.1 薪资来源和构成

工资按自然月计算。财务可按月从生产日报汇总生成薪资台账草稿；没有生产日报的办公室员工可手工创建月度台账。

薪资台账至少支持以下构成：生产计件/计时金额、基本工资、加班、考勤扣款、绩效奖惩、补贴、房补、社保、个税、其他调整和实发金额。薪资构成类目由管理员维护，后续可增删改；V1.0 不自动计算社保、个税或考勤工资。

生产日报金额按员工+月份自动汇总为不可编辑的“生产薪资来源”。财务只能以独立调整行增删改台账，不能反写生产日报或来源金额；调整必须填写原因并审计。

### 4.2 状态、支付与更正

状态机：`草稿 -> 已确认 -> 部分支付 -> 已支付 -> 已关闭`。

工资付款支持一次性或分批支付。已确认台账不得直接覆盖金额；已付款记录不得删除，错误通过工资付款冲销、补付或独立调整处理，并联动更新未付余额与状态。

## 5. 应收与收款

### 5.1 应收来源与金额

- 成品出库自动生成可追溯的应收来源草稿；财务确认后形成生效应收。签收日期、物流凭据作为确认参考，V1.0 不作为强制阻塞门禁。
- 应收金额保存来源金额快照、币种、含税/未税、税率、折扣、运费和其他费用；最终应收金额由财务确认，调整必须保留原因。
- 分批出库时，每笔出库形成独立应收来源明细；财务可按订单、客户和期间汇总为应收单。
- 其他应收使用管理员可维护的业务类型，如样品费、运费、赔偿、预收和杂项。必须填写相对方、类型、金额、发生日期和原因；附件可选。不能关联订单时必须显式标记为其他事项。

### 5.2 收款、状态与更正

- 收款支持一次性或多次分批；一笔收款可核销多笔应收，一笔应收也可由多笔收款核销。
- 收款记录至少保存收款日期、金额、币种、方式、银行流水号、收款人和可选附件；累计核销不得超过应收未核销余额。超额收款按预收或异常处理的具体规则由财务开发设计落实。
- 应收状态机：`草稿 -> 已确认 -> 部分收款 -> 已收清 -> 已关闭`，并支持取消。
- 错开应收、退款、坏账、折让、汇率差异使用红字/冲销、退款或独立调整记录处理，不直接改写已确认应收和收款事实。

## 6. 应付与付款

### 6.1 应付来源与金额

- 采购原料 QC 合格入库自动生成不可重复的应付来源草稿；财务确认后形成生效应付。金额依据是实际入库数量乘最终确认单价。
- 分批入库时，每笔入库保留独立应付来源；财务可按供应商、采购单、订单和期间汇总为应付单。
- 其他应付使用管理员可维护的业务类型，如外加工费、运费、维修、租金和杂项。必须填写相对方、类型、金额、发生日期和原因；附件可选。外加工费具体计量和结算规则后续细化。

### 6.2 付款、状态与更正

- 付款支持一次性或多次分批；一笔付款可核销多笔应付，一笔应付也可由多笔付款核销。
- 付款记录至少保存付款日期、金额、币种、方式、银行流水号、付款人和可选附件；累计核销不得超过应付未核销余额。超额付款按预付或异常处理的具体规则由财务开发设计落实。
- 应付状态机：`草稿 -> 已确认 -> 部分付款 -> 已付清 -> 已关闭`，并支持取消。
- 仓库退供应商回冲应付来源。已确认/已付款应付的退款、折让、价格差异和预付款通过冲销、退款或独立调整处理，保留采购单价差异审计。

## 7. 共同规则、告警与输出

- 凡来源于销售出库、采购入库、生产或外加工的应收应付必须填写 `order_no`；其他事项允许为空，但必须有类型、相对方和原因。
- 应收应付维护发票号、开票/收票日期、发票金额、是否已开/已收、对账状态，并统一支持非必传 `attachment` 上传发票、对账单、银行回单和合同资料。
- 维护到期日并提供逾期、超额核销、来源差异、未关联订单告警；告警状态为“待处理、已确认、已恢复”。告警通常不阻塞保存，但超额核销必须阻止保存。
- 固定报表：员工目录、考勤、绩效、薪资台账/付款、应收与收款明细、应付与付款明细、应收账龄、应付账龄、订单收支追溯、财务告警。均支持日期、订单号、客户/供应商/员工、状态筛选和 Excel/CSV 导出。
- 人事、财务、销售、采购、管理员按模块授权；审批人字段预留，V1.0 不实现审批流。

## 8. 审计与影响联动

修改薪资来源、薪资调整、应收应付、收付款或来源单据前，系统必须展示受影响订单、来源单据、未核销余额、已核销金额、员工薪资、仓库出入库事实、状态、告警和风险。

确认后，应收应付余额、核销进度、薪资未付余额、逾期/差异告警和报表数据在同一事务中更新。已确认收款、付款、工资付款及仓库出入库为独立事实，必须通过冲销、退款、补收、补付或独立调整更正。所有新增、修改、取消、逻辑删除、调整、冲销和告警处理均记录操作人、时间、原因、对象快照和变更前后值。

## 9. 与开发文档的边界

本文定义业务对象、规则、状态机和跨模块数据流，不定义数据库列、NestJS 模块、REST 路由、页面组件或任务拆分。后续需细化销售单价格来源、外加工费、预收预付、超额核销、会计口径和审批规则后，再形成开发规格与任务文档。
