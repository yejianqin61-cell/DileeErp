# 财务表格：一屏看全一行，不需要左右拖动（2026-09-16）

## 来源需求

> 「财务部分的表单，我希望能一次性在页面上展示全貌，不需要左右拖动条来拖动。你有什么好办法吗」

屏幕条件（用户确认）：**1600 / 1920**。

## 一、先量：可用宽度与瓶颈

| 项 | 值 |
| --- | --- |
| 内容区上限（改前） | `max-width: 1440px`，左右内边距各 32px |
| 左侧导航 | 固定 `232px` |
| 表格可用宽度（改前） | `min(1440, 视口 − 232) − 64` → 1920 屏 **1376px**、1600 屏 1304px、1440 屏 1144px |
| 表格可用宽度（改后） | 上限 1920 → 1920 屏 **1624px**、1600 屏 1304px（吃满） |
| 每列最低开销 | 内边距 28px + 不换行的内容 |

改前实测（真实 Chromium + 本项目 CSS + 真实列头与代表性数据；本机没有 PostgreSQL，
所以用静态页复现这几张表，量 `.table-wrap` 的 `clientWidth` vs `scrollWidth`）：

| 表 | 列数 | 1366 | 1440 | 1600 | 1920 |
| --- | --- | --- | --- | --- | --- |
| 应付对账 | 17 | 溢出 227px | 153px | ✅ | ✅ |
| 应收对账 | 16 | 108px | 34px | ✅ | ✅ |
| 销售对账明细表（老报表） | 23 | 624px | 550px | 390px | 318px |
| 工资台账 | 19 | 455px | 381px | 221px | 149px |
| 应付台账 / 银行账户池 | 11 | ✅ | ✅ | ✅ | ✅ |

**结论：不是「列太多」，而是「单元格不换行」。** 自动表格布局下，表格只有在「各列 min-content 之和」
超过容器时才溢出；`white-space: nowrap` 让每个单元格的 min-content 等于它的完整文本宽度 ——
「香港迪礼国际贸易有限公司」这种长客户名会把整列撑宽，把整张表顶出容器。
实测证据：只把 `th` 改成可换行，列宽**一点没变**（min-content 仍 1304）；把 `td` 也放开，
min-content 立刻降到 800。

## 二、做法（四条，互相依赖）

1. **内容区上限 1440 → 1920px**：1920 屏可用宽度 1376 → 1624px。
   保留上限而不是 `max-width: none`：超宽屏上纯文本页的行长会失控。
2. **紧凑**：内边距 14 → 8px、内容 13 → 12px、行高 44 → 38px、数字用等宽（`tabular-nums`）。
   每列省约 12px（17 列省 200px 以上）。
3. **表头与单元格都允许换行**（关键的一条）：中文可逐字断行，长客户名/物料名不再撑宽整列；
   表格放得下时不折行，放不下才折行 —— 折行是「不横向滚动」的必然取舍。
4. **金额不被折断**：`money()` 里金额与币种之间改用**不换行空格**（U+00A0）。
   放开换行后，普通空格会把「500.0000」和「USD」拆到两行；数字本身没有断行机会，所以不需要逐格加类。

**没有采用的做法**，以及为什么：

- **给每一列指定宽度 / `table-layout: fixed`**：固定布局下如果各列宽度之和超过容器，表格会**变宽**
  （横向滚动照旧）；要真保证放下就得给 17~23 列逐列写百分比，收益不比放开换行大，维护成本高得多。
- **把币种从单元格移到表头**（如「金额(CNY)」）：应收/应付是**多币种混在一张表**的
  （同一条对账单里就有 USD 与 CNY 行），格内去掉币种会看错钱。
- **逐列截断（省略号）**：要改十几个单元格的渲染；而且用户要的是「看全貌」，
  把客户名截成「香港迪礼国际…」与这个目标相反。放开换行能把全名显示出来。
- **给每张表加「列显示配置」**：不牺牲字段但要多一层交互，且需要业务先定「默认列集」。
  本轮只做排版，字段一个没动；如果将来列还要增加，再考虑它。

四张最宽的表在 **1366 / 1440 / 1600 / 1920 全部不出现横向滚动条**（用户是 1600/1920，余量更大）。

## 四、范围与守卫

- 紧凑与换行规则全部限定在 `.finance-page` 内：其它模块的表格各自调过密度
  （领料单 11px + 固定列宽、采购工作台等），不该被牵连；全站 `.data-table` 仍是原来的 nowrap。
- `apps/web/lib/finance-table-width.test.mjs`（5 条）把「内容区上限 1920」「紧凑尺寸」
  「th/td 可换行」「money() 用不换行空格」「规则限定在财务页」钉住 ——
  这些是排版约束，类型检查与组件测试都发现不了，改回去最宽的表就会重新出现滚动条。

## 五、已知缺口

- **本机没有 PostgreSQL**：页面取不到真实数据，实测用的是「同一份 CSS + 真实列头 + 代表性数据」的
  静态复现页（真实 Chromium）。**真实数据下的极端长文本**（超长客户名、超长备注）会让对应行折行变高，
  但不会重新出现横向滚动条（这正是放开换行的意义）。
- **折行的观感**需要在真实系统上看一眼：列被压窄时文本折成 2~3 行、行变高。
  若觉得太挤，可选的下一步是「列显示配置」（默认列集）而不是把 nowrap 改回来。
- 老报表（23 列）与老表的列位一一对应，本方案**没有动任何列**，导出仍与老表一致。
