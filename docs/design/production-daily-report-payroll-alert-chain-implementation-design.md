# D5 生产日报、员工计件/计时日报与差异告警链路实现设计

> 文档类型：跨模块纵向链路开发设计
>
> 链路：生产单/工序 -> 工序日报 -> 员工计件/计时日报 -> 差异与超单告警
>
> 对应路线图：D5；依赖 D1-D4
>
> 状态：设计完成，待拆分开发任务

## 1. 问题陈述

D1-D4 已提供员工目录、工序池与计价、厂内生产单、工序任务及原料领退料事实，但系统还不能记录每天每道工序完成了多少，也不能把车间员工的计件/计时工作量转换为可供薪资台账使用的参考金额。没有两套日报之间的核对关系，生产单的累计进度、超单风险和员工薪资来源都无法可靠解释。

D5 只处理厂内生产。外加工过程不进入 ERP，不创建外加工现场日报、员工日报、进度或超单数据。

## 2. 方案与交付边界

```text
生产中的厂内生产单 + 有效工序任务 + 员工/工序计价
  -> 工序日报（工序完成量）
  -> 员工日报（计件/计时工作量与薪资参考）
  -> 员工日报件数汇总与工序日报完成量核对
  -> 差异告警 / 超单告警
  -> 生产单工序累计进度与薪资来源查询
```

本批交付：

- 厂内工序日报的新增、编辑、逻辑删除、查询和累计统计；
- 员工计件/计时日报的新增、编辑、逻辑删除、查询和参考金额快照；
- 员工日报与工序日报的日维度差异告警；
- 生产单工序累计完成、目标数量、差额、超单量和状态展示；
- 告警确认、备注、自动恢复和完整审计；
- 为 F2 薪资台账提供按员工、日期和周期汇总的不可编辑生产薪资参考来源。

本批不实现成品 QC/入库、外加工直发、最终工资台账确认、工资支付、自动排产和移动端。

## 3. 用户故事

1. 作为车间/物控操作员，我要选择生产中的厂内生产单和有效工序，录入某日工序完成量，以便生产单能累计显示真实进度。
2. 作为操作员，我要修改或逻辑删除录入错误的工序日报，并保留原因、操作人和时间，以便错误可纠正且历史可追溯。
3. 作为操作员，我要按订单号、生产单号、工序和日期查询工序日报，以便核对车间实际产量。
4. 作为操作员，我要为每位车间员工录入同一生产单/工序/日期的计件日报，以便计算计件薪资参考金额。
5. 作为操作员，我要为员工录入计时日报的时长和件数，以便按时长核算薪资，同时用件数核对工序产量。
6. 作为物控员，我要看到日报录入时带出的有效单价和计薪方式快照，以便历史金额不因未来调价而变化。
7. 作为物控员，我要在确需覆盖单价时填写原因，以便人工调整不丢失业务依据。
8. 作为生产负责人，我要看到同一生产单同一工序同一日期的工序日报量与员工日报件数合计，以便发现漏报、重复报工或录入差异。
9. 作为生产负责人，我要在日报数量超过工序目标时收到超单告警，但仍允许保存真实产量，以便系统不阻碍现场继续生产。
10. 作为操作员，我要在差异或超单告警上填写处理备注并确认，以便异常有明确的人工处理记录。
11. 作为操作员，我要在日报修改后看到告警自动恢复或重新变为待处理，以便告警状态反映当前数据而非旧快照。
12. 作为财务/人事操作员，我要按员工和工资周期查看生产计件/计时参考金额，但不能直接修改生产日报来源，以便薪资调整与生产事实分离。
13. 作为生产负责人，我要在生产单详情看到每道工序的目标量、累计完成量、差额、超单量和状态，以便决定是否可以完成生产单。
14. 作为审计人员，我要查看日报新增、修改、删除、告警确认和恢复的操作人、时间、原因及前后值，以便追溯所有业务变化。
15. 作为系统管理员，我要确保暂停、已关闭生产单和外加工生产单不能新增日报，以便状态边界不会被页面绕过。

## 4. 实施决策

### 4.1 领域对象

| 对象 | 核心字段 | 规则 |
| --- | --- | --- |
| 工序日报 | `production_order_id`、工序任务、`order_no`、生产日期、完成量、备注 | 只允许厂内生产单；完成量为正十进制字符串；引用有效且未取消工序任务；保留生产单/工序快照。 |
| 员工日报 | 生产单、工序任务、`order_no`、员工、生产日期、计薪方式、件数、时长、单价、参考金额、备注 | 只允许厂内生产单和有效员工；件数、时长按计薪方式校验；保存单价和金额快照。 |
| 告警 | 类型、订单号、生产单、工序、生产日期、当前数量快照、状态、处理备注、确认人/时间、恢复时间 | 类型至少为 `over_order`、`daily_discrepancy`；同一业务键只保留一条持续告警，历史通过状态和审计保留。 |
| 生产薪资来源 | 员工、工资周期、生产日报集合、计薪方式、参考金额汇总 | 由有效员工日报汇总生成，只读；不反写日报；F2 可引用并以独立调整行更正。 |

所有表使用 UUID 主键及统一 `created_at`、`updated_at`、`created_by`、`updated_by`、`deleted_at`、`deleted_by`、`remark` 字段。业务日期使用日期类型；数量、时长、单价和金额通过 API 以十进制字符串传输。

### 4.2 日报输入规则

- `production_order_id` 是客户端唯一必需来源，服务端据此取得 `order_no`、执行方式、生产单状态、工序任务和单位；客户端不得覆盖这些快照。
- 只有 `execution_mode = in_house` 且生产单状态为 `in_progress` 的生产单可新增或修改日报；`paused`、`closed` 和外加工生产单拒绝新写入。
- 生产单进入 `completed` 后允许补录、修改和逻辑删除日报；`closed` 默认只读，恢复为 `completed` 后才可调整。
- 工序日报完成量必须大于 0；员工日报件数必须大于 0；计时日报时长按分钟录入且必须大于 0。计时日报仍必须录入件数，但件数只参与差异核对，不参与薪资金额。
- 同一员工、日期、生产单、工序、计薪方式默认允许多条记录，以适应分班/补录；汇总按有效记录求和。若后续确认不允许多条，可在数据库增加业务唯一约束，不改变汇总语义。
- 员工必须在日报日期处于可报工状态；离职/停用员工不得新增日报，但历史记录可查询。

### 4.3 计价与金额

- 员工计件日报：`参考金额 = 件数 × 计件单价`。
- 员工计时日报：`参考金额 = 时长（分钟） × 计时单价`；员工件数不进入金额计算。
- 日报创建时按员工、工序、计薪方式和生产日期取得有效计价；保存单价、计薪方式和计算结果快照。
- 物控员允许覆盖单价，但必须填写覆盖原因；覆盖不改写工序池历史计价。
- 金额使用定点十进制计算，不使用 JavaScript 浮点累计；展示和 API 传输保留字符串。
- 生产模块仅输出参考金额，F2 薪资台账负责工资周期汇总、独立调整和最终确认。

### 4.4 累计进度与状态

对每个有效厂内生产单工序计算：

```text
累计完成量 = 有效工序日报 completed_quantity 之和
差额 = 目标数量 - 累计完成量
超单量 = max(累计完成量 - 目标数量, 0)
```

- 累计量小于目标量：工序状态为 `in_progress`；累计量等于目标量：`completed`；累计量大于目标量：`over_order`，同时视为完成。
- 状态由有效日报和目标数量计算，不允许操作员手工把工序改成完成或超单。
- 超单不阻止日报保存、后续日报累加或生产单完成；保存前必须显示强提示并产生告警。
- 已取消工序不再接收新日报，但既有日报和累计历史保留；是否计入生产单总进度由服务端明确排除取消工序。
- 生产单详情和列表返回工序累计摘要，前端不自行汇总跨表数据。

### 4.5 差异告警

对每个 `生产单 + 工序 + 生产日期` 计算：

```text
员工日报件数合计 = 当日所有有效员工日报件数之和
差异量 = 工序日报完成量 - 员工日报件数合计
```

- 两者不相等时创建或更新 `daily_discrepancy` 告警；相等时自动标记为 `recovered`，保留恢复时间和前后数量。
- 计时日报的件数参与上述核对，但不参与计时薪资金额。
- 超单和差异告警统一状态：`pending`（待处理）、`confirmed`（已确认）、`recovered`（已恢复）；不设置忽略状态。
- 操作员确认告警必须填写处理备注；确认人和确认时间写入告警及审计。
- 已确认告警再次异常或异常加重时复回 `pending`，更新数量快照并记录审计，不新建重复告警。
- 告警更新必须与日报写入处于同一事务，避免日报已变更而告警仍显示旧结果。

### 4.6 修改、删除与联动

- 草稿/有效日报允许编辑；逻辑删除通过反向重算累计量、差异量和告警状态完成联动。
- 已确认日报不物理删除；修改/删除必须填写原因，保存前返回影响预览，至少展示生产单工序累计、员工件数合计、薪资参考金额和告警变化。
- 影响预览确认后，在一个事务内写日报、重算汇总、更新告警和审计日志；失败时整单回滚。
- 不直接修改生产单目标数量或员工计价历史来“消除”告警；应通过日报更正或独立基础资料变更处理。

### 4.7 API 与权限

统一使用 `/api/v1`、JSON 信封、`snake_case`、请求 ID、十进制字符串和稳定错误码。建议资源：

- `GET/POST /production/operation-reports`
- `GET/PATCH/DELETE /production/operation-reports/:id`
- `GET/POST /production/employee-reports`
- `GET/PATCH/DELETE /production/employee-reports/:id`
- `GET /production/orders/:id/progress`
- `GET /production/daily-alerts`
- `POST /production/daily-alerts/:id/confirm`
- `GET /production/daily-alerts/:id/audit-events`
- `GET /production/payroll-sources`

服务端必须提供日报影响预览和按订单/生产单/工序/员工/日期的查询；列表返回订单号、生产单号、工序、数量、告警摘要，避免前端拼接跨模块数据。

管理员拥有完整权限；生产/物控操作员可维护日报和处理告警；人事/财务可读取生产薪资来源但不得修改生产日报；具体权限复用现有 RBAC，不新增审批流。

### 4.8 审计、附件与导出

- 新增、修改、逻辑删除、日报过账、告警确认/恢复、状态拒绝和影响预览确认均写统一审计事件，包含操作人、时间、`order_no`、生产单、工序、原因和前后值。
- 日报可复用统一 `attachment` 关联凭证或说明；附件非必传，不建设独立文件系统。
- 本批预留生产进度表、工序日报表、员工日报/薪资参考表和告警表的筛选/导出接口，但复杂 Excel 模板不在首个编码切片中优先实现。

## 5. 测试决策

最高测试缝隙为生产日报 REST API + 真实 PostgreSQL 事务；浏览器验证物控/车间操作员的真实工作流。沿用现有 `node:test`、HTTP/API、独立 PostgreSQL 和 Playwright 分层，不断言 Prisma 内部实现。

至少覆盖：

1. 生产中厂内生产单可新增工序日报和员工日报；暂停、已关闭、外加工和无效工序被拒绝。
2. 计件金额为件数乘计件单价；计时金额为分钟乘计时单价，计时件数不计入金额。
3. 日报保存单价/金额快照；未来调价不改写历史日报；覆盖单价缺少原因被拒绝。
4. 工序日报累计量、差额和超单量计算正确；超单允许保存并生成唯一持续告警。
5. 工序日报与员工日报件数相等/不等时，差异告警分别自动恢复/待处理；计时件数参与核对。
6. 已确认告警再次异常会恢复待处理；告警确认必须有备注并写审计。
7. 日报修改/逻辑删除在单事务中联动累计进度、薪资来源和告警；失败不留下半成品事实。
8. 重复请求幂等、并发版本冲突、未登录 401、越权 403、非法数量/状态 422 均符合全局契约。
9. Playwright 覆盖登录、创建工序日报、创建计件/计时日报、查看差异/超单告警和修改恢复。

## 6. 不在本批范围

- 外加工现场日报、外加工员工薪资、外加工进度和外加工直发；
- 成品送检、成品 QC、成品入库/出库、应收和发货；
- 考勤、绩效、月度薪资台账确认、工资支付和财务调整；
- 自动排产、产能预测、移动端、离线操作和消息通知；
- 复杂产品规格、工艺模板、单位换算和跨工序自动分摊；
- 全局告警中心。本批只提供生产日报相关告警查询和处理接口。
