# 销售单 Excel 补录（上传 → 字段匹配 → 系统表单核对 → 确认建单）

- 日期：2026-11-02
- 用户原话：「针对销售模块，现在要加一个补录功能。用户上传销售单 excel，系统进行字段读取与匹配，展示一份系统表单，让用户进行修改与确认。用户通过之后，再确认建立销售单。」
- 同日拍板两件事：
  1. **两种版式都认** —— 先按我们自己的工艺单/生产单版式逐格对（`example/销售单/` 那两份就是），认不出的再按字段名在整张表里找；最后把没认出的格子列成清单，让用户在表单里补。
  2. **一份文件 = 一张单**（表中若出现多个「客户单号」，只认第一个并在核对清单里如实上报）。

## 1. 为什么是"版式驱动"，而不是像其它导入那样"模板驱动"

仓库里已有的四个导入（物料清单、库存盘点、其他应付、员工花名册）都是**模板驱动**：下载模板 → 填写 →
上传 → 按**表头名**认列 → 逐行校验 → 行级错误不连坐。

补录的场景不是这样：用户手上的是**已经写给工厂的单子**（或客户发来的订单），不是拿来给系统导入的模板。
所以这一轮的解析器是**版式驱动**：锚点是纸上的中文标签（「客户单号」「伞骨（孔对孔）」「工艺要求」），
不是列序号。两条纪律不变：

- **认得出就填，认不出就报**（`unrecognized` 逐格列出原文与单元格地址），绝不猜；
- **不静默丢**：同一类目多行 → 「同类目再加一款」（2026-10-29 的口径）；不认识的类目 → 「其它」行。

不给「必须先下载补录模板」的理由：那等于把单子重新誊一遍，补录就不省事了（用户当日选型时明确否掉了这条）。

## 2. 三段流程与"只读预览"

```
① 上传（POST /sales-orders/import-preview，multipart，10MB，只放行 .xlsx/.xls）
      ↓ 纯函数解析 + 查主数据（客户/单位/订单号占用）
② 预览（本次返回 JSON，**一字节都不写库**）
      ↓ 前端把 copy 载荷灌进**正式的新建销售单表单**
③ 核对修改 → 「确认建立销售单」 → POST /sales-orders（既有 DTO / 归一 / 快照 / 审计 / 草稿状态）
```

为什么预览必须只读：用户要的是"先看系统表单、改完再确认"。只要预览阶段落了库（哪怕落成草稿），
放弃一次就会在列表里留下一张幽灵单；而"预览说 3 款、建出来 2 款"这种分叉将无法自查。

为什么建单仍走 `POST /sales-orders`：补录只是把"手工打字"换成"预先填好"。另起一条建单路径，就得把
DTO 校验、37 个细化标量的归一、版本快照 v1、客户/联系人快照、审计、订单号冲突翻译全部再写一遍 ——
那是必然会慢慢分叉的一份副本。

## 3. 解析口径

### 3.1 两版真实样本的差异（解析器要同时认）

| 位置 | 样本1 `DL260134 JBN生产单(1).xls` | 样本2 `DL260001-1 花色生产单-IS(...).xlsx` |
| --- | --- | --- |
| 表头 | 「客户单号：DL260134」**标签与值同格** | 「客户单号」「DL260001-1 FLOWER1」**分格** |
| 正文分栏 | A 列材料类目、B–F 明细、G–J 工艺要求 | A 材料、B–G 明细（合并）、H 起工艺要求 |
| 细分明细 | **嵌在材料区中间**（第 10–16 行），左右两块并排 | 没有伞布表；尾部另有一张「伞头」表（英文名/配色/条码/数量打） |
| 数量 | `1960支`（数字格，单位在显示文本里） | `2505打` |
| 正唛/侧唛 | 标签在第 29 行、值在**第 30 行** | 值在**下一行**的同一列 |
| 布量 | 只有标签（`伞面（Y/DZ)`），没有值 | 无此块 |
| 末尾 | 「材料到货状态」勾选表（伞骨/纸箱/不干胶…） | 同上 + 尾部伞头表 |

### 3.2 锚点

- **表头 14 个字段**：工厂 / 客户单号→订单号 / 客户代码→客户（待匹配） / 客户 PO / 合同号 / 下单日期 /
  完工日期（值里的「进仓」等尾巴进 `completion_remark`）/ 数量（尾缀单位一起读）/ 品名规格 / 货号 /
  地区（只用于核对客户）/ 注意事项 / 单位 / 币种。只在正文分栏**之上**的行里找（下面「数量」「客户」
  这些词还是明细表的列头，在整张表里找必然抓错一行）。
- **18 个材料类目**：锚点清单只存"纸上可能怎么写"（`伞布` 是样本2 的写法、`织唛` 是到货状态表里的写法），
  类目名本身来自 `sales-material-labels.ts`（与导出、与「再加一款」共用一份，不另抄）。
- **工艺要求 9 项**：按词认、不按编号认（两张样本的编号都是断的：1、2、4、5、6、7 + 吊牌位置 + 质检报告）。
- **布量 5 格**：靠 `Y/DZ` 认 —— 标签里带（样本1）或值里带（我们自己导出的「伞面 | 12（Y/DZ)」）都算；
  否则「伞带」在材料区与布量区同名，分不开。
- **正唛/侧唛**：值可能在同一行右边、也可能在下一行的同一段里；窗口 = 本标签列 .. 同排下一个标签列。
- **细分明细**：某一行同时有「数量」类列头与它左边的「品名/品番/名字」类列头即为表头，左右并排的多块
  各读各的；分组名取自表头上方**带「明细」二字**的横幅（没有横幅就按表头里的「伞头/伞布」说一个，
  再不行叫「明细」——分组名在表单里可改，不为好看去猜）。

### 3.3 停表与"不猜"的几处硬判定（都是第一版真实踩过的）

1. **明细表结束**：整行没有数量 或 品名列里出现下一个区块的标签（「伞头」「正唛」）。只看"品名与数量都空"
   会把紧随其后的整片材料区读成明细（第一版样本1 多读了 19 行）。
2. **材料区结束**：读到「材料到货状态」就停 —— 以下是仓库收货的勾选表（伞骨/纸箱/不粘胶…），
   继续读会把勾选项当成类目内容（第一版把「纸箱」「不干胶」读成 OPP、伞头的第二款）。
3. **标签 vs 值**：我们自己导出的工艺单里**有类目的值就是类目名**（「织标 | 织标」「钥匙扣 | 钥匙扣」）。
   只按"文本等于类目名"判标签会整块错位；判定是「行首一定是标签；行中间的格子若与当前段同类目且右边
   没内容 → 它是值」。
4. **右栏不是材料值**：材料区的右边界取「明　细」这一格**合并范围的右端**（样本2 的 B6:G6 说明材料值到
   G 列为止），H 列起的「吊牌图稿发客人确认」是工艺内容，不能灌进上一格材料里。
5. **续行**：只有值没有标签的行，只有"上一行刚有一个材料标签"且"值落在值列（第 2 列起）"时才并进上一格
   （样本2 第 22 行「OPP袋、伞头…」是「印刷」的续写；第 10 行「Flower1 外层花色」是小标题，不是续写）。

## 4. 主数据匹配（查库的三件事，都不写库）

| 项 | 口径 | 对不上时 |
| --- | --- | --- |
| 客户 | 名称全等 → 编码全等 → **去掉括号备注后**的编码全等（样本2 的「IS（PO32366-1)」括号里是客户自己的 PO）。**不做前缀模糊**（IS / ISUZU 会串户，错账当场看不出来） | 错误：「请在表单里选客户」，并把表里的原文与地区摆出来 |
| 订单号 | 只查**未删除**的行（唯一性是"未删除行上唯一"，软删单占过的号可以再用） | 错误：点出这个号被谁占着、状态是什么，请改号或换历史号 |
| 单位 | 名称归一到单位池里的写法（`pcs` → `PCS`） | 提醒（不拦）：请在下拉里选一个 |
| 币种 | Excel 一般没有 → 用客户的默认币种 | 客户没匹配上时留空并提醒 |

**不自动新建客户/单位**：与物料导入「不自动新建单位」同一条纪律 —— 一张旧 Excel 顺手建出来的主数据，
只会让「家百纳 / 家百納 / JBN」各占一条。

## 5. 前端

- 入口：销售单列表页头「从 Excel 补录」（次要按钮；偶发动作不占新建单的主位）→ `/sales/orders/import`。
- 补录页只做上传；解析成功后**整页换成 `SalesOrderEditor`**（同一张系统表单，带 `imported` 预填载荷），
  页头多一个「换一个文件重新读取」（只回调，不发请求，不留半张单）。
- 表单顶部「Excel 补录核对」横幅：文件名/工作表 → 一句话汇总（读出 N 处/明细 X 行/追加 Y 行/没认出 Z 处/
  待修正 K 项）→ **必须改**（红）→ 提醒（黄）→ 折叠的逐格清单（`C2 订单号：DL260134`）与没认出的格子。
- 四个"必须重填"的格子（订单号/下单日期/数量/交货日期）这一路是**按表填好**的，提示语从「（复制后必填）」
  变成「（按表填好，请核对）」；主按钮叫「确认建立销售单」（补录的语义是建单，不是存草稿）。
- 建出来的单仍是 `draft`：之后照常走既有的「确认」流程。

## 7. 没做 / 非目标（写清楚，免得以后当 bug 报）

- **一份文件只当一张单**：表里若有多张单的痕迹，只取第一张并在核对清单里上报，不自动拆分。
- 不认识 **PDF / 图片订单**（用户说的是 Excel）；不认 `.csv`（Multer 白名单只放行 xlsx/xls）。
- 不做「列名映射」界面（用户自己指定"第几列是数量"）：两版样本的共同点是**标签就在纸上**，
  真遇到第三种版式，应该把它加进锚点清单，而不是让每个操作员各配一遍。
- 不自动新建客户/单位/物料主数据；不自动生成订单号（订单号必须由人确认，重号会在预览里就报出来）。
- 不写库、不落审计：这一步是只读预览；真正的建档由 `POST /sales-orders` 的既有审计留痕。
- 「材料明细」的**物料引用**（`material_refs`）不自动匹配：Excel 里只有文字，没有物料编码；
  需要引用物料时在表单里点下拉选。
