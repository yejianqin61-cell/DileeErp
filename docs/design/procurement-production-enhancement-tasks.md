# 采购与生产增强实施任务拆解

## 使用方式

本文件是 `docs/design/procurement-production-enhancement-design.md` 的执行版。任务按依赖顺序执行；每个任务完成后必须：

1. 运行该任务的验收检查。
2. 只提交本任务相关文件。
3. 使用 Conventional Commit。
4. 在本文件勾选任务状态并单独提交。

当前业务口径：BOM 的核定用量采用 `订单数量 / 生产配料基数 × 基准用量`。因此“基准用量”作为 BOM 行必要字段；若产品最终确认另一公式，必须在执行 Task 1 前修改本文件和设计文档。

## Task 1：BOM 数据模型与核定用量

状态：`[ ]`

前置：无。

目标：让 BOM 行能够持久化规格型号、颜色、生产配料基数、基准用量、核定用量和单位，并由服务端统一计算核定用量。

工作项：

- Prisma 增加 BOM 行字段，保留旧 `model` 读取兼容。
- 新增并执行数据库迁移。
- BOM 创建、详情、编辑、替换明细接口补齐字段。
- 服务端根据订单数量计算核定用量，禁止客户端提交结果覆盖。
- 校验生产配料基数、基准用量为正 Decimal。
- BOM 只允许启用的原料物料，禁止成品物料。
- 增加服务层测试：正常计算、零值/负值、成品物料、重复 BOM。

验收：

- Prisma generate、迁移和 API 构建通过。
- 同一订单号第二次建 BOM 返回 `BOM_ALREADY_EXISTS`。
- API 返回的核定用量与公式一致。
- 测试覆盖 Decimal 计算而非浮点计算。

提交：`feat(bom): add specification and approved usage calculation`

## Task 2：物料编码模式与默认单位新增

状态：`[ ]`

前置：Task 1。

目标：新建物料支持自动编码或手动编码；默认单位下拉支持在当前表单中新增并立即选中。

工作项：

- 创建物料 DTO 增加 `code_mode=auto|manual`。
- 自动编码由服务端生成，并处理唯一约束冲突。
- 手动编码校验唯一、长度和允许字符。
- 编辑已被业务事实引用的物料时禁止修改编码。
- 物料候选统一过滤 `raw_material`，销售成品不进入 BOM/采购原料候选。
- 修复 ActionDialog 类目创建返回：保留父表单值、刷新选项、自动选中新单位。
- 在物料创建页面接入单位新增子弹窗。
- 增加 API 测试覆盖自动/手动/冲突和类目流程。

验收：

- 自动创建得到唯一物料编码。
- 手动编码重复时接口拒绝。
- 新增单位后回到物料表单，原名称/类型等值仍保留且下拉立即出现新单位。
- 成品物料不会出现在 BOM 物料选择器。

提交：`feat(materials): support generated and manual material codes`

## Task 3：生产工序池和预置数据

状态：`[ ]`

前置：Task 2。

目标：生产工序池支持增删改查、启用/停用，生产单只能从工序池选工序。

预置且幂等创建：

`大裁、拉边、小裁、验片、合片、剪线头、打顶打带、打珠尾、缝伞、品检、折伞、外发加工、其他、包装`

工作项：

- 为预置工序增加唯一约束或幂等 seed。
- 确认生产工序 CRUD API 完整，删除采用停用。
- 生产单新增工序只接受工序池 ID，并保存名称/单位快照。
- 增加生产页面“工序池”表格和新增/编辑/停用操作。
- 类目新增返回父页面并刷新工序选择项。
- 增加 seed/API 测试，确认重复执行不产生重复工序。

验收：

- 首次 seed 有 14 个启用工序。
- 重复 seed 后数量不变。
- 停用工序不能添加到新生产单，历史生产单仍显示快照。
- API 与前端构建通过。

提交：`feat(production): add operation pool and default operations`

## Task 4：生产领料单服务端联动

状态：`[ ]`

前置：Task 1、Task 2、Task 3。

目标：生产领料单绑定生产单和 BOM，服务端返回全量库存/采购/领用计算列，并保证过账事务一致性。

工作项：

- 复用或扩展原料领料单模型，增加 BOM 行、核定用量快照、申请补料数量。
- 增加按生产单/BOM 的 preview 接口。
- 计算库存数量、采购入库数量、采购未入库数量、生产领用数量、生产未领用数量。
- 创建/编辑/删除草稿；过账时事务内重读库存并校验。
- 强制领料物料为 BOM 原料，物料 ID 使用物料清单唯一 ID。
- 增加 API 测试：库存足够、不足、采购部分入库、重复过账、非 BOM 物料。

验收：

- preview 返回全部 11 个业务字段。
- 过账后库存事实和生产领用累计一致。
- 并发或旧 preview 不会绕过库存不足校验。
- 非 BOM 成品物料被拒绝。

提交：`feat(production): link material issues to orders and bom`

## Task 5：生产领料单大尺寸悬浮表格

状态：`[ ]`

前置：Task 4。

目标：在生产页面提供生产领料单入口和大尺寸居中悬浮页面，桌面端一次完整展示全部业务列。

工作项：

- 使用现有 Dialog/Sheet、DataTable、Button、Select、Input 组件。
- 桌面端悬浮页面宽度至少为视口 80%，表格不使用横向滚动隐藏字段。
- 一次展示物料名称、物料代码、型号、颜色、核定用量、库存数量、采购入库数量、采购未入库数量、生产领用数量、生产未领用数量、申请补料数量。
- 支持新建、编辑、删除草稿、过账、冲销。
- 服务端计算列只读，申请补料可编辑。
- 库存不足和未领用量使用警示样式。
- 增加 Playwright 页面验收，检查 11 个表头同时可见。

验收：

- 生产单详情可打开领料悬浮页面。
- 桌面截图中 11 列全部存在且无横向滚动容器。
- 草稿可编辑/删除，过账后状态正确。
- 所有控件来自项目组件库。

提交：`feat(production): add full-width material issue dialog`

## Task 6：工序员工日报一次多选员工

状态：`[ ]`

前置：Task 3。

目标：在生产单 -> 工序日报页面一次选择多个员工，再展开为日报行逐行填写。

工作项：

- 使用项目 Select/Popover/Checkbox 组件实现多选，不使用原生多选控件。
- 批量选择生成员工行，默认去重。
- 每行选择计件或计时，填写人工单价。
- 计件要求件数、时长可空；计时要求时长、件数可空；两者单价必填。
- 保存前前端校验，API 再次校验。
- 日报金额按当天人工单价计算并同步工资来源。
- 生产单和工序上下文始终绑定，不能跨工序保存。
- 增加多选、去重、计件/计时校验和工资来源测试。

验收：

- 一次选择 2 个以上员工可生成多行。
- 重复选择不会生成重复员工行。
- 计件空时长可保存；计时空时长被拒绝；无人工单价被拒绝。
- 保存后工资台账周期汇总包含日报金额。

提交：`feat(production): support multi-employee daily reports`

## 每个任务的停止条件

- 需求口径不明确时停止编码并更新设计文档。
- 数据迁移失败时停止后续任务，不在生产库猜测或重建数据。
- 当前任务验收未通过时不得提交“完成”。
- 每个任务只允许一个功能提交，部署包、临时文件和无关格式化不得混入。
