# 原料仓储情况：模糊搜索 + 规格型号列

- 日期：2026-09-14（第三轮）
- 状态：已实施
- 范围：`apps/web/app/warehouse/raw-material-storage/page.tsx`、新增纯函数 `apps/web/lib/material-search.ts`
  （2026-09-16 改名为 `apps/web/lib/fuzzy-search.ts`：同一套匹配规则被全部主数据池复用，名字不该再只提物料）
- 需求来源：用户 2026-09-14 直接指令（第 5、6 条）

## 1. 需求

1. 原料仓储情况加搜索功能，支持模糊搜索；
2. 库存汇总表要加「规格型号」列。

## 2. 为什么需要

- 原料主数据允许「同名不同规格/颜色」（`materials` 的唯一约束是 名称+规格型号+颜色），
  只显示「编码 / 名称」时，仓库在库里看到两行「涤纶布」无法判断是哪一种；
- 物料与入库单变多以后，靠翻页找一条记录不可行。

## 3. 实现

### 3.1 「规格型号」列

`GET /materials` 返回物料全字段（`ProcurementMasterDataService.listMaterials` → `include: { defaultUnit: true }`），
因此**不需要改后端**：页面把 `Material` 类型补上 `specificationModel` / `color`，
库存汇总表在「物料」列后新增「规格型号」列（空值显示 `-`，而不是 `undefined`）。

未维护规格的物料不会因此被隐藏：它照样出现在表里，只是这一列显示 `-`。

### 3.2 模糊搜索

匹配规则抽成纯函数 `lib/material-search.ts`：

```ts
fuzzyMatch(query, fields): boolean
```

- 查询按空白拆词，**所有词**都要出现在该行的任一字段里（AND 语义）→「涤纶 150D」能同时收窄物料与规格；
- 大小写不敏感、忽略空白 →「150 D」「m - 001」都能命中；
- 空查询不过滤（返回 true）；
- `null` / `undefined` / 数字字段安全参与匹配（后端可选字段很常见）。

**一个搜索框同时过滤两张表**（页面叫「原料仓储情况」，两张表是同一个业务视角的两个切面，
分成两个搜索框会让用户不知道自己在筛哪一张）：

| 表 | 参与匹配的字段 |
| --- | --- |
| 库存汇总 | 物料编码、名称、规格型号、颜色、单位、订单号 |
| 原料入库单 | 入库单号、订单号、采购单号、到货记录、批次序号、质检状态、入库状态（中文）、备注 + **该入库单物料的**编码/名称/规格型号/颜色 |

入库单本身不带物料名，靠 `materialId` 映射物料主数据补齐后再参与匹配，否则「按规格搜入库单」永远搜不到。

搜索是**纯本地过滤**：输入时不发任何请求（有测试断言 fetch 调用次数不变），
否则每敲一个字符都会打一次接口。

### 3.3 交互细节

- 搜索框放在标题下方、两张表之上的独立面板里，带占位提示列出可搜字段；
- 有搜索词时出现「清除搜索」按钮；
- 两张表面板标题旁显示「筛选后 N / M 条」；
- 搜不到时两张表分别回落到「没有匹配的原料库存」/「没有匹配的原料入库单」，
  与「暂无…」（确实没有数据）区分开，避免用户以为数据被删了；
- 「入库单与库存关系」的计数仍是总数，加了搜索时额外标注「（筛选后 N）」，不改变统计口径。

## 4. 明确不做

- 不做服务端搜索/分页：原料主数据与入库单在当前数据量下是全量加载的，
  本地过滤零延迟；等数据量真的上来再改（届时需要给 `/materials`、`/raw-material-inbounds` 加查询参数）；
- 不做拼音/近义词/拼写纠正：模糊仅指子串分词匹配，避免「搜 A 出 B」这种不可解释的结果。
