## 一、「不能一起付款」的根因

**不是批量确认坏了，是批量出单坏了。**

`批量确认` 一直是对的：勾选 N 条 → 一个支付银行 + 一个会计科目 → 后端给**每条**写一条收支流水
（所以每条都追得回来源单号）。问题出在紧接着的那一步 —— 「导出付款单」：

| | 2026-09-20 的实现 | 后果 |
|---|---|---|
| 跨供应商勾选 | `POST /finance/payment-slips/draft` 直接 422 `PAYMENT_SLIP_MULTI_COUNTERPARTY`（「请按供应商分批导出」） | 她只能一家一家重新勾、重新开弹窗 |
| 跨币种勾选 | 同样 422 `PAYMENT_SLIP_MULTI_CURRENCY` | 同一家的外币应付还要再拆一轮 |
| 同供应商一次导出 | 一张单子装下全部条目 | 这一张确实能用 |

所以她的体感正是「只能算是一起确认了，然后还是一个个的改付款单」——
**确认**是一个动作，**出单**是 N 个动作（N = 供应商数 × 币种数）。收款侧一模一样
（`RECEIPT_SLIP_MULTI_COUNTERPARTY` / `_MULTI_CURRENCY`），「收束收款」同样只收束了确认那半步。

### 修法：把「一次勾选」变成「一队单子」，而不是报错

模板本身就是分组依据：付款单上「收款单位 / 开户银行 / 银行账号」**各只有一格**，
所以一张单子在会计上只能对应**一个对方单位 + 一个币种**（单子也只有一个大写金额与小写金额）。
既然一张单子装不下，就不要让她手工拆 —— 由系统拆：

- `groupSlipEntries(entries, counterpartyOf)`（`finance-slip.ts`，纯函数）按 `${对方单位}|${币种}`
  分组，**保持首次出现顺序**（队列顺序必须稳定，否则每次打开看到的次序都不一样）；
- `draft()` 的返回从「一张单子」改成「**一组单子**」(`FinanceSlip[]`)，控制器包成
  `{ data: { slips }, meta: { slip_count } }`；
- 每张单子各自算自己的单号、附单据张数、开户行/账号（**按本组的流水判**，不能拿全批的账户去填 ——
  那会让一张单子填上另一家那笔钱走的账户，打印出来是一张指错账户的银行单据）。

配套的三件事：

1. **队列编辑器**（`finance-slip-editor.tsx`）：顶部一行是各张的标题
   （`2. 富雨鑫（USD） 合计 70`，见 `slipQueueLabel`），每张**各自保存**自己的编辑（切走再切回不丢）。
   标题里必须带对方单位与币种：同一家公司的两个币种拆成两张时，只写「第 1 张 / 第 2 张」认不出谁是谁。
2. **「全部导出」**（`POST /finance/{payment,receipt}-slips/batch.xlsx`，最多 100 张）：
   一个工作簿、**一张单子一个工作表**。为什么不逐张下载：十几张的连续下载会被浏览器拦掉，
   财务看到的是「只出来了第一张」，而且不知道丢了几张。工作表名 `付款单2-晋江大田`
   （带序号是必须的 —— 同名工作表 ExcelJS 直接抛错；31 字上限与 `[]:*?/\` 非法字符都处理了）。
3. **队列底部接回确认**：这一批里还没确认的条目在队列里显示为
   `确认这 N 条（付款 / 收款）`，点它就关掉队列、按**同一批 id** 打开原来的批量确认弹窗。
   「一起付款」= 出单 + 确认两个动作在同一个地方完成，不用在两个页面之间来回跑
   （`batchConfirm(ids?)` 因此加了可选入参：队列可能是从行内单条打开的，那时它不在勾选里）。

### 顺带修掉的两处

- **单号可能重复**：编号口径是「该对方单位本月第几笔结算」，同一家拆成两张（CNY + USD）时
  两次调用算出来的基数相同 → 两张同名单据。`suggestNumber(..., offset)` 加了「同一批里已经给这家
  开出去几张」的偏移。跨供应商之间重号**不修**：那是编号本身的语义（每家各有自己的 002），
  编号是可改的建议值，口径写在 `suggestNumber` 的注释里。
- **「确认这 N 条（付款）」写死在组件里**：收款单队列底部会出现「确认这 2 条（**付款**）」——
  它确认的是收款。抽成 `slipConfirmPendingLabel(kind, count)`，测试逐字断言两种单据的文案。

## 二、跨行转账单（编辑 + 打印 + 导出）

模板：`example/财务/跨行转账单.html`（19 个 `data-docx-field` 占位符）。
单据本身**不落库**（与收/付款单同一处理）：系统里的事实是 `bank_transfers` 那条记录，
这张纸是交给银行的打印件。

### 逐格映射（预填）

| 模板格 | 系统来源 |
|---|---|
| 单据编号 | `bank_transfers.transfer_no`（可改：财务按银行要求的号写） |
| 付款人全称 / 账号 / 开户行 | 转出账户 `banks.account_name / account_number / bank_name` |
| 收款人全称 / 账号 / 开户行 | 转入账户的同三项 |
| 联行号 | **留空** —— 银行账户档案里没有这一列（见遗留） |
| 转账日期 | `transfer_date` |
| 币种 / 汇率 | `from_currency` / `exchange_rate`（去掉无意义的尾零：`1.000000 → 1`） |
| 转账金额（原币） | `from_amount` |
| 折合人民币 | **是人民币的那条腿**：转出是人民币取转出，转入是人民币取转入，两条都不是（外币转外币）留空 |
| 金额大写 | 由后端按折合人民币算（见下） |
| 用途／附言 | `remark` |
| 制单人 / 复核 / 出纳 / 审批 | 只预填制单人；其余三格留空 —— 那是手签的位置，印名字等于替人签了 |

### 金额大写：界面不算，留空即「让系统算」

人民币大写只有**后端一份实现**（`finance-slip.ts` 的 `amountInWords`，见那里的注释）。
所以这张单子的做法是：

- 预填带上来的是后端算好的；
- 财务**一改原币 / 折合人民币 / 汇率就清空大写**（`clearWordsOnAmountChange`，单点实现）：
  留空 = 导出时由后端按金额重算 → 纸上永远不会出现一段过期的大写；
- 她自己写了大写也可以（外币转外币时系统算不出来，只能她写），但**必须与系统算出来的一致**，
  否则 422 `TRANSFER_SLIP_WORDS_MISMATCH` 并把正确写法写进消息里
  （一张大写与小写对不上的银行单据会被退回或被读错）。

### 两条出口

- **打印 / 另存 PDF**：走浏览器打印（与记账凭证纸同一做法）。弹窗里那张纸本身就是可编辑的
  表单 —— 每一格是无边框输入框（`.transfer-slip-input`），屏幕上看着就是一张填空的单子，
  打印时 `@media print` 只留 `.transfer-slip-sheet`（并把灰底标签强制印出来）。
  不做「上面表单、下面预览」两套版式：那样迟早出现「屏幕上对的、纸上错的」。
- **导出 XLSX**：`POST /finance/bank-transfer-slips.xlsx`（走裸 fetch，**必须自带 `/api/v1`**）。
  版式照模板三段逐格对齐，金额落 Excel 数值类型，表尾加全站统一的落款。
  请求体里带 `transfer_id`（只进审计）：从这张纸追得回那笔资金动作。

入口挂在**银行余额互转页**的每一行（`bank-transfer-slip-<id>`）。已冲销的互转**也允许出单**：
它是一张打印件，不改任何数据；财务常常是先冲销错的、再照原样补一张纸，把按钮禁用只会让她去翻别的办法。

## 三、遗留（需要财务定或下一轮做）

1. **付款单/收款单的「开户银行 / 银行账号」到底是谁的？**
   模板上这两格紧跟在「收款单位」后面，代码里的类型注释写的是**对方**开户银行（会计惯例），
   但 2026-09-20 的实现填的是**我方**账户（取 `cash_flow_entries.bank_id`）。
   两者必有一错，而这是**钱**的字段，所以本轮没有猜着改 —— 等财务一句话：
   若是对方的，就需要在供应商档案上补「开户银行 / 账号 / 联行号」三个字段（`settlement_info` 已有 Json 位）。
2. **联行号没有存档**：`banks` 表只有 `swift_code`，没有联行号（CNAPS）。加一列是小事
   （与 swiftCode 完全同构：DTO + service + 表单 + 一条迁移 + 守卫测试），但会引入本轮的第一次迁移，
   所以先按「每次手填」交付，等确认后再补。
3. **同一家多币种的两张单子共用「附单据张数」口径**：现在按本组条目数算，跨组不合计 ——
   财务若按「本次结清这家全部单据」打印，需要她说明期望值。
4. 单张导出保留原来的 `POST /finance/{payment,receipt}-slips.xlsx`（一个文件一张单子）。
   银行要一张一张给时走这条；批量那条只是「一次拿全」，两条都留着。
