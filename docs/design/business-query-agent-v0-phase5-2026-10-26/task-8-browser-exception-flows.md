# Task 8：浏览器断线、冲突、限流与撤权流程

## 目标

在隔离测试数据库中，以真实浏览器登录、真实 Next 代理和真实 API 覆盖 Phase 5 尚缺的四条用户流程：SSE 断线重连、同用户活动 run 冲突、全局并发忙碌，以及已建 SSE 连接中的档位撤销。

## 范围

- 断线：浏览器离线后显示恢复状态；恢复网络后同一 run 完成，且不再 POST。
- 409：页面在同用户已有活动 run 时保留草稿并显示稳定提示；后台 run 随后取消清理。
- 429：四个临时隔离账号占满真实闸门，第五个已登录页面保留草稿并显示忙碌提示；所有临时 run 都取消。
- 撤权：管理员将独立浏览器中 full 用户降到 operational；既有 SSE 只得到 `ACCESS_REVOKED`，页面显示错误并清空本地可见内容。
- 临时账号只在名称含 `test` 的隔离数据库中创建；测试结束时停用，运行和会话由终态或停用处理收束。

## 不做

- 不改生产权限、闸门、SSE 或查询页实现。
- 不将 fake provider 当作真实模型验收；真实模型和代表订单仍留给 Phase 6。

## 验收

- [ ] 四个场景在浏览器 E2E 中通过。
- [ ] 429 与 409 后输入框仍含用户原草稿。
- [ ] 断线与刷新均不重复 POST；撤权后出现稳定拒绝提示。
