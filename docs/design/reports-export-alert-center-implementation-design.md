# G2/G3 报表、导出与告警中心开发设计

## 1. 目标

在 G1 订单全链路只读聚合的基础上，提供可筛选的模块报表、Excel 兼容 CSV 导出和跨模块告警中心，帮助 2-3 名操作员快速发现待处理问题并留存可审计的业务数据。

本版本全部能力为读取和导出，不修改订单、库存、QC、生产、收付款等业务事实；告警确认只改变告警处理状态，不改变来源事实。

## 2. 范围

### G2 报表与导出

- 订单推进报表：订单号、客户、总体状态、阻塞数量、更新时间。
- 采购与应付报表：采购单、供应商、订单号、采购金额、应付金额、已付和未付状态。
- 库存报表：订单号、库存类别、来源、数量变动、单位和更新时间。
- 生产/QC 报表：生产单、工序、日报完成量、超单量、QC 结论和合格/不合格数量。
- 薪资报表：员工、期间、应付、已付、未付和台账状态；不返回敏感身份或银行卡信息。
- 所有报表支持订单号、日期范围、状态和业务对象筛选，并返回分页元数据。
- 导出与当前筛选条件一致，首版输出 UTF-8 BOM CSV，扩展名为 `.csv`，可直接使用 Excel 打开；字段顺序和列名固定并记录导出条件。

### G3 告警中心

聚合以下已有事实产生的待处理清单：超单、日报差异、库存不足、来料/成品 QC 不合格、超额收付款核销、外加工来源差异、应收应付逾期或未解决对账差异。告警状态包括 `pending`、`acknowledged`、`resolved`，确认/解决必须保留操作人、时间和备注。

## 3. API 契约

统一前缀 `/api/v1`、认证、模块权限和 `{ data, meta }` 响应。

```text
GET /reports/orders
GET /reports/procurement-payables
GET /reports/inventory
GET /reports/production-qc
GET /reports/payroll
GET /reports/:report/export?format=csv
GET /alerts
GET /alerts/:id
POST /alerts/:id/acknowledge
POST /alerts/:id/resolve
```

报表查询参数统一：`order_no`、`from`、`to`、`status`、`employee_id`/`supplier_id`（适用时）、`page`、`page_size`。Decimal 以字符串传输，日期为 ISO 字符串。导出使用相同筛选参数，响应 `text/csv; charset=utf-8`，第一行 BOM，单元格中的逗号、引号、换行必须 RFC 4180 转义。

告警参数：`alert_type`、`status`、`order_no`、`severity`、`from`、`to`、`page`、`page_size`。告警返回 `source_type`、`source_id`、`order_no`、标题、严重级别、建议、状态、操作人和时间线。

## 4. 数据与一致性规则

1. 报表从现有业务事实和 G1 读模型实时查询，不维护可漂移的报表余额缓存。
2. 报表不得因为缺少下游事实而填充“已完成”；没有数据返回空集合或 `not_started`。
3. 导出是查询快照，文件名包含报表类型和生成日期；服务端限制最大导出行数，超出必须分页或提示缩小筛选范围。
4. 告警按来源事实去重：同一 `source_type + source_id + alert_type` 只返回一条有效告警；已解决告警保留历史，不物理删除。
5. 告警确认/解决只更新告警处理记录或既有告警状态，不静默修改来源业务数据。
6. 所有告警写操作保留审计事件、操作人、操作时间和备注；读取接口不产生审计事实。

## 5. 前端交互

- 新增“报表与告警”页面，使用 tabs 分隔报表和告警，表格使用 TanStack Table。
- 报表顶部统一筛选栏，支持重置、刷新、分页和“导出当前筛选”。
- 告警按严重级别、状态和订单号筛选；详情展示来源编号、建议和处理记录，确认/解决使用带备注的表单。
- 提供加载、空数据、导出失败和服务错误状态；导出按钮显示进行中状态并防止重复点击。

## 6. 测试与验收

- 领域测试覆盖 CSV 转义、Decimal 字符串、日期筛选、告警去重和严重级别排序。
- API 测试覆盖权限、分页、筛选、导出 content type、BOM、敏感字段排除和告警状态转换。
- Web 构建和浏览器测试覆盖报表切换、筛选、导出、告警确认/解决及错误状态。
- `verify:chain` 的真实 PostgreSQL/API/Playwright 运行条件不足时，必须明确记录环境阻断。

## 7. 完成判定

G2/G3 仅在报表 API、CSV 导出、告警中心 API、前端页面、单元/API/Web 测试、测试记录和路线图均完成后，标记为“代码/单元/构建完成；真实链路待环境”。
