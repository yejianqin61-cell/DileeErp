# 池子搜索与 BOM 表的「新建物料」（2026-09-16）

## 来源需求（用户原话）

1. 「供应商池，要支持搜索。」
2. 「所有池子，都要支持搜索」
3. 「BOM表的新建物料按钮怎么不见了。」

用户对第 1、2 条的追问选择：**只做池页面上的搜索框**（不动表单里的下拉）。
对第 3 条的选择：**三处入口都恢复成真能用的**。

---

## 一、先盘点：哪些池子有搜索，哪些没有

系统里被称为「池」的页面一共 9 个。改前逐个查证（有没有关键字输入框）：

| 池 | 文件 | 改前 |
| --- | --- | --- |
| 供应商池 | `app/procurement/suppliers/page.tsx` | ❌ **没有** |
| 物料池（物料清单） | `app/procurement/materials/page.tsx` | ❌ **没有** |
| 客户池（销售页内嵌，`/customers` 复用） | `app/sales/page.tsx` | ❌ **没有** |
| 工序池 / 加工地点池 | `components/production/master-data-pool-page.tsx` | ✅ 有，但只有 `<label>搜索<Input/></label>`，没有筛选条与计数 |
| 单位池 | `components/production/unit-pool-page.tsx` | ✅ 有 |
| 部门池 / 岗位池 | `components/hr/organization-pool.tsx` | ✅ 有 |
| 银行账户池 | `components/finance/bank-workspace.tsx` | ✅ 有 |
| 员工目录（人事） | `app/hr/page.tsx` | ✅ 有（本轮不动，见 §五） |

**根因不是「漏写」，而是「池子是一批各自实现的页面」**：每个池子自己写一句
`xxx.toLowerCase().includes(query.toLowerCase())`，所以「有没有搜索框」和「怎么匹配」
两件事都靠人记得住。缺的三个恰好是最常被问到的三个主数据（供应商 / 物料 / 客户）。

## 二、做法

### 1. 匹配语义统一到一个纯函数

`lib/material-search.ts` → **`lib/fuzzy-search.ts`**（改名：它现在是全站搜索框的公共规则，
名字不该再只提物料）。规则不变，仍是 `fuzzyMatch(query, fields)`：

- 查询按空白拆词，**所有词**都必须命中该行的任一字段（AND）；
- 大小写、词内与字段内的空白都不敏感（`150 D` 命中 `150D`）；
- 空查询不过滤；`null`/`undefined`/数字字段安全参与。

为什么单字查询看不出差别也要统一：`香港 迪礼` 这种两词查询在「拆词」与「不拆词」的实现下
结果不同，用户在别的池子里习惯了多词搜索，回到没拆词的池子就会觉得「这个页面的搜索坏了」。
改后 8 个池页面（员工目录除外）全部 import 这个函数。

### 2. 三个池子补上搜索框（同时补计数与空态）

- 供应商池：编码 / 名称 / 联系人 / 电话 / 备注；标题上给「共 N 个供应商（启用 X 个 / 停用 Y 个），当前列出 M 条」；
- 物料池：编码 / 名称 / 规格型号 / 颜色 / **默认单位名**（物料表里存的是单位 id，人搜的是「米」，
  所以先用单位池把名字解析出来再匹配）/ 物料类型（原料/成品，按界面说法而不是 `raw_material` 这个值）；
- 客户池：编码 / 名称 / 国家地区 / 地址 / 付款条件 / 备注，**以及每个联系人的姓名、职位、电话、邮箱**
  （现场常常只记得联系人姓名或电话）。

三个池子的空态都区分两种情况：**没有数据** → 「暂无…」+ 新建引导；
**搜不到** → 点名关键词并说明总数（「没有匹配“宁波”的供应商 / 共 3 个供应商，换个关键词或清空搜索框」）。
不区分的话，用户搜错一个字会以为整个池子空了。

### 3. 顺带把工序池 / 加工地点池的筛选条补齐

原来只有 `<label>搜索<Input/></label>`（没有 `filter-bar` 类、没有 placeholder、没有计数）。
现在与其它池子一致：筛选条 + 「搜索工序名称或编码 / 加工地点名称或类型」+ 「共 N 条，当前列出 M 条」+ 搜不到时的空态。

### 4. 守卫（把「所有池子都要有搜索」变成机器可检查的约定）

新增 `apps/web/lib/pool-search-guard.test.mjs`（源码守卫，2 条）：

1. 清单里的每个池页面都必须：import `lib/fuzzy-search`、调用 `fuzzyMatch(`、有 `filter-bar`、筛选条附近有「搜索」与 `<Input>`；
2. **反向检查**：任何把「池」写进界面文案的文件都必须登记在清单里 —— 将来新增池子时，
   漏加搜索框会在这一条上直接红，而不是等用户发现。

注释会先被剥掉：`app/finance/banks/page.tsx` 这种路由壳文件注释里写着「银行账户池」，
但界面上的「池」字在组件里，不算漏登记。

## 三、BOM 表的「新建物料」：三个入口的真实情况

BOM 工作区（`components/bom/bom-workbench.tsx`）由采购与生产共用，
「新建物料」按钮的渲染条件是 `onCreateMaterial` 存在（不传就只显示一句「物料池归采购」）。
改前逐个查证：

| 入口 | 改前 |
| --- | --- |
| 采购 → BOM表（`app/procurement/boms/page.tsx`） | 按钮**在**，但 `onCreateMaterial={() => {}}` 是空函数 —— **点了没反应** |
| 采购单 → 编辑BOM表（`app/procurement/orders/page.tsx`） | **整个 BOM 工作区不可达**：`openBom()` 还在，但没有任何按钮调用它（页面拆分时把入口丢了） |
| 生产 → BOM表（`app/production/page.tsx`） | 不传 `onCreateMaterial` → **按钮不渲染**，只有提示文字 |

也就是说用户看到的「不见了」在生产侧是字面意思，在采购两处是「按钮在但没用」。

### 改法

1. 抽出共享组件 `components/bom/material-create-dialog.tsx`（`MaterialCreateDialog`）：
   字段与物料清单页原来的「新建物料」完全一致（编码方式 / 物料编码 / 名称 / 规格型号 / 颜色 /
   默认单位 / 物料类型 / 备注），POST `/materials` 的请求体也一字不差；
2. 三处入口都接上；新物料先并进页面的物料池，再回填到 BOM 当前行：
   **只填 id 不并池会让那一格的下拉变成空白**（下拉是按 options 渲染名字的）；
3. 采购单页补回「编辑BOM表」入口（草稿里选中 BOM 后可点，未选时禁用），BOM 工作区不再不可达；
4. 物料清单页（采购 → 物料清单）也改用同一个组件 —— 全站只剩一份「新建物料」表单，
   字段与校验不会在两个页面之间漂移。

## 四、共享弹窗里踩到的两个坑（都写进了代码注释）

1. **「新建单位」会继承物料的名称**：`ActionDialog` 是按**字段名**保留已填值的
   （`current[field.name] || field.defaultValue`），而两个表单都有 `name` 字段，
   于是「新建单位」的名称框里带着物料名，实测会拼成「伞骨打」。
   解法：给两个 ActionDialog 不同的 `key`，强制换实例（物料草稿由 `draft` 状态自己带着走）。
2. **单位建好后弹窗被顺手关掉**：`ActionDialog.submit()` 在 `onSubmit` 成功后还会再喊一次
   `onOpenChange(false)`。我们为了「建完单位回到物料表单」已经切了页，那一次回调会被当成
   「用户关窗」→ 草稿被清空、选中态丢失。解法：用一个 `keepOpenRef` 标记「这次是程序切页」，
   把那次关闭请求吃掉（`单元新增成功后不能把关窗当用户意图`）。
3. 失败必须 **reject**（而不是 `notifyError` 就算了）：这样弹窗保持打开、显示后端原因、
   用户不用重新填。这条是全站 `ActionDialog` 的既有契约（`test/action-dialog-submit-guard.test.tsx`）。

## 五、没做 / 已知缺口

- **表单里的下拉仍不可搜索**（用户本轮明确选了「只做池页面」）：新建采购单/销售单时从
  供应商、客户、物料下拉里选值仍然要滚动。池子变大之后这是下一个该做的东西。
- **员工目录没并入统一语义**：它是自己写的 `employeeNo + name` 子串匹配，本轮不动 ——
  该文件正由另一个 agent 改（身份证解析），避免同工作树互相踩。
- **搜索是前端过滤**：池页面一次性把主数据拉全（`/suppliers`、`/materials` 等无分页），
  所以搜索本身不发请求。几千条以上时需要后端搜索 + 分页，那时这套前端 `fuzzyMatch` 要换成
  「把关键字交给接口」。
- **没有「清空搜索」按钮**：清空靠手动删字（搜索框自身可选中全删）。若财务反馈不便，再加。
- 「新建物料」弹窗**没有做重复预检**：同名同规格同颜色的物料由后端 409 拒绝，前端只显示原因。
