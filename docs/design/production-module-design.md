# 迪礼 ERP V1.0 生产模块初步设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：初稿，需由生产负责人、物控负责人和总经理确认后才能进入数据库/API设计与开发拆任务。

## 1. 设计目标

生产模块负责以 `order_no` 为主线，记录订单对应的生产任务、工序要求、每日完成量、员工计件/计时数据，并对超单和异常进度进行提示。

V1.0 的设计原则：

- 订单号是跨模块追溯主线，相当于订单身份证；所有生产记录必须能追溯到订单号。
- 生产单是订单生产任务的汇总表，不直接承担每日报工明细。
- 工序由物控员从可维护的工序池中选择，生产单只保存本单实际采用的工序及目标数量。
- 厂内生产和外加工共用订单、生产单和工序池等基础模型，通过执行方式区分；外加工点的现场报工、薪资和进度不进入 ERP。
- 员工日报与工序日报分开记录：前者用于薪资依据，后者用于生产进度汇总。
- 系统保存原始日报数据，汇总数据可重新计算；禁止用手工修改汇总值替代原始记录。
- 未确认的业务规则不写死在数据库或代码中，统一标记为“待确认”。

## 2. 业务范围

### 2.1 V1.0 包含

- 生产单创建、修改、查询和逻辑删除。
- 生产单与 `order_no` 的默认一对一关联，并允许人工扩展多个补单、返工或拆分生产单。
- 工序池维护及工序选择。
- 生产单工序目标数量维护。
- 工序日报录入、修改、查询和汇总。
- 员工生产日报录入，支持计件和计时两种计薪方式。
- 计时日报同时记录件数，避免只记录时长而无法核对产量。
- 生产单/工序超单告警。
- 厂内生产与外加工的执行地点记录。
- 以订单号、生产单号、工序、日期、员工等条件查询和导出。

### 2.2 暂不包含

- 自动排产、设备排程、产能优化。
- BOM、配方、自动物料需求计算。
- 自动计算工资、个税、社保或发薪。
- 外加工供应商结算、对账和应付流程（由采购/财务模块定义）。
- 生产质量检验流程（由质量/仓库相关设计定义），但预留关联键。
- 移动端、离线录入和外部系统实时对接。

## 3. 核心概念与关系

```text
订单 order
  |
  | order_no
  v
生产单 production_order
  |
  +-- 生产单工序 production_order_operation
  |       |
  |       +-- 工序日报 operation_daily_report
  |
  +-- 员工日报 employee_daily_report
          |
          +-- 计件/计时明细与工序关联

工序池 operation_catalog ----(物控员选择)----> 生产单工序
```

### 3.1 订单

订单实体属于订单/销售领域，本模块只保存其关联标识，不复制订单主数据。生产模块所有查询和日报均应展示 `order_no`，内部关联使用订单 UUID。

### 3.2 生产单

一个订单默认对应一个生产单，但不做一对一硬限制。操作员可按业务需要人工扩展同一订单下的多个生产单，例如分批生产、补单或返工。V1.0 一个订单只有一款产品，生产单不展开产品明细表；产品规格和生产工艺作为预留字段保存，详细产品定义由销售单后续约定。生产单是订单生产任务的汇总对象，包含执行方式、执行地点、生产目标和整体状态，并汇总其工序目标与日报完成量。

扩展生产单必须继续关联同一个 `order_id/order_no`，并通过生产单类型和父生产单关联说明其用途。V1.0 固定使用以下类型：`standard`（标准单，无父单）、`supplement`（补单）、`rework`（返工）、`split`（拆分）。后三类必须关联同一订单下的父生产单。

### 3.3 工序池

工序池是全厂（包括外包业务）共用的基础资料，保存工序名称、编码、默认计量单位、启用状态和说明。工序池记录可以被多个生产单引用；生产单工序必须保存当时选择的工序快照名称/单位，避免后续修改工序池影响历史数据展示。工序池共用不等于外加工过程由系统管理，外加工点的实际生产过程不进入 ERP。

工序池是稳定的全厂基础资料，日常基本不调整或删除。工序池禁止物理删除；即使未被历史数据使用，也仅允许逻辑删除。已被生产单引用的工序只能设置为停用；停用工序不得被新生产单选择，但历史生产单继续保留工序引用和快照。

### 3.4 生产单工序

生产单工序是生产单上的实际任务行，至少包含工序、顺序、目标数量、计量单位、累计完成量和进度状态。工序顺序由物控员维护，系统不假设固定工艺路线。

新建厂内生产单时，新增工序默认带入生产单计划伞数作为目标数量。开始报工后仍允许物控修改工序目标数量、增加工序和调整工序顺序；每次目标数量调整必须填写原因，系统不自动改写其他工序目标。已存在工序日报或员工日报的生产单工序任务不得删除，只能标记为“已取消”；这里取消的是生产单上的工序任务，不是工序池定义。所有变更必须记录变更前后值、操作人、操作时间和原因。工序目标数量变更后，系统立即重算累计量与超单告警。

工序进度状态由系统计算，不允许手工设置为完成或超单：累计量为零时为“未开始”，大于零且小于目标时为“进行中”，等于目标时为“已完成”，大于目标时为“超单且视为已完成”；“已取消”由操作员手动设置并填写原因。界面在超单时优先展示超单状态和超单数量。

已取消工序任务的历史工序日报、员工日报、薪资依据和审计记录全部保留，不再允许新增或修改日报；默认生产进度和超单统计不再计入该任务，历史报表可按“包含已取消工序”筛选查看。

### 3.4.1 生产执行地点

厂内车间和外加工点统一作为生产执行地点基础资料维护。地点至少区分 `workshop`（厂内车间）和 `outsource_site`（外加工点）两类；生产单通过执行地点关联，并由 `execution_mode` 保留厂内生产/外加工语义。厂内车间必填名称和启用状态；外加工点必填名称、联系人、联系方式、地址和启用状态；两类地点均保留备注。停用地点不得用于新生产单。

### 3.5 工序日报

工序日报按“生产单 + 工序 + 日期”记录当日完成量，是生产进度的原始事实。日报可以由操作员补录或修改，但每次修改必须保留审计字段和备注。

### 3.6 员工生产日报

员工日报按员工、日期和生产单工序记录薪资计算依据。支持：

- 计件：件数 × 件单价；
- 计时：工时 × 时薪，同时记录件数；
- 单价、件数、时长由物控员维护；系统保存录入时的单价快照。

V1.0 只提供计算依据和金额参考，不自动生成最终工资单。计件模式薪资参考金额为“件数 × 计件单价”；计时模式薪资参考金额为“时长 × 计时单价”，计时模式下填写的件数不参与薪资金额计算。

### 4.4 `operation_daily_report` 工序日报

| 字段 | 类型建议 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | UUID | 是 | 内部主键 |
| production_order_id | UUID | 是 | 生产单 |
| production_order_operation_id | UUID | 是 | 生产单工序 |
| report_date | date | 是 | 日报日期 |
| completed_quantity | decimal | 是 | 当日完成量，必须大于等于 0 |
| operator_id | UUID | 是 | 录入人 |
| remark | text | 否 | 备注 |

同一生产单工序同一天允许多次操作，也允许修改已有日报的完成数字。系统不要求以“生产单工序 + 日期”做唯一约束；每次修改保留统一审计字段、操作人、操作时间和备注。生产单工序累计完成量按当前有效日报数据重新汇总，不直接累加历史修改前的数字。

工序日报完成量、员工日报件数和计时日报时长必须大于零；时长以分钟录入。不允许用负数冲销，更正通过修改或逻辑删除原记录完成。禁止录入未来日期；允许补录历史日期，但补录必须填写原因并记入审计日志。日报均使用 `report_date` 保存当日生产日期。

### 4.5 `employee_daily_report` 员工生产日报

| 字段 | 类型建议 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | UUID | 是 | 内部主键 |
| employee_id | UUID | 是 | 员工 |
| report_date | date | 是 | 日报日期 |
| production_order_id | UUID | 是 | 生产单 |
| production_order_operation_id | UUID | 是 | 对应工序 |
| wage_mode | enum | 是 | `piece_rate` 计件 / `time_rate` 计时 |
| piece_quantity | decimal | 是 | 件数；计时模式也必须填写 |
| piece_unit_price | decimal | 否 | 计件单价快照 |
| duration_minutes | integer | 否 | 计时分钟数 |
| time_unit_price | decimal | 否 | 计时单价快照 |
| calculated_amount | decimal | 是 | 按日报字段计算的参考金额；计时模式只按时长 × 计时单价 |
| maintained_by | UUID | 是 | 物控维护人 |
| remark | text | 否 | 备注 |

约束：计件模式要求件数和计件单价；计时模式要求时长、计时单价和件数。计时模式的件数不参与薪资金额计算，但参与员工日报件数汇总和与工序日报的差异核对。单价一旦用于日报，后续修改物控价格不应改写历史日报快照。

V1.0 单价维护的匹配范围为“员工 + 工序”，计件单价和计时单价分别维护，并维护生效日期。产品规格暂不作为单价匹配条件；如后续确认同一员工/工序因产品规格不同而使用不同单价，再扩展价格规则模型。日报默认带入当前有效单价；物控可手动覆盖，但必须填写原因。日报保存单价快照，历史日报不随价格维护变化而重算。

同一生产单、同一工序下，员工日报中的计件件数和计时件数统一进入同一个“员工日报件数累计”口径，不因计薪模式不同而拆开统计。计薪模式只决定金额计算方式：计件按“件数 × 计件单价”，计时按“时长 × 计时单价”。员工日报是员工薪资计算依据；工序日报是生产件数统计和超单判断的主口径。两套数据不直接相加，系统按“同一生产单 + 同一工序 + 同一日期”汇总员工日报件数，并与工序日报完成量核对；不相等时生成差异告警。

同一员工、同一日期、同一生产单、同一工序允许录入多条员工日报，按当前有效明细汇总，不覆盖已有记录。员工日报由获生产模块权限的操作员录入；系统 `created_by/updated_by` 记录实际系统操作人，`maintained_by` 记录业务维护人，两者可以相同或不同。V1.0 的操作员类型限定为物控、采购、财务、销售和管理员，具体模块授权由平台权限配置决定。

车间工人的生产薪资等于其计件/计时日报参考金额的累计，生产模块向薪资模块提供按员工、日期、工序、生产单汇总的生产薪资数据。薪资模块允许财务对汇总结果新增、修改和删除调整记录；调整不得反写生产日报金额，且必须全量审计、记录操作留痕。

## 5. 生产流程

1. 操作员以 `order_no` 创建生产单，选择厂内生产或外加工，并填写执行地点。
2. 物控员从工序池选择本单工序，维护工序顺序、目标数量和计量单位。
3. 生产执行过程中，每日录入各工序完成量，形成工序日报。
4. 车间/物控录入员工生产日报，选择计件或计时，并填写件数、单价或时长。
5. 系统按日报汇总生产单工序累计完成量，更新进度视图。
6. 当累计完成量大于工序目标数量时，允许保存日报，但必须进行强提示并生成待处理的超单告警；系统不得因超单阻止如实录入现场数据。
7. 生产单完成、关闭或返工等状态由业务人员维护，状态转换遵循平台状态机；工序状态和告警由系统按日报数据计算或恢复。

## 6. 外加工模型

外加工订单仍需建立生产单，但该生产单只保留订单、生产单、外加工地点、计划伞数、状态、外加工直发物料关联、备注和审计等最小追溯信息。外加工生产单由迪礼操作员手动标记完成，并记录完成日期、实际完成伞数和备注；统一附件系统支持可选上传送货单、回厂单或对方签收单等凭据。系统不根据外加工点日报自动判断完成，也不要求外加工点登录 ERP。外加工使用与厂内相同的订单/生产单关联和工序池，但外加工点的实际生产过程不进入 ERP，不由本系统维护工序日报、员工日报或生产进度。系统仅保留必要的外加工业务留痕：

- `execution_mode = outsourced`；
- `execution_location_id` 指向外加工点；
- 外加工复用统一的`生产中`状态，不新增`外加工中`状态；通过`execution_mode = outsourced`区分执行方式。
- 可选选择工序作为工艺说明；不开放任何外加工工序日报、员工日报、进度或超单告警。
- 原料可由采购直接发往外加工点，不要求经过厂内原料库存入库；系统仍需生成带“外加工直发”特殊标记的物料发运/出库记录，关联采购单、订单、生产单和外加工点，但不得虚构厂内原料入库余额后再扣减；
- 外加工点收发料、回厂、加工费和质量交接的具体单据关系待采购、仓库和财务负责人确认。

本设计不把“外加工”简单建成采购单，但也不把外加工点的实际生产日报、员工产量和进度强行纳入 ERP；相关外部过程由线下业务负责，系统只记录必要的关联和物流留痕。

## 7. 超单告警机制

### 7.1 触发条件

对每个生产单工序计算：

```text
累计完成量 = 该生产单工序所有有效工序日报 completed_quantity 之和
超单量 = 累计完成量 - 目标数量
```

当 `累计完成量 > 目标数量` 时，生成或更新 `over_order` 告警。

### 7.2 告警展示

- 生产单列表显示超单标记和超单量。
- 工序详情显示目标量、累计完成量、超单量和触发日期。
- 工作台/报表可按订单号、生产单、工序和日期筛选告警。

### 7.3 已确认规则

- 超单告警只提示，不阻止日报保存。
- 触发超单时，保存前必须给出明确的强提示；保存后生成待处理告警。
- 日报修改或删除使累计完成量回落至目标数量以内时，超单告警自动转为“已恢复”；告警历史必须保留，不得物理删除。
- 同一生产单、同一工序、同一告警类型只保留一条持续超单告警；后续日报可持续累加，系统只更新该告警的实际累计量和最后更新时间，不生成重复告警，也不锁定该工序。
- 超单告警支持操作员手动标记为“已确认”，并填写处理备注；V1.0 不设置处理人指派、处理期限或审批流。
- 工序日报与员工日报件数不一致时，按“生产单 + 工序 + 日期”只生成一条差异告警；任一日报变更时更新同一条告警，两者重新相等时自动标记为“已恢复”，历史记录保留，并支持操作员确认和填写备注。
- 超单和日报差异告警统一使用“待处理、已确认、已恢复”状态；不设置“已忽略”。手动确认必须填写备注，已恢复记录恢复时间及恢复前后的关键数量。
- 已确认告警在后续日报变更后仍异常或异常加重时，保留同一告警记录并更新最新数量，状态重新变为“待处理”，同时写入新的审计日志。
- 生产单状态采用最小状态机：`草稿 → 生产中 → 已完成 → 已关闭`，并支持 `生产中 ↔ 暂停`。返工不重新打开原生产单，而是在同一订单下新建返工类型生产单。
- `已完成`状态仍允许补录、修改或逻辑删除工序日报和员工日报，但必须保留审计字段和备注；`已关闭`状态默认只读。确需调整已关闭生产单时，先恢复为`已完成`并记录恢复原因，再进行日报操作。
- `暂停`状态不允许新增、修改或逻辑删除工序日报和员工日报；恢复为`生产中`后才允许继续报工。暂停、恢复及任何被拒绝的操作均应留下审计记录。
- `草稿`状态不允许新增或修改工序日报、员工日报；只有进入`生产中`后才能正常报工，`已完成`状态仅允许补录和修改日报。
- 生产单从`草稿`进入`生产中`前必须完成完整性校验：订单号、执行地点、计划伞数必填；厂内生产至少选择一道工序，外加工可不维护工序任务；产品规格和生产工艺预留字段可为空。
- 仅`草稿`生产单允许逻辑删除；进入`生产中`、`暂停`、`已完成`或`已关闭`后禁止删除，只能按状态流转或在同一订单下新建补单/返工生产单。删除操作必须记录删除原因、操作人、时间和对象快照。
- 当同一订单下全部生产单已完成或已关闭时，系统只提示“生产单已全部完成”，不自动修改订单推进状态；订单状态由操作员按全流程业务手动维护。
- 厂内生产单从`生产中`变更为`已完成`时，不强制所有未取消工序达到目标伞数；系统必须强提示未达标或超单工序，操作员填写完成原因后才允许完成状态变更，并保留该原因的审计记录。
- 存在未确认的超单告警或日报差异告警时，仍允许生产单进入`已完成`，但系统必须强提示，并记录“带未处理告警完成”的原因和操作审计。
- 仅`已完成`生产单可进入`已关闭`；关闭时必须填写关闭原因，不强制所有告警已确认。关闭和恢复均进入审计日志，并记录执行人和审批人预留字段。

### 7.4 计划日期

生产单支持计划开始日期和交货日期，用于生产查询、筛选和后续延期/排程能力预留；V1.0 不根据日期自动排产、自动变更状态或发送延期通知。

## 8. 共享字段与审计

所有实体使用平台统一的 UUID 主键、审计字段、逻辑删除字段和备注字段。日报与告警还必须保留业务日期、录入人和修改人。生产单、工序和日报的修改/删除均不得物理删除，汇总结果必须能由有效原始日报重算。

### 8.1 全量操作追溯

生产模块的一切业务操作都必须可追溯。除实体上的 `created_at`、`updated_at`、`created_by`、`updated_by` 外，系统应建设统一操作审计日志，至少记录：

- 操作类型：新增、修改、逻辑删除、状态变更、日报提交、告警确认、告警恢复等；
- 操作对象类型及对象 ID；
- 关联订单号、生产单号和工序（适用时）；
- 操作执行人；
- 操作时间；
- 操作结果（成功/失败）；
- 备注或操作原因；
- 修改操作的变更前值与变更后值；新增、删除和状态变更也应记录对应的对象快照或关键字段值；
- 审批人字段（当前仅作为设计预留，审批规则和是否必填后续约定）。

操作日志不得因业务数据逻辑删除而删除或修改，查询权限和日志保留期限由平台审计规范统一定义。

### 8.2 修改追溯示例

日报数字修改必须能够还原为可读的变更记录：

```text
对象：工序日报
字段：completed_quantity
修改前：100
修改后：120
操作人：张三
操作时间：2026-08-20 15:30
修改原因：补录上午产量
```

## 9. 跨模块暂缓事项

本轮生产负责人访谈中，生产单、工序、日报、薪资数据、告警、状态、外加工、附件和首批报表规则已确认。以下事项按跨模块边界暂缓，待对应负责人访谈后定义：

1. 外加工直发后的退料、余料回收、成品回厂、加工费、质量交接；
2. 生产质量检验；
3. 物料/BOM/自动物料需求；
4. 工资周期、最终薪资确认和发放；
5. 审批人的必填规则、审批流、角色和权限；
6. 自动排产、延期规则和消息通知。

## 10. 附件、报表与导出

生产单使用平台统一的 `attachment` 系统，附件非必传。初始附件类别包括产品图片、生产工艺资料、客户要求、变更说明、外加工交接资料和其他；附件关联生产单，并可按订单号检索。

V1.0 首批固定生产报表如下，均支持按日期、订单号、生产单号筛选，并支持 Excel/CSV 导出：

1. 生产单列表：订单号、生产单号、执行方式、地点、计划伞数、状态、完成日期；
2. 工序进度表：订单号、生产单、工序、目标数、累计完成数、差额、状态；
3. 工序日报表：生产日期、订单号、生产单、工序、完成量、录入人；
4. 员工日报/薪资参考表：生产日期、员工、订单号、生产单、工序、计薪方式、件数、时长、单价、参考金额；
5. 告警表：超单和日报差异告警、状态、处理备注。
