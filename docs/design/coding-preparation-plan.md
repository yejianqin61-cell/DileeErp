# 编码准备计划

## 目标

在不提前锁死全量业务数据库的前提下，完成平台验证、业务核心边界和首个可运行纵向切片，为后续按模块开发提供稳定基线。

## 阶段

### 1. 平台基线复核

- 验证 API 构建、类型检查和现有平台测试；
- 验证 PostgreSQL 迁移、Prisma Client 生成和健康检查；
- 确认认证用户、当前操作人、审计字段、软删除、附件、字典和状态机可被业务模块复用；
- 记录本机部署和失败恢复方式。

### 2. 跨模块核心契约

- 固定 `order_no` 的格式、唯一性和查询索引策略；
- 固定业务实体的 UUID、审计字段、软删除和状态记录接入方式；
- 固定来源引用、附件关联、影响预览和业务操作日志的 API 结构；
- 设计版本化可扩展表单定义的最小契约，不实现万能业务表。

### 3. 首个纵向切片

- API：客户、销售单草稿、订单号校验、确认、BOM 版本引用占位；
- Web：销售单列表、创建/编辑表单、确认操作、订单链路摘要；
- 验证：状态流转、审计、编辑影响预览、逻辑删除、前后端错误契约。

### 4. 逐模块扩展

按订单链路依次接入采购、仓库、生产、财务、人事；每个模块先更新设计和任务文档，再实现一个可验收的纵向切片。

## 数据库策略

当前只实现平台表和首个纵向切片所需的最小业务表。未确认的 BOM/QC 字段通过版本化定义和结构化扩展承载；待负责人确认后再增加稳定字段或专用表。所有迁移必须可回滚、可审计，禁止为了“预留”创建无法解释的全量表。

## 交付门槛

- `npm run build`、`npm run typecheck`、`npm run test` 可重复执行；
- 首个切片具备 API 契约测试和关键状态/审计测试；
- 前端可在本地 Web UI 完成创建、编辑、确认和查看链路；
- 文档、任务、测试记录和每日开发日志同步更新。
