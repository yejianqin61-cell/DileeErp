# 采购单打印信息与 Excel 导出（2026-09-16）

## 来源需求（用户原话）

> 「采购模块
> 1.供应商，需要多一个字段，地址
> 2.现在，需要允许导出 excel 采购单出来
> 采购单里面要有 订单号，供应商名称，供应商联系人，采购人，操作人，下单录入的时间，操作时间，备注，
> 序号，产品名称，规格型号，数量，含税单价，总价，交货日期，付款方式，交期条款，交货地址，
> 厂家回签意见，厂家回签，主管签字
> 其中，订单号，供应商名称，供应商联系人，采购人，操作人，下单录入的时间，操作时间，总价，交货日期，
> 付款方式，交期条款，交货地址作为表头
> 厂家回签意见，厂家回签，主管签字这些作为表尾，提供大格子
> 3.对应的，系统中采购单，也要支持对这些字段进行填写和设置。
> 4.付款方式，有月结30天，月结60天，当月付款」

用户对四条追问的选择：

1. **采购人 / 操作人**：**保持现状**（采购人 = 创建人、操作人 = 最后修改人，两个都由系统自动记，不新增可填字段）；
2. **表尾三格**：**系统里存文本，但导出仍留空手写**（回签内容存在采购单上供追溯，纸面那三格保持空白给现场手写）；
3. **付款方式**：**固定三项下拉、库里存文本**（以后加「月结90天」只改前端一处，不动后端与数据库）；
4. **明细列**：**保留现有 9 列**（序号 / 产品名称 / 规格型号 / **单位** / **供应商** / 含税单价 / 数量 / 含税总价 / **交货日期**）——
   多出的三列是此前业务确认要加的（单位：否则数量对供应商不明确；供应商：一张采购单可能拆给多家；交货日期：逐行给）。

## 二、做法

### 1. 供应商：新增地址

`suppliers.address VARCHAR(300)`（可空 —— 历史供应商没有这一项，不能因为加列变成必填）。
新建 / 编辑弹窗加「地址」字段、列表加「地址」列（空值显示 `-`）、搜索也认地址
（与其它池子共用 `fuzzyMatch` 的多词 AND 语义）。新建时留空**不发 `address` 键**，
编辑时清空发 `null`（服务端的「清除」语义）。

### 2. 采购单：六个打印字段 + 一个专门的更新入口

```
purchase_orders
  payment_terms          VARCHAR(50)    付款方式（月结30天 / 月结60天 / 当月付款）
  delivery_terms         VARCHAR(1000)  交期条款
  delivery_address       VARCHAR(300)   交货地址
  supplier_reply         VARCHAR(1000)  厂家回签意见
  supplier_signed        VARCHAR(200)   厂家回签（经办人 / 日期）
  supervisor_signature   VARCHAR(200)   主管签字
```

全部可空、不加索引（只有打印与人工查看，没有按它们筛选的场景）。
**为什么不塞进已有的 `extension_data`（JSON）**：这六项要在页面上直接编辑、要被打印表逐格读取、
还要能被审计（「哪些单还没填付款方式」）——JSON 三样都做不到，字段一多就变成一坨看不见的数据。

**为什么单独一个 `PATCH /purchase-orders/:id/print-fields`，不并进 `PATCH :id`**：
后者按「已有下游事实或非草稿不可编辑」锁死整张单（`PURCHASE_ORDER_NOT_EDITABLE`），
而**厂家回签本来就是下单之后才发生的事**（先把单发给厂商、厂商签回来、我们再登记）。
新入口只碰这六个字 + 备注 + 交货日期，**不动 items / totalAmount / status / supplierId**，
所以草稿、已下单、部分到货、到货完成的单子都能填；已取消的拒绝（它不再对外）。
空串按「清除这一格」处理（表单里删空 = 不印字），未传的字段不动（只改付款方式不会把交货地址清掉）。
每次更新写审计 `purchase_order.print_fields`，带上单号、状态与被改的字段名。

### 3. 导出：表头按用户清单重排，表尾三格改大

版式行号全部**由常量推出**（`ADDRESS_ROW` / `HEADER_GRID_START` / `TERMS_ROW` / `TABLE_HEADER_ROW`），
不再到处写字面行号 —— 上一版把「明细表头在第 6 行」写死在测试里，加两行表头就全线错位。

```
第 1 行   标题【采购订单】（草稿时标注）
第 2 行   交货地址：<值>                                   ← 整行
第 3 行   订单号：     | 供应商名称：   | 供应商联系人：
第 4 行   采购人：     | 操作人：       | 下单录入时间：
第 5 行   操作时间：   | 总价：         | 交货日期：
第 6 行   付款方式：   | 电话：         | 采购单号：
第 7 行   交期条款：<值>                                   ← 整行（长句塞两列会被挤成一条线）
第 9 行   明细表头（9 列，列序不变）
第 10 行起 明细数据 → 小计（只对含税总价 SUM）→ 备注（3 行）→ 交易条款（4 条）→ 表尾三格
```

- 表头网格 = 用户点名的 12 项（交货地址与交期条款各占整行），**外加原模板就有的电话与采购单号**：
  采购单号是厂商对账的唯一抓手，不能因为清单里没写就不印；
- 总价 = 单头 `total_amount`（= 明细金额之和），写成**数字格 + `0.00##`**，能直接参与计算；
- 交货日期 = 单头 `expected_date`（明细行另有逐行的交货日期，两处都在）；
- 表尾三格改名为业务用语（**厂家回签意见 / 厂家回签 / 主管签字**）并加高到 **4 行**（「提供大格子」）；
- 三格内容**不回填打印**（用户选定）：回签文本存在系统里供追溯，纸面留空给现场手写 ——
  代码里写明「不是漏了，是口径如此」，要改成回填只需接一行。

### 4. 界面入口

采购单列表每行新增两个按钮（任何状态都有）：

- **打印信息** → 弹窗填付款方式（下拉：月结30天 / 月结60天 / 当月付款 /（不填））、交货日期、
  交期条款、交货地址、厂家回签意见、厂家回签、主管签字、备注 → PATCH `print-fields`；
  初值直接取列表行（列表返回整行），不再多打一次详情接口。
  失败**抛回给 ActionDialog**（保持弹窗打开 + 显示原因，用户填的几行字不丢）——
  注意不能写 `void savePrintInfo(...)`，那会把异常吞掉、弹窗照关；
- **导出** → `GET /procurement/reports/purchase-order.xlsx?purchase_order_id=…`，
  文件名 `采购订单-<采购单号>.xlsx`。**这就是此前缺失的那个入口**。

付款方式的「清空」靠哨兵值（Radix Select 不接受空串），转换逻辑抽到
`lib/purchase-order-print.ts`（`paymentTermOptions` / `paymentTermValue` / `paymentTermPayload` /
`printFieldsDefaults` / `printFieldsPayload`）并用 lib 测试逐条推演边界：
空串在服务端表示「清除」，而 `undefined` 表示「这一格不要动」——两者写反了就会出现
「我删空了却没保存上」或「我只改了付款方式，交货地址被清掉了」。

## 三、刻意不做的事

- **不新增可填的「采购人 / 操作人」**（用户选择保持自动：创建人 / 最后修改人）；
- **不回填打印回签三格**（用户选择：纸面留空手写）；
- **不做付款方式的枚举校验与字典**（存文本 + 前端三项）：以后加值不用改后端；
- **不改明细列序**（保留 9 列，原模板 7 列顺序不变）；
- **不改既有 `PATCH :id` 的草稿门禁**：整体编辑（明细/金额/供应商）仍然只允许草稿；
- **不做导出历史的留档**（导了哪几张、谁导的没有单独记录；导出本身是只读，不进审计）。
