# D7 生产进度、生产计量与订单推进状态链路实施设计

> 文档类型：跨模块纵向链路开发设计文档
>
> 链路：生产单/工序日报/外加工交接 -> 生产计量 -> 生产进度 -> 订单推进状态
>
> 对应路线图：D7；依赖 D1-D6、A1-A3、A6
>
> 状态：待开发

## 1. 问题说明

D1-D5 已建立生产单、生产单工序、厂内工序日报、员工日报及超单/差异告警；D6 已建立外加工原料直发、签收、成品回厂和直装柜交接事实。当前这些事实分散在各模块中，操作员仍需打开多个页面才能回答：某个订单每道工序完成多少、还差多少、是否超单、外加工交接到哪一步、订单是否可以进入成品 QC 或发货。

D7 不再创建第二套产量事实。它将已有业务事实按 `order_no`、生产单、工序和日期统一计量，并计算生产单和销售订单的推进状态。所有汇总必须可由来源事实重算，避免手工修改汇总后与日报、库存或外加工交接脱节。

## 2. 目标与边界

### 2.1 本批目标

- 统一查询厂内生产和外加工生产单的计划数量、有效完成数量、差额、超单量和完成率。
- 汇总工序级、生产单级和订单级生产计量，支持按日期、工序、执行方式和状态筛选。
- 将 D5 工序日报和 D6 外加工成品回厂/直装柜事实纳入订单推进视图，但不伪造外加工现场工序进度。
- 计算订单推进状态，显示当前阻塞原因和下一可执行环节。
- 生产日报或外加工交接更正后，汇总和状态自动更新并保留审计；不静默改写原始事实。
- 提供订单全链路可读工作台所需的稳定 API 数据结构。

### 2.2 不在本批范围

- 外加工现场工序日报、员工报工、加工费或外加工进度录入。
- 新建第二套工序日报/生产事实表；D5 仍是厂内产量录入入口。
- 成品 QC、成品入库、成品出库、应收收款的领域实现；D7 只输出其上游状态和待办原因。
- 自动排产、产能预测、移动端、离线操作、消息推送和审批流。
- 改变订单目标数量、生产单工序目标数量或历史计价快照。

## 3. 业务流程

```text
销售单（order_no）
    |
    +--> 一个或多个生产单
            |
            +--> 厂内工序目标
            |       +--> D5 工序日报/员工日报
            |       +--> 工序计量、完成率、超单/差异告警
            |
            +--> 外加工交接
                    +--> D6 签收/成品回厂/直装柜

来源事实变更
    -> 同事务重算生产计量
    -> 重算生产单进度
    -> 重算订单推进状态
    -> 记录状态变化与待处理原因
```

外加工过程本身显示为“交接状态未知/待回厂或直装柜”，不显示未经 ERP 记录的工序完成量。外加工成品回厂和直装柜数量可以作为订单级交付计量，但必须标注来源类型。

## 4. 领域对象与数据口径

### 4.1 生产计量行

生产计量是由来源事实计算出的统一读模型，不是操作员直接录入的业务事实。

| 字段 | 说明 |
| --- | --- |
| `id` | UUID 主键 |
| `order_id` / `order_no` | 订单身份，服务端回填 |
| `production_order_id` / `production_order_no` | 生产单身份 |
| `production_order_operation_id` | 厂内工序；外加工交接计量可为空 |
| `source_type` | `operation_report`、`outsource_finished_goods_return`、`outsource_direct_shipment` |
| `source_id` | 来源事实 ID |
| `measurement_date` | 来源业务日期 |
| `planned_quantity` | 工序或生产单目标数量，十进制字符串 |
| `actual_quantity` | 有效来源事实累计数量，十进制字符串 |
| `unit` | 来源单位快照 |
| `execution_mode` | `in_house` 或 `outsourced` |
| `status` | `not_started`、`in_progress`、`completed`、`over_order`、`not_applicable` |
| `warning_codes` | 当前告警代码数组 |
| `calculated_at` | 最近计算时间 |

计量行可以按来源实时计算，也可以由服务端维护可重建的汇总表。无论采用哪种实现，来源事实是唯一真相；汇总表损坏时必须可以全量重建。

### 4.2 生产单进度

生产单进度按有效、未取消的生产单工序汇总：

```text
计划总量 = 有效生产单工序目标数量之和
完成总量 = 各工序有效工序日报完成量之和
差额 = 计划总量 - 完成总量
超单量 = max(完成总量 - 计划总量, 0)
完成率 = 完成总量 / 计划总量（计划为 0 时返回 null）
```

工序是否完成、超单及日报差异继续遵循 D5 规则。D7 只汇总，不改变 D5 告警状态。工序被取消后不再计入计划和完成总量，但其历史计量仍可通过审计和来源查询查看。

### 4.3 订单进度

订单可关联多个生产单。订单级生产计量合并同一 `order_no` 下的有效生产单，不将不同产品或不同单位强行相加；当单位不一致时按生产单/工序分组返回，订单总量字段返回 `null` 并附 `mixed_units` 警告。

订单生产推进状态使用以下状态机：

```text
not_started -> in_production -> production_completed
      |              |                  |
      +--------------> blocked <----------+
                       |
                       v
                 ready_for_qc
                       |
                       v
                  ready_to_ship
```

状态为计算结果，不允许操作员直接编辑：

- `not_started`：没有有效生产单开始事实。
- `in_production`：存在未完成生产单，或已有工序完成量但尚未满足生产完成条件。
- `production_completed`：所有未取消生产单工序达到目标或被允许以超单完成，且不存在待处理的生产阻塞告警。
- `blocked`：存在未处理的日报差异、数量/单位异常、外加工交接短收或必要来源缺失。
- `ready_for_qc`：生产完成，存在待成品 QC 的成品回厂/厂内完工来源；不代表 QC 已通过。
- `ready_to_ship`：后续成品 QC/入库链路已明确可出库来源；D7 只允许读取该状态，不创建成品出库。

在 E1-E5 尚未实现时，`ready_for_qc` 和 `ready_to_ship` 只返回可计算的前置条件和 `capability_not_implemented` 标记，不得误报为已完成。

### 4.4 订单状态阻塞原因

阻塞原因使用稳定代码并携带数量/来源上下文：

- `daily_discrepancy`：工序日报与员工日报件数不一致。
- `over_order_unconfirmed`：超单告警仍待处理。
- `missing_operation_report`：厂内生产单有目标但没有有效工序日报。
- `outsource_pending_handoff`：外加工生产单尚无成品回厂或直装柜事实。
- `outsource_short_receipt`：外加工签收短收或差异未处理。
- `mixed_units`：订单下计量单位不一致，不能形成总数量。
- `source_reversal_pending`：来源被冲销但下游状态尚未完成更正。

阻塞原因必须指出关联订单、生产单、工序、来源和可执行建议；前端不得通过字符串猜测状态。

## 5. 联动与更正

- D5 有效工序日报新增、编辑、逻辑删除、恢复或告警确认后，D7 在同一业务事务内重算受影响的生产单和订单摘要。
- D6 成品回厂或直装柜事实新增、编辑、冲销后，D7 更新对应订单的交付计量和外加工推进状态；不增加厂内库存。
- 生产单、工序目标、来源单位或 `order_no` 关联发生修改时，服务端先返回影响预览；已产生事实的记录不得原位覆盖，必须通过版本/更正机制处理。
- 并发写入使用版本号或条件更新；读模型重算失败时原始业务事务整体回滚，不留下旧状态和新事实不一致的情况。
- 状态变化写入审计事件，记录前状态、后状态、触发来源、计算时间和操作人；定时重算由系统账号执行时保留触发请求 ID。

## 6. API 与权限

统一复用 `/api/v1`、JSON 信封、`snake_case`、请求 ID、稳定错误码和十进制字符串契约。建议资源：

- `GET /production/orders/:id/progress`
- `GET /production/orders/:id/measurements`
- `GET /production-orders/:id/progress`
- `GET /production-progress/measurements`
- `GET /production-progress/order-statuses`
- `GET /production-progress/order-statuses/:order_no/timeline`
- `POST /production-progress/rebuild`（管理员/维护脚本，支持按订单或日期范围）
- `GET /production-progress/:id/audit-events`

所有订单接口必须返回 `order_no`、销售单号、生产单号、执行方式、计划/完成/差额/超单、完成率、单位分组、状态、阻塞原因和来源摘要。分页、筛选和排序由服务端完成；前端不拼接跨模块数据。

管理员拥有完整读取和重建权限；物控/生产操作员可读取生产进度和订单状态；财务/人事可读取计量及生产薪资来源；销售可读取订单推进状态；普通角色不能手工写入计量或状态。生产日报、外加工交接的写权限继续由 D5/D6 权限控制。

## 7. 前端工作台

- 订单列表展示 `order_no`、客户、生产单数、当前状态、完成率、阻塞数量和最近更新时间。
- 订单详情按“生产单 -> 工序/外加工交接 -> 计量 -> 告警/阻塞”展开，支持按来源和日期筛选。
- 生产单详情显示目标、累计完成、差额、超单量、完成率及各工序状态；单位不一致时分组展示并提示。
- 状态徽标和阻塞原因使用服务端代码映射；超单允许继续累计但显示高风险样式。
- 所有修改入口跳转到 D5/D6 原始事实页面；D7 页面不提供直接编辑汇总数据的表单。
- 提供来源详情、审计时间线和重算结果时间；重算失败展示请求 ID 和可执行建议。

## 8. 测试与交付门槛

至少覆盖：

1. 一个生产单多工序的计划、完成、差额、超单和完成率计算。
2. 多个生产单共享同一 `order_no` 时按单位正确聚合，单位混合不错误相加。
3. D5 日报更正/删除后生产单和订单摘要即时重算，D5 告警保持一致。
4. D6 成品回厂、直装柜、冲销分别产生正确来源计量，且不改变厂内库存。
5. 待处理差异、短收和来源冲销正确形成阻塞原因；告警恢复后订单状态自动推进。
6. E1-E5 未实现时不误报 `ready_for_qc`/`ready_to_ship` 为已完成。
7. 未登录 401、越权 403、错误订单/生产单 404、并发重算 409、非法筛选 422 符合全局契约。
8. 真实 PostgreSQL 事务、HTTP API、D1-D6 回归和 Playwright 订单工作台验收通过。

交付必须包含迁移/生成、API/Web 构建、单元测试、集成测试、浏览器测试和重算脚本证据；任何汇总表均需提供按订单/日期范围重建并与来源抽样核对的结果。
