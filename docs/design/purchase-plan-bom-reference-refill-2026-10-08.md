# 已有采购计划拿不到 BOM 参考单价：根因与修法（2026-10-08 第二轮·第 1 件的补）

## 一、用户报的症状

> 「为什么BOM表保存了单价之后，采购计划显示不了单价，下单不了」

## 二、根因：**预填只发生在「新建采购计划那一刻」**

`POST /purchase-plans` 建计划时，`itemsFromBom()` 把 BOM 行的参考单价写进计划行（`purchase-plans.service.ts:795`）。
但那之后**再也不会回头读 BOM** —— 计划的明细是**建立时的快照**（口径 12：BOM 后来新增物料也只在页面上提示、
不自动插行）。于是：

```
先建计划（BOM 上海没价）→ 计划行单价 0
        ↓
去 BOM 表填「参考单价」→ 只改了 BOM，计划行还是 0
        ↓
打开计划：单价 0 → 「第 N 行还没填单价，不能下单」
```

用户感受到的就是"我明明填了价" —— 他填在 BOM 上，而系统只认计划行里的那一格。
（顺带说清另一件可能被误判的事：**下单还要求每行有供应商**（一个供应商一张单）。若单价明明是 > 0 仍下不了单，
看报错文案是哪一句就能分辨 —— 本轮把 0 价那一句补上了出路说明，见 §三.3。）

## 三、修法：把「当前 BOM 的参考单价」随计划详情下发，前端对**空的**格子预填

### 1. 取数侧（`GET /purchase-plans/:id`）

同一次 `bomItem.findMany`（原本只为算"BOM 比计划多几个物料"）顺带把 `referenceUnitPrice` / `referenceCurrency`
读回来，**按物料**匹配后挂在每一行上（`bomReferenceUnitPrice` / `bomReferenceCurrency`）：

- 按**物料**匹配，不按 BOM 行 ID：`BomsService.replaceItems` 存一次 BOM 就把全部行 ID 换掉（既有口径）；
- 参考价为空或 0 → 给 `null`（0 与"没填"在这里同解：0 价不能下单）；
- 币种没填时兜底人民币（与计划行同一套默认值）；
- **BOM 已软删时不下发**（那份 BOM 已经不是当前事实，计划上本来就有"这张 BOM 已被删除"的告警条）。

### 2. 界面侧（`plan-detail-sheet.tsx`）

`load()` 里对同时满足**三条**的行预填：**未下单** + **单价还是 0** + **BOM 上有 > 0 的参考价**。
预填只写进**界面状态**：

- 币种跟着这一格里的价走（预填的可能是美元价，留着人民币会让"计划合计按币种分列"说谎）；
- 那一格加浅黄底（`.plan-price-from-bom`）+ `title` 写明来源与"还没保存"；
- 面板上一句说明：几行、来源是 BOM 参考单价、**保存计划后才会写进计划**、逐行都能改；
- 用户一改那一格，标记就消失（这一格从此是他填的）；
- **点「保存计划」才落库** —— 计划行单价仍是唯一真源，下单与应付都只认它。

### 3. 被拦时的出路写进提示

0 价拦住下单时报文补上：可以在 BOM 表给这些物料填「参考单价」后重新打开本计划（会自动带过来），
或直接在这一格里手填。原来只说"不能下单"，用户不知道该去哪儿填 —— 这正是他这次的困惑。

### 4. 为什么这不算"系统猜价格"

上一轮定的口径是"不猜价格"（不拿上次成交价替采购员定价）。这次预填的是**采购员自己填在 BOM 上**的
参考单价，而且：只填空的格子、谈过价的行一律不动、界面上标出来源、不点保存不落库。
所以它是"把用户已经录过的值送到他正在用的那一格"，不是替他定价。

## 四、边界（都被测试钉住）

| 情形 | 行为 |
|---|---|
| 未下单 + 单价 0 + BOM 有参考价 | 预填那一格（浅黄底 + 面板说明），保存后生效 |
| 单价已经 > 0（谈过价） | **不覆盖**，也不出现标记 |
| 已下单的行 | **不预填**（服务端把那些行硬锁，预填等于制造一次注定被拒的保存） |
| BOM 上没填价 / 填了 0 | 不预填、不出说明；0 价下单仍被拦，提示给出出路 |
| 物料不在 BOM 上（补料/替代料） | 没有参考价，不下发 |
| BOM 已软删 | 不下发（页面本来就有"BOM 已被删除"的告警） |

## 五、没做 / 待确认

- **计划列表的「计划金额」列不会因此变化**：那一列显示的是**库里已存**的价（保存计划后才更新）。
  列表要显示"按 BOM 参考价预估"的钱，得再定一个口径（已存 vs 预估混在一起最容易读错），本轮不做。
- **供应商不做同样的回填**：BOM 行上的默认供应商也只在建计划时预填，之后 BOM 改了同样不会进已有计划。
  与单价不同，供应商那一格本来就在计划里、且是"这张单发给谁"的事实，回填它会改变下单对象 ——
  要改必须先定规则（是否只在为空时回填、要不要提示）。本轮不动。
- **没有改成"计划实时跟着 BOM"**：数量/物料/供应商仍是快照（口径 12 不动）。单价之所以能回填，
  是因为它是**参考值**、且只填空格；这是刻意的例外，不是把快照改成视图。
