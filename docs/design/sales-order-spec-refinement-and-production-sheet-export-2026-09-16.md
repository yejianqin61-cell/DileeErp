# 销售单下单口径细化 + 工艺单导出（2026-09-16）

> 用户原话：「针对销售模块，在新建销售单的时候，要细化口径。产品规格这边要更细化成伞头伞布等等一些更细化的口径。
> `example/销售单/DL260134 JBN生产单(1).xls` 你先看看这个销售单模板，我们按照这个模板来进行设计字段和设计可导出的excel。
> 其中的图片格，我们不做导出，留空。」
>
> 模板样本：`example/销售单/DL260134 JBN生产单(1).xls`（A–J 表）与
> `example/销售单/DL260001-1 花色生产单-IS(FLOWER1 PO#32366-1).xlsx`（A–K 表）。
> 用户已拍板：**① 材料/工艺做成固定字段（两样本并集）② 明细表做成「一张通用表 + 分组名」
> ③ 导出两张合一、空盘位自动省略 ④ 新建销售单改成整页编辑器 ⑤ 材料到货状态不做**。

---

## 一、模板读到了什么

这不是销售单本身，是**随单下给工厂的工艺单**。骨架（两张样本一致）：

```
表头      公司抬头 / 工厂 / 客户单号 / 客户代码 / 下单日期 / 数量 / 品名规格 / 地区 / 完工日期 / 注意事项
正文左列  材料 × 明细（一组「材料名 → 明细文本」）
正文右列  工艺要求（编号条目）
嵌入式    明细表（花色 / 伞头配色）  ← 形态随产品变，见下
下部      正唛 / 侧唛 / 布量
表尾      制单 / 审核 签字栏
图片格    花色「图片」列、【相关图片】大格、伞头图片列
```

**两张样本的差异（决定了字段必须是「并集」而不是照抄一张）**：

| | 样本1 `DL260134 JBN` | 样本2 `DL260001-1 FLOWER1` |
| --- | --- | --- |
| 材料行 | 伞骨(孔对孔)、伞布规格、伞头、**伞头带**、伞尾笠、伞束珠、伞带、**伞带粘扣**、内标、**织标**、吊牌、OPP、布套、包装明细 | 伞骨、伞布、伞头、伞尾笠、伞束珠、伞带、内标、吊牌、**钥匙扣**、OPP、布套、**印刷**、**天布**、**木耳** |
| 明细表 | **伞布明细**：品番/品名 + 颜色 + 数量，12 款，**两栏并排** | **伞头配色表**：伞头英文名 + 配色 + 条码 + 数量/打，15 行；另有「外层花色 × 内层配色」6 组 |
| 工艺条目 | 大货样 / 拉边 / 小裁 / 合片 / 打顶 / 缝伞 / 吊牌位置 | 产前样 / 大裁开布 / 伞带 / 打顶 / 缝伞 / 吊牌图稿 / 质检报告 |
| 布量 | 伞面、伞带、木耳、天布、布套（Y/DZ） | 无此区 |
| 图片格 | 花色图片列 C11:D16、【相关图片】G24:J34 | 花色/伞头图片区 G24:J34、伞头图片 A41:D56 |

**核出一条可自检的业务规则**：明细数量合计 = 单头数量。
样本1：100+200+200+100+120+120+200+200+120+200+200+200 = **1960** = 表头 `1960支`；
样本2：15 款伞头 × `167打` = **2505打** = 表头 `2505打`。两张单都成立。

### 2.5 细分明细子表 `sales_order_spec_details`

一张通用表，用**分组名**区分样本1 的「伞布明细」与样本2 的「伞头配色」/「外层花色搭配」：

| 字段 | 说明 |
| --- | --- |
| `groupName` | 分组名：伞布明细 / 伞头配色 / 外层花色搭配 … |
| `name` | 品番/品名（样本1「27621 流水花扇PKGY」）或伞头英文名（样本2「Hawái」） |
| `color` | 颜色 / 配色 / 内层颜色（样本1「PKGY」；样本2「配色按图片」） |
| `barcode` | 条码（样本2 的「内标、吊牌、纸箱：条形码」列） |
| `quantity` | 数量（样本1「100pcs」、样本2「167打」） |
| `unit` | 单位（pcs / 打） |
| `sortOrder` | 排序（导出按它落格） |

**不做**：图片列与「相关图片」大格（用户明确：不导出、留空）；材料到货状态清单（用户明确不做）。

### 2.6 与现有字段的关系

- `productSpec`（现有自由文本）**保留不动**：它是「品名规格」那一行（模板 R3「50cm*5K 三折手开碳纤维伞」），
  与新的细分字段是**并存**关系，不做数据迁移（老单没有细分字段，导出留空）。
- 制单 / 审核签字栏直接落到系统已有的「创建人 / 最后修改人」，不新增手填字段
  （上一轮的全站治理已经把这套做完了）。

## 三、写入与版本

- **不进 `coreFields`**：`coreFields` 是「有 BOM/采购/生产下游就被锁死」的商业条款字段
  （产品名称/规格/数量/单位/币种/单价/金额/税率/结算*）。细化字段是工厂的技术说明，
  与上一轮采购单「打印信息」同一性质：**已确认的单子仍可填，但要填修改原因**
  （`update` 对已确认单已经强制 `reason`）。改成「一改就锁」会让下单后补填包装说明变得不可能。
- **子表替换语义**：与采购单明细一致——老行 `updateMany({ deletedAt })` 软删 + `createMany` 新行，
  同一个事务。传了 `spec_details` 就整体替换，没传就不动。
- **版本快照**：`SalesOrderVersion.snapshot` 是 JSON，会把新增的标量字段纳入；
  `spec_details` 在传了的时候一并进快照，便于回看「当时下给工厂的是什么」。

## 四、导出（两张合一）

`POST/GET /sales-orders/:id/production-sheet.xlsx`：
- 版式按模板落位；**空盘位自动省略**——例如没有伞头配色表就不留那块空白区，
  布量整块为空就不印（样本2 就没有布量区）。
- 材料行按「两样本并集的固定顺序」印，值为空的**不印该行**（老单导出只剩表头也不会难看）。
- 工艺要求按编号条目印，值为空的跳过但**编号连续重排**（否则会出现「1、2、5、7」）。
- 明细表：行数不定，按 `sortOrder` 顺序；列数多于一屏时按样本1 的做法**两栏并排**。
- **图片格一律留空**（花色图片列、【相关图片】格、伞头图片列），单元格保留位置与边框。
- 表尾：制单人 / 制单时间（北京时间，复用 `makerStamp`）+ 明细数量合计与单头数量的核对提示。

## 五、验收标准

1. 新建销售单是**整页编辑器**，能填全部细化字段并增删明细行；
2. 导出与模板逐格对得上（列位置、合并单元格、区块顺序），空值不产出空盘位；
3. **任何单元格都不出现 UUID**（沿用上一轮的口径，制单人写姓名）；
4. 明细数量合计 ≠ 单头数量时**给出提示但不拦截**（单位可能是支/pcs 也可能是打）；
5. 老销售单（没有细化字段）导出不报错、不印空区块。
