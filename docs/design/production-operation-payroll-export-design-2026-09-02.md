# 生产工序盘点表导出开发设计

状态：ready-for-agent  
版本：2026-09-02  
适用模块：生产、财务报表

## Problem Statement

当前系统可以登记工序员工日报，但缺少面向管理人员的 Excel 盘点导出。管理人员需要按“工序”或“订单号”核对某一期间内员工的计薪事实、工作量和薪酬，现有日报页面按单据和日期查看，无法快速形成月度工序盘点，也无法在一个订单内聚合指定工序的全部员工记录。

## Solution

新增“生产工序盘点表”导出能力，提供两种互斥的报表形态：

1. **工序盘点表**：选择一个工序和月份，汇总该月份内该工序（不区分订单号）的所有有效工序员工日报。
2. **订单号盘点表**：选择一个订单号，可选工序；按订单号限定范围，导出所选工序的全部员工日报。未选择工序时导出该订单号下全部工序。

两种导出均输出真实 `.xlsx` 文件，文件首部包含表头说明，正文逐行展示员工的计薪事实，不修改日报、工资来源或工资台账。

## User Stories

1. 作为财务人员，我想选择一个工序和月份，以便盘点该工序当月所有订单的人工成本。
2. 作为车间主管，我想查看某工序当月所有员工，以便比较员工工作量和薪酬。
3. 作为财务人员，我想在工序盘点表中看到员工姓名、工号和所属部门，以便核对人员身份。
4. 作为财务人员，我想看到每行的计薪方式，以便区分计件和计时记录。
5. 作为财务人员，我想在计件记录中看到件数，在计时记录中看到时长，以便核对计薪依据。
6. 作为财务人员，我想看到单价和总薪酬，以便复核工资来源金额。
7. 作为财务人员，我想按订单号盘点，以便核对单笔订单的人工成本。
8. 作为车间主管，我想在订单号盘点中先选择工序，以便只查看订单内某个工序的员工记录。
9. 作为车间主管，我想不选择工序时导出订单下全部工序，以便获得完整订单人工明细。
10. 作为使用者，我想在导出文件表头看到报表类型、订单号/工序、月份和生成时间，以便文件脱离系统后仍可解释。
11. 作为使用者，我想只导出有效日报，不包含已逻辑删除或已被更正替代的无效记录，以便报表与当前业务事实一致。
12. 作为使用者，我想在没有符合条件的日报时得到明确的空结果提示，而不是下载一张无法判断范围的空表。
13. 作为使用者，我想导出结果沿用系统当前权限，以便未经授权的人员不能查看员工薪酬。
14. 作为使用者，我想重复相同筛选得到一致的查询快照，除非日报事实本身发生变化。
15. 作为审计人员，我想知道导出发生的时间、操作者和筛选条件，以便追溯敏感薪资数据的使用。
16. 作为系统管理员，我想导出接口限制最大行数，以便避免大文件拖垮 API 或浏览器。
17. 作为使用者，我想导出文件在客户端下载后即可使用，服务器不长期保存导出文件，以便减少敏感数据留存。
18. 作为使用者，我想金额和数量在 Excel 中保持精确小数表现，以便避免二进制浮点误差。

## Implementation Decisions

### 1. 报表形态与筛选

- 在生产模块增加“工序盘点表”和“订单号盘点表”两个入口，可使用 tabs 或分段控件切换。
- 工序盘点必填：工序、月份。月份按自然月解释，查询范围为该月第一天 00:00:00 至最后一天 23:59:59（服务端统一使用 UTC 日期边界策略，与日报查询保持一致）。
- 订单号盘点必填：订单号；工序为可选。工序为空时不增加工序过滤。
- 订单号下拉使用现有订单/生产单事实，展示订单号，不向用户暴露 UUID。若订单号存在多个生产单记录，查询按订单号字段聚合。
- 工序下拉使用现有工序池/生产单工序快照的可用名称；查询应按生产单工序关联 ID 过滤，名称仅用于展示，避免同名工序串错数据。
- 仅统计 `employee_daily_reports.deleted_at IS NULL` 的有效记录；不重新计算或覆盖日报中的 `quantity`、`duration_minutes`、`unit_price`、`calculated_amount`。

### 2. 导出列与表头说明

文件使用 `.xlsx`，工作表名称分别为“工序盘点表”和“订单号盘点表”。前置说明区至少包含：

- 报表名称
- 统计月份（工序盘点）或订单号（订单号盘点）
- 工序筛选（未选择时显示“全部工序”）
- 数据范围说明：仅统计有效工序员工日报；计件展示件数，计时展示时长
- 生成时间
- 操作人

说明区之后空一行，再输出固定列，顺序如下：

1. 订单号
2. 生产单号
3. 工序
4. 工序日期
5. 工号
6. 员工姓名
7. 部门
8. 员工类型
9. 计薪方式
10. 件数
11. 时长（分钟）
12. 单价
13. 总薪酬
14. 备注

“件数”和“时长（分钟）”同时保留原始值；不适用的一列为空。计薪方式使用中文显示“计件”/“计时”，金额和数量以字符串或 Excel 数值格式保持 Decimal 精度，禁止先转 JavaScript `number` 再累计。

### 3. API 契约

统一前缀 `/api/v1`、认证、生产模块权限和 `{ data, meta }` 响应约定。建议接口：

```text
GET /production/reports/operation-payroll.xlsx
GET /production/reports/order-operation-payroll.xlsx
```

工序盘点参数：

```text
operation_id (required, UUID)
month (required, YYYY-MM)
```

订单号盘点参数：

```text
order_no (required, string)
operation_id (optional, UUID)
```

两接口均支持 `download` 形式直接返回文件，不返回服务器文件路径。响应设置正确的 XLSX `Content-Type`、UTF-8 文件名、`Cache-Control: no-store`。服务端设置最大导出行数；超过上限返回稳定错误码并要求缩小月份或订单范围。

### 4. 查询与一致性

- 报表从工序员工日报及其关联员工、生产单、生产单工序实时查询，不维护报表缓存或第二套薪酬汇总事实。
- 关联展示优先使用日报中的快照字段（员工姓名、工序名称、订单号），组织信息使用当前关联数据；历史快照缺失时不得阻断导出，使用空值并在说明中保留“历史主数据可能已停用”的提示策略。
- 不把工序日报（完成数量）混入工序员工日报明细；本报表只盘点员工计薪记录。
- 同一员工同一工序同一天已由日报服务累加为一条有效记录；导出层不得再次去重或合并，避免重复计算。
- 结果按工序日期升序、订单号升序、工序升序、员工工号升序排列，保证可复核。
- 没有结果时仍可返回带说明区和固定列的空表，前端同时展示“暂无符合条件的日报”。

### 5. 前端交互

- 在生产页面增加报表入口，使用现有 `Dialog`/`Sheet`、`Select`、`Input`、`Button`、`DataTable` 等组件，不使用浏览器原生 `alert`、`confirm` 或原生下拉替代组件库。
- 工序盘点表提供月份选择和工序选择；订单号盘点表提供订单号选择和可选工序。
- 导出按钮在请求期间禁用并显示进行中状态；成功后通过浏览器下载 Blob，前端立即释放对象 URL。
- 导出失败显示服务端稳定错误消息；不显示内部堆栈或数据库错误。
- 订单号切换后清空或重新校验工序选项，防止提交不属于该订单的工序组合。
- 报表入口保留加载、空数据、权限不足和网络失败状态。

### 6. 审计与数据安全

- 每次成功或拒绝的导出请求记录必要审计事件：报表类型、筛选条件、操作者、时间、结果行数或拒绝原因。
- 导出文件只在响应流和浏览器内存中存在，不写入附件表、对象存储或服务器持久目录。
- 薪酬列属于敏感业务数据，接口沿用生产/财务模块权限；前端不得通过隐藏按钮代替后端鉴权。

### 7. 测试 Decisions

- 服务层测试覆盖：月份边界、工序过滤、订单号过滤、订单号不选工序时全工序、逻辑删除排除、固定排序、空结果、最大行数限制。
- 导出测试覆盖：说明区存在且字段正确、固定列顺序、中文计薪方式、Decimal 精度、XLSX content type、UTF-8 文件名和 `no-store`。
- 权限测试覆盖未认证、无生产模块权限和有权限用户的差异。
- 审计测试覆盖成功导出和校验失败均记录筛选条件，且不记录或保存原始文件。
- 前端测试覆盖两种 tab 切换、必填校验、订单号联动工序、下载中禁用和错误状态。
- 沿用现有生产日报服务测试、报表导出测试和 Web typecheck/build 作为先例；测试外部行为，不绑定具体 XLSX 库内部实现。

## Out of Scope

- 不新增自动计薪规则、不根据工序标准价重算工资。
- 不修改工序员工日报、工资来源、工资台账或工资支付状态。
- 不做跨月份自定义日期区间；本期工序盘点固定按自然月。
- 不做员工、订单或工序的批量编辑。
- 不导出考勤、绩效、采购、库存、应付等非工序员工日报数据。
- 不保存导出文件历史版本，不提供服务器端再次下载。
- 不改变现有订单号、生产单号、工序等领域术语。

## Further Notes

- “订单号盘点表”中的订单号使用系统统一的 `order_no` 业务编号，不使用数据库 ID，也不改称“销售单号”。
- “总薪酬”直接取工序员工日报的 `calculated_amount`；若未来发生可追溯更正，重新导出即可看到最新有效事实。
- 实施前应确认现有生产页的报表入口位置和管理员/财务角色权限映射；不应为本报表另建一套角色体系。
- 推荐最高测试接缝为报表查询服务：由两个导出控制器参数适配到同一查询/导出核心，减少重复筛选和列映射逻辑。
