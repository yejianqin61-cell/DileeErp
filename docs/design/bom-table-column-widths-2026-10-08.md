# BOM 表：悬浮居中页放大 + 列宽固定 + 物料名称省略（2026-10-08 第四轮）

## 一、用户原话

> 「1.BOM表页面，物料名称一长，后面的column就被压缩很窄。这很不好。我要求，扩大BOM表悬浮居中页面的
> 占页面大小，并且固定物料名称这一列的宽度。一旦字数超出，就省略显示，鼠标hover时显示全部文字。」

三件事一句话说完，**没有歧义，所以这一轮没有先问**（与前几轮"先问后做"的区别就在这里）：
① 放大那个悬浮居中的 BOM 表页面；② 物料名称列宽固定；③ 列内文字超出就省略、hover 看全文。

改动只落在两处：`components/bom/bom-workbench.tsx` 与 `app/globals.css`。
**没有 API 改动、没有迁移、没有数据**——前后端不必同时上线。

## 二、改前实测：这句话对应的数字与机理

三个入口（采购 → BOM表、采购单 → 编辑BOM、生产 → BOM表）渲染的是**同一个组件**
(`BomWorkbench`)，所以症状在三处一样。

用真实 Chromium 加载 `app/globals.css` + 这张表的真实 DOM（1920 视口，含供应商列，
物料名从「M-001 / 面料A」换成 46 字的「M-001 / 超细纤维防风防水涂层复合单面摇粒绒面料（加厚款 320g）」）：

| 列 | 改前（短名） | 改前（长名） | 改后（两者相同） |
|---|---|---|---|
| 物料名称 | 154px | **487px**（+333） | 451px |
| 型号 | 179px | **92px**（−87） | 198px |
| 规格型号 | 184px | **110px**（−74） | 216px |
| 颜色 | 179px | **92px**（−87） | 162px |
| 数量 | 179px | **92px**（−87） | 144px |
| 单位 | 79px | 79px | 162px |
| 供应商 | 170px | 170px | 307px |
| 序号 | 52px | 52px | 72px |
| 操作 | 66px | 66px | 90px |

这就是用户说的「被压缩很窄」：一根长名字把四列各自吃掉 74~87px 交给物料名称列。
1366 视口更糟：整张表被顶到 1086px，而悬浮页只给得出 1055px，于是底下出现横向滚动条（33px）。

**机理**（为什么"固定宽度"必须靠 `table-layout: fixed`）：
表格是默认的自动布局，列宽按各列 **min-content** 分配；而 `.data-table` 上写着
`white-space: nowrap`，于是「长物料名」这一列的 min-content = 整串文本的宽度。
CSS 的 `width` 在自动布局里只是**建议值**——内容更宽时它会被推翻。所以"给这一列写个宽度"在自动布局下
不成立，只有固定布局（`table-layout: fixed`，列宽由第一行的 width 决定、与内容无关）才成立。

## 三、方案

### 1. 悬浮居中页放大（`globals.css`）

居中摆位来自 `.ui-sheet-right` 的 `min(80vw, 1280px)`（(0,1,0)）。新增
`.ui-sheet-content.bom-workbench { width: min(96vw, 1880px, calc(100vw - 24px)); max-height: calc(100vh - 24px); }`。

- 选择器写成 **(0,2,0)** 而不是 `.bom-workbench`：同样权重时就变成"赌我的规则排在后面"。
  这个文件里已经因为这种赌法静默失效过一次（`.cell-ellipsis` 的注释），守卫里也钉了这一条。
- `min()` 的**第三个参数是给窄屏的**：375px 屏上 96vw 比 `100vw - 24px` 还宽 9px，会把居中页顶出屏幕；
  而 `@media (max-width: 720px)` 那条只有 (0,1,0)，压不过这条 (0,2,0)。
- 实测悬浮页宽（改前 → 改后）：**1024 屏 819 → 983、1366 屏 1093 → 1311、1440 屏 1152 → 1382、
  1600 屏 1280 → 1536、1920 屏 1280 → 1843**（+164 / +218 / +230 / +256 / +563）。
  1600 与 1920 原来都是 1280，是因为上限卡在 1280px ——所以"放大"在大屏上才最明显。

### 2. 九列固定布局 + 显式百分比列宽

`.bom-table { table-layout: fixed; min-width: 1180px; }` + 九列各一条 `width`：

| 序号 | 物料名称 | 型号 | 规格型号 | 颜色 | 数量 | 单位 | 供应商 | 操作 |
|---|---|---|---|---|---|---|---|---|
| 4% | **25%** | 11% | 12% | 9% | 8% | 9% | 17% | 5% |

总和正好 100%（守卫见 `apps/web/lib/bom-table.test.mjs`）：固定布局下这九条 width 就是九个列宽，
浏览器**不必再替任何一列"猜"宽度**——而"猜"正是长名字挤别人的入口。
单元格内边距 14px → 10px：固定布局下列宽不再随内容变，省下的 8px 是每列实打实的可用宽度。

### 3. 物料名称列省略 + hover 全文

- 省略：`.bom-table .bom-col-material .ui-select-trigger { min-width: 0 }` +
  `> span { display:block; min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap }`。
  **`min-width: 0` 不能省**：`.ui-select-trigger` 是 flex 容器，里面的 Radix `SelectValue` 那个 `<span>`
  默认最小宽度是 min-content，只写 overflow/text-overflow 它照样把列撑开（同一条规则在
  `.purchase-workspace`、`.purchase-plan-sheet` 上已经用过两次）。
- hover：每行物料下拉的 `SelectTrigger` 带 `title={materialLabelOf(row.materialId)}`，
  文案取 `materialOptions` 里那一项的 label —— **与触发器里显示的是同一份字符串**
  （「编码 / 名称」），不会出现"hover 出来的是另一份文案"。
- 实测省略确实发生且长名字在最大屏也放不下：1366 视口触发器文字框 266px（文本 422px）、
  1600 视口 321/422、1920 视口 395/422 —— 短名字 89px 完全放得下、不触发省略。

## 四、两处取舍（都会被问到）

1. **列宽全用百分比，一个 px 都不用。** 生产侧不显示供应商列（`showSupplier={false}`，少 17%），
   实测**混用 px** 时浏览器会把多出来的宽度整块塞给 px 那两列：1920 屏序号 48→**208px**、操作 56→**243px**，
   两个畸形列；全百分比则按比例摊给每一列（1920 屏物料名称 451→543、序号 72→87），两种模式都不会
   出现一根撑得莫名其妙的列。首次实测就是这么翻车的，所以把它写进了守卫的注释里。
2. **`min-width: 1180px` 意味着窄屏宁可横向滚动。** 因为列宽是百分比，窄屏上"不横滑"只能靠把每列压到
   放不下内容——那正是用户投诉的东西。滚动只出现在视口 ≤ ~1240px 时（1024 视口 237px，且这个滚动条
   本来就归 `.table-wrap`，改前长名字同样会拖出 307px）。1280 屏及以上实测横向溢出 0px。

## 五、刻意不做 / 已知相邻缺口

- **不省略型号 / 规格型号 / 颜色三列**：它们是可编辑的 `<input>`，值长了可以在框内左右看、点进去就能改，
  截断反而妨碍编辑；用户点名要省略的只有「物料名称」这一列（那是触发器文字，不可编辑）。
- **不改「物料不在池里时那一格看起来是空的」**（相邻缺口，本轮不碰）：BOM 行引用的物料被停用/软删后
  不在 `GET /materials` 里，Radix 的 `SelectValue` 找不到对应项就退回占位符「请选择物料」。
  采购计划那边为此专门补过"把这一行自己的值当成一个 disabled 选项加进列表"
  （[purchase-plan-readability-and-ref-wrap-2026-09-30.md](purchase-plan-readability-and-ref-wrap-2026-09-30.md) §二.1）。
  BOM 这边没有照做，理由有两条：① 保存时 `boms.service.ts` 本就要求 `material.isActive === true`，
  这样的行**根本存不下去**，那一格看起来是空的并不掩盖一份能存的值；② 补成一个 disabled 选项属于
  "这一格显示什么"的独立决定，要连同"选了别的行会怎样"一起定，不该搭在本轮的列宽改动里。
  要做的话是十行上下的事，随时可做。
- **没有做列宽拖拽 / 列宽记忆**：用户要的是"固定"，不是"能自己调"。
