# 迪礼 ERP V1.0 采购模块初步设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：访谈中。本文只记录已确认事实；待确认规则收录于 [采购模块集中待确认事项](../memo/0820-采购模块集中待确认事项.md)。

## 1. 设计目标

采购模块以 `order_no` 为跨模块追溯主线，承接销售单和物控 BOM 表的采购需求，记录采购单、原料分批到货及其向仓库原料入库、财务应付的数据流转。采购单号由系统生成，但不能替代订单号的追溯作用。

V1.0 设计原则：

- 订单号是采购记录的业务身份证；采购单、到货、原料入库关联和应付来源均须可追溯至 `order_no`。
- 销售单和 BOM 表是采购业务上游；采购文员据此编制采购单并核算采购成本。
- 仓库原料入库是采购到货完成的下游业务事实；同一采购单及同一采购明细允许分批到货、分批入库。
- 财务应付以原料实际入库数量为报送依据，而不是仅以采购下单数量为依据。
- 采购单号由系统生成；编号规则作为平台编号规范的采购单据实例落实。
- 不在本模块复制销售单主数据；通过内部 ID 关联，并冗余保留 `order_no` 用于查询和展示。
- 所有业务表统一保留 `created_at`、`updated_at`、`created_by`、`updated_by`；业务操作须保留操作人、操作时间、备注和前后值审计。禁止物理删除。
- 采购业务遵循“提供后悔药”原则：允许在规则范围内更正，但编辑前必须展示与销售单、BOM、入库和应付相关的影响与风险；确认后联动重算可派生数据，已确认的下游事实不被静默改写。

## 2. 已确认业务范围

### 2.1 包含

- 以销售单和物控 BOM 表为依据创建采购单。
- 采购单与订单号关联，采购单号由系统生成。
- 采购成本核算。
- 原料采购的分批到货与原料入库衔接。
- 根据原料入库数量向财务报送应付依据。
- 采购物料计量单位的维护与使用。

### 2.2 暂不写死

- 物料主数据、BOM 的具体字段、版本和变更规则。
- 供应商、价格、币种、税额和附加费用规则。
- 采购单状态机、修改、取消和关闭规则。
- 来料质检、不合格品、退货、短到/超到和采购直发规则。
- 应付单的生成时点、合并规则和财务调整边界。
- 采购报表、附件和权限细节。

## 3. 已确认业务链路

```text
销售单（order_no） + 物控 BOM 表
              │
              ▼
采购文员创建采购单（系统生成 purchase_order_no）并核算采购成本
              │
              ▼
供应商分批到货
              │
              ▼
仓库原料入库（记录实际入库数量）
              │
              ▼
向财务报送应付依据
```

采购单、到货记录、原料入库记录和应付来源记录均需保留内部关联 ID 与 `order_no`。一张采购单可存在多笔到货/入库事实，以入库明细累计作为应付报送数量的基础。

## 4. 核心对象（初步）

| 对象 | 业务职责 | 当前已确认关系 |
| --- | --- | --- |
| 销售单 | 采购业务上游，提供订单号与订单要求 | 一个销售单对应一个订单号；具体字段由销售模块定义 |
| BOM 表 | 物控定义的物料需求依据 | 与销售单/订单关联；具体版本规则待确认 |
| 采购单 | 采购文员向供应商采购的业务单据 | 必须关联 `order_no`；系统生成采购单号 |
| 采购单明细 | 单张采购单中的物料、数量、单位、成本信息 | 具体字段待确认 |
| 到货/收货记录 | 记录采购物料的分批到货事实 | 同一采购单明细可多次到货 |
| 原料入库单/入库明细 | 仓库确认的实际原料入库事实 | 是向财务报送应付数量的依据；由仓库模块详设 |
| 应付报送记录 | 向财务表达某笔入库对应的应付来源 | 具体生成和汇总规则由采购/财务共同确认 |
| 单位池 | 采购物料及相关数量字段的计量单位基础资料 | 初始单位为打、码、个、包、捆；允许用户增删改查 |

## 5. 初步数据边界

以下仅用于明确对象边界，不构成最终数据库表设计；字段、约束和状态机待集中确认后再补充。

| 对象 | 最低需要追溯的信息 |
| --- | --- |
| 采购单 | `order_id`、`order_no`、`purchase_order_no`、来源销售单/BOM、采购文员、状态、备注 |
| 采购单明细 | 采购单、物料、采购数量、单位、成本/单价快照 |
| 到货记录 | 采购单明细、到货日期、到货数量、单位、关联入库状态 |
| 原料入库关联 | 原料入库明细、采购单明细、订单号、实际入库数量 |
| 应付报送记录 | 原料入库明细、订单号、供应商、应付数量/金额、报送状态、财务接收信息 |
| 单位池 | 单位名称、启用状态、备注及统一审计字段 |

## 6. 跨模块边界

- 销售模块维护销售单及其订单信息；采购模块消费已生效的销售单作为上游依据。
- 物控维护 BOM 表；采购模块读取其物料和需求数据，不在采购单中篡改原始 BOM。
- 仓库模块维护原料入库单及入库明细；采购模块以已确认的实际入库数量形成应付报送依据。
- 财务模块维护应付确认、付款和财务调整；采购模块只提供可追溯的入库来源和采购业务数据。
- 生产模块的外加工直发原料须由采购、仓库和生产三方共同确定库存与应付口径后才能进入开发。

## 7. 待确认后再进入开发设计的关键项

采购单与订单/BOM 的关联粒度、物料池、供应商、采购价格与成本、分批到货/质检/入库、外加工直发、应付生成、异常处理、状态机和报表，详见待确认清单。未确认项目不得提前固化为数据库约束或 API 行为。

## 8. 采购编辑的影响联动原则

采购单、采购明细、BOM 引用、价格、交期、供应商及取消操作的具体可编辑范围，由本模块状态机确认。无论具体规则如何，以下原则固定：

1. 编辑前，系统按 `order_no`、采购单明细和来源关联识别受影响的 BOM 差异、累计入库、应付来源、采购成本和采购单状态。
2. 界面必须在保存确认前展示影响预览，包括变更前后值、受影响的单据/数量/金额、重新计算结果、自动触发的告警和需要人工处理的风险。
3. 确认保存后，采购单的可派生进度、成本汇总、缺口/超收告警和报表数据须同步更新；更新和审计记录必须在同一事务中完成。
4. 已形成的原料入库记录及已报送的应付来源是独立业务事实。采购单数量、价格或 BOM 来源变更不得直接篡改它们；系统应保留原来源、重新计算未入库部分，并产生差异/复核提示。需要修正入库或应付时，由仓库或财务建立对应的退货、冲销或调整记录。
5. 取消采购单或采购明细前，系统必须展示已入库数量、未入库数量、已报送应付、关联附件及未解决异常。存在下游事实时，不得直接逻辑删除，应执行已确认的取消、退货或调整流程。

具体字段级联动、状态限制、警告级别和冲销动作待采购、仓库及财务负责人确认后补充。
