# 迪礼 ERP V1.0 销售模块设计

> 文档类型：业务/领域设计文档，不是开发任务文档。
>
> 状态：V1.0 领域规则已确认。销售单价的具体来源、字段管理界面和模板映射实现方式将在开发设计阶段继续拆解。

## 1. 设计目标与哲学

销售模块维护客户池、销售单、订单级产品要求和销售单导出。销售人员在 ERP 填写销售单，物控以已确认销售单为依据建立订单 BOM；采购、生产、仓库和财务沿 `order_no` 追溯。

`order_no` 由销售人员人工填写，必须唯一，是全流程唯一认可的业务身份证。客户 PO/客户单号、外部合同号均为可选参考字段，不得替代 `order_no`。

模块遵循“灵活为上”原则：销售单的可维护字段、区块、重复明细、必填规则、业务类目和导出模板都支持授权用户增删改。现有 Excel 文件只用于调研基础字段，不是永久模板；后续可完全采用迪礼自有模板。

灵活性不影响跨模块一致性。客户、人工订单号、产品规格、数量、单位、交期、BOM 关联、审计、状态机和历史版本是固定核心约束；任何已使用字段、模板或类目必须保留历史版本/快照，不能因配置变更而篡改历史销售单、BOM 或已导出文件。

V1.0 不包含询盘、报价、打样、英文合同和接单转化。

## 2. 参考模板与可配置导出

调研样本：`example/销售单/DL260001-1 花色生产单-IS(FLOWER1 PO#32366-1).xlsx`。

该样本是单页 `A1:R56` 的纵向打印 Excel，包含客户单号、客户代码、下单日期、数量、品名规格、完工日期、材料明细、工艺要求、包装明细、材料到货状态、制单/审核、花色或伞头配色、条码、每款数量与图片区域；其中总数量使用公式汇总。

这些内容定义了首批可维护字段的参考范围，不锁定模板版式或单元格地址。导出体系应由以下可配置对象组成：

```text
销售单固定核心数据 + 可配置字段/区块/重复明细
                         │
                         ▼
                版本化销售单导出模板
                         │ 字段映射、公式、图片区域、打印设置
                         ▼
                     Excel / 打印 / PDF
```

- 授权用户可新增、修改、启用、停用销售单导出模板及其字段映射；新模板可完全使用迪礼自有版式。
- 表单字段、材料/工艺/包装区块、配色/条码等重复明细均可维护；固定核心字段不可被配置删除。
- 模板版本、表单定义版本和字段映射版本均需保留。每次导出生成独立记录和 `attachment`，关联销售单版本、模板版本、操作人和时间；历史文件不随模板更新变化。
- 导出前校验销售单已确认、模板必填字段完整、重复明细数量合计一致。导出可重复，不改变销售单状态。

## 3. 客户池与销售单

### 3.1 客户池

客户池维护客户名称、客户代码、国家/地区、地址、联系人、电话、邮箱、付款条件、币种、启用状态和备注。客户名称和客户代码各自唯一。

一个客户支持多个联系人，每个联系人可维护姓名、岗位、电话、邮箱、是否默认联系人和备注。销售单选择客户后可选择默认联系人，并保存客户、代码和联系人快照。客户禁止物理删除；已被销售单或应收使用后仅可停用。

### 3.2 销售单核心与可配置内容

一张销售单对应一个手工 `order_no` 和一款产品。销售单核心字段至少包括：客户、订单号、客户单号/PO、外部合同号、下单日期、产品名称、品名规格、数量、单位、交货/完工日期、客户联系人、币种、单价、销售金额、税率、折扣、运费、生产工艺、包装要求、备注和附件。

其中客户、订单号、下单日期、数量、单位、品名规格、交货/完工日期为确认前必填；其余字段与自定义字段、区块、明细通过版本化表单定义维护。

销售单支持可选的配色/花色明细。明细可维护名称、配色说明、条码、数量、单位、图片/附件和其他自定义字段；明细存在时，数量合计必须等于销售单总数量，否则不允许确认。

材料、工艺、包装和客户要求由销售维护为可配置字段/区块；材料到货状态由采购/仓库派生展示，只读，不允许销售手工改写。

### 3.3 状态、版本与取消

状态机：`草稿 -> 已确认 -> 已关闭`。草稿可取消或逻辑删除；已确认销售单恢复草稿后才可常规编辑。每次修改保留销售单版本历史和审计快照，不建立平行销售单。

“已导出”仅是导出记录，不是销售单状态。已确认销售单取消必须填写原因并展示影响预览；已有 BOM、采购、生产、仓库或财务下游事实时，禁止直接取消，必须由各模块的冲销、调整或关闭流程完成。

## 4. 销售单、BOM 与下游联动

物控只能依据已确认销售单建立 BOM，且 BOM 必须保存来源销售单版本。导出不是建立 BOM 的门禁。

销售单已关联 BOM 后，产品规格、数量、材料/工艺、包装、交期、配色、客户、价格等变更必须提示物控复核。所有已建立 BOM 均不自动改写：系统建立销售单与 BOM 差异/复核提示，由物控决定新建 BOM 版本或调整后续采购、生产。

若已存在采购单、生产单、出入库或应收来源，销售人员仍可按权限修改销售单，但必须填写原因、查看影响预览并确认。系统重算可派生展示/告警，创建差异提示；下游事实不自动改写。

销售单维护并确认价格/金额来源。成品出库按出库数量和销售单价格形成应收来源草稿，财务可独立确认和调整，保留来源金额快照。

## 5. 附件、报表与权限

- 销售单统一使用 `attachment`，支持客户 PO、外部合同、客户图稿、产品图片、包装资料、导出文件及其他附件；默认不设必传，可按订单号检索。
- 固定报表：销售单列表、订单产品/配色明细、BOM 交接/复核表、模板导出记录、客户订单汇总、销售变更/风险提示表。支持订单号、客户、日期、状态、模板版本筛选和 Excel/CSV 导出。
- 销售操作员维护客户池、销售单和导出；物控创建/复核 BOM；管理员维护表单定义、业务类目和模板；审批人字段预留，V1.0 不实现审批流。

## 6. 审计与影响预览

销售单、客户、表单定义、模板、导出、BOM 交接、修改、取消和差异处理均记录操作人、时间、原因、对象快照、变更前后值和关联订单号。修改销售单前，影响预览至少展示 BOM 版本、采购单、已入库数量、生产单、领料、成品收发存、应收来源、已导出文件和未解决告警。

确认后可派生展示、差异/复核提示和报表在同一事务中更新。已确认的 BOM、采购、生产、库存和财务事实不被静默改写。

## 7. 与开发文档的边界

本文定义销售领域对象、可配置表单/模板边界、状态、导出和跨模块规则，不定义数据库列、动态字段存储方式、Excel 引擎、NestJS 模块、REST 路由、页面组件或任务拆分。后续形成销售模块开发规格时，需先选择可审计的字段定义、模板映射和版本发布实现。
