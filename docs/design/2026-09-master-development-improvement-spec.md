# 迪礼 ERP 跨模块业务管线合并开发改进规格

状态：ready-for-agent  
确认日期：2026-09-03  
适用范围：销售、BOM、采购、来料质检、仓库、生产、财务、人事工资、成品交付及部署运行

## 1. 目标

将当前分散的业务要求合并为一套可追溯、可回退、可验收的跨模块规则。后续开发以本文件为主规格，原有设计文档和任务文档作为领域细节与历史记录，不得与本文件冲突。

## 2. 统一业务口径

- 用户可见的跨模块身份统一使用“订单号”；UUID 仅用于内部关联。
- “物料清单”统一称为“BOM 表”。BOM、采购和库存只允许引用原料物料；销售产品属于成品链路，不得混入物料清单。
- 物料唯一身份是物料主数据 ID，名称、型号不能替代 ID；单位是库存和数量计算的必要维度。
- 库存余额只能由原料入库、生产领料、退料、报废及其反向事实改变；到货、质检和入库草稿不改变库存。
- 所有单据区分草稿、确认、过账、完成和回退/冲销。草稿可编辑删除；已产生下游事实的记录必须受控回退或冲销，不能静默覆盖。
- 所有删除、回退、冲销、金额覆盖和核心字段更正都必须填写原因并写审计记录。

## 3. 端到端管线

### 3.1 销售单到 BOM、采购和生产

已确认销售单可创建且只能创建一份 BOM 表；BOM 可编辑，明细至少包含物料、型号、颜色、数量和单位。采购单绑定订单号、销售单、BOM、供应商及原料明细，可带入 BOM 行并允许因补料或替代料新增原料。生产单绑定订单号，可在进行中继续追加工序；生产工序日报必须按生产单和工序隔离。

### 3.2 采购到货、质检、入库和应付

采购单按明细登记多个收货批次，每批保存到货数量、单位和批次号。累计到货达到或超过计划量时显示“超单”，要求填写超收原因，并允许关闭到货；关闭后禁止继续到货。每个收货批次自动生成且只生成一条来料质检记录和一条待确认应付来源。质检可分次累计，合格/条件接收数量才可建立对应原料入库批次；入库可多次维护并支持草稿编辑、过账和受控冲销。每个批次应在采购、质检、入库和财务页面显示采购单号及批次序号。

### 3.3 库存与生产领料

库存按物料+单位全局汇总，不按订单预留。生产领料绑定生产单，按物料和单位校验可用库存并阻止负库存；退料、报废和冲销必须生成相反库存事实。库存页面提供原料仓储情况的独立表格工作区，支持查询、编辑草稿、删除草稿和受控更正。

### 3.4 生产工序员工日报与工资

生产页面先展示未完成生产单，再按工序进入居中工作区；不同生产单、不同工序、不同日期的数据互不串联。工序日报表头展示计划数量和是否超单，表格列不重复展示这两个字段；支持按日期切换。员工日报唯一业务键为生产单、工序、员工和日期，同键重复登记必须累加为一行；同一天同员工同工序只能使用一种计薪方式。计件不强制时长，计时不强制件数；单价完全由人工填写，系统按实际件数/时长计算当日员工总薪资。保存、修改或删除日报后，工资来源必须在同一事务内同步。

### 3.5 财务应付、应收和工资结算

每批到货自动进入供应商应付来源，默认金额为到货数量乘采购单价；金额覆盖必须填写原因。应付按供应商、订单号、采购单和批次对账，付款过账必须至少核销一条有效应付，禁止超额核销和无来源付款。成品出库过账必须校验库存和销售单价，并自动生成唯一应收来源；收款必须核销有效应收。工资台账按姓名检索，重名必须选择具体工号；工资总览独立页面分为车间与非车间，车间使用计件/计时日报累加，非车间由财务人工维护。已确认、部分支付或已支付财务事实不得静默修改，来源变化时标记过期并通过调整单处理。

### 3.6 人事和基础资料

员工支持筛选、编辑、离职状态及入职/离职时间；员工类型固定为“车间”和“非车间”，前后端均不得创建自定义类型。部门、岗位、工序和加工地点分别提供可增删改查的池子页面，并在业务表单中即时刷新。员工名单导出和员工批量导入均在内存中完成，不落盘、不保存原始 Excel；导入使用固定中文表头，先全表校验，存在错误整批不导入，已有工号整行报错不覆盖。

### 3.7 全站新增类目与编辑体验

所有表单中的“新增类目”都必须打开项目组件库的对话框或工作区。保存后返回原调用页面，恢复原表单内容，立即刷新下拉并自动选中新类目。适用范围包括客户联系人、供应商、物料、单位、部门、岗位、员工类型、绩效、质检项目和送检项目。确认状态的单据要提供编辑或回退 draft 入口；有下游事实时显示明确的受控更正路径。

## 4. 实施拆解与依赖

1. **基础约束与历史数据**：统一物料类型、单位维度、业务唯一键、状态迁移、审计和重复日报清理。所有后续任务依赖本项。
2. **采购批次管线**：整单批次工作区、到货状态、自动质检、自动应付来源及批次回退。
3. **质检与原料入库**：分次质检累计、合格量门禁、多批入库、入库过账和冲销。
4. **库存与领料**：库存事实聚合、单位隔离、负库存校验、领料/退料/报废及仓储情况页。
5. **生产日报与工资**：生产单/工序隔离、日期视图、日报累加、人工单价、工资来源和工资总览。
6. **财务结算**：应付批次对账、付款分配、应收来源、收付款冲销、工资台账保护。
7. **人事及基础资料**：员工状态、固定类型、部门/岗位/工序/地点池、Excel 导入导出。
8. **全站体验与部署**：新增类目返回刷新、确认后编辑、PWA manifest/service worker、发布包和缓存验收。

每项完成后必须单独提交 Conventional Commit，并在任务文档中记录构建、迁移、API 回归和浏览器验收证据。

## 5. 验收标准

- 采购单一批到货后，采购、来料质检、原料入库和财务应付均能按同一批次追溯；任一环节回退后，上游状态和下游可操作性正确恢复。
- 库存余额只因库存事实变化，物料和单位不同不得互相抵销；并发重复请求不产生重复事实。
- 同一生产单、工序、员工、日期重复日报只产生一行累加记录，计件/计时条件校验正确，工资金额与人工单价一致。
- 所有确认/过账事实的编辑、回退、冲销均有权限、原因和审计记录；已支付事实不会被静默改写。
- 前端所有关键流程使用项目组件库，批次和日报工作区至少占原页面 80% 宽度；生产日报按生产单、工序、日期隔离。
- 员工 Excel 导入导出不在服务器留下原始文件；导入错误时数据库无部分写入。
- 本地和远程部署包根目录包含项目清单、锁文件、API/Web 构建产物及 PM2 配置；迁移后健康检查返回 API 与数据库均为 ok，浏览器无旧 chunk 或 manifest 404。

## 6. 测试要求

测试只验证外部业务行为、状态、数量、金额、权限、幂等和审计。必须覆盖 PostgreSQL 事务/API 回归、并发唯一性、采购到货至应付、质检至入库、库存领料、生产日报至工资、应收收款、人事导入校验和浏览器关键链路。每条管线同时验证正常流转、重复提交、错误输入、回退/冲销和下游事实存在时的拒绝行为。

## 7. 不在本期范围

自动排产、自动采购建议、标准自动计薪、税费社保、银行自动对账、订单级库存预留、库位与批号成本、无审批盘盈盘亏，以及把销售单核心变更自动改写到历史 BOM/采购/生产单。
