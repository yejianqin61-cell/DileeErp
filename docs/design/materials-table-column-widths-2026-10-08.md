# 物料清单：表格列宽固定 + 超长省略 + hover 看全文（2026-10-08 第七轮）

## 一、用户原话

> 「物料清单太宽了，表格所有列宽限定长度，超过就省略显示，鼠标hover才显示所有文字。尽量保证所有column一次性展示。」

「物料清单」是侧栏 **采购 → 物料清单**（`app/procurement/materials/page.tsx`）那一页 ——
和上一轮的「BOM 表」是两张不同的表（BOM 表是十列、悬浮居中页；这一页是主页面上的一张 10 列表，
带缩略图与上传按钮）。用户这次说的四件事：

① 表格太宽（要横向拖动才看得全）；② 每列限长；③ 超出省略、悬停看全文；④ 尽量一屏放得下所有列。

改动只落在三处：`app/procurement/materials/page.tsx`、`app/globals.css`、
`components/data/data-table.tsx`（外加 `audit-columns.tsx` 一行 title）。
**没有 API 改动、没有迁移、没有数据**——前后端不必同时上线。

## 二、改前实测：这句话对应的数字与机理

用真实 Chromium 加载 `app/globals.css` + 这张表的真实 DOM（表头/单元格/缩略图/按钮都按真实类名与
真实数据复刻；改前那份用同一份 CSS 但按改前的类名与列定义还原）：

| 视口 | 表可用宽度 | 改前 主表宽 / 横向滚动条 | 改前「未导入的行」小表 | 改后横向滚动条 | 改后行高 |
|---|---|---|---|---|---|
| 1280x800 | 948px | 1387.4px / **439px** | **588px** | **0px** | 80.5px |
| 1366x768 | 1034px | 1387.4px / **353px** | **502px** | **0px** | 80.5px |
| 1440x900 | 1108px | 1387.4px / **279px** | **428px** | **0px** | 80.5px |
| 1600x900 | 1268px | 1387.4px / **119px** | **268px** | **0px** | 44.5px |
| 1920x1080 | 1588px | 1588px / 0px | 0px | **0px** | 44.5px |

表可用宽度 = 视口 − 232（侧栏） − 64（内容区内边距） − 32（面板内边距） − 4（两层边框）。

**机理**（与 BOM 表同源）：`.ui-table-cell` 上写着 `white-space: nowrap`，表格又是默认的**自动布局**，
于是每一列的 min-content 等于那一格里最长的那串文本 —— 一个 26 字的物料名称 + 一段 24 字的规格型号
就把整张表顶到 **1387.4px**（1366 屏只有 1034px，多出 353px，只能左右拖）。
CSS 的 `width` 在自动布局里只是**建议值**，内容更宽时会被推翻；所以"给每列写个宽度"必须配合
`table-layout: fixed` 才成立。

同一次实测里改前的**行高是 128.5px**：自动布局把「图片」（94px）与「操作」（70px）两列压到最窄，
`action-row` 里的按钮各折成三行 —— 用户没提这一条，但它是同一个病因的另一半。

## 三、方案

### 1. 页面给每一列显式宽度（`COLUMN_WIDTH`，总和 100%）

`DataTable` 一旦发现某列带 `meta.width`，就给 `<table>` 加上 `data-table-fixed`
（`components/data/data-table.tsx`），于是 2026-09-27 起通用的那三条接手：
`table-layout: fixed` + `.cell-ellipsis`（`white-space: nowrap; text-overflow: ellipsis`）+
单元格 `title`。**总和恰好 100% 时表宽 = 容器宽**，"一次性展示"由布局保证，而不是靠文本恰好不长。

| 列 | 物料编码 | 物料名称 | 规格型号 | 颜色 | 默认单位 | 图片 | 状态 | 创建人 | 最后修改人 | 操作 |
|---|---|---|---|---|---|---|---|---|---|---|
| 宽度 | 12% | **14%** | 11% | 7% | 7% | 15% | 5% | 8% | 8% | 13% |
| 性质 | 文本 | 文本 | 文本 | 文本 | 文本 | 控件 | 枚举 | 两段文字 | 两段文字 | 控件 |

分配依据是**量出来的宽度需求**，不是平均分：

- 「图片」一格要放 40px 缩略图 +「换图」+「删除图片」，单行 **162px**（无图时 70px）；
- 「操作」三个按钮（编辑/停用/删除）单行 **142px**；
- 「创建人 / 最后修改人」两行布局后需要 **58.7px**（同年）/ 86.9px（跨年）；
- 文本列按"1366 屏还看得见一段有意义的前缀"取值（物料编码 12% = 124px，1366 屏因内边距只剩
  108px、17 个字符的自动编码会省略最后两个字符；1440 屏 133px 就看全了）。

### 2. 页面级紧凑（`globals.css`）

`DataTable` 支持 `tableClassName`，这一页三张表都挂 `materials-page-table`，配套四条 CSS：

```css
.ui-table.materials-page-table { font-size: 12px; }
.materials-page-table .ui-table-head, .materials-page-table .ui-table-cell { padding: 6px 8px; }
.materials-page-table .audit-actor-cell { display: grid; gap: 1px; }
.materials-page-table .audit-actor-time { color: var(--text-muted); font-size: 11px; }
```

- **内边距 12 → 8px**：十列光内边距原来吃掉 240px，收一收每列多出 8px 可用宽度（十列 ≈ 80px）。
  字号 13 → 12px 同理。这一类取舍与财务页、采购计划页一致。
- **审计两列的两行布局**：`auditActorCell` 从 2026-09-16 起的注释就写着「姓名 + 次行小字时间」，
  但全站**一直没有对应的 CSS**，实际渲染成一行（实测 88.1px，跨年 118.8px），比 8% 列的内容盒
  （1366 屏 66.7px）宽，会被 `overflow: hidden` 裁掉。这里把注释里的意图补上，宽度需求降到
  58.7px / 86.9px。**只作用于本页**（类挂在 `<table>` 上），其它页面的审计格一个字都没变。
- 跨年的行（`2025-12-31 09:05` = 86.9px）仍会被裁掉尾巴，靠同一次改动给审计格容器加的 `title` 兜住
  （见下一条）。

### 3. 悬停看全文：DataTable 的 title 原来对最常见的列写法失效（本轮修的第四个文件）

`meta.ellipsis` 只给**字符串**渲染结果加 `title`。而 TanStack 对**没写 `cell` 的列**用的是默认 cell
（`props => props.renderValue()`），`flexRender` 见到函数就 `createElement` —— 于是
`typeof rendered === "string"` 永不成立：

> `accessorKey` 写法的文本列：**省略号照常出现，鼠标悬停却一片空白**，而且看不出来是坏的
> （物料清单页的「物料编码 / 物料名称」第一次上线正是这个样子）。

修法是给 `ellipsisTitle` 加第二层：渲染结果不是字符串时，回退到**这一格的值**
（`cell.getValue()`，仍然是字符串/数字才给）。前提是这一列**有值**：

- `accessorKey` / `accessorFn` 的列取得到 → 「默认单位」因此从 `id` + 自定义 `cell` 改成
  `accessorFn: (row) => unitNameOf(row.defaultUnitId) || "-"`，屏幕上显示的就是这个值，两边不会漂；
- 只有 `id` + 自定义 `cell`（没有 accessor）的列取不到 → 要么改成 `accessorFn`，要么像审计格那样
  自己在容器上写 `title`（`auditActorCell` 现在带 `title="{姓名} {时间}"`）。这是一条**契约**，
  已写进 DataTable 的注释与 `test/data-table-ellipsis.test.tsx`（包含"这种列拿不到 title"的反向用例）。

按钮那类 ReactNode 列依旧不给 title（把按钮文案拼成一句提示比没有更让人困惑），
所以「图片 / 操作」两列**不加** `ellipsis`：它们靠 `action-row` 换行，加了 nowrap 只会把按钮裁没。

### 4. 批量导入结果的两张小表同样固定列宽

同一页的「未导入的行」（Excel 行号 12% / 字段 18% / 原因 70%）与「已新增的物料」
（行号 14% / 编码 30% / 编码来源 18% / 名称 38%）也挂上同一个类。原因是一整句中文提示
（实测 588px 溢出，1366 屏）在自动布局 + nowrap 下能把小表顶出面板 —— 现在超长即省略、悬停看全文。

## 四、取舍（都会被问到）

1. **不给表设 `min-width`。** BOM 表那轮选择了"窄屏宁可横向滚动"（`min-width: 1180px`，因为它的列
   装的是可编辑控件）；这一页用户要的是「一次性展示」，所以十列全按百分比分完、**任何视口都不横向
   滚动**。代价：窄屏上「图片 / 操作」会折成两行（行高 44.5 → 80.5px），文本列更多地省略 ——
   但省略的部分都有 hover 全文，而不像改前那样"要么看不到、要么得拖"。
2. **1366 及以下让「图片 / 操作」折行，把宽度让给文本列。** 想让这两列在 1366 也不折行，需要
   18% + 16% = 34%，只能从文本列里拿 —— 那会把物料编码压到 10% 以下（17 个字符的编码一上来就被
   截掉一半）。1600 屏（内容宽 1268px）起这两列分别有 190px / 165px，三个控件一行放得下，
   行高回到 44.5px；1920 屏余量更大。
3. **列宽是百分比，不混 px。** 上一轮 BOM 表实测过：混用 px 时浏览器会把多出来的宽度整块塞给 px
   那几列（1920 屏序号 48 → 208px），全百分比则按比例摊开。这一页没有列是按条件隐藏的，
   但仍然沿用同一条（守卫见 `lib/materials-table-width.test.mjs`）。

## 五、刻意不做

- **不动「图片」那两列的内容**：三个按钮（上传/换图、删除图片）保持原样。把它们收进弹窗、
  或把「删除图片」藏起来能省下 60~70px，但那是"这一列该有什么操作"的独立决定，不该搭在列宽改动里。
- **不做列宽拖拽 / 列宽记忆**：用户要的是"限定长度"，不是"能自己调"。
- **不改批量导入那张小表的列定义（除宽度）**：字段名与原因文案一个字没动。
