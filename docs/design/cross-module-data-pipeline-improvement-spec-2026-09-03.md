# 迪礼 ERP 跨模块数据管线开发改进规格

状态：ready-for-agent  
确认日期：2026-09-03  
范围：销售、BOM、采购、来料质检、仓库、生产、财务、人事工资及成品交付链路

## Problem Statement

当前系统已经具备销售单、BOM、采购单、分批到货、来料质检、原料入库、生产日报、工资来源、应收应付和成品出库等领域模型，但部分链路仍存在口径不一致和状态机边界不足：

- 采购单可能通过后端 API 选择成品物料；
- 库存事实带订单维度，采购页面却按物料覆盖读取，可能显示错误库存；
- 一批到货可能被手工创建多条来料质检；
- 采购单关闭或批次撤销后的状态回退不完整；
- 同日同工序日报可能重复成行；
- 工序员工日报在不同计薪方式下无法严格遵守同日唯一口径；
- 生产单可在有效工序未完成时直接标记完成；
- QC 更正可能绕过已经发生的成品入库事实；
- 工资台账、应收应付和库存的来源快照需要明确刷新与锁定规则。

## Solution

建立统一的跨模块数据事实和状态规则：

1. 订单号是跨模块业务身份，UUID 只作内部关联键。
2. BOM、采购、生产和仓库均使用统一物料主数据；采购和 BOM 只能使用原料物料，成品只能进入成品链路。
3. 库存余额只由原料入库、生产领料、退料、报废及其反向事实派生，不提供直接改余额入口。
4. 到货、来料质检、原料入库、应付来源按批次一一追溯；每批到货自动产生一个质检批次和一条待确认应付来源。
5. 所有可变单据区分草稿、确认、过账、完成、冲销/回退；已发生下游事实的核心字段必须锁定。
6. 生产日报按生产单和工序隔离，按日期汇总；员工工资来源只累计实际保存的人工单价和数量/时长。
7. 成品出库过账自动生成应收来源；付款必须核销有效应收/应付。

## User Stories

1. 作为物控人员，我想从已确认销售单创建唯一 BOM 表，以便采购和生产使用稳定的订单版本。
2. 作为物控人员，我想在 BOM 中增删原料、型号、颜色、数量和单位，以便维护真实用料。
3. 作为物控人员，我想在采购单中带入 BOM 行，也想临时新增 BOM 外物料，以便处理替代料和补料。
4. 作为物控人员，我希望 BOM 外新增物料只能是原料，并必须填写新增原因，以便避免成品误入采购链路。
5. 作为物控人员，我想在采购单中看到物料的全局当前库存，以便决定实际采购数量。
6. 作为物控人员，我想按采购明细登记多批到货，以便处理分批交付。
7. 作为物控人员，我想看到每个明细的计划量、累计到货量、剩余量和超单状态，以便判断是否可以关闭到货。
8. 作为物控人员，当每个采购明细均达到或超过计划量时，我想关闭采购单到货，以便进入来料质检阶段。
9. 作为物控人员，我想在关闭到货后不能继续登记到货，以便防止批次事实被绕过状态机。
10. 作为物控人员，我想撤销尚未产生下游事实的到货批次，以便纠正录入错误。
11. 作为物控人员，我希望撤销到货后采购单按剩余有效到货量自动恢复状态，以便继续处理未完成收货。
12. 作为质检人员，我想在每批到货下看到系统自动生成的来料质检批次，以便保证一批到货一批质检。
13. 作为质检人员，我想分次检验同一批到货但累计写入同一条质检记录，以便避免重复质检批次。
14. 作为质检人员，我想对质检记录进行开始、完成和受控回退，以便处理实际检验流程。
15. 作为仓库人员，我想只使用合格和条件接收数量建立原料入库，以便不合格原料不会进入可用库存。
16. 作为仓库人员，我想同一质检批次分多次建立入库草稿，以便处理分批入库。
17. 作为仓库人员，我想编辑或删除入库草稿，过账后通过冲销纠正，以便保留库存事实完整性。
18. 作为财务人员，我想每批到货自动看到待确认应付来源，以便不遗漏供应商应付款。
19. 作为财务人员，我想应付默认按本批到货数量乘采购单价计算，并能在修改时填写差异原因。
20. 作为财务人员，我想按批次确认应付并进行多批核销，以便支持分批付款。
21. 作为财务人员，我想付款过账必须核销应付，避免出现没有业务来源的已过账付款。
22. 作为财务人员，我想按供应商、订单号、采购单和期间进行应付对账，以便核查外部余额差异。
23. 作为生产负责人，我想在进行中的生产单继续添加工序，以便处理临时增加的工序任务。
24. 作为生产负责人，我想按生产单再按工序进入员工日报，以便不同工序的数据彼此隔离。
25. 作为生产负责人，我想按日期切换查看某工序的员工日报，以便进行日级核算。
26. 作为生产负责人，我想同一员工、同一生产单、同一工序、同一天重复登记时累加到一行，以便避免重复行。
27. 作为生产负责人，我想同一业务键同一天只能使用一种计薪方式，以便件数和时长不会混淆。
28. 作为生产负责人，我想每天人工填写单价，系统按件数或时长计算当天薪资，以便符合人工计价规则。
29. 作为生产负责人，我想同一生产单、同一工序、同一天的工序日报重复登记时累加，以便工序产量保持日汇总口径。
30. 作为生产负责人，我想生产单只有在所有有效工序完成且告警处理后才能完工，以便防止提前完工。
31. 作为外加工负责人，我想外加工生产单以回厂交接累计量达到计划量作为完工条件，以便区分发出和完成。
32. 作为财务人员，我想日报保存后立即形成生产工资来源，以便工资结算不依赖重复手工录入。
33. 作为财务人员，我想草稿工资台账随着日报变化自动刷新，以便结算金额保持最新。
34. 作为财务人员，我想已确认或已支付工资台账不被静默改写，以便已确认财务事实可追溯。
35. 作为财务人员，我想同名员工生成工资时必须选择具体工号，以便避免工资归属错误。
36. 作为质检人员，我想成品 QC 有下游入库事实时不能直接更正，以便库存与 QC 事实一致。
37. 作为仓库人员，我想成品出库过账时自动生成应收来源，以便销售交付和财务应收联动。
38. 作为财务人员，我想没有销售单价时不能出库过账，以便不产生无金额应收。
39. 作为管理员，我想所有核心编辑、回退、冲销和金额差异都保留原因与审计记录，以便追溯责任。
40. 作为管理员，我想历史重复日报在加唯一约束前被盘点、合并或标记异常，以便迁移不丢失工资和产量事实。

## Implementation Decisions

### 领域和主数据

- 物料类型固定为 `raw_material` 和 `finished_product`。
- BOM 明细和采购明细只能引用启用的原料物料；采购允许 BOM 外新增原料，但新增明细必须携带原因。
- 库存余额按物料和单位全局汇总；订单号保留在库存事实中用于追溯，不参与余额分组，不做订单级库存预留。
- 原料入库接口强制库存类别为 `raw_material`，成品、不良品和报废使用独立业务单据。

### 采购、到货和来料质检

- 采购单绑定订单号、销售单、BOM、供应商和物料明细。
- 关闭到货按采购明细逐行判定：每个明细累计有效到货量必须大于或等于计划量。
- 明细到货量大于计划量时标记超单，并要求在具体到货批次填写超收原因。
- 采购单关闭后状态为 `arrived_complete`，禁止新建到货。
- 到货批次撤销后重新计算采购单状态：无到货为 `ordered`，未完成为 `partially_arrived`，仍完成为 `arrived_complete`。
- 到货成功在同一事务内创建唯一来料质检记录和待确认应付来源。
- 正常流程不得为同一到货批次新建第二条有效来料质检；分次检验累计更新原记录。
- 有质检或入库下游事实时禁止直接修改/删除到货；草稿下游应先删除或回退。

### 库存

- 库存增加：原料入库过账、退料过账及对应反向事实。
- 库存减少：生产领料过账、报废过账及对应反向事实。
- 登记采购到货、来料质检、创建入库草稿不改变库存。
- 库存余额由有效库存事实聚合，不允许直接修改余额；所有过账必须幂等并进行负库存校验。

### 应付与付款

- 每批到货自动生成待确认应付来源，金额默认为到货数量 × 采购单价。
- 不合格数量不自动改变原始到货应付；退货、折价或赔偿通过财务应付调整处理，并填写原因。
- 应付来源接收后形成草稿应付，确认后才可被付款核销。
- 付款允许先保存草稿，但过账必须至少核销一条有效应付；不允许无分配付款过账。
- 应付支持按批次明细和采购单汇总对账；差异保留外部余额、系统余额和处理说明。

### 生产日报和工资

- 工序日报唯一业务键为生产单、生产单工序和日期；重复登记累加完成数量。
- 工序员工日报唯一业务键为生产单、生产单工序、员工和日期；同日只能使用一种计薪方式，重复登记累加件数/时长和金额。
- 日报单价必须人工填写，不读取 `OperationRate` 作为默认值；工资来源只累计日报实际保存金额。
- 工序员工日报变更实时同步生产工资来源。
- 生产单人工完工时，后端事务内校验所有有效工序达到计划量且无未处理告警。
- 外加工生产单人工完工时，校验回厂交接累计量达到计划量；发出不等于完成。
- 草稿工资台账自动刷新；已确认、部分支付、已支付台账标记来源过期，回到草稿后重新结算；已支付差额使用工资调整单。
- 按姓名生成工资台账时，重名必须返回候选并要求选择具体工号。

### 成品、应收和 QC

- 允许已检验合格/条件接收数量先分批成品入库，未检验和不合格数量不可入库。
- 成品 QC 更正前必须检查是否存在成品入库草稿或过账事实；存在时先删除/冲销下游。
- 成品出库过账校验成品库存和销售单价，自动生成唯一草稿应收来源。
- 收款过账必须核销有效应收；应收、收款、出库和退货均通过冲销而非物理删除纠正。

### 编辑与历史数据

- 草稿单据可编辑、删除；确认或过账后的事实字段锁定，非事实字段可按规则编辑。
- 销售单确认后仍可编辑；存在 BOM/采购/生产下游时，客户联系人、交期、备注等非核心字段可改，产品、规格、数量、单位、单价等核心字段需先回退下游。
- 采购单已有到货后锁定订单号、BOM、物料、单位和计划数量，只允许修改预计到货日期、联系人、备注等非事实字段。
- 历史日报迁移前按业务键盘点；同口径重复记录合并数量、时长、金额并软删除原行；计件/计时冲突不自动合并，标记人工处理。
- 所有更正、删除、回退、冲销和金额覆盖均要求原因并写入审计事件。

## Testing Decisions

- 测试只验证外部业务行为、状态变化、数量金额结果、权限、幂等和审计，不绑定具体内部实现。
- 采购链路测试：销售单/BOM 来源校验、原料类型门禁、BOM 外新增原因、明细级到货完成、超单、关闭后禁止到货、撤销后状态恢复。
- 质检入库测试：一批到货一条质检、重复质检拒绝、分次检验累计、合格/条件接收数量上限、入库草稿编辑删除、过账库存和冲销。
- 库存测试：原料入库/领料/退料/报废余额、单位隔离、全局物料汇总、负库存拒绝、并发过账和幂等请求。
- 财务测试：每批到货应付来源、金额覆盖原因、不合格数量不改原始来源、应付确认、分批付款核销、超额核销拒绝、无分配付款拒绝、对账差异。
- 生产测试：进行中追加工序、同日工序日报累加、员工日报同日唯一、跨计薪方式拒绝、人工单价必填、日报到工资来源、完工条件和外加工回厂条件。
- QC/成品测试：部分合格先入库、QC 下游存在时禁止更正、成品出库库存门禁、销售单价门禁、应收唯一生成和收款核销。
- 历史迁移测试：重复日报合并金额守恒、计件/计时冲突不误合并、唯一约束上线后并发重复请求只产生一条业务事实。
- 前端验收：所有操作使用项目组件库；采购详情按批次展示到货、质检、入库、应付状态；生产页面按生产单/工序隔离并支持日期切换；所有草稿编辑和回退入口与后端状态一致。
- 参考既有测试模式：HTTP API 回归、PostgreSQL 事务测试、浏览器链路验收、质量门禁和订单工作台聚合测试。

## Out of Scope

- 自动排产、自动采购建议和自动标准计薪。
- 工资税费、社保和银行自动对账。
- 订单级库存预留、库位管理、批号成本和复杂计价。
- 自动将销售单核心变更同步改写到历史 BOM、采购单或生产单。
- 无审批流程的盘盈盘亏直接调整库存。
- 将到货应付改为按质检合格量自动计价。

## Further Notes

- 术语统一使用“订单号、BOM 表、收货批次、来料质检批次、原料入库批次、应付来源、工资台账”。
- UUID 仅作隐藏关联值；面向用户的定位使用订单号、采购单号、生产单号、批次号、供应商名称、员工姓名和工号。
- Excel 导出和员工批量导入均在内存中处理：不落盘、不保存原始文件；导入必须全表校验，存在错误时整批不导入。
- 所有跨模块写入优先在最高层事务边界完成，并在来源记录中保存数量、单位、单价、币种、税率和业务快照。
- 开发完成后必须执行 API 构建、前端类型检查、数据库迁移验证、全量回归测试和浏览器关键链路验收。
