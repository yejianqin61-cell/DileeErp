# 后端平台层开发计划

## 目标

在各业务模块负责人完成访谈前，建设后端可复用的平台能力，使后续生产、采购、财务、仓库、人事和客户池模块能在统一规范下开发，而不提前锁定业务数据库模型。

## 已确认决策

- 后端采用 NestJS + TypeScript，API 采用 REST 风格并返回 JSON。
- 数据库为 PostgreSQL，但当前阶段不创建订单、物料、库存、工序、采购等业务表。
- API 使用 `/api/v1` 前缀；成功和失败 JSON 结构遵循 SRS。
- 所有未来业务表统一使用 UUID 主键、审计字段和逻辑删除。
- 操作员独立账号，权限为管理员 + 模块授权；业务规则和字典不写死在代码中。
- 附件统一使用 `attachment` 模型。

## 工作范围

### 阶段 1：应用基础层

- 配置模块与环境变量校验。
- 全局异常过滤器、统一 JSON 响应和稳定错误码。
- 请求 DTO 校验、分页、排序、筛选参数约定。
- 健康检查、结构化日志和 API 文档入口。

### 阶段 2：身份与模块权限

- 用户账号、密码安全存储、登录和会话/令牌机制。
- 当前登录用户上下文，供审计字段写入。
- 管理员和模块权限模型；模块枚举仅描述六个已确认模块。
- 未登录返回 `401`，无模块权限返回 `403`。

### 阶段 3：跨模块基础能力

- 可配置字典管理：状态、币种、计量单位等。
- 通用状态机服务：合法转换校验和状态变更记录。
- `attachment` 上传、下载、逻辑删除及授权校验。
- 逻辑删除和审计字段的共享数据访问约定。
- 导出和打印/PDF 的接口契约预留，不实现未确认的业务格式。

### 阶段 4：数据库基础设施

- 选择并配置 PostgreSQL 迁移工具。
- 创建仅支撑平台能力所需的表：用户、角色/模块授权、字典、状态定义/转换、附件及其关联。
- 为所有平台表落实 UUID、审计字段和逻辑删除。
- 不创建万能订单表、万能单据表、万能属性表或未经访谈确认的业务表。

### 阶段 5：质量与交付

- API 契约测试：响应结构、错误码、分页和参数校验。
- 认证/授权测试、审计字段与逻辑删除测试。
- 状态机、附件类型/大小/下载授权测试。
- 备份与恢复演练说明及执行记录。

## 模块实施前置条件

每个业务模块开始编码前必须具备：

1. 对应负责人确认的模块规格。
2. 更新后的术语词典。
3. 明确实体、字段、状态、状态转换、边界校验和真实验收案例。
4. 位于 `docs/task/` 的可执行任务文档。
5. 对数据库变更、API 契约和测试边界的记录。

## 非目标

- 不在本阶段实现任何生产、采购、财务、仓库、人事或客户池业务流程。
- 不先行设计复杂 BOM、产品/SKU、库存成本、工序、批次、审批或自动排产模型。
- 不与仁和云或其他外部系统集成。

## 验收标准

- API 可稳定启动并提供健康检查。
- 所有平台接口遵循统一的 REST/JSON、鉴权、校验和错误处理规范。
- 平台数据库迁移可在空 PostgreSQL 实例重复执行。
- 一名模块授权操作员仅能访问获授权模块；管理员可维护平台字典和权限。
- 每项开发决策、任务和验证均在文档及当日开发日志中可追溯。
