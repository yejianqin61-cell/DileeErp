# 凭证管理：从收支流水生成记账凭证（2026-09-15）

> 用户口径：「凭证管理，从收支流水中 fetch，每条收支条目都可以生成对应的条目。
> 这个凭证怎么做才好呢？做一个图片返回来？」

## 1. 结论：不要把凭证做成图片

| 方案 | 问题 |
| --- | --- |
| 服务端渲染一张 PNG 返回 | 不可搜索、不可复制（财务要复制凭证号、核对金额）、缩放/打印会糊，改一个字就要重新生成；还要引入 canvas/无头浏览器依赖 |
| 前端把凭证纸截图成图片下载 | 可以作为**附加**导出，但不能当主形态：数据仍是分录，图片只是它的一种视图 |
| **结构化分录 + HTML 凭证纸 + 浏览器打印/另存 PDF**（采用） | 可查、可核、可追溯、可重打；零新增依赖；需要 PNG 时在打印视图上再套一层截图即可 |

因此本期落地的是：**凭证是记录**（`vouchers` + `voucher_lines`），页面按「记账凭证」版式排版，
出纸方式是浏览器「打印 / 另存 PDF」，避免下一个人又去接无头浏览器。
（2026-09-16 更新：页面上那段说明文字 `voucher-policy-note` 已按用户要求删除 —— 财务模块不再有任何
成句的说明性文案，这条口径现在只由本文档承载。）

## 2. 数据模型

```
vouchers                          -- 凭证头
  voucher_no      记-2026-09-0001（期间内顺延，唯一）
  voucher_date/period             -- 日期 / 会计期间 YYYY-MM
  source_type/source_id           -- cash_flow_entry（收支流水）| voucher（红冲）
  summary/currency/remark
  debit_total/credit_total        -- 借贷合计（两边恒为正，方向在分录上）
  status                          -- draft → posted → reversed
  @@unique([source_type, source_id])   ← 幂等根：一条来源只能有一张凭证
voucher_lines                     -- 分录（借/贷各一行，红冲时可多行）
  line_no / direction             -- debit | credit
  subject_key / subject_label     -- 科目编码 + **科目名快照**
  summary / amount / currency
  cash_flow_entry_id              -- 回指来源流水（流水被删则置空，凭证留着）
  @@unique([voucher_id, line_no]) / onDelete: Cascade（随凭证删）
```

**金额恒为正数、方向由 `direction` 决定** —— 与 `cash_flow_entries` 同一约定：
如果允许「支出填负数」，就无法区分「填错了」和「红冲」。

## 3. 生成规则

每条收支流水一张凭证，**幂等**（该流水已有凭证就返回原凭证，不重复建单）：

| 流水方向 | 借方 | 贷方 |
| --- | --- | --- |
| 收入 | 银行存款 / 库存现金 | 收支项目（如「货款」） |
| 支出 | 收支项目（如「原材料 成本」） | 银行存款 / 库存现金 |

- **资金科目**：流水上挂了银行账户（`cash_flow_entries.bank_id`）→ `银行存款` 并**引用该账户**
  （科目名快照 `银行存款—农业银行5706`）；没有账户且结算方式或结算账户名里含「现金」→ `库存现金`；
  否则 → 不引用账户的 `银行存款`。（2026-09-16 增补，见
  [银行存款改为引用具体银行账户](finance-voucher-regenerate-and-ledger-export-2026-09-16.md#二银行存款--引用具体银行账户需求-2)；
  本行在第十三轮之前的口径是靠文本猜科目，已被取代。）
- **摘要**：`对方名称 · 收支项目`（有备注则补「（备注）」），截断到 500 字；
- **凭证号**：`记-YYYYMM-####`，取同期间已有编号的**最大值 +1**（不是按张数，跳号也不重号）；
  并发撞号由 `vouchers_voucher_no_key` 兜底报错，绝不静默重号；
- **已冲销的流水不能生成凭证**（钱没真的动过，生成了会污染账目）。

## 4. 科目从哪来（当前口径，可替换）

库里**还没有正式会计科目表**（产品文档把「会计科目」列在 V1 之外，凭证页此前一直是占位），
所以本期采用**业务科目口径**：

- 损益/成本类科目 = **收支项目字典的 label**（`货款` / `原材料 成本` / `管理费用` / `人 工费` …）
  —— 财务本来就是按这张表分类的；
- 资金类科目 = `银行存款` / `库存现金`（两选一，见上）。

将来接入正式科目表时，**只改 `voucher.domain.ts` 里 `subject_key/subject_label` 的取值来源**
（例如查一张「收支项目 → 科目」映射表），凭证/分录模型、页面、打印视图都不用动。

同时，草稿凭证允许**整组分录的人工编辑**（科目名与金额），所以即使自动映射不准，
财务也能在过账前改成自己账套的科目 —— 编辑后必须借=贷，否则 422 `VOUCHER_NOT_BALANCED`。

## 5. 状态机与不可变性

```
生成 → draft ──过账(POST /:id/post)──→ posted ──红冲(POST /:id/reverse)──→ reversed
         │                                  │
         └──删除(DELETE /:id，软删除)        └──另开一张红字凭证（借/贷对调，同事务直接过账）
```

- **过账后不可改、不可删**：已过账的凭证是账务事实，删除会让账目无法追溯；
- **红冲**：原凭证标 `reversed`，并生成一张红字凭证（`source_type=voucher`、`source_id=原凭证 id`、
  借/贷对调、摘要「红冲 记-…：原因」）。红字凭证在**同一事务里直接过账** ——
  否则会出现「原凭证已红冲、对冲凭证还没过账」的空档，账目不自洽；
- 红冲必须填原因（`REVERSAL_REASON_REQUIRED`）。

## 6. 接口与页面

接口（`@RequireModules("finance")`，`voucher.controller.ts`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/finance/vouchers?period=&status=` | 凭证清单（带分录、来源流水号、状态中文） |
| GET | `/finance/vouchers/:id` | 凭证详情（来源流水 / 被红冲凭证 / 红字凭证） |
| POST | `/finance/vouchers/from-cash-flow/:entryId` | 由收支流水生成（幂等） |
| PATCH | `/finance/vouchers/:id` | 改摘要/备注/整组分录（仅草稿） |
| POST | `/finance/vouchers/:id/post` | 过账 |
| POST | `/finance/vouchers/:id/reverse` | 红冲（需原因） |
| DELETE | `/finance/vouchers/:id` | 删除（仅草稿，软删除） |

页面（`/finance/voucher`）：

- 上半张表 = **收支流水**（`GET /finance/cash-flow-entries`）：每条流水显示「凭证」列（凭证号 / 未生成）
  与行内「生成凭证 / 查看凭证」；可按「全部 / 未生成凭证 / 已生成凭证」筛选 + 搜索；
- 下半张表 = **记账凭证**：凭证号/日期/期间/摘要/借贷合计/状态/来源 + 行内操作
  （凭证纸 / 编辑 / 过账 / 删除 / 红冲）；
- **凭证纸**：对话框里按记账凭证版式排版（凭证号、期间、币种、来源、摘要、会计科目、借方金额、
  贷方金额、合计、制单/审核/记账/单位负责人签字栏），「打印 / 另存 PDF」调用 `window.print()`，
  「导出 PNG」见第 7 节。

打印 CSS 用 `visibility`（而不是 `display`）让祖先隐藏、凭证纸重新可见，并把对话框在打印时
改成普通文档流（`position: static`、去掉 `max-height/overflow`），否则 `position: fixed` 的对话框
会被裁成一页的一部分。

## 7. 一键导出 PNG（用户追加要求）

用户看过方案后追加：「还要一键导出 PNG」。实现方式**不引新依赖**：

```
voucherSvg(凭证)  →  SVG 字符串（记账凭证版式，纯函数、可单测）
   ↓ Blob(svg) → new Image() → canvas.drawImage → canvas.toBlob('image/png')   ← 浏览器自己栅格化
   ↓ <a download="记账凭证-记-2026-09-0001.png">
2 倍分辨率（1000 逻辑宽 → 2000px 位图）
```

- **为什么不用 html2canvas / html-to-image**：两者都要新增前端依赖（本机也无法假设能联网安装），
  而且靠遍历 DOM + 内联样式「猜」版式；凭证纸是固定表格，用 SVG 反而更可控、更清晰。
  同源 `blob:` 不会污染 canvas，所以 `toBlob` 可用；不引外部字体/图片，离线也能出图。
- **两个渲染视图的分工**：HTML 凭证纸服务于**打印/另存 PDF**，SVG 服务于**出 PNG**，
  两者用同一批字段；组件测试断言 PNG 入参（凭证号/科目/金额/来源），lib 测试断言 SVG 内容。
- **失败给可执行原因**：canvas 不可用（如无 canvas 的环境）时抛
  「当前环境不支持导出图片（canvas 不可用），请改用『打印 / 另存 PDF』」，页面 toast 出来，
  绝不静默失败，也不丢英文异常让人猜。
- 文件名做安全化（`/:*?"<>|` 与空格 → `-`），XML 文本转义（摘要里的 `&<>"'` 不会破坏 SVG），
  单元格按 CJK 1em / ASCII 0.55em 估算宽度裁剪加省略号（SVG 不做自动换行），
  行数变化时画布高度跟着长。

## 8. 测试与未验证

- 纯逻辑 `voucher.domain`：7 条（借贷方向、资金科目识别、摘要拼装与截断、期间、红字分录、平衡判定）；
- 服务层 `voucher.service`：13 条（生成幂等/凭证号顺延/已冲销流水拒绝、过账/编辑/删除/红冲的状态门禁、
  借贷不平衡拒绝、红冲生成红字凭证）；
- 迁移守卫：4 条（两表 DDL、幂等唯一索引、外键语义、schema 一致性）；
- 出图纯逻辑 `lib/voucher-image`：9 条（文件名安全化、XML 转义、单元格裁剪、SVG 要素齐备、
  借贷不串列、画布随行数长、无备注不留空行、非浏览器环境的可执行报错、尺寸解析）；
- 前端组件：`finance-page.test.tsx` 7 条（流水→生成→凭证纸打印、编辑整组分录 PATCH、过账/删除、
  红冲原因、后端拒绝时弹窗不关、导出 PNG 的接线与失败提示）；
- **未验证**：无可用 PostgreSQL，迁移未在真实库执行；`window.print()` 的真实出纸效果、打印 CSS 在
  各浏览器下的分页表现需要实机确认；**PNG 的实际像素效果没有端到端验证过** —— jsdom 里没有 canvas，
  出图路径只到「lib 层单测 + 组件层接线断言」，字体回退与中文渲染要在真实浏览器里点一次才算数；
  也没有验证并发下凭证号撞号时的唯一索引报错路径。
