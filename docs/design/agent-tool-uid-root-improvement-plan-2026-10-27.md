# Agent 工具调用改进计划：单号只做入口，uid 做联动

日期：2026-10-27
基线：`a71b704`；缺陷与验收清单来自 `docs/review/agent-tool-invocation-audit-2026-10-27.md`
范围：本计划只做工具调用链与关系键，不改业务口径与页面结构

## 1. 要求

- **R-1 让采购单号、生产单号也能作为查询入口** — 审计 P-1；本轮对话确认
- **R-2 根查询不再让模型复述业务单号，改用 uid 派生句柄** — 审计 P-2；本轮对话确认
- **R-3 工具与界面文案写明 order_no 是销售单号** — 审计 P-3
- **R-4 单号检索容忍大小写与空白差异** — 审计 P-4
- **R-5 工具入参以脱敏摘要落库，事后可还原** — 审计 P-5
- **R-6 检索为空或参数失败时给出部分答案，而不是整轮失败** — 审计 P-6
- **R-7 部署健康检查带重试，线上版本可签核** — 审计 P-7
- **R-8 27 张只冗余单号的表补销售单外键并回填** — 本轮对话，阶段 2
- **R-9 读路径从单号 join 换成 id join** — 本轮对话，阶段 3

## 2. 做法，逐条

### R-1 让采购单号、生产单号也能作为查询入口

- **Approach**：把检索从「只搜销售单」扩成「按号查任意单据」，统一返回该单据所属销售单的句柄。
- **Touches**：agent 工具目录、检索实现、界面步骤文案。
- **Test seam**：现有工具执行器入口，不新增接缝。
- **Acceptance**：[ ] 用采购单号能返回所属销售单句柄　[ ] 生产单号同样能　[ ] 目录断言与注册表一致　[ ] 步骤条不再显示「销售订单」
- **Hard part**：同号跨表重名。采购单号与销售单号同形时，要先定解析顺序。

### R-2 根查询不再让模型复述业务单号，改用 uid 派生句柄

- **Approach**：检索结果给每张命中的单据发一个本轮有效的句柄；后续根查询只传句柄，编排层还原成内部主键；一轮只涉及一张单时可省略。
- **Touches**：编排层、模型工具 schema、检索投影。
- **Test seam**：编排层现有单测入口，加一条端到端。
- **Acceptance**：[ ] 第二个工具调用的入参没有业务单号原文　[ ] 伪造句柄不触达数据库　[ ] 单张单时可省略参数　[ ] 多张单缺句柄时明确报错
- **Hard part**：句柄只在本轮有效；历史回放时旧句柄如何呈现还没定。

### R-3 工具与界面文案写明 order_no 是销售单号

- **Approach**：模型可见的描述与界面步骤文案，把 order_no 明确成「销售单号」。
- **Touches**：模型工具描述、前端步骤文案。
- **Test seam**：provider 单测里现有的描述文本断言。
- **Acceptance**：[ ] 描述里出现「销售单号」　[ ] 步骤条显示「销售单号检索」
- **Hard part**：文案会改变模型行为，改完要跑一次真实问答对比，不能只看单测。

### R-4 单号检索容忍大小写与空白差异

- **Approach**：检索词与单号先归一（去首尾空白、合并连续空格、忽略大小写）再匹配。
- **Touches**：检索实现、根解析。
- **Test seam**：检索实现现有单测，不新增接缝。
- **Acceptance**：[ ] 小写单号命中　[ ] 多余空格命中　[ ] 全角与半角命中
- **Hard part**：大小写不敏感匹配会让单号上的索引失效，大表上的分页要重测。

### R-5 工具入参以脱敏摘要落库，事后可还原

- **Approach**：每次工具调用把 operation 与关键入参（单号、检索词、页码）以摘要写进事件，不写结果。
- **Touches**：编排层、观测、事件负载。
- **Test seam**：事件负载的现有单测。
- **Acceptance**：[ ] 每个工具调用都能还原入参　[ ] 事件与日志仍不含查询结果与答案正文
- **Hard part**：单号算业务信息，与「日志不含业务值」的既有约束冲突，要显式开一个白名单。

### R-6 检索为空或参数失败时给出部分答案，而不是整轮失败

- **Approach**：检索为空或失败预算耗尽时，用已取得的事实生成降级回答，写明检索词与命中数。
- **Touches**：编排层。
- **Test seam**：编排层现有失败路径单测。
- **Acceptance**：[ ] 空结果回答写明检索词与 0 条　[ ] 已取得的事实在失败时仍进答案
- **Hard part**：降级回答不能变成编造业务结论，措辞边界要卡死。

### R-7 部署健康检查带重试，线上版本可签核

- **Approach**：健康检查改成有上限的重试，日志同时打印 build 与 release。
- **Touches**：部署脚本。
- **Test seam**：部署脚本现有单测。
- **Acceptance**：[ ] 冷启动 30 秒内判成功　[ ] 失败日志同时含 build 与 release
- **Hard part**：重试会拉长部署时长，失败时的总超时要先定。

### R-8 27 张只冗余单号的表补销售单外键并回填

- **Approach**：给只冗余单号的表补销售单外键，回填历史行，再加一致性校验。
- **Touches**：数据库 schema、迁移、各模块写路径。
- **Test seam**：迁移校验测试，与现有的改号登记表守卫同一类。
- **Acceptance**：[ ] 27 张表都有外键且无空值　[ ] 回填后单号与外键指向一致　[ ] 改号仍全链生效
- **Hard part**：历史脏数据。手填单号的现金流与其他应付可能对不上任何销售单。

### R-9 读路径从单号 join 换成 id join

- **Approach**：读路径的 join 从单号换外键，按模块分批，财务报表放最后。
- **Touches**：各领域查询服务、报表、对账。
- **Test seam**：现有端到端与领域单测，不新增接缝。
- **Acceptance**：[ ] 改号后报表数字不变　[ ] 对账差额为 0　[ ] 检索仍可按单号
- **Hard part**：替换期两套 join 并存，任何一处漏改都表现为静默少行。

## 3. 阶段

### 阶段 1 — 先能看清线上发生了什么

**Covers**：R-5 工具入参以脱敏摘要落库、R-7 部署健康检查带重试。

**Goal**：一次真实提问之后，能说出线上是哪一版、模型每个工具传了什么。

**Tasks**

- 给健康检查加有上限的重试
- 部署日志同时打印 build 与 release
- 给工具事件加脱敏入参摘要
- 用一次真实提问回放事件表，还原三个工具调用

**Proof**：事件表能还原每个工具调用的入参，部署日志的 build 与 release 对得上。
**Not here**：句柄、入口泛化。

### 阶段 2 — 一条只靠 uid 走通的链路

**Covers**：R-2 根查询改用 uid 派生句柄。

**Goal**：对同一张订单追问，第二个工具的参数里不再出现业务单号原文。

**Tasks**

- 检索结果额外返回一个本轮句柄
- 编排层建句柄到内部主键的映射
- 根查询从句柄还原主键，替掉单号透传
- 一轮只有一张单时允许省略句柄
- 端到端跑通一次「检索 → 三个根查询」
- 补伪造句柄被拒的用例

**Proof**：一次 run 的第二个工具入参不含单号原文，伪造句柄返回 422。
**Not here**：采购单号入口，外键改造。

### 阶段 3 — 任何单号都能进

**Covers**：R-1 采购单号与生产单号入口、R-3 文案写明销售单号。

**Goal**：拿采购单号提问，答案里出现正确的销售单与采购单信息，步骤条不再显示「销售订单」。

**Tasks**

- 把检索扩成按号查任意单据，统一返回句柄与所属销售单号
- 定义同号跨表的解析顺序
- 更新模型工具描述与界面步骤文案
- 更新目录断言与注册表
- 用真实采购单号跑一次问答

**Proof**：采购单号提问得到正确答案，步骤条显示「单号检索」。
**Not here**：外键回填。

### 阶段 4 — 查不到也说得清楚

**Covers**：R-4 单号检索归一、R-6 部分答案。

**Goal**：单号写错或大小写不一致时，用户看到「按某词检索到 0 条」，而不是「什么都找不到」。

**Tasks**

- 检索词与单号统一归一后再匹配
- 检索为空时给出带检索词与命中数的回答
- 失败预算耗尽时用已取事实生成降级回答
- 覆盖小写、多余空格、空结果三条用例

**Proof**：三条用例的答案文本都说明检索词与命中数。
**Not here**：模糊纠错与同音字。

### 阶段 5 — 关系键换成外键

**Covers**：R-8 补外键与回填。

**Goal**：改一次单号，全链跟着变，不再依赖 38 张表的文本联动。

**Tasks**

- 列出现存 27 张表与各自的写入点
- 先给采购链路补外键并回填
- 加一致性校验：单号与外键指向同一张单
- 扩到生产、库存、成品链路
- 把改号联动登记表缩到只剩历史与手工单据

**Proof**：新增一张订单走完采购到入库，改号后所有下游仍指向同一张销售单。
**Not here**：读路径改写。

### 阶段 6 — 读路径走 id（2026-10-27 关闭，不做）

**Covers**：R-9 读路径换 id join。

**关闭理由**：审计推翻了前提。在生产快照上跑一致性审计，38 张带单号与外键的表里
「文本键与外键不一致」0 行、「有单号但无外键」0 行——文本 join 与 id join 查到的就是同一批行。
此时重写 62KB 的财务服务是零行为收益 + 一次真实的回归风险，而基线只能证明「本来就不用改」。

**保留下来的护栏**：

- `scripts/snapshot/audit-order-linkage.sql` —— 任意库可复跑，输出 PASS/FAIL；
- `apps/api/test/integration/order-no-linkage.test.cjs` —— 有测试库时自动跑，红了说明两条路会分叉。

**什么情况下重开**：审计出现 mismatch 或 orphan 且不是脏数据，说明文本关联真的会丢行。
