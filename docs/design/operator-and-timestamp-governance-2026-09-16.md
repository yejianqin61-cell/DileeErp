# 操作人与操作时间 · 全站统一治理设计（2026-09-16）

> 上游盘点：`docs/design/operator-and-timestamp-governance-inventory-2026-09-16.md`
> 用户已拍板：**① 两列「创建人 + 最后修改人」② 全站彻底治理 ③ 时间统一固定北京时间、展示到分**。

---

## 一、先解决一个前提：北京时间「固定」得起来吗

盘点发现时间列全是 `TIMESTAMP(3)`（**无时区**），而同一行的两个时间**来源不同**：

| 列 | 谁写的 | 落盘的是什么 |
| --- | --- | --- |
| `created_at` | 数据库默认 `CURRENT_TIMESTAMP` | **数据库会话时区的墙上时间** |
| `updated_at` | Prisma 客户端（`@updatedAt`） | **UTC 墙上时间** |

数据库会话时区若是 `Asia/Shanghai`，同一行的「创建时间」会比「最后修改时间」**早 8 小时**——正好是我们要展示的两列。

部署事实（`docker-compose.yml:1-17` + `deploy-remote.sh:19-23`）：`postgres:16-alpine` **没有设 `TZ`**（容器默认 UTC），但部署脚本明确写着远端主机上**还有一套原生 PostgreSQL**（容器映射 15432、原生占 5432）。**所以线上到底是 UTC 还是本地时区，从代码里判定不了，必须实测。**

### 处置（不猜、让事实可见、可一键修）

1. **把事实变可见**：`GET /api/v1/health` 除 `SELECT 1` 外，再报三项——
   会话时区 `timezone`、`timestamp_offset_detected`（在若干主表上统计 `updated_at - created_at` 的异常样本数）、
   以及判定结论。工厂里打开这个地址就知道要不要修，不必等业务发现时间不对。
2. **把展示口径钉死**：**所有展示与导出统一走固定 `Asia/Shanghai` 的格式化函数**，
   不再用 `toLocaleString()`（它按运行时宿主时区走：导出在 API 容器里跑、界面在浏览器里跑，两边会不一致）。
   这样「展示规则」是确定的，不受部署影响。
3. **给出运维修复命令**（不进 Prisma 迁移）：`ALTER DATABASE <db> SET timezone TO 'UTC';`——
   纯 PostgreSQL 语义、必然可用、对**新会话**生效；不进迁移是因为在非 compose 部署里应用账号可能**不是库 owner**，
   迁移会直接失败卡住发布。命令与校验方式写进 `scripts/` 与部署说明。
4. **历史数据不自动改**：如果实测发现库里确实是本地时区，已写入的 `created_at` 都是偏移值。
   自动减 8 小时在「本来就没偏」的环境上会把数据改坏，所以只提供**带前置校验的**订正脚本，由人确认后执行。
   在订正之前，界面上的「创建时间」对这些历史行就是偏的——**这一点会明确告诉用户**，不静默糊过去。

> 结论：**展示口径我能保证确定；已存数据的正确性依赖一条运维命令，我会把检测手段和修复命令都给到。**

## 二、两列长什么样（口径）

用户点名的两列：**「创建人」「最后修改人」**。时间放哪？财务表格在第十六轮刚做过「一屏看全、不用左右拖」，
再加 4 列必然横向滚动，所以：

- **列单元格 = 姓名 + 次行小字时间**：`张三` / `09-16 14:30`（北京时间、到分、当年省略年份，跨年显示 `2025-12-31 09:05`）。
- 姓名取不到（历史行的 `created_by` 指向已删用户）时显示 `—`，**绝不显示 UUID**。
- 提供 `auditColumns({ withTime: true })` 开关；详情区空间足够，改用具名四行：
  「创建人 / 创建时间 / 最后修改人 / 最后修改时间」。

### 覆盖策略（四层各怎么办）

| 层 | 做法 |
| --- | --- |
| **列表**（单据、主数据） | 表尾加「创建人」「最后修改人」两列 |
| **详情**（抽屉/弹窗/详情页） | 加四行具名字段（人不挤） |
| **明细子表**（单据行） | **不加**：行随父单写入、`created_by` 与父单同源，加了只是重复噪声 |
| **汇总/报表**（跨记录聚合） | **不加单行操作人**（聚合行没有单一操作人）；页脚标注「数据生成时间 + 生成人」 |
| **导出/打印** | 表内加两列（有单行的）；表尾补「导出人 / 导出时间」；**导出人 ≠ 记录的操作人**，两者必须能分辨 |
| 纯导航页、无数据的占位页 | 不适用 |

## 三、三层机制

### 3.1 数据层

- 补 `DailyReportMergeAnomaly` 的 `updated_by` / `updated_at`（唯一真缺口），解决动作写入。
- `AuditEvent` / `InventoryFact` / `UserRole` **不加**（追加型账本与关联表语义，见盘点 3.1）。
- 时区：见第一节，**不改 schema 默认值**（那会动 84 张表的迁移，收益不抵风险）。

### 3.2 接口层：批量姓名解析（全站共同前置）

现在**没有任何 id→姓名通道**，前端只能从 `/auth/me` 拿到自己。因此：

- 新增 `AuditActorService`（`platform/audit/audit-actor.service.ts`）：
  - `namesOf(ids: string[]): Promise<Map<string, string>>` —— **一次 `findMany({ where: { id: { in: ids } } })` 取全部**，
    按 `id` 去重、剔除空值；**禁止在循环里逐行查**（现存 `material-slip-export.service.ts:250` 的批量导出就是逐行查的 N+1，本轮一并改掉）。
  - `attach<T>(row)` / `attachAll<T>(rows)` —— 给行补 `created_by_name` / `updated_by_name`，
    并**保留**原始 `created_at` / `updated_at`（ISO，UTC）。
- **字段命名**：`created_by_name` / `updated_by_name`（snake_case，与既有计算字段 `status_label` / `line_count` 一致）。
- 形态 B 的接口（用 `select` 裁掉审计字段的：报表、告警、质检）**要补上** `createdAt/updatedAt` + 走 `attachAll`。

### 3.3 界面层：公共列工厂（避免 50+ 处各写各的）

- `apps/web/lib/audit-time.ts`：`formatBeijing(value, { seconds?: boolean })`，
  用 `Intl.DateTimeFormat("zh-CN", { timeZone: "Asia/Shanghai", ... })` —— 在 Node 与浏览器里结果一致，**不读宿主时区**。
- `apps/web/components/data/audit-columns.tsx`：`auditColumns<T>(options?)` 返回两个 `ColumnDef`，
  header 固定为 `创建人` / `最后修改人`，`id` 固定为 `created_by_name` / `updated_by_name`。
  **所有列表页改为展开这个工厂**，而不是各自手写两列——这样列名、时间格式、空值兜底、排序规则只有一处定义，
  以后要改（比如改成 4 列）只改一处。
- 详情区用 `auditDetailFields(row)` 返回四行 `{ label, value }`，接进各页已有的详情字段数组。

## 四、验收标准

1. **无 UUID**：全站任何界面/导出都不出现 UUID 形态的操作人（凭证纸与凭证 PNG 的 `制单：{createdBy}` 必须修掉）。
2. **两列一致**：所有业务列表的列名就是「创建人」「最后修改人」，时间格式一致（北京时间到分）。
3. **导出与界面同源**：同一行的操作人姓名与时间，界面与导出**必须一致**（同一个格式化函数、同一份姓名解析）。
4. **导出人不冒充操作人**：生产工序导出的「操作人」当前是**点导出的人**，必须改名或拆成两个字段。
5. **聚合行不冒充**：汇总/报表不得把某一行的人当成整表的操作人；页脚写「生成人 / 生成时间」。
6. **时区可见**：`/health` 能回答「这个库的会话时区是不是 UTC、有没有偏移样本」。
7. **测试**：姓名解析（批量、缺人兜底、不产生 N+1）、北京时间格式（跨年、跨时区输入、空值）、
   公共列工厂（列名/格式/空值）、迁移守卫，全部有测试；API 构建与既有测试全绿。

## 五、已知风险与不承诺

- **历史数据的偏移**：若实测库时区非 UTC，历史 `created_at` 需要人工确认后订正，**不自动改**。
- **本机无 PostgreSQL**：迁移、`/health` 自检、端到端姓名解析都**没在真库验过**，只做静态与单测验证。
- **`updated_at` 的语义**：它是「最后一次写库」，包含系统自动写入（如状态重算）。
  界面上叫「最后修改人」时，含义是「最后一次改动这条记录的人」，**不等于业务上最后一次人工操作**。
- **改名追溯**：现在只存 `id`，用户改名后历史显示会跟着变。若要「当时叫什么」，需要另加姓名快照字段——**本轮不做**，
  已在盘点第七节列为待拍板项。
