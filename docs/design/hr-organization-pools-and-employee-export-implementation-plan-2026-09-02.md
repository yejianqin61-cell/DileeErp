# 人事组织池与员工名单导出施工文档

> 版本：v1.0  
> 日期：2026-09-02  
> 范围：人事模块的部门池、岗位池，以及员工名单 Excel 导出。  
> 本文只定义本期施工方案，不代表本期已经完成开发。

## 1. 目标与边界

### 1.1 本期目标

1. 在人事模块提供独立的“部门池”和“岗位池”页面。
2. 部门和岗位支持查询、新增、编辑、停用/启用、删除（采用可恢复的软删除）。
3. 员工名单支持按不同粒度筛选，并导出真正的 `.xlsx` 文件。
4. 导出字段尽量覆盖员工及其组织归属的完整业务信息，并固定字段顺序，便于财务、人事和管理层使用。

### 1.2 不在本期范围

- 不新增员工薪资字段，不改变车间/非车间员工类型规则。
- 不删除数据库历史记录，不做物理删除。
- 不把部门、岗位改造成可由普通业务用户任意维护的全局字典；权限仍由管理员控制写操作。
- 不导出密码、session token、用户认证凭据等安全字段。

## 2. 当前实现审计结论

当前后端已有：

- `GET/POST/PATCH /production/departments`
- `GET/POST/PATCH /production/positions`
- 部门和岗位启用状态接口。
- 员工列表接口，已返回部门、岗位、员工类型、在离职日期和状态。

当前缺口：

- 部门和岗位没有独立的人事池页面，用户只能在员工表单或生产基础资料中间接维护。
- 当前接口没有明确的删除入口；本期应提供软删除接口，并阻止删除仍被员工、生产单或历史业务引用的组织项，或转为停用。
- 没有员工筛选结果导出 `.xlsx` 的接口和页面操作。
- 导出任务需要明确筛选快照、字段顺序、权限和文件名规则。

## 3. 信息架构与页面施工

### 3.1 人事模块入口

在人事主页面增加“组织资料”区域，提供两个明确入口：

- 部门池
- 岗位池

两个入口分别进入独立页面，而不是把大量维护内容直接平铺在员工目录中：

- `/hr/departments`
- `/hr/positions`

页面必须使用现有组件库：`PageHeader`、`DataTable`、`Button`、`Input`、`Select`、`ActionDialog`、`EmptyState`、`ErrorState`。不得新增浏览器原生业务下拉、原生确认框或裸表单控件。

### 3.2 部门池

表格列：

| 列 | 说明 |
| --- | --- |
| 部门编码 | 唯一业务编码 |
| 部门名称 | 唯一或按现有数据模型约束 |
| 岗位数量 | 当前未删除岗位数 |
| 员工数量 | 当前未删除员工数 |
| 状态 | 启用、停用、已删除 |
| 备注 | 部门备注 |
| 更新时间 | 最后修改时间 |
| 操作 | 编辑、停用/启用、删除/恢复 |

新增/编辑字段：部门编码、部门名称、备注。

行为规则：

- 新增和编辑均校验编码、名称非空及唯一性。
- 被员工或岗位引用的部门不能物理删除；点击删除时应提示“请先停用，或迁移关联数据”，并保留审计记录。
- 停用部门后，员工新建、员工组织调整和岗位新建不得选择该部门；历史记录仍可查询。
- 恢复只能恢复软删除记录，恢复前再次校验编码和名称冲突。

### 3.3 岗位池

表格列：

| 列 | 说明 |
| --- | --- |
| 岗位编码 | 唯一业务编码 |
| 岗位名称 | 岗位名称 |
| 所属部门 | 部门编码 / 名称 |
| 员工数量 | 当前关联员工数 |
| 状态 | 启用、停用、已删除 |
| 备注 | 岗位备注 |
| 更新时间 | 最后修改时间 |
| 操作 | 编辑、停用/启用、删除/恢复 |

新增/编辑字段：所属部门、岗位编码、岗位名称、备注。

行为规则：

- 所属部门必须是启用部门。
- 编辑岗位所属部门时，必须校验目标部门启用；已有员工不会被自动改派。
- 被员工引用的岗位不能物理删除；优先停用，必要时由管理员迁移员工后再软删除。
- 停用岗位后，员工新建和员工编辑不能选择该岗位；历史员工记录仍保留原岗位快照/关联。

### 3.4 池页面筛选

部门池支持：关键词（编码、名称）、状态。  
岗位池支持：关键词（编码、名称）、所属部门、状态。

筛选只影响当前表格，不改变数据库；筛选状态可保留在页面内返回时恢复。

## 4. 员工名单导出设计

### 4.1 导出入口

在人事员工目录顶部增加“导出员工名单”按钮。点击后打开导出条件面板，显示当前筛选条件，并允许在导出前细化条件。

导出默认使用当前员工目录筛选条件，用户可以调整后再导出；不会导出未筛选的全量名单，除非用户明确选择“全部员工”。

### 4.2 筛选粒度

支持以下条件，均为可选，组合使用为 AND：

- 关键词：工号、姓名。
- 员工状态：全部、在职、离职、停用。
- 部门：全部或指定部门。
- 岗位：全部或指定岗位；岗位选项随部门筛选收窄。
- 员工类型：全部、车间、非车间。
- 入职日期范围：起始日期、结束日期。
- 离职日期范围：起始日期、结束日期；可选择“未离职”。
- 是否绑定系统用户：全部、已绑定、未绑定。

日期范围使用闭区间，按数据库日期字段比较；结束日期不得早于开始日期。

### 4.3 导出字段

Excel 第一行固定为中文表头，建议字段顺序如下：

1. 工号
2. 姓名
3. 员工类型
4. 员工状态
5. 入职日期
6. 离职日期
7. 部门编码
8. 部门名称
9. 岗位编码
10. 岗位名称
11. 绑定系统用户名（只导出用户名，不导出认证信息）
12. 员工备注
13. 创建时间
14. 更新时间

空值统一导出为空单元格；日期统一为 `YYYY-MM-DD`，时间统一为 `YYYY-MM-DD HH:mm:ss`；员工类型和状态导出中文显示值，同时保留不暴露内部 ID。

### 4.4 文件规则

文件名格式：

```text
迪礼ERP-员工名单-YYYYMMDD-HHmmss.xlsx
```

文件内容按工号升序、姓名升序排序，与页面排序无关，确保重复导出可比较。

导出响应必须设置：

- `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- `Content-Disposition: attachment; filename*=UTF-8''...`
- `Cache-Control: no-store`

## 5. API 施工方案

### 5.1 部门池接口

- `GET /production/departments?include=counts&status=active|inactive|deleted`
- `POST /production/departments`
- `PATCH /production/departments/:id`
- `PATCH /production/departments/:id/active`，请求 `{ "is_active": boolean }`
- `DELETE /production/departments/:id`，执行软删除；有引用时返回明确业务错误。
- `POST /production/departments/:id/restore`，恢复软删除记录。

### 5.2 岗位池接口

- `GET /production/positions?department_id=:id&include=counts&status=...`
- `POST /production/positions`
- `PATCH /production/positions/:id`
- `PATCH /production/positions/:id/active`
- `DELETE /production/positions/:id`，执行软删除；有引用时返回明确业务错误。
- `POST /production/positions/:id/restore`

写接口继续使用认证、模块权限和管理员权限守卫；列表接口按现有人事/生产模块权限控制。

### 5.3 员工导出接口

新增：

```text
GET /production/employees/export.xlsx
```

查询参数对应第 4.2 节筛选项：`query`、`employment_status`、`department_id`、`position_id`、`employee_type`、`hired_from`、`hired_to`、`left_from`、`left_to`、`has_user`。

服务层必须复用员工列表的查询条件构造器，确保页面查询与导出结果一致，避免两个接口各自实现导致数据不一致。导出只查询必要字段，并按固定排序流式/低内存生成文件。

## 6. 数据与安全约束

- 保持现有 `deletedAt` 软删除和审计字段；禁止物理删除组织主数据。
- 部门、岗位编码唯一性必须在数据库唯一约束和服务层错误映射两层保证。
- 组织项停用/删除不能自动修改员工的历史组织归属。
- 导出接口禁止返回 `passwordHash`、session、角色权限明细等敏感字段。
- 导出操作记录审计事件，至少包含操作者、筛选条件摘要、导出行数和时间；不记录完整员工隐私内容。
- 对导出行数设置合理上限（建议 50,000），超过上限返回可理解错误，后续再扩展异步导出。

## 7. 测试与验收标准

### 7.1 后端测试

- 部门新增、编辑、停用、恢复、软删除及重复编码/名称冲突。
- 被员工/岗位引用的部门删除保护。
- 岗位新增、编辑、部门变更、停用、恢复、软删除及引用保护。
- 导出筛选组合与员工列表查询结果一致。
- 导出文件 MIME、文件名、表头顺序、日期格式和中文编码正确。
- 导出不包含敏感字段，权限不足返回 403。

### 7.2 前端验收

- 人事主页面能进入部门池和岗位池两个独立页面。
- 两个池页面均支持表格查看、筛选、新增、编辑、启用/停用、删除/恢复。
- 员工目录筛选后点击导出，下载内容与当前筛选一致。
- 导出失败显示错误状态，不清空员工目录筛选条件。
- 所有弹窗、表格、选择器使用现有组件库；不使用浏览器原生 `alert`、`confirm` 或业务 `<select>`。

### 7.3 回归验收

- 员工新建/编辑时，部门和岗位下拉只显示启用项。
- 部门池新增后，员工新建弹窗无需整页刷新即可出现并可选中。
- 岗位池新增后，员工新建/编辑弹窗无需整页刷新即可出现并可选中。
- 停用部门/岗位后，已有员工名单、历史日报和工资记录不丢失。
- 导出的员工名单可用 Excel/WPS 正常打开。
