# 银行账户池的界面入口（2026-09-15）

> 用户反馈：「银行池在哪？我咋没看见/」

## 1. 排查结论：后端全套都在，前端一个页面都没有

| 层 | 状态 |
| --- | --- |
| 数据模型 | `banks` 表（bank_code / bank_name / account_name / account_number / currency / swift_code / is_active / remark + 软删除与审计） |
| 接口 | `BankController`（`@RequireModules("finance")`）：`GET /finance/banks`、`GET /:id`、`POST`、`PATCH /:id`、`PATCH /:id/toggle`、`DELETE /:id` |
| 前端 | **只有下拉数据源**：应付管理里「新建付款」「创建应付对账」会 `GET /finance/banks` 填「支付银行」选项；`components/finance/voucher-workspace.tsx` 之类都不涉及 |
| 页面入口 | **没有**。财务一级页当时只有 应收/应付/薪资/收支/报表/凭证 六个板块 |

也就是说：账户只能靠接口写；页面上既看不到池子里有什么，也没法新建第一个账户 ——
「支付银行」下拉永远是空的。用户看不见是必然的。

## 2. 决策

- **D1：放在财务一级页作为第 7 个板块「银行账户」**（`/finance/banks`）。理由：银行账户是**跨模块财务主数据**
  ——应付付款与对账用它（`bank_id`）、收款/工资/收支也会用；而收支管理页已经承担了「收支项目字典维护」，
  再把银行维护塞进去会让那一页负责两种职责。用户的问题正是「找不到」，放一级页最直接。
- **D2：停用优先于删除**。`PATCH /:id/toggle` 是主操作（移出下拉、保留档案、可再启用）；
  删除做**二次确认**（软删除，已引用它的付款单/对账单仍显示账户名称，只是不再出现在下拉里）。
- **D3：不依赖 `components/ui/alert-dialog.tsx`**。实现二次确认时先试了它，发现**它在当前依赖版本下一渲染
  就抛 Radix 的 `Primitive.div failed to slot onto its children`**；隔离实验（直接用 Radix 原语、
  以及与该文件同构的本地包装）都能正常渲染，说明问题在这个包装本身。它当时是**全站唯一没有任何调用方**
  的 UI 组件，所以一直没人踩到。本次改用全站已验证的 `Dialog` 原语，并把这条发现记在这里
  （不建议在修好之前使用该组件）。
- **D4：与「结算账户字典」的区别写在页面上**。收支管理里的「结算账户」是老表「结算方式」的**字典项**
  （`农业银行5706`），收支流水的 `settlement_account_id` 指向它；银行账户池是**主数据**，
  付款单/对账单的 `bank_id` 指向它。两者没有外键关系，自动写收支流水时按账号做保守匹配
  （见 `payable-flow-and-cash-flow-coverage-2026-09-15.md`）。页面上写明这一点，避免财务把它们当成同一份。

## 3. 页面能力

`components/finance/bank-workspace.tsx` + `app/finance/banks/page.tsx`：

- 满页表格：银行编码 / 银行名称 / 账户名称 / 银行账号 / 币种 / SWIFT / 状态 / 备注 / 操作；
- 本地搜索（编码、名称、账号、币种），顶部显示「共 N 个账户（启用 M 个）」；
- 新建与编辑走 `ActionDialog`（币种取币种字典，编辑时保留当前值）；
- 行内「停用 / 启用」与「删除（二次确认）」；
- 空态明确指路：「新建账户后，它才会出现在应付付款、应付对账的『支付银行』下拉里」；
- 顺手把应付页两个「支付银行」字段的标签改成「支付银行（可选；账户在「财务 → 银行账户」里维护）」，
  从使用处反向指路。

## 5. 未验证与待办

- 未在真实 PostgreSQL 上跑过：接口与页面在本机没有可用库，端到端（建账户 → 在应付付款下拉里选中 →
  过账 → 收支流水带上该账户）需要在可用库上验证；
- **历史数据**：老系统「结算方式」里的银行账户（`农业银行5706`、`中国银行（美元）7624`）目前只在
  **结算账户字典**里，银行账户池里没有对应记录 —— 要不要按这两条初始化 `banks` 由业务确认
  （本次没有擅自造主数据）；
- `components/ui/alert-dialog.tsx` 的渲染缺陷没有修（没有调用方，也不是本次范围）；若要修，
  应从「与 `ui/dialog.tsx` 的工作结构对齐」入手并补一条渲染测试。
