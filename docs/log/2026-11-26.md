# 2026-11-26 开发日志

## PWA 首次访问不再整页刷新

### 问题

`sw.js` 安装时 `skipWaiting()`、激活时 `clients.claim()`，首次访问（原本没有 controller）的页面
也会收到 `controllerchange`；`PwaRegister` 对任何 `controllerchange` 都 `reload()`，
导致首访整页刷新一次、已输入内容丢失。基于 `461b9d1` 的浏览器端到端里，多条用例因此停在
`/login`（用户名被清空，必填校验挡住提交）。

### 决定（用户 2026-11-26 确认）

- 只改 `apps/web/components/pwa-register.tsx`：挂载时记录是否已有 controller。
  原本没有时，第一次 `controllerchange` 只记为已接管、不刷新；之后的版本替换照常刷新。
- 原本已有 controller 时版本替换仍刷新；`dilee-static-chunk-missing` 消息仍刷新；最多刷新一次。
- `sw.js` 不改。不采用「删掉 `clients.claim()`」：首访页面在下次导航前不受接管，
  离线兜底与缺失资源通知会失效。
- 不在端到端测试里屏蔽 Service Worker。

### 已知边界

强制刷新（Shift+刷新）后的页面 `controller` 也是 `null`，其后第一次版本替换不会自动刷新。
该页面刚从网络加载，接受这一点。

### 验证

- 新增 `apps/web/test/pwa-register.test.tsx`（9 条）。改动前 8 过 1 失败（首访接管那条），改动后全过。
- `npm run test:unit:web`：lib 461/461、组件 91 文件 1459/1459 通过；web `typecheck` 无错误。
- 真实 Chromium 探针（本地 standalone，按生产 Dockerfile 带上 `public/`）：首访加载 1 次、
  已填用户名保留；改动 `sw.js` 触发更新后加载变为 2 次（版本更新刷新仍在）。
- `npm run test:e2e`（一次性 `postgres:16-alpine` 测试库，Service Worker 未屏蔽）：14 条 10 过 4 失败。
  登录相关失败已消失。
