# 2026-11-09

## 用户拍板（承接 11-07 财务链路诊断的三个 A 级问题）

11-07 主报告 [finance-flow-and-ap-cashflow-voucher-review-2026-11-07.md](../audit/finance-flow-and-ap-cashflow-voucher-review-2026-11-07.md) §0.4 提出三个必须先定口径的问题，用户今日答复：

> 1. 「原材料作为存货吧」
> 2. 「确认即过账」
> 3. 「业务科目只作为辅助核算维度」

设计文档：[finance-accrual-policy-2026-11-09.md](../design/finance-accrual-policy-2026-11-09.md)。

## 决策

| # | 口径 | 影响 |
|---|---|---|
| D1 | 采购入库的挂账借方首选**资产类「原材料」（存货）**，不再首选损益类「主营业务成本」；「主营业务成本」退为兜底 | 资产负债表存货 + 利润表成本不再同时错列 |
| D2 | 确认应收/应付 → **挂账凭证直接 `posted`**，且确认与挂账**同一事务** | 确认后资产负债表立刻有应付/应收；挂账失败整笔回滚；已过账凭证只能红冲 → 大幅收窄手改面 |
| D3 | 业务科目只作**辅助核算维度**，不决定凭证借贷科目 | R1 先按现状（费用类其他应付的借方仍取所选科目），R2 落 `voucher_lines` 的科目 id 与辅助维度 |

## 部署/上线注意

1. **报表数字会变**：确认即过账后，已确认未付款的应付/应收会立刻进资产负债表；红字凭证被排除后，历史红冲不再虚增。上线前应先备份并对上月报表做一次口径差异核对。
2. **旧草稿挂账凭证不会自动过账**：库里存量 draft 挂账凭证需财务在凭证页逐张过账或作废（R2 可提供批量处理）。
3. **新 422 属预期**：对已确认单据做回退/冲销/删除前，必须先红冲其挂账凭证；这是「已过账凭证不可消失」的落地。
4. **未做数据迁移**：本轮无 schema 变更（R1 不涉及 `voucher_lines.subject_id`），生产无需跑迁移。

## R2 / R3（同日第二轮：财务收口）

### 用户拍板（第二次）

11-07 §9 B4/B5 两个问题今日第二次答复（原话见 [R2/R3 brief](../design/finance-governance-r2-r3-briefs-2026-11-09.md) §0 第 11–12 行）：

> 1. 「强制核销额=单据额」
> 2. 「含税/未税按专票/普票拆进项税」

设计文档：[finance-governance-r2-r3-2026-11-09.md](../design/finance-governance-r2-r3-2026-11-09.md)。
**D5 部分取代 2026-09-20 旧口径**（「凭证模板金额一律留空、不按税率自动拆进项税」）：自动挂账专票现在拆进项税；手工凭证模板仍只给结构、金额留空。旧设计/日志顶部已加一行 supersedes 注记，正文未改。

### 决策

| # | 口径 | 影响 |
|---|---|---|
| D4 | 强制核销额=单据额：每条核销 = 该单据未核销余额，Σ核销 = 单据金额；不引预付/预收 | 部分核销/多付少付被封死；**同一张单据不能分次付款/收款**（要分次只能拆单） |
| D5 | 含税/未税按**发票类型**拆进项税：专票三行（借业务科目不含税 + 借应交税费-进项税 / 贷应付账款含税）；普票/无票/未录两行全额 | 成本/费用按不含税入账；付款单/流水/打印件仍含税全额；应收侧不拆销项税 |

### 实现（R2/R3）

- **R2-1 强制核销额=单据额**：`supplier-payment.post` / `customer-payment.post` 新增 `ALLOCATION_MUST_SETTLE_PAYABLE`/`_RECEIVABLE` 与 `PAYMENT_AMOUNT_MUST_EQUAL_ALLOCATION`（details 带单据额/可核销额/请求额）；历史 `partially_paid` 只结剩余余额、不回算。
- **R2-2/R2-3 进项税**：`voucher.service.ts` 加 `INPUT_TAX_SUBJECT_NAMES`、`resolveAccrualTaxSplit`（专票三行、`net=round(amount/(1+r),4,HALF_UP)`、`tax=amount−net`、缺税率/缺进项税科目分别 422）、`r>=1` 守卫；`supplier-payable.service.ts` 加 `invoice_type` 落库、税率边界归一（`parsePayableTaxRate`：>1 视为百分数、归一后必须 0<r<1，否则 `INVALID_TAX_RATE`）、`resolvePayableInvoice` 三入口统一、台账/详情返回 `invoice_type/tax_rate/amount_net/tax_amount`；其他应付建单/确认必须给专票税率；非专票传税率被忽略并审计 `ignored_tax_rate`。
- **R3-3 迁移**：`20261109130000_finance_governance_r3` —— `invoice_type`、`voucher_lines.subject_id/business_subject_id/business_subject_label` + 外键/索引、历史 `subject_id` 按「唯一同名」回填、`(source_type, source_id)` 全局唯一键改**部分唯一索引** `vouchers_source_active_key`。已写好，**未提交**（仓库约定由用户 commit）。
- **R3-1 科目 id / 辅助维度**：所有分录构造落 `subject_id`（唯一同名才落，歧义留空 → 报表 label 兜底）；业务科目只落业务分录行；红字行沿用原行 id。
- **R3-2 报表按 id**：三大报表/明细按 `subject_id`（内部 `@id:` 键）归集，为空回退 label；单行只归集一次；期初表只有 `subject_key`（改名后落 unmapped，不翻倍，R4 处理）。
- **R3-4 红冲后按来源重算**：`activeVoucherOf` 统一「按来源找有效凭证」；部分唯一索引后红冲可重建 posted；`accrual_status` + `reaccrue` 入口。
- **R3-5 冲销联动**：`VoucherService.reverseBySource`；付款/收款冲销 → 回冲流水 → 红冲流水凭证；流水冲销 → 红冲其凭证；幂等不重复。契约外补充：**draft 凭证在冲销/更正时软删作废**（草稿不是账务事实，避免孤儿；lead 已确认保留）。
- **R3-6 业务侧**：`accrual_status = posted > draft > reversed > none`；`POST /finance/payables/:id/reaccrue`、`/receivables/:id/reaccrue`（仅 confirmed/partially_paid；已 posted → 422 `ACCRUAL_ALREADY_POSTED`；删除/草稿/回退/取消 → 422 `*_NOT_RECALCULABLE`；同事务）。
- **R3-7 自动过账 + 流水护栏**：`createFromCashFlowEntry` 生成即 `posted`（显式传参，`createVoucher` 默认值/手工凭证/`createAccrual` 均未改，补 `voucher.post` 审计）；`cash-flow.update` 遇有效 posted 凭证 → 422 `CASH_FLOW_HAS_POSTED_VOUCHER`（details 带 voucher_id/voucher_no）；草稿凭证允许改并作废；存量草稿不自动过账；`regenerate` 对存量草稿仍保持 draft（lead 确认）。流水→凭证仍是**独立请求/独立事务**（按 brief 未重构支付链）。
