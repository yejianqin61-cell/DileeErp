## 2. 意味着什么

### 2.1 财务操作

1. **不能再部分核销/分次付款收款**：一张应付/应收必须一次结清（要分次只能拆成多张业务单据）；多付/少付、预付/预收都被 422 封死。
2. **开票信息必须录**：应付条目要录发票类型；专票必须录税率（价内税率，13 或 0.13 都可，系统归一）；其他应付开专票必须建单/确认时给税率。
3. **收付款凭证不再人工过账**：由流水生成的凭证生成即已过账；已过账凭证的来源流水不可直接改，**要改先冲销**（冲销会红冲凭证），再重开流水。
4. **红冲后可重算**：挂账凭证被红冲后，业务单据通过 `accrual_status=reversed` 可见，可用「按来源重算」重建 posted；已 posted 时不能再重算，必须先红冲。
5. **台账新增信息**：应付台账「发票类型」列，详情显示税率/不含税/税额（非专票为「—」）；挂账状态显示在状态列第二行；只有挂账已红冲才出现「按来源重算」按钮。

### 2.2 账与报表

1. **专票成本/费用按不含税入账**：应交税费-进项税单列；普票/无票/未录不变；付款单、流水、打印件仍是含税全额（资金口径）。
2. **凭证不再只有文本科目**：分录落 `subject_id`，报表按 id 归集（科目改名不再影响历史报表行），历史行按 label 兜底，不会 id+label 双计。
3. **红字凭证不进报表**（R1 已修）+ **红冲后按来源重算**：红冲 → 重算的数字回到报表，不再出现「红冲后永远补不回来」。
4. **冲销不再留孤儿**：付款/收款/流水冲销会同步红冲凭证；凭证红冲不写业务状态，业务侧用 `accrual_status` + `reaccrue` 收口。

### 2.3 数据与上线

1. **必须先跑迁移**：`20261109130000_finance_governance_r3`（新列/回填/部分唯一索引）先于代码上线；生产写稿时尚未应用。
2. **历史凭证不回写**：D5 只影响此后生成的挂账凭证；历史错账按 11-07 批次 D / R3-8 清单人工处理。
3. **存量草稿凭证不自动过账**：生产 9 张草稿挂账（存活 1 / 69.90）、7 张草稿流水凭证（存活 2 / 97.10）由财务按 R3-8 清单人工过账或作废。
4. **查询纪律**：所有「按来源找有效凭证」必须带 `deletedAt:null, status != reversed`（`activeVoucherOf`）；部分唯一索引只约束「未删且未红冲」的行。

## 3. 还没做与去向

**3.1 R4 清单（来自本轮验证，如实记录）**

| 编号 | 项 | 说明 / 理由 |
|---|---|---|
| R4-1 | 期初余额表无 `subject_id` | 科目改名后旧期初落 `unmapped`（金额不翻倍，表尾点名）；需期初迁 id 或保留旧键映射 |
| R4-2 | 历史付款「有核销无 posted 凭证」 | 报表余额与台账 `outstanding` 分叉；需数据修复/补挂账或报表口径调整 |
| R4-3 | 利润表 `unmapped` 把非损益发生额当「未归位」 | 需按报表类型过滤非损益发生额 |
| R4-4 | 进项税留抵是否重分类到资产侧 | 财务口径待拍板；当前资产负债表以 −13 冲减「应交税费」 |
| R4-5 | `withLineSubjects` 每凭证多 2 次科目查询 | 与 `subjectByName` 重复；合并会改 R2-2/R3-1 已验收契约 |
| R4-6 | `voucher_lines.subject_id` 回填覆盖率巡检 | 生产仍有 16 行无法唯一回填，需定期巡检 + 科目文本映射 |
| R4-7 | Excel / PNG 导出未加「业务科目（辅助）」列 | 凭证页/打印有，导出件还没有 |
| R4-8 | 对账列表未返回逐条 `invoice_type` | 对账明细需逐条显示发票类型/税额 |
| R4-9 | 集成测试 R1–R3 全量翻修 | 构造服务未注入 `VoucherService`、引用已删除 `flow.itemId`/`dictionaryItem` 旧字段；本轮记 TEST_BLOCKED，不伪造通过 |
