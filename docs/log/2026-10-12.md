# 2026-10-12

## 其他应付的「明细」与「会计科目」：采购对账明细加两列 + 其他应付可指定科目

### 1. 用户原话与三问三答

用户转来财务反馈并附了 2026-10-10 15:30 导出的
`迪礼ERP-采购对账明细-20261010153051-97行(1).xlsx`：

> 「这边的周金红那几行，也就是备用金付款，看不到明细。你排查一下，系统中是否有相应填写会计科目的地方，
> 导出时，会计科目和明细会放在表格的哪些 column？能不能如果是其他应付，就在订单号那边写出明细」

| 财务问的 | 查证结果 |
| --- | --- |
| 有没有地方填会计科目 | **其他应付一个入口都没有**：条目没有这一列、新建弹窗没有这一格、导入模板没有这一列。科目只在「建应付对账」时整体填一个、或在「登记付款」时填 |
| 导出时科目/明细在哪些 column | 采购对账明细 17 列里**两样都没有**（明细在库里，在 `source_no_snapshot`）；收支明细/汇总有「分类/项目」，付款单有「总账科目」，应付台账原先什么都没有 |
| 能不能把明细写进「订单号」列 | 问了用户，**他选了新增一列「费用说明」**（不建议占用「订单号」：那一列是销售单号） |

### 2. 那张导出件的实况（逐格数的，97 行）

| 类别 | 行数 | 特征 |
| --- | --- | --- |
| 采购行 | 31 | 物料 / 单号 / 数量都有值 |
| 其他应付行 | 66 | 这些列全空，只有 日期 / 供应商 / 币种 / 单价 / 数量=1 / 金额 |
| ↳ 周金红 | 62 | 第 25–86 行（同一批备用金里的一家） |
| ↳ 其余 | 4 | BOSS 直聘、陈镝，以及**两行导入模板的示例行**「示例-请替换成供应商名称」 |

> 那两行示例行是 `OTHER_PAYABLE_SAMPLE_ROWS` 被连示例一起导进了正式库，系统还按名称自动建了
> 一个同名供应商。台账里建议清掉（模板说明第 1 条早写了「上传前删掉示例」，没人看）。

### 3. 根因：备用金被系统**猜**成了「管理费用」

其他应付的来源类型是 `other`，`PAYMENT_SUBJECT_NAMES.other = ["管理费用", "其他管理费用"]`
（`accounting-subject-catalog.ts:348`），于是 62 行备用金全部按损益类「管理费用」归类。

**而备用金在财务那张科目表里是资产类「库存现金（备用金）」**（`accounting-subject-catalog.ts:35`，
同一份表里还有「其他应收款」）。钱出去了但仍是自己的资产，记成费用等于多一笔费用、少一笔资产。
房租（成本类「房租费」）、水电同理 —— 它们的来源类型**全是 `other`**，一条候选链分不开。

### 4. 处置

| # | 改动 | 关键取舍 |
| --- | --- | --- |
| 1 | 采购对账明细**去掉来源过滤**，其他应付留在表里 | ⚠️ **推翻 10-11 的口径**。用户 10-11 说「不要进采购对账单」、10-12 说「排除后看不到明细」——同一件事的两面：她不要的是**认不出来的空壳行**，不是那笔钱 |
| 2 | 17 列 → **19 列**：`费用说明` 紧跟采购单号，`会计科目` 插在合计列前 | 明细**没塞进「订单号」**（那一列是销售单号，混两种含义以后没法按单号筛/排） |
| 3 | 合计列 `[15,16]` → **`[17,18]`** | 下标逐列数出来的：沿用会让合计悄悄落到别的金额列上（都右对齐，报表上看不出来） |
| 4 | 表尾报「采购行 X 行 + 非采购支出 Y 行」并说明靠哪列认 | 一片空的「产品名称 / 产品代码」不加说明会被读成「导出坏了」 |
| 5 | `supplier_payable_entries.subject_id`（可空 / 外键 RESTRICT / 带索引）+ 迁移 | 可空 = 历史行为一字不变；不回填 = 不替财务决定历史账目 |
| 6 | 其他应付**新建 + 导入**两个入口都能选/填科目 | 导入按**名字**解析（财务只会写「库存现金（备用金）」，不会写 UUID）；认不出或重名**按行报错、该行不入库**，好行照常 |
| 7 | 科目优先级统一为 **条目自己的 > 对账单/确认流水的 > 按来源候选链** | 一张对账单可同时含备用金/房租/水电，而单上的科目只有**一个**值 —— 拿它盖住所有条目，备用金又被记成管理费用。三处（挂账 / 付款单 / 台账）逐一改齐 |
| 8 | `usageCount()` 补上 `supplierPayableEntry` | 外键 RESTRICT，少数一张表 → 财务删科目时撞数据库约束（报错她看不懂） |
| 9 | 应付台账（页面 + 导出）加「会计科目」列 | 用户问的正是「导出时科目在哪些 column」；台账是另一张她会看的表 |

**「会计科目」列为什么留空而不写候选链**：其他应付没手选科目时，科目是**确认应付那一步**才归类的
（`other → 管理费用`）。写进报表就是一句「可能还没发生的归类」，而且会把备用金显示成一个费用科目。
这张表是拿来核对的，宁可留空 + 表尾点名。

### 6. 复核抓到的三条缺陷（已修 + 补守卫）

| 缺陷 | 处置 |
| --- | --- |
| **（高，真写错账）** 「确认应付」页的逐条 / 批量两条入口挂账时**完全不看条目自己的科目**（`batchConfirm` 的 `select` 连 `subjectId` 都没查）→ 走这条路确认的备用金照样被记成损益类「管理费用」 | `accrue` 改 `row.subjectId ?? options.subject_id`；两条入口取数带 `subjectId`；前端两个确认弹窗默认带出条目科目；批量弹窗只在整批科目一致时才带默认值 |
| **（中）** 手写迁移写 `RESTRICT` + 索引，`schema.prisma` 没写 `onDelete`（默认 SET NULL）、无 `@@index` → 两边永久漂移且工具报不出来（本仓库连 `migration_lock.toml` 都没有） | schema 补 `onDelete: Restrict` + `@@index([subjectId])`；迁移注释改成如实说明（不能照抄 `supplier_payments` 那条 SET NULL） |
| **（中）** 应付台账的「会计科目」列只看条目自己的科目，看不到对账单级科目，可能与凭证不一致 | 台账改走与记账逐字对齐的三级链：条目 > 覆盖它的对账单 > 候选链 |

### 7. 遗留

1. **备用金归哪个科目是会计判断**（资产类「库存现金（备用金）」/「其他应收款」都可能对），
   系统只把选择权交回去，默认值仍是管理费用 —— 需要财务一句口径。
2. 候选链首位 `other → 管理费用` 对房租/水电是对的、对备用金是错的；在没拿到口径前不动
   （改了会让所有历史的自动归类跟着变）。
3. `prisma migrate deploy` 本机没有可用 PostgreSQL，只做了 schema ↔ SQL 的静态核对。
4. 那两行示例应付 + 自动建档的同名供应商建议清掉。

## 采购订单打印件：单位/含税单价/数量/含税总价 合并成一列四行（同日晚）

用户：「单位，含税单价，数量，含税总价，由于字数比较少，可以合并在一个 column 的四行中。
同时，产品名称和规格型号宽度可以变宽。为了美观」

这是同一张打印件**一天里的第 4 次版式调整**，所以只动版式层，字段与口径一个没动。

| # | 改动 | 关键取舍 |
| --- | --- | --- |
| 1 | 明细 **7 列 → 4 列**：序号 / 产品名称 / 规格型号 / `单位·含税单价·数量·含税总价` | 先问清「四行」的两种读法，用户选**一个产品仍占 1 行**、四对「标签：值」堆在同一格（另一种读法是每个产品占 4 行、页数 ×4） |
| 2 | 产品名称 `22 → 30`、规格型号 `16 → 24` | 腾出来的 3 列宽度全给这两列（用户点名「为了美观」） |
| 3 | 四句话用全角空格把标签补到同宽，冒号对齐 | 格子里第 4 行是「含税总价」，标签 4 个字；不补齐会参差不齐 |
| 4 | 行高写死 60px + `wrapText` | ExcelJS 不算自适应高度：不写死四句话会被压成一行，不 wrapText 会被截断 |
| 5 | 表头网格脱区的 E~I 重新配宽（`[4, 3.5, 3.5, 13, 4]`） | ⚠️ **不能按「哪列原来多宽」照搬**：I 是第三组的**值**格、里面有手机号，要 13；G 是标签格，3.5 够 |
| 6 | **小计从 `SUM()` 公式改成服务端算好的真数字** | 含税总价不再是独立数值列，`SUM` 会指向文字格 → 纸面上小计变 0（比没有小计更糟）。代价：财务在 Excel 里改数量不会自动重算 —— 已写进代码注释与设计文档遗留项 |
| 7 | 明细外框仍画到 I（`TABLE_LAST_COLUMN = 9`） | 表只剩 4 列，再画竖线会把「那一列」切碎；但外框到底才像一张完整的表 |

**没动**：表头 11 格字段、交货地址 / 交期条款整行、备注、交易条款 4 条、签署栏三格。

**验证**：`test/purchase-order-export.test.cjs` 11/11（新增 2 条：四句话逐字内容 + wrapText + 行高；
两列宽度确实变宽）。API 单测全量 **2465 / 2465**（196 文件，`http`/`integration` 除外）。

**给人看的预览**：`docs/review/purchase-order-print-preview-2026-10-13.html`（浏览器打开/直接打印）、
`docs/review/purchase-order-sample.xlsx`（样例数据的真实导出件）。
