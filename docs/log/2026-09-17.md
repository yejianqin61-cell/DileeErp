## Decisions

- **科目表是全站财务口径的唯一来源**，`accounting-subject-catalog.ts` 是它在本仓库的唯一留存处；
  迁移 SQL、`seed.ts`、并入映射、自动归类候选链全部从它生成或与它比对（由 3 组守卫测试钉住）。
- **迁移只做加法**：唯一的 `DROP` 是那张用完即弃的临时映射表；业务表与列一律**改名**而不是重建
  （`DROP COLUMN` 会连数据一起丢）。
- **不做银行账户 → 银行存款明细科目的映射**：科目表里有 `100201`–`100205` 五个银行存款明细科目，
  但 `banks` 没有科目字段，所以凭证的资金分录仍是「银行存款—农业银行5706」这种名字快照，
  不是真正的科目引用。要做需要给 `banks` 加 `subject_id` 并迁移存量账户，本期**明确不做**。
- **本期只接「收支」两张报表的统计口径**，利润表/资产负债表虽有科目表支撑，但不在这句需求里。
- **不上「未分类」以外的兜底分类**：迁移只在「对照表覆盖不到的自定义旧项目」场景下用「未分类」，
  且它是提示财务来改的信号，不是长期分类。

### 第二轮（采购列序、工资批量付款与按月导出、外汇一览表）

开工前先问了 6 个问题（用户逐条选定后才动手）：明细行粒度 = 一次成品出库 + 一张客户汇总 sheet；
期间按**收款到账日期**；定金/货款靠**新增的「款项性质」**区分；批量付款**每人一张付款单**；
跟单与银行手续费**留空 + 表尾写清**；款项性质**加在收支流水上**并给收入流水加一个可选订单号。

**第四问的前提被推翻**：提问时我以为系统里还有「客户付款单」可以加字段，开工后发现它已于
2026-09-16 从界面撤掉（改为「确认即记账」）。已回头向用户说明真实情况并重新征询，而不是照着一个
不存在的前提动手 —— 最终「款项性质 + 订单号」加在 `cash_flow_entries` 上。

做了什么：

- **采购对账明细表**：产品名称移到采购单号之前（用户要求的唯一一处刻意偏离 R1）。金额/含税金额仍在
  最后两列，合计列下标不变；单测同时钉住列序与合计列下标。
- **工资付款批量付款**：`POST /hr/payroll-ledgers/pay-batch`，复用既有 `payLedger` 逐人串行执行、
  逐条 catch 隔离；发放银行在动手之前校验一次；前端勾选/全选/清除，失败行保留勾选并点名原因。
- **工资付款按月导出**：`GET /hr/payroll-ledgers/payment-sheet.xlsx`，18 列，含用户要的**「是否付款」**
  （无需付款 / 已付清 / 部分付款 / 未付款）。三个金额列是 Excel 数值类型；**单币种才给合计**，
  混币种不给并在表尾说明（绝不跨币种相加）。取数不按状态过滤 —— 导出必须与页面同批。
- **外汇一览表**：新的报表 key，导出是**一个工作簿两张表**（外汇一览 + 客户汇总）。
  为此把 `tableFor()` 改成返回 `ReportTable[]`、`sendWorkbook()` 接受数组，页面用 `extra_sheets`
  明说「导出文件还包含：客户汇总（N 行）」。归属规则、四处刻意偏离、不做的事都写进了设计文档。
- **收支流水加两列**：`payment_nature`（定金/货款/尾款/其他）与 `order_no`（可空）。
  确认应收的三条入口（逐条 / 勾选批量 / 按对账单一键）都在弹窗里问款项性质（默认货款），
  由 `recordConfirmation` 落到流水上；手工录定金则在流水表单里填客户名 + 订单号 + 性质。
  `requirePaymentNature` 是全站唯一实现（三条确认入口 + 流水新建/更正共五处都走它）。
  更正时 `undefined = 不改`、空串 = 清空 —— 不区分就会出现「只改金额把性质抹掉」或「永远清不掉」。

过程中发现并修掉的三个真缺陷：

1. `receivable_source` 流水被挂到「订单最早那次出库」上：一张订单多次出库时每笔货款都堆到第一次
   出货，那一行欠尾款变成负数、后面几行虚高。已改为「自己指向的那次出库」，只有订单级收款
   （出货前收到的定金）才退化成「最早那次」。
2. 既没有订单号也没有来源的手工收入流水被**静默丢掉**：候选收款按「订单/来源」收窄查询捞不到它们，
   于是连表尾都进不去 —— 表里的汇入总金额会小于银行流水，财务看不出少在哪。已把「期间内的全部
   收入流水」并回候选集合。
3. `cash-flow-page` 的单测断言歧义：新增两列后有多个 `-`，原来的 `getByText("-")` 匹配到多个元素。
   改为按行、按列计数断言（顺带把款项性质与订单号也纳入了断言）。
