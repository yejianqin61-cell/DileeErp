# 2026-11-04

## 超收（到货 > 订购）与「来料质检按实收登记」完成

用户原话：「仓库模块，采购通知入库进入到来料质检，假如采购伞布数量是1500码，实际到货的1600码，在来料质检中无法修改。因为供应商会多送原料，但是系统不允许到货的大于订购数量。这点要允许。」

**一条规则**：到货数量以实收为准；采购数量只是订单上的计划数，不构成到货上限。超收允许发生、允许登记，但采购单**不改单**（订购量、采购计划、BOM 需求一律不动）。

**后端**

- 到货登记 / 编辑到货批次（`receipt` / `receiptV2` / `updateReceipt`）不再因「到货 > 采购数量」抛 `PURCHASE_OVER_RECEIPT_REASON_REQUIRED`：超收照收，批次 `extension_data` 记 `over_receipt: true` + `over_receipt_reason`（原因由必填改为选填），审计 `purchase_receipt.create` / `purchase_receipt.update` 带 `over_receipt`。
- 来料质检（`incoming-inspections.service.ts` 的 `create` / `update`）去掉「累计检验数量不能超过到货数量」硬上限：实收大于到货时，在**同一事务**里把到货批次 `quantity` 抬到累计实收量（只升不降），并写 `over_receipt` / `over_receipt_corrected_from` / `over_receipt_reason`，另记一条 `purchase_receipt.over_receipt` 审计（from / to / source）。入库上限（合格 + 条件接收）与应付（入库数量 × 单价）随之按实数走。
- 质检、入库、应付的既有门禁一条没松：拒收不可入库、已有下游事实不可改到货/质检、到货关闭后不可再到货、质检分流必须配平。
- 未改 schema、未加迁移；数量关系没有 DB check，抬数量不会撞约束。

**前端**

- 采购单详情：编辑到货批次补「超收原因（选填）」字段并随 PATCH 提交（此前弹窗没有这个字段、PATCH 也不发，1500→1600 在界面上根本走不通）；到货列对超收批次显示「 · 超收」，悬停显示原因。
- 来料质检：登记/编辑弹窗写明「超过到货数量的部分会自动把本批到货数量改成实收数量，不拦单」；送检数量标签改为「可大于到货数量：多送按实收填」。

**测试与门禁**

- API 单测 **2706/2706**：改写「累计检验数量不能超过到货数量」为「超收抬到货数量 + 审计 from/to」；新增「未超收时不改到货」「不填超收原因也能登记并标 over_receipt」「编辑到货改大不再要原因」。

**没做 / 留作后续**

- 不做「超收审批 / 阈值告警」中心：超收目前只在采购单详情标记，报表里体现为到货 > 采购数量。

## 财务「会计科目三处不一致」排查与修复

用户报障：厦门纳益联合专利代理事务所这笔支出，应付确认时选的是「损益类 / 销售费 推广费」，
凭证模块显示「负债类 / 应付账款」，凭证单据里又变成「管理费用 服务费」——
「会计科目要跟着收入支出一条龙走下去，凭证和三大报表都要用这个统计」。

**排查结论（生产库只读核对，未写入）**

- 三个值来自三个字段：应付条目 `subject_id`（销售费 推广费，正确）；收支流水主科目
  `cash_flow_entries.subject_id`（销账对方科目 = 应付账款，权责发生制下正确）；
  凭证分录 `voucher_lines`（财务手工改过）。
- 凭证是**手改的**：`voucher_lines` 行时间戳 = 06:59:53 / 07:37:07（凭证生成时间 06:50:47 / 06:49:58），
  `audit_events` 今天 12 条 `voucher.update (line_edited)`，全是财务账号；线上 dist 与本地 HEAD 哈希一致，
  可确认系统原生成的是「确认应付 = 借销售费推广费/贷应付账款、付款 = 借应付账款/贷银行存款」。
- 真正的代码缺陷：现金流量表第 5 行把「应付账款/应付票据」写在「资产类」分支里，负债类一条都匹配不上，
  **已挂账的付款整笔落进 `unmapped`**（现金流量表里钱凭空消失、期末现金与资产负债表勾稽不上）；
  且落行时没有使用已存的「收支类目」。
- 放大因素：凭证改分录不留改前/改后（审计只有 `line_edited: true`）；挂账凭证没有「重新生成」入口，
  财务只能手改或红冲。

**用户拍板**：修现金流量表（有收支类目就按类目落行）；线上数据先不动；凭证要支持重新生成。

**本轮改动**

- 现金流量表：`StatementVoucher` 增加 `categorySubject`，落行优先用来源流水的收支类目，没有才退回分录科目；
  第 5 行匹配拆成「资产类（存货 + 预付账款）」与「负债类（应付账款、应付票据）」两个分支。
  取数层批量查 `cash_flow_entries.category_subject_id` 并挂到本期/上期的凭证上。
- 凭证重新生成：`regenerate` 支持 `supplier_payable` 草稿（应收挂账暂不开，理由见报告 §7.2）；按来源应付单重建
  「借 业务科目 / 贷 应付账款」，与 `createAccrual` 共用 `accrualDraft`（第一次生成与重新生成逐字一致）；
  资金搬运类应付拒绝并提示删草稿；审计记改前/改后科目。前端对这两种草稿也显示「重新生成」。
- 排查报告：`docs/audit/finance-subject-chain-diagnosis-2026-11-04.md`（含线上证据与时间线）。

**测试**

  voucher-service 新增「挂账凭证重新生成」。
- web：`finance-page` 新增「挂账凭证也能重新生成」行为测试。

收支类目仍只在收支明细表出现（凭证模块展示是下一步）。
