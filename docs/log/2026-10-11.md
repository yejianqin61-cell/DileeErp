### 2. 工序月度汇总（用户选乙）

生产月报表（`GET /production/reports/monthly-production-report.xlsx`）新增第二张 sheet
**「工序月度汇总」**：`工序 | 执行方式 | 单位 | 数量 | 计件金额（元） | 工时（小时，仅计时）`。

工作表顺序改为 **总表 → 工序月度汇总 → 每道工序一张明细**（汇总不放最后：明细有十几张，
放最后等于每次都要翻到最后）。

财务要它的理由：核算表的「计件人工」就是按工序逐道累加出来的，她拿按工序汇总的表才能和账对上；
总表回答的是「哪张单做到哪道工序了」，回答不了「这个月缝伞一共做了多少、花了多少人工」。

四条口径：

1. **与总表共用同一份 `cells`（同一套逐日取大结果），但切法不同 —— 是加总关系，不是单格相等。**
   总表按**工序列**切，而一列可能把多个东西并进同一格（字典名与客户叫法 `验片`/`验伞面`、
   以及未按执行方式拆分的工序列里本厂与外发两批活）；本表按 **(工序, 单位, 生产单执行方式)**
   切成明细行。成立的是：

   > **本表同一道工序各行相加 = 总表该工序列各订单格子相加。**

   ⚠️ **第一版这里写错了**（原话是「数量复用 `cellValue`、三处同一个数」），而且分组键用的是
   **原始工序快照名** → 别名 `验伞面` 与字典名 `验片` 在总表是同一列（合计 300），在本表却成了
   两行（各 100/200），且两行都显示「验片」，看起来像系统重复统计。由独立复核发现，已改成
   **分组键取总表列名**并补了别名用例钉住。
2. **分组键 (工序列名, 单位, 生产单执行方式)**：单位进键 = 「数量不跨单位合计」
   （也正因为单位进了键，行内单位必然一致，数量永远给数值而不会退化成文本）；
   执行方式进键 = 本厂与外发是两批不同的活（`拉边` 因此出两行）。金额是元，不受那条纪律约束。
3. **金额与工时只来自员工日报**（只有它有员工维度与计薪方式），所以两列不做等值假设：
   那天只有员工面报了数而被工序面顶掉时，数量会取更小的工序面（甚至 0），金额却照记 ——
   sheet 表头写明这是正常现象而不是漏算。
4. **工时只算计时行，且没有计时工时留空而不是 0**：一行是一道工序的全月汇总，全月没有计时行
   不是「零工时」而是「没有计时工」，写 0 会被读成「有计时工但一小时都没干」。为此单独加了
   `hoursOrBlank`，**没有改 `hours()`**（明细表那一行的 0 分钟是真的「报了 0 小时」）。

合计行的**数量刻意留空**（一行一个单位，跨行相加会跨单位）；空月份给一行
「（本月无生产日报数据）」而不是一张只有表头的空表。

### 3. 备用金不进采购对账明细表

**根因**：「备用金」是资产类科目（`资产类 / 库存现金（备用金）`）——**不是欠供应商的货款**。
但财务录它走「其他应付」，而其他应付落库时就是一条 `supplier_payable_entry`（`source_type = "other"`）。
采购对账明细表原来的 `where` **一个来源类型都没筛**，于是备用金、房租、水电、运费一起进来了；
这些行没有供应商物料、没有数量、没有采购单，在表里就是一排对不上的空壳。

**改法**：`sourceType: { not: "other" }`（排他而非白名单 —— 将来新增的采购类来源自动进表，
写白名单则每加一种来源都要记得回来改，漏改就是静默漏数）。查过 `schema.prisma:1349` 的
`sourceType` 是**非空** `String`，所以 `not` 不会连 NULL 一起漏掉（可空字段上写 `not` 会静默丢 NULL 行）。

**排除必须在表尾点名**：这张表里原本**有**那些行，现在不见了。只删不说，财务对不上时只能靠回忆，
且无从知道是被有意排除还是导出漏了。取数层额外数一遍被排除的笔数（`excludedOtherCount`）写进表尾，
并给出它们仍在于「应付对账」与「收支流水」——只说「不含」会读成「这些钱不在系统里」。

**连带项**：`purchaseReconciliationDetail` 返回类型从 `T[]` 改成 `{ rows, excludedOtherCount }`。
**被排除的笔数与主查询共用同一个 `scope`**：否则筛了供应商却报出全公司的备用金笔数，表尾那句话
就成了假话；单测有一条逐键比对两个 `where` 的守卫。

**没动应付侧**：其他应付进「应付对账」是对的（其他应付导入后立刻出现在待创建对账），
本轮只把**采购**对账明细表收窄。

## 第二轮：销售单「复制」+ 采购计划「没确定单价的先不下单」

用户同一天又提了两条：

> 「1.销售部分：销售单这边添加一个复制，把别的单的所有详情可以整单导入。用户原话"就是订单描述基本差不多，
> 可以直接用原有的复制，然后我们改下单号和里面的细节就行了，可以这样吗"
> 2.采购部分，采购计划，要支持，确定单价的能下单，没确定单价的先不下单。」

**先问后做**（三个问题、每题给推荐项）：

| 问题 | 他的回答 |
| --- | --- |
| 「复制」的适用范围 | **普通复制**：任何状态都能复制（含草稿）、不要求货号、**新单不记来源**，与既有「返单」并存 |
| 复制出来的新单号 | **留空、必填**（与新建单一致） |
| 采购计划 0 价怎么处置 | **去掉「价格待定」放行**：0 价的行就是不下单，留在计划里 |

### 1. 销售单「复制」——与「返单」是两件事

系统里**早就有**复制机制：**返单**，但它有三道硬门槛（来源必须已确认/已关闭、必须有货号、新单记来源并归进
【返单与总结】的货号分组）。用户这次要的「复制」三条都不需要，所以是**另一个功能**，不是返单的开关。

复制清单照抄返单那条规律：「这一单卖的是什么」照抄（客户/产品/规格/单位/币种/客户单号/外合同号/结算方式/
单价三兄弟/货号/37 个细化标量/`extension_data`/细分明细含列名/材料引用/「其它」行）；
「卖多少、什么时候交」「由数量派生的金额三兄弟」「走到哪了（状态/版本/BOM）」一律不带。

**最要紧的一处**：不写 `reorder_from_order_no`。两头一起挡 —— 接口返回里**根本没有这个键**，
保存走标准 `POST /sales-orders` 且不带它。写错了新单会被归进返单分组，销售会以为这是客户返单。

**第二处**：复制旧单时把**已不存在的物料引用剔掉**并回报（复用返单那两个函数）。不过滤的话新建页会卡死在
`MATERIAL_NOT_FOUND`，提示还叫人「重选」—— 而复制这条路根本没有"重选"这个动作。

### 2. 采购计划：0 价不下单（**推翻 10-09 的「价格待定」**）

这条是同一个用户**前后相反**的要求：10-09 他说「其他辅料是要等客户确认资料了，才有价格出来的……
也问不来的价格的」，于是做了显式放行；10-11 他说「确定单价的能下单，没确定单价的先不下单」。
所以本轮**先问再做**，他选了去掉放行。

**三处一起删**：`PlanOrderDto.allow_pending_price` → `order()` 的例外分支 → `assertOrderableItems` 的
`allowPendingPrice` 例外与 `collectGroups` 第三个参数。**只改默认值而留着开关等于仍然有一条通往
0 元采购单 → 0 元应付的路**（应付 = 入库数量 × 采购明细单价）。`receipt()` 的
`PURCHASE_ITEM_PRICE_PENDING` 仍留着兜住 10-09~10-11 已下出去的历史单。

**前端**：勾中的行全没价 → 直接拦住并说清「先点填单价」；有价没价混在一起 → 只下有价的那几行、
弹一次复核框点名哪几行留在计划里；预览面板多一句 `plan-held-back-note`。

**踩到的两个坑（都记下来）**：
1. **按钮的禁用规则**：第一版把「勾了但都没价」也灰掉了，结果采购员点不下去、页面上也没有任何解释
   —— 与 10-09「我真没看到哪里可以手填单价的」是同一类坑。改成只有「一行都没勾」和
   「有价的行还没选供应商」才灰。
2. **测试里的整页文本查询**：`getByText(/第 1 行/)` 会同时撞上表格行号，报 "multiple elements"。
   断言必须限定在 `plan-error`（顺手给它补了 `role="alert"`，对读屏也更正确）。

### 4. 过程：一个功能派了同伴，我改另一个

两条需求互不相干、文件不重叠，所以把「销售复制」整块派给一个同伴（共享任务板 task-1），
我自己改采购那条。**不重叠**这一点是刻意选的：两边都碰 `dist/`，同时跑全量测试会打架，
所以终验（全量 API + 全量 web）由我在这边收口时统一跑。

同伴交付后我独立复核了它最要紧的几处，而不是只看它的测试报告：
`copy-snapshot` 的路由**声明在 `@Get(":id")` 之前**（否则会被当成 UUID 吃掉）、
返回的 `copy` 里确实**不含** `order_no`/`order_date`/`quantity`/`delivery_date` 与金额三兄弟、
**没有来源键**、`usableMaterialRefs`/`usableMaterialExtras` 的签名与返回值（`{refs, dropped}`）对得上、
编辑器的保存分支在 copy 模式下**只带 `extension_data`**、不写 `reorder_from_order_no`；
并替它把两处占位日期（`2026-10-XX`）补成 `2026-10-11`。

### 5. 待用户拍板

1. **复制是否继承 `extension_data`**：同伴带了（用户要「整单导入」，而表单里没有它的输入格，
   不带就是静默丢数据）。若口径上不该继承，一行可改。
2. **复制是否该拦「有下游事实」的单**：按用户口径**不拦**（任何状态都能复制）。复制一张已有
   BOM/采购/出库的单是安全的（只抄字段，下游事实不跟着复制），但若希望「连 BOM 一起抄」那是另一个功能。
3. **历史「价格待定」单的存量**：库里还有多少「已下单但单价是 0」的行，本机查不到。那些行在补价前
   **不能登记到货**，上服务器后值得看一眼。
4. **`allow_pending_price` 的部署顺序**：DTO 已删该字段，旧前端若还带着它会被 `forbidNonWhitelisted`
   拒绝（有意为之：宁可报错也不要静默生效），所以**前后端要一起上**。
