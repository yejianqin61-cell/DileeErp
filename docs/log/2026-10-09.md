# 2026-10-09

## 第八轮：采购计划「填单价」重新设计 + 「价格待定」下单与补价

### 8.1 用户原话与追问

> 「我还是希望在采购计划中前端也能允许填写价格。也可以选择导入BOM的对应的物料的价格。
> 因为用户反馈：其他辅料是要等客户确认资料了，才有价格出来的，现在客户都没给资料，也问不来的价格的。」

追问「0 价怎么下单」时他的回答是：「我真没看到哪里可以手填单价的。可以重新设计这一块。」
（导入范围他选了：只填还没填（0 价）的未下单行。）

### 8.2 根因：入口藏在 14 列的第 8 列里（宽 6%）

计划详情是 14 列的浮层，单价那一列 `width: 6%`、没有标签、没有说明，混在数量/库存/单位/行总价中间。
同时「单价 0 不能下单」是硬门禁，对"要等客户确认资料才有价"的辅料来说等于把流程卡死。

### 8.3 做了什么

1. **填价入口**：计划面板顶部加状态条（「共 N 行，还有 M 行是 0 价」）+ 按钮
   「填单价（还有 M 行没填）」；点开是一个逐行填的浮层（行/物料/数量/单价/行总价/状态）。
   改的是同一份草稿状态，**点「保存计划」才落库**。
2. **导入 BOM 参考单价**：浮层里一个按钮，**先重新取一次详情**（BOM 上的价可能是打开计划之后才填的），
   再只填空的未下单行；手填过的价、已下单的行一个字都不动，结果文案把"没填上的"也报出来。
3. **「价格待定」下单**：0 价行被勾中时先弹确认框（说清哪几行 + 后果），确认后才发请求，
   请求体带 `allow_pending_price: true`。这个开关**只有计划接口有**，两个原始采购单接口一个字没松。
4. **补价**：已下单且库里单价是 0 的行可以在计划里补价（其余字段照旧锁死；补上就重新锁死）。
   一次事务里改三处：计划行、采购明细（unitPrice + amount）、采购单头 totalAmount；留两条审计。
   已**有到货事实**的 0 价行不许补（钱早按 0 走过账），要走财务的应付调整。
5. **门禁挪到到货登记**：0 价明细不许登记到货（`PURCHASE_ITEM_PRICE_PENDING`）——
   所以"0 元应付"这条链的终点仍然不存在。

### 8.4 下一轮要留意的一个写法的修正

`plan-detail-sheet.tsx` 里那个"数字显示形式"的本地函数原来是
`String(v).replace(/0+$/, "").replace(/\.$/, "")` —— 它在 `"10"`（没有小数点）上会剥成 `"1"`。
接口一律给 4 位小数所以一直没暴露，但它是个"看着一样、错得很安静"的写法。
现在实现只有一处：`lib/purchase-plan-price-entry.ts` 的 `trimPlanNumber`（只在**小数点之后**剥零），
有用例钉着。
