### 3. 修法（08824d9，15:04 提交 / deploy8 15:14 上线）

- **BigInt 不再靠调用点自觉**：新增 `apps/api/src/platform/http/bigint-json.ts`（`installBigIntJson()`），
  在 `main.ts` 启动时打全局补丁 —— 漏转的 BigInt 序列化成**字符串十进制**而不是 500。
  ①按全站约定新增 `openingBalanceTotalsPayload()` 出字符串；③被同一个补丁一并覆盖。
- **审计的 `entity_id` 做规范化**：非 UUID 的值不落 UUID 列，改记 `details.entity_id_raw` 并打警告。
  口径是「审计是附带记录，不该因一个字段格式问题打断业务；但也不能静默吞掉，否则调用方的 bug 永远看不见」。
  ②的调用点同时改成传 `undefined`、编码进 `details.material_code`。
- **测试夹具与生产同形状**：5 个测试文件里合成的 id（`unit-created` / `customer-created` / `def-1` /
  `handling-1` / `entity-1`）改成 **UUID 形状** —— 7 条既有用例原本断言「服务接受任意字符串作为 entityId」，
  这条假设在真实库上不成立。
- 新增 9 条单测（含「整份响应必须过得了 `JSON.stringify`」与「未打补丁时确实会抛」）。

## 当天稍后（用户）：付款单的汇率与保存键 + 交税凭证模板

用户原话：**「付款单要有填写汇率的地方，保存键。生成凭证时要有交税的那一项。」**
（同一条消息里还有「提交，push」——那件事是：把积压的文档提交为 `c00b05d` 并推送，
`origin/main` 与本地 0/0。）

三件事各拍了一次口径，落地方式与**刻意不做的部分**都写在
`docs/design/finance-slip-archive-and-tax-voucher-template-2026-09-26.md`，这里只记要点与代价：

1. **汇率与折合人民币**：单子版式加一整行 R6（币种 / 汇率 / 折合人民币），分录区与合计行整体下移。
   汇率精度取 **8 位**（与 `exchange_rates` 同精度），不跟跨行转账单的 6 位 —— 汇率的精度只该有一个出处。
   **不自动折算**：折合人民币是手填的一格，留空就是留空（与「不按税率自动拆进项税」同一条口径），
   界面上把这句话写出来（这两格看起来是一对，不说财务会以为系统算过了）。
2. **保存键 → 单子落库**：新表 `finance_slips` + `finance_slip_lines`（迁移
   `20260926120000_finance_slips`）。边界是这一轮最要紧的事：**保存不改任何账** ——
   不写收支流水、不生成凭证、不动应付/应收状态；「钱付没付」仍由确认付款回答。
   校验随之**分层**：`validateFinanceSlipShape`（保存：只拦结构）与 `validateFinanceSlip`
   （导出：另加编号、对方单位、借贷平衡）—— 逼财务填平才能存，等于把保存变成「必须一次做完」。
   新板块「收付款单」（`/finance/slips?kind=`）：找回、打开继续改（**覆盖同一张**）、再导出、作废（原因必填）。
3. **交税凭证模板**：借 应交税费 / 贷 银行存款，落在既有的模板机制里；候选科目只到「应交税费」本体，
   不猜税种明细（猜错了凭证上看不出异常）。

### 顺带查出来的一处**长期红着的守卫**

给新控制器补 HTTP 契约覆盖时逐条数了一遍 `finance-contract.test.cjs` 的路由表，发现
`finance.route_table_matches_the_controller_size` 的断言**早就不成立了**：
表里实际有 **27 条 POST**，断言写的是 **25**，总数也写着 50（实际 52）。
来由是 2026-09-24 那一批加了 3 条 POST 路由（两张 `batch.xlsx` + `bank-transfer-slips.xlsx`）却只把断言从 24 改到 25。

它为什么没人发现：`npm run test:unit:api` 只跑 `test/*.test.cjs` 与 `test/unit/**`，
而 `test/http/**` 要 `TEST_DATABASE_URL` 才跑（部署侧那一步是**条件执行**，环境没配就跳过）。

处理：① 断言与表对齐（20 GET / 28 POST / 5 PATCH / 3 DELETE = 56 条登记路由）；
② 把「本表等于控制器规模」这句话改成实话 —— 四个控制器实际声明 **67** 个路由，
本表是**精选子集**（56/67），差额（`batch-confirm*`、`payable-entries/import`、`other`、
两张导入模板、`confirm-receivables` 等带必填业务 body 或导出路由）作为**已知缺口**写在文件头，
并说明「要补上得先给每条路由设计一个只读且能抵达校验层的探测方式」；
③ 新控制器（`finance-slip-store.controller.ts`）进 `authorization-matrix-contract.test.cjs`
的矩阵（38 → 39 个控制器，新增 `finance-slips.list` 条目）与 `finance-contract.test.cjs` 的
5 条路由（列表 / 详情 404 / POST / PATCH / DELETE 的校验层探测）。
