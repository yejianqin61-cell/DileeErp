## 二、完成事项

### 1. 领域模型与数据结构

- 建立工序日报、员工日报、生产薪资来源、生产日报告警四类领域模型。
- 统一使用 UUID、审计字段和逻辑删除字段，并保留 `order_no` 及必要的业务快照。
- 新增迁移：`20260822120000_production_daily_reports_alerts_payroll_sources`。
- 新增日报幂等与版本控制迁移：`20260822123000_daily_report_idempotency_and_versions`。

### 2. 后端 API 与业务规则

- 完成工序日报的列表、详情、新增、修改、逻辑删除和影响预览 API。
- 完成生产单工序累计进度查询，计算目标量、累计量、差额、超单量和当前状态。
- 完成员工计件/计时日报及只读薪资来源查询；计时日报保留件数用于统计和差异核对，但件数不计入薪资金额。
- 服务端按有效计价、员工状态、数量/时长和适用日期执行校验，并使用 Decimal 计算金额。
- 完成差异、超单告警的查询、详情、确认和审计 API，支持 `pending -> confirmed/recovered` 状态流转。
- 日报新增、修改、删除均在事务内重算进度、差异和告警，并写入操作审计。
- 修改和删除要求填写原因，支持幂等键、乐观版本校验、影响预览、附件关联和联动回退。

### 3. 前端工作流

- 生产页面已接入真实工序日报、员工计件/计时日报、进度、告警和薪资来源数据。
- 使用 React Hook Form 处理录入；累计量、金额和状态统一由服务端计算，前端不重复实现业务规则。
- 支持影响预览后逻辑删除、告警备注确认、附件上传关联和幂等提交。
