# 2026-11-03

## 销售单删除与孤立单据（Round 9 第 1 条）完成

用户原话：「针对销售单部分，我需要能够删除销售单。相对应的采购单及其后续绑定的单据不删除而是显示孤立单据。」

同日拍板（三问都选推荐项）：**显示方式** = 下游列表打「孤立」标记 + 销售模块新增「孤立单据」汇总页；**删除防护** = 弹窗列出会变成孤立的单据 + 非草稿必须填原因（草稿仍一键删）；**权限** = 有 `sales` 模块权限的人都能删，不额外锁管理员。

**一条判定**：孤立 ⇔ 下游单据的 `sales_order_id` 指向的销售单 `deleted_at` 非空。下游单据一行都不动（不删、不解绑、单号不变）——「孤立」是读取时算出来的，不是写进下游表的标记；删错了清掉 `deleted_at` 就自动接回。也因此 phase 5 的单号联动守护继续成立（`mismatched`/`orphan` 仍为 0）。

**后端**

- `DELETE /sales-orders/:id` 对所有状态开放，不再因「已有下游事实」拒绝；草稿一键删、已确认/已关闭必须填原因，且**锁行后再判一次**（防并发 confirm 绕过）。审计记 `reason` + `orphan_documents`（各类型计数）+ `orphan_total`。
- `GET /sales-orders/:id/delete-preview`：11 类下游单据计数，只列 `count > 0`；`reason_required` 由状态给。与执行共用同一张清单（新 `modules/sales/orphan-documents.ts`）。
- `GET /sales-orders/orphans`：按被删销售单分组（删除时间倒序、删单人姓名解析、姓名取不到补 null 不回落到 UUID）；单体单据明细归一成「类型/单号/状态/金额/发生时间」，明细上限 1000 行但 `totals.documents` 是真实总数（`truncated` 单独标）。BOM 没有单号列，显示 `BOM v3`；采购计划没有状态列，给 `null`。
- `orphaned` 下发到 8 类接口（列表 + 详情）：采购单、采购计划、生产单、成品出库单、出库通知、应收来源、应收对账、BOM。下发时剥掉 `salesOrder` 对象，只留布尔，避免接口形状漂移。
- 路由顺序：`@Get("orphans")` 必须声明在 `@Get(":id")` 之前，并加了一条源码级守卫。

**前端**（7 个 commit，全部 apps/web）

- 销售单列表：删除对所有状态开放；非草稿 → 先读影响面 → 确认框按类型列出「会留下哪些单据、各多少张」→ 必填原因 → `DELETE`（body 带 reason）；草稿仍一键删（2026-10-08 的口径不变）；失败把服务端原因留在弹窗里。
- `OrphanBadge` / `OrderNoWithOrphan` 只有一份实现，判定只认后端 `orphaned`，前端不按单号推断（删除后单号可被新单复用，按号猜会把旧单据错挂到新单）。
- 新页 `/sales/orphans`：按 `sales_order_id` 分组（不按单号分组）、空态「没有孤立单据」、1000 行截断提示、销售板块入口。
- 覆盖：采购单列表/详情、采购计划列表/详情 Sheet、BOM 表（孤立 BOM 也列出来且能打开）、生产单列表/详情、仓库成品出库单与出库通知、应收来源、应收对账列表/详情、汇总页。
