# 2026-11-11

## 用户反馈：生产和采购模块的 BOM 表要能搜索

> 「用户反馈，需要在生产和采购模块的BOM表页面加上搜索功能」

### 现场盘点

BOM 表是**同一份业务、两处界面**：

| 入口 | 表实现 | 数据源 | 之前 |
|---|---|---|---|
| 采购 → BOM表（`app/procurement/boms/page.tsx`） | `DataTable` 5 列 | `/sales-orders?status=confirmed&page_size=200` + `/boms` 的孤立行 | 无搜索 |
| 生产页【BOM表】面板（`app/production/page.tsx`） | 手写 `<table>` 3 列 | 同上第一段 | 无搜索（**同页**的「生产单查找」有搜索框，用户自然会以为 BOM 表也有） |

生产库只读实测：未删销售单 55 张（已确认 54 / 草稿 1）、未删 BOM 48 张 —— 这一页 200 张的取数上限远没有被摸到，
所以是**纯前端过滤**，不需要新接口。

顺带发现同一页两个搜索缺陷（都与本轮改动同源：过滤口径 ≠ 展示口径）：

- **A**：`searchSalesOrders()` 把服务端搜索结果写进页面主列表 `orders`，而 `orders` 同时是【BOM表】的数据源 ——
  在「新建生产单」对话框里搜个单号、关掉，BOM 表就只剩被搜到的那几张。
- **B**：「生产单查找」用后端原值 `draft` 匹配，而屏幕上显示「草稿」—— 照着屏幕输关键词搜不到
  （`test/production-page.test.tsx` 里以 `KNOWN_DEFECT` 钉着）。

## 决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 两个入口**都**加搜索，各自一份状态 | 用户说的就是两个模块；只加一处等于让「找单子」取决于你去哪个模块 |
| D2 | 匹配语义复用 `lib/fuzzy-search` 的 `fuzzyMatch`（空格分词 AND、忽略大小写与空白） | 全站搜索框同一套语义；各页各写 `includes` 会出现「同一个词这页能搜、那页搜不到」 |
| D3 | 只搜**这张表看得见的列** | 搜到一行却看不出哪段命中，用户会以为搜索坏了 |
| D4 | 状态的中文标签与后端原值**都能**命中 | 单元格显示的是「草稿 / 已确认」，用户照着屏幕搜 |
| D5 | **客户端过滤**，不新增 `/search` 请求 | 数据本来就全量在手（54 张）；服务端搜索还会漏掉孤立 BOM（它们不在 `/sales-orders` 里） |
| D6 | UI 三件套：`.filter-bar` + 计数条 + **分层空态** | 形状与全站一致；计数条是「筛掉了多少」的唯一证据；空态要分清「没有匹配」与「真的没有数据」 |
| D7 | 生产页两个搜索框状态不共享（`query` / `bomQuery`） | `query` 还被 `?order_no=` 深链预填，共用会出现「点了深链 BOM 表也只剩一张」 |
| D8 | 顺手修掉同页 A、B 两个缺陷 | 新加的搜索框旁边不能摆着两个同样难用的搜索框；缺陷 A 会让新搜索框「用过对话框之后就骗人」 |

设计文档：[bom-table-search-2026-11-11.md](../design/bom-table-search-2026-11-11.md)。

## 实现

### 采购 → BOM表（`apps/web/app/procurement/boms/page.tsx`）

- 新增 `query` 状态与 `filteredBomRows`（空查询直接返回原数组）。
- `searchableFieldsOf(row)` = 订单号 + BOM 状态（原值）+ `displayText` 中文标签 + 孤立行的「孤立」。
- section 加 `panel-heading`（「BOM表」+ 计数 `data-testid="bom-count"`：`共 N 条，当前列出 M 条`），
  `panel-body` 顶部加 `.filter-bar` + `Input data-testid="bom-search"`（placeholder「输入关键词，空格分隔多个词」）。
- 空态分层：搜索无命中 → 「没有匹配“…”的 BOM 表」+ 总数；完全无数据 → 原「暂无已确认销售单」+ 草稿提示。
- 取数、列定义、删除/新建入口一律不动。

### 生产页【BOM表】（`apps/web/app/production/page.tsx`）

- 新增 `bomQuery` + `bomVisible`（订单号 / 数量 / 单位）。
- 面板加计数 `data-testid="production-bom-count"`（`共 N 张确认单，当前列出 M 张`）与
  `Input data-testid="production-bom-search"`（placeholder「输入订单号或数量」，**刻意**与「生产单查找」的「输入关键词」不同名）。
- 只在有数据时渲染搜索框与计数；无数据保持原空态。
- 缺陷 A：拆出 `dialogCandidates`，对话框的服务端搜索只写它 + `ordersRef`；`orders` 保持全量，
  `candidateHint` 只认全量；关窗时 `dialogCandidates` 复位。
- 缺陷 B：「生产单查找」的过滤改成 `fuzzyMatch(query, [生产单号, 订单号, status, displayText(status)])`。

### 测试

- `apps/web/test/procurement-bom-page.test.tsx`：新增 `describe("采购 → BOM表：搜索（2026-11-11）")` 6 例
  —— 按订单号过滤 + 计数、空格分词 AND、中文状态/原值都能搜、孤立行可搜、无匹配空态（不能退化成「暂无已确认销售单」）、清空恢复。
- `apps/web/test/production-page.test.tsx`：
  - `KNOWN_DEFECT：按界面上显示的中文状态搜索返回空结果` → 改成**正向**用例（「草稿」「进行中」「draft」都命中，清空恢复全量）；
  - 新增 `describe("生产单列表页：BOM 表搜索（2026-11-11）")` 7 例 —— 按订单号（且「生产单查找」不受影响）、
    按数量 + 分词 AND、无匹配空态、清空恢复、**缺陷 A 回归**（对话框里搜完关窗后 BOM 表仍是全量）、
    搜索框位置与 placeholder 区分、无数据时不渲染搜索框与计数。
- 新增约定守卫 `apps/web/lib/bom-search-guard.test.mjs`：两个 BOM 表入口都必须有 `.filter-bar` +
  带「搜索」提示的输入框 + `fuzzyMatch` + 约定的 `data-testid`，且清单里的文件必须真实存在。
