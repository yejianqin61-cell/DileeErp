### 1. 这一版交付了什么

登录员工在「业务查询」页提问，FakeLlmProvider 经**唯一**的只读工具通道（`search_orders`）查到订单事实，
流式返回带来源的回答；两档数据档位（`laoban/caiwu` = full，其余 = operational）、
单用户单活动 run、幂等键、SSE 断线续接全部生效。六个任务、六个提交，每任务先红后绿。

| 提交 | 内容 |

### 2. 关键取舍（写进代码注释的）

- **数据档位不是表面权限**：`administrator` 在表面权限里最高，在数据档位里只是 operational——
  管理员要查财务必须显式分配 `laoban/caiwu`（工程布局明文）。
- **栏目排最后**：「业务查询」加进 SURFACE_SECTIONS 时放在末尾（account 之后），
  否则 `landingPathFor` 会改掉人事（→/hr）与普通员工（→/）的登录落点；菜单位置由 app-shell 自行决定。
- **部分唯一索引**是单用户单活动 run 的最后闸门（Prisma 表达不了，只落在迁移里），
  `agent-run-constraints.test.cjs` 把迁移 WHERE 清单与 `AGENT_ACTIVE_STATES` 三边同步锁死。
- **状态与事件同事务、条件更新**：取消后迟到的模型增量、异常收尾都写不进终态（有单测钉住）。
- **SSE 绕信封**：`ResponseEnvelopeInterceptor`/`ApiExceptionFilter` 对 `headersSent` 的响应放行，
  这是全局管线里唯一为 agent 动的两处平台代码，各有单测。
- **生产凭据**：`AGENT_READ_DATABASE_URL`（业务只读）与 `AGENT_STATE_DATABASE_URL`（agent_* 专用）
  生产缺一拒绝启动；开发回退 `DATABASE_URL`。

### 4. 过程中修掉的问题

- `QueryPermissionGuard` 的接口依赖 Nest 解析不了 → token 化（agent-tokens.ts）+ `@Inject`。
- 契约测试误用 `expectSuccessEnvelope(response, 201)`：helper 第二参是 options 对象，
  裸数字会被吞掉默认成 200；`api-client` 的 body 需自行 `JSON.stringify`。
- 迁移排序断言的老惯例是「必须排最后」，从本批起改为「紧跟前驱」（新迁移会继续追加）。
