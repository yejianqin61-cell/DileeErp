### 2. 关键取舍（写进代码注释的）

- **数据档位不是表面权限**：`administrator` 在表面权限里最高，在数据档位里只是 operational——
  管理员要查财务必须显式分配 `laoban/caiwu`（工程布局明文）。
- **栏目排最后**：「业务查询」加进 SURFACE_SECTIONS 时放在末尾（account 之后），
  否则 `landingPathFor` 会改掉人事（→/hr）与普通员工（→/）的登录落点；菜单位置由 app-shell 自行决定。
- **部分唯一索引**是单用户单活动 run 的最后闸门（Prisma 表达不了，只落在迁移里），
  `agent-run-constraints.test.cjs` 把迁移 WHERE 清单与 `AGENT_ACTIVE_STATES` 三边同步锁死。
- **状态与事件同事务、条件更新**：取消后迟到的模型增量、异常收尾都写不进终态（有单测钉住）。
- **SSE 绕信封**：`ResponseEnvelopeInterceptor`/`ApiExceptionFilter` 对 `headersSent` 的响应放行，
  这是全局管线里唯一为 agent 动的两处平台代码，各有单测。
- **生产凭据**：`AGENT_READ_DATABASE_URL`（业务只读）与 `AGENT_STATE_DATABASE_URL`（agent_* 专用）
  生产缺一拒绝启动；开发回退 `DATABASE_URL`。

### 2. 关键取舍

- **plan 单步、执行归编排器**：AI SDK 只做参数解析与消息组装（generateText+stopWhen(1)），
  工具永远经 Tool executor——provider 不拿 principal，多步由编排器循环驱动。
- **工具结果消息自包含**（id+tool+args+content）：provider 据此合成 DeepSeek 要求的
  assistant(tool_calls)+tool(tool_result) 消息对，provider 实例无需按 run 记状态。
- **上下文=轮数不是 token**：最近 8 个完成轮次的问答对，应用层不裁剪；超窗由 DeepSeek
  400/context_length_exceeded 映射为 `AGENT_MODEL_CONTEXT_EXCEEDED`，绝不静默删改。
- **生产防呆**：生产环境缺 `AGENT_LLM_PROVIDER=deepseek`/`DEEPSEEK_API_KEY` 拒绝启动——
  静默回退假 provider 会让线上用户拿到演示答案而不自知。
- **观测脱敏靠形状**：事件类型里没有 prompt/答案/参数字段；实测日志 0 处问题原文。

### 3. 证据（本机复跑：起一次性 postgres:16 容器 5434 + migrate deploy + 种子 + API）

### 4. 证据运行揪出的缺陷（都修了，见 fix 提交）

1. `AgentContextManager` 没有 @Injectable → emitDecoratorMetadata 不发参数元数据 → Nest 注入
   undefined → 所有 run 10ms 内 AGENT_INTERNAL_ERROR。教训：**带构造参数的 class provider 必须有装饰器**。
2. failRun 只留稳定码不留堆栈——内部错误无从排查。补：服务端日志记堆栈（不进 SSE/信封）。
3. 假 provider 每轮 plan 都返回同一搜索调用 → 多步循环空转到 8 步上限。改：消息里已有该工具
   结果即返回空调用（无状态判据，provider 是进程级单例不能记 run 状态）。
