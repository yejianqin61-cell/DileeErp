## 销售单 Excel 补录（Round 8 第 4 条）完成

用户原话：「针对销售模块，现在要加一个补录功能。用户上传销售单 excel，系统进行字段读取与匹配，展示一份系统表单，让用户进行修改与确认。用户通过之后，再确认建立销售单。」
同日拍板：**两种版式都认**（先认我们自己的工艺单/生产单，认不出的再按字段名在整张表里找）、**一份文件 = 一张单**。

- **流程三段**：上传（`POST /sales-orders/import-preview`，multipart / 10MB / 只放行 xlsx-xls）→ 服务端**只读解析**并查主数据 → 前端把预填载荷灌进**正式的新建销售单表单** → 用户核对修改 → 「确认建立销售单」走既有 `POST /sales-orders`（草稿状态）。预览阶段一字节都不写库。
- **解析（新 `modules/sales/sales-order-import.ts`，纯函数）**：版式驱动、锚点是纸上的中文标签 —— 表头 14 项（客户单号→订单号、客户代码→客户待匹配、完工日期尾巴进完工备注、数量尾缀读单位）、18 个材料类目（同义词如「伞布」「织唛」）、工艺要求 9 条（按词认，编号是断的）、布量 5 格（靠 `Y/DZ` 与同名材料区分）、正唛/侧唛（值可能在下一行）、细分明细（左右并排多块 + 尾部「伞头」表，分组名取带「明细」的横幅）。认不出的逐格上报，不猜。
- **几处硬判定**（第一版真实踩过）：明细表「整行没有数量」即停（否则把后面整片材料读成明细，多读 19 行）；「材料到货状态」以下不再读（否则把勾选表读成 OPP/伞头的第二款）；「值等于类目名」（织标|织标、钥匙扣|钥匙扣）不算新标签（否则整块错位）；材料区右边界取「明　细」合并范围的右端（否则右栏工艺内容灌进材料格）。
- **主数据匹配（新 `sales-order-import.service.ts`）**：客户按「名称 → 编码 → 去掉括号备注的编码」**唯一命中**（不做前缀模糊，IS/ISUZU 会串户）、订单号只查未删除行的占用、单位按名字归一（pcs→PCS）、币种取客户默认值；对不上就报错/提醒，**不自动新建主数据**。
- **前端**：列表页头「从 Excel 补录」→ `/sales/orders/import`；解析成功整页换成 `SalesOrderEditor`（预填 + 顶部「Excel 补录核对」横幅：一句话汇总 / 必须改 / 提醒 / 可展开的逐格清单与没认出的格子）+「换一个文件重新读取」（只回调不发请求）；四个"必须重填"格这一路按表填好，主按钮叫「确认建立销售单」。
- **测试**：API 新增 `sales-order-import.test.cjs` 27 条（含**导出→解析回读**逐字段相等、两张真实样本端到端 status=ok、内存构造两种版式、日期/数量归一、预填载荷过真实 `SalesOrderDto`、服务层客户/单位/单号/币种/422、源级守卫）；web 新增 `lib/sales-order-import.test.mjs` 6 条 + `test/sales-order-import.test.tsx` 4 条。
- **门禁（补录后）**：`npm test` exit 0 —— 部署脚本 **38/38**、API **2686/2686**、web lib **393/393**、web 组件 **1175/1175**（69 文件），api / coding-worker / web 三处 typecheck 全绿；`next build` 通过（`/sales/orders/import` 静态预渲染）。
- **文档**：`docs/design/sales-order-excel-import-2026-11-02.md`。
- **没做**：一份文件多单拆分、PDF/图片订单、列名映射界面、物料引用自动匹配（Excel 里只有文字没有物料编码）；不自动生成订单号。

## 出库单导出 Excel 与打印（Round 8 第 5 条）完成

用户原话：「现在针对系统中的出库单，要支持导出 excel，支持打印」。同日拍板：**两张都要**（成品出库单导出+打印；领料单/补料单只补打印，导出本来就有）、**逐张**（每行两个入口，不做批量套打）。

- **一条原则**：纸面与导出件是**同一份数据**。成品出库单新增 `FinishedGoodsOutboundExportService.buildDocument`，`GET /finished-goods/outbounds/:id/slip-document` 与 `GET .../export.xlsx` 都吃它；领料/补料单沿用既有的 `slip-document`（明细四个数量同源）。
- **成品出库单版式**（A4 竖版 8 列）：标题（**草稿/已取消/已冲销印在标题上**）+ 表头 3 行 × 4 组（单号/日期/状态/客户、订单/生产单/产品/规格、数量/发货日期/承运商/通知）+ 明细（序号/产品名称/规格型号/单位/数量/备注，合计）+ 发货与签收（运单号/装箱单号/发票号/签收日期/签收凭证/备注）+ 签字栏 + 制单/打印时间页脚。**不印单价金额**（这张纸先到司机与客户手上，价格走财务口径）；空值印空格留给手写。
- **导出**：ExcelJS 渲染同一版式（`fitToWidth: 1`），文件名 `迪礼ERP-成品出库单-<单号>.xlsx`，导出的 xlsx 本身可直接打印；**打印**：仓库成品仓储页每行「出库单」→ 弹窗里就是那张纸 → 「打印 / 另存 PDF」走浏览器打印（`@media print` 只留 `.outbound-slip-sheet`，与记账凭证纸/跨行转账单同一做法）。
- **领料单/补料单打印**：新增纸面组件（版式照样例 xlsx：标题含状态、三行表头、明细 10/8 列、小计、备注），入口在领料单列表页与生产单领料面板每行「打印」；与导出件同一份 `slip-document`。
- **测试**：API 新增 `finished-goods-outbound-slip.test.cjs` 7 条（字段口径 / 状态印标题 / xlsx A4·列名·合计·签字行 / 404 / 路由声明顺序 / 模块注册）；web 新增 lib 测试 8 条（两条 lib）+ 组件测试 7 条（打印弹窗、window.print、导出下载、无数据不留空纸、领料/补料两套版式）；`table-width-coverage` 豁免清单登记了两个打印件（对准纸样的版式件）。
- **样张**：`docs/samples/成品出库单-样例.xlsx` + `成品出库单-样例-预览.png`（LibreOffice 渲染后肉眼核对：表头标签不再被截断）。
- **门禁（出库单导出/打印后）**：`npm test` exit 0 —— 部署脚本 **38/38**、API **2694/2694**、web lib **401/401**、web 组件 **1182/1182**（71 文件），三处 typecheck 全绿；`next build` 通过。
- **文档**：`docs/design/outbound-slip-export-and-print-2026-11-02.md`。
