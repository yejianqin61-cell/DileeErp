## 3. 三个盲区

| 盲区 | 结论 | 证据 |
|---|---|---|
| 正向财务路径 | `laoban1`（full 档）能读到财务事实，无 `AGENT_TOOL_FORBIDDEN`，且**真的调到了**对应财务 operation | `finance_positive` 4/4；账号由 `bootstrap-permission-accounts.mjs --keep-legacy` 建 |
| 答案数值 | 数量、交期、状态都能对上种子数据字面量 | `known_answer` 5/5（1000 / 600 / 2026-09-20 / 非草稿 / 双单并列） |
| `model_steps` | 已随 `completed` 事件下发，中位数 3 | `agent-model-steps.test.cjs` 2 条 |

两个盲区的验证本身也踩了坑，都修了：

1. **正向财务的断言差点是恒真的**。第一版只断言「completed 且无 `AGENT_TOOL_FORBIDDEN`」—— 模型回一句「我查不了财务」也能通过。
   补上 `opsInclude` 到对应财务 operation 才真正验到。
2. **`model_steps` 从未被计数过**。它原来写成 `observability?.record({ step: ++modelSteps })`：`observability` 没接时可选链整体短路，
   `++modelSteps` 根本不执行，`usage.model_steps` 永远是 0。移到 `record` 之前才生效。
   这是本轮唯一一个「为了验证盲区，反而发现原有实现是错的」的例子。

## 4. 顺带修的两处

- **检索词上限 100 → 200**。单号列是 `VarChar(100)`，超过 100 字符的检索词在库里不可能命中 —— 那是「查无结果」不是「参数非法」。
  原来的 100 上限让模型白占一次失败预算去读懂 400。改成 200 后，100~200 之间的检索词照常查询、由既有空结果说明回答。
- **前端补三个 operation 的中文标签**。新入口缺标签会兜底成「订单」「库存」这类域名词，用户看不出模型做了什么。
