### 2.1 门禁失败的唯一原因：一条过期的字符串断言

失败用例（两次部署同一个）：

```
not ok 445 - 一个生产单可以开多张领料单/补料单：三处界面都要有「再建/新建」入口
文件：apps/web/lib/warehouse-issue-sheet.test.mjs:85
error: 列表页要支持按生产单深链筛选
```

断言是**字面量匹配源码**：

```js
assert.match(listPage, /new URLSearchParams\(window\.location\.search\)\.get\("production_order_id"\)/)
```

而 `d18e6bdc`（T-0020 首页任务提醒）在这个页面加 `movement_id` 深链时，把同一段代码提取成了
中间变量：

```ts
const params = new URLSearchParams(window.location.search);
const target = params.get("production_order_id");   // 行为完全一样
const movement = params.get("movement_id");         // 新增的深链
```

**功能没退化，是守卫写法太死。** 用宽松断言（允许中间变量）验证过：页面仍按
`production_order_id` 预筛选 → `true`；现断言 → `false`。

修法一行（把断言改成 `/new URLSearchParams\(\s*window\.location\.search\s*\)[\s\S]{0,240}?\.get\("production_order_id"\)/`），
待批准后改，改完一次部署即可把 T-0018/0020/0021/0022 四条一起上线。

**这个 bug 的代价**：一条断言写法失效 → 全部需求停摆两天。守卫测「行为」不能测「排版」。

### 6.3 修命令判定：命令词不在句首也算指令

`isCommand()` 重写：先反复剥客气/重复前缀（请、麻烦、帮我、现在、再、再次、重新、尝试、
可以、能不能…）与语气尾巴（一下、下、吧、试试、一次），再看剥完的主体。

服务器实测（`/opt/dilee/agent/ticket-agent` 上的代码）：

```
部署                     -> command     操作指令
再次尝试部署             -> command     操作指令      ← 原来是 needs_info
麻烦部署一下             -> command     操作指令
帮我上线                 -> command     操作指令
重新部署                 -> command     操作指令
部署脚本要改             -> requirement 默认按需求     ← 不能被误当指令
把部署脚本改成幂等       -> requirement 改动动词「改成」
需要部署吗               -> question    疑问语气
T-0022 进度              -> status      短问句「进度」
```

实现坑：前缀必须**长词优先**剥，否则 `再次` 被 `再` 吃掉一半剩 `次尝试部署`。
`intent.test.ts` 用例 35 → 43；ticket-agent 全量 **229/229 通过**（服务器 Node 24 下无跳过），
已 `pm2 restart dilee-ticket-bot`，重启未误杀生产进程（`dilee-api`/`dilee-web` uptime 连续）。
