## R-3 Activation 轮次记录完成

- **桥接**：独立 Cordis patch 将 `subagent/start/end` 追加到每个 attempt 独占的 JSONL 文件。
- **字段**：记录单调序号、`runId`、子 Session、provider、local 和结束原因，不写对话正文。
- **防混用**：trace 文件必须由新 attempt 创建；已有文件、缺失路径和畸形记录都会失败。
- **证据**：真实 Builder/Validator 产生两组配对事件与两个不同 `runId`；目标测试和类型检查通过。

## R-3 Session 子树收口完成

- **完成语义**：Worker 固定执行 `run → session/wait → close`，Root 首次 idle 不再直接结束批次。
- **失败收口**：run 失败跳过 wait；wait 失败保留原错误；两种路径都关闭 runtime 一次。
- **证据**：4 个注入式顺序/失败用例与 1 个真实 SDK smoke 通过，Worker 类型检查通过。

## R-3 原 Builder 返工闭环完成

- **链路**：Builder 产出 `h1`，Validator 因缺少跨订单隔离测试拒绝；Root 用 `send_message` 续接原 Builder 产出 `h2`，第二个 Validator 批准 `h2`。
- **身份**：Builder 两轮使用同一子 Session，并产生两个不同 `runId`；四轮 Activation 都有配对 start/end。
- **哈希门禁**：将 `h1` 通过记录重放到当前 `h2` 返回 `revision-mismatch`；绑定 `h2` 的通过记录才接受。
- **完成判定**：纵切经过 `session/wait` 后关闭 runtime；母 Agent 最终返回 `ORCHESTRATOR_COMPLETE_H2`。
- **上游差异**：发布包在 Builder 冷恢复时再次发出同一 Session ID 的 `subagent.started`；Worker 必须按 Session 聚合通知，并用 `runId` 区分轮次。
- **边界**：本次使用本地脚本模型和字面量哈希，不调用外部模型、业务数据或生产发布面。
