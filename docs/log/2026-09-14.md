## Decisions

- 币种是**可配置字典**而不是前后端写死的枚举（PRD/SRS + 宪法 Configurable Business Categories）；管理员可增改停用，已被业务数据引用的编码保留为「历史值」快照而不删除。
- 币种校验放服务层而不是 DTO：字典是数据库数据，同步校验拿不到；字典缺失时放行（部署状态问题不应锁死全站金额录入），一旦有启用项就以字典为唯一口径。
- 采购单币种是**整单一个**，沿用 `purchase_orders.currency`，不做行级币种（与应付来源、付款、对账口径一致）。
- 「一张订单多张采购单」= 按供应商自动拆分；组内明细的供应商强制取组供应商，保证采购单头部供应商与后续到货/应付/对账只有一个口径。
- 草稿行移除只影响草稿，BOM 不变；移除后把「带入 BOM表明细」置为否，避免用户误以为草稿仍是 BOM 的镜像。
- `DataTable` 的既定契约是「默认渲染后端原值，需要中文化的列显式给 cell」（workbench / QC / 外协面板的测试都钉住这一点），因此本轮不改成全局翻译，只补 `statusCell` 工厂。

# 2026-09-14（第二轮：BOM 双模块共同维护 + 生产进度表版式）

设计见 `docs/design/bom-shared-editing-and-progress-sheet-transpose-2026-09-14.md`。

## Completed

- **BOM 表允许生产模块操作**：`BomsController` 的模块门禁改为 `@RequireAnyModules("procurement", "production")`；采购页与生产页共用新组件 `components/bom/bom-workbench.tsx`；生产页新增「BOM表」面板（按订单显示「新建BOM表 / 编辑BOM表」）。
- **冲突用乐观锁而不是「自裁」**（用户选定方案）：保存回传打开时的 `updatedAt`（`expected_updated_at`），服务端在事务里 `SELECT … FOR UPDATE` 后比对，不一致返回 422 `BOM_UPDATE_CONFLICT`；前端显示冲突提示 + 「重新加载最新版本（放弃本次修改）」，本地未保存的改动留在屏幕上。**比对在任何写入之前**，冲突是零写入而不是写一半。
- **生产进度表横纵表头互换**：导出表从「行 = 工序、列 = 日期」改为「列 = 工序、行 = 日期」，目标数量与加工地点保留为表头下两行标注，表尾一行合计（无日报时也输出，值为 0），出货数量移到表头上方的元信息行不再逐工序重复；重名工序补生产单号保证列名唯一。合并工作表（原料对应表 + 生产进度表）沿用同一版式。
- 「新建物料」入口只在采购侧开放：生产侧可以增删 BOM 行、切换物料、改数量/单位/规格/颜色，但不建物料主数据（页面提示物料池归【采购 → 物料清单】）。
- 缺 BOM 的候选提示文案改为「请在本页【BOM表】或【采购 → BOM表】建立」，少一次跨模块跳转。

## Decisions

- 冲突处理选**乐观锁 + 冲突提示**，否决「最后写入者获胜」：宪法《Reversible Business Changes》明确「不得静默覆盖历史」，BOM 直接决定生产单领料量与采购单用料快照，静默覆盖等于让一个人的现场修正凭空消失。
- 令牌用 `updated_at`（不新增表结构）：`Bom.version` 的语义是「BOM 版本」不能挪用；`updatedAt` 已随 API 返回。
- 采购与生产**共用同一个编辑组件**：各自实现必然导致字段口径与冲突处理漂移（历史上「规格型号/颜色被 material_snapshot 覆盖」就是这样出现的）。
- 进度表用「工序做列」是因为列数由工序数决定（本厂约 14），日期改用纵向增长；用户明确选择保留目标数量/加工地点为表头下两行标注。
