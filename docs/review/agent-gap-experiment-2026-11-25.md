## 1. 结论

**判据结果：`adopt_C`，采用最近邻差异方案。** C 组真缺口召回 28/30（底线 80%），诱饵误报 1/30（上限 10%）。
B 组数值略好，但召回与误报各只领先 1/30，未到重开矩阵所需的同时领先 10 个百分点。

270 次运行，出错 0 次，跑满步数上限 0 次。

| 指标 | A 自由文本 | B 四轴坐标 | C 最近邻差异 |
|---|---|---|---|
| 真缺口召回率 | 24/30（80.0%） | 29/30（96.7%） | 28/30（93.3%） |
| 诱饵误报率 | 5/30（16.7%） | 0/30 | 1/30（3.3%） |
| 缺数据误报率 | 0/15 | 0/15 | 0/15 |
| 判出缺口前领域工具调用均值（真缺口题） | 0.58 | 0.17 | 0.25 |
| 同题三次结论一致率 | 17/30 | 27/30 | 26/30 |
| 最近邻与标注一致率 | 不适用 | 不适用 | 23/30（76.7%） |
| 无结构题判缺口（不进判据） | 7/15 | 2/15 | 1/15 |

A、B 的指标口径与 C 相同，只是它们不报最近邻。

## 2. 它改变什么

方向定了：缺口判定按最近邻差异做。但设计里的两处细节照原样施工会出问题，数据如下。

**归并键会把同一缺口拆散。** C 组 10 道真缺口题报出 28 次缺口。

| 归并键 | 不同键数 |
|---|---|
| 最近邻 + 差异类型 + 差异短语原文 | 28（每次都不同） |
| 最近邻 + 差异类型 | 12 |
| 理想值（每题一个） | 10 |

差异短语是模型每次现写的，28 次没有两次相同。设计 §2.4 的归并键依赖「短语归一化」，
按现在的数据，任何字面归一化都合不拢它们。多出的两个键来自 gap-01 与 gap-04。

**`needed_fields` 不是约定格式。** C 组填了 115 个字段名，符合 `模型.字段` 的为 0 个，多数是中文描述。
设计 §2.3 的第 3 条核对若照现在的工具声明实现，带字段的声明会几乎全部被驳回。
实验的工具声明没有写格式要求，所以这说明「不写要求时模型不会自己遵守」，不说明写了之后会怎样。

**最近邻不一致集中在三题。** 7 次不一致全部来自 gap-01（2 次）、gap-03（3 次）、gap-06（2 次）。
gap-01 与 gap-06 的标注是跑之前按审阅建议改过的，模型选的正是改之前的那两个。
若按改前标注计，一致率会是 26/30；这是事后换算，判据与本表一律按审过的标注。
一致率本身不进三选一判据。

**按计划，阶段 3、4 的走向。** 计划只为「停在观测层」与「重开矩阵」规定了改法。
本次结论两者都不是，阶段 3（`report_gap` 与四条核对）、阶段 4（候选归并与门槛）按原计划施工，
阶段 5 起不受影响。

## 3. 局限

- **桩应答污染了误报数。** 领域工具返回固定的 `{"示例字段":"示例值"}`。
  A 组诱饵与无结构题的 12 次误报、C 组的 2 次误报，理由文本全部提到拿到的是占位数据。
  所以误报率偏高于真实数据下应有的值，A 组受影响最大，A 与另两组的差距不能当作方案优劣的证据。
  B 组只交坐标，没有理由文本，无法做同样的归因。
- 这个污染只会抬高误报；C 组带着它仍在上限内。真缺口题的判定大多发生在任何领域调用之前
  （C 组 28 次里 22 次，B 组 29 次里 24 次，A 组 24 次里 17 次）。
- 只用了 `deepseek-chat` 一个模型，每题每组 3 次。B 与 C 相差 1 次运行，不能据此说 B 更好或更差。
- 题集是单轮、题面清晰的问法，由同一作者起草，并与三组提示出自同一批简报；没有用真实用户问句。
- B 组用的是审阅后的六行轴声明（销售对象含物料，库存粒度含跨单行集）。
  实验不检验 B 组坐标是否填对，只看它判不判缺口。
- 无结构五题的标注有争议，只作描述。
- 缺数据类的 0 误报来自「桩返回空数组」，真实系统里部分缺数据的表现可能不同。
- 运行记录不含 token 用量，本报告没有费用数字。
