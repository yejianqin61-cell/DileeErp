### D-1 缺口候选两表未授权，写入被吞

- **症状**：迁移建了两张表，但 `GRANT` 只给了超级用户 `dilee`。Agent 走的是 `agent_state` 账号，写入必失败。
- **证据**：`SET ROLE agent_state; SELECT 1 FROM agent_gap_candidates` 返回 `permission denied for table agent_gap_candidates`。
  `information_schema.role_table_grants` 里两张表只有 `dilee` 一个受权者，共 14 行；`git grep -n GRANT apps/api/prisma` 为空。
- **影响**：模型报缺口后，`record()` 抛权限错，被 `.catch(warn)` 吞掉，工单照常问答。
  线上两表 0 行、`gap_declared` 事件 0 条，至今没人发现。第一个真实缺口会静默消失。
- **判据**：阶段 4 总结已写明「上线前两张表的 `SELECT, INSERT, UPDATE` 权限要手工授」，但没有交付。
- **附带**：`scripts/verify-agent-database-privileges.mjs` 只探 `sales_orders` 与 `agent_sessions`，不覆盖两张新表，所以权限证明是漏测而绿。

### D-2 部署主干闸门在生产被静默关闭

- **症状**：`deployConfigFromEnv` 用 `env.WORKSPACE_MAIN_BRANCH?.trim() || undefined` 取主干名，闸门条件是 `config.mainBranch !== undefined`。
- **证据**：生产 bot 的 `.env` 五个键里没有 `WORKSPACE_MAIN_BRANCH`（`grep -c` 得 0），故 `mainBranch` 为 `undefined`，闸门整段跳过。
- **影响**：工单分支未合入时也允许部署半成品，正是这道闸门要防的事。`main.ts:78` 的另一处默认值是 `agent/main`，两处取值不一致。

### D-3 看门狗看不见子进程 CPU

- **症状**：采样器按 `DILEE_RUN_ID` 找子孙进程，但它拿到的 runId 与子进程环境里的值不是同一串。
- **证据**：`coordinator.ts:968` 传 `runId: ticket-${ticket.no}`。
  `harness-runner.ts:307` 自己生成 `run-${randomUUID()}` 并注入 `DILEE_RUN_ID`（`:353`）。
  `runHarnessImpl` 调用处（`coordinator.ts:825`）没有 `runId`，两边对不上。
- **影响**：`findTagged` 永不命中，只剩主进程被跟踪，而主进程又在 `run-sampler.ts:260` 被排除。
  `maxChildCpuPercent` 恒 0，`watchdog.ts:121` 的第三条判据恒真，跑着 tsc 也会被判疑似卡死。
  测试用假采样器掩盖了这一点（`coordinator-watchdog.test.ts:115`）。

### D-4 磁盘余量不足

- **症状**：根分区 33G/40G，剩 4.9G；每次构建新建 `app.release-*` 约 2.7G，且没有任何脚本清理它。
- **证据**：`df -h /` 得 88%；`du -sh /opt/dilee/app.release-*` 得 2.3G × 3 = 6.8G；`git grep -n app.release -- scripts/deploy` 只在 `remote-build.sh:11` 出现，无清理。
- **影响**：本次部署峰值需约 2.7G，余量 4.9G 勉强够；但历史残留已积 6.8G，正是 88% 的主要来源。再落一次失败构建就可能写满。

### D-5 散文注释违反注释政策

- **症状**：设计 §7.2 要求本轮新写与改动的代码不写散文注释，实际新增 1,049 行。
- **证据**：`git diff dc85d80..HEAD -- apps/api/src apps/web` 计 412 行（非测试）；`tools/ticket-agent/src` 计 637 行。
  最密的 `sales-order-sort.ts` 44/74 行、`warehouse-transfer.domain.ts` 46/109 行。
- **影响**：P6 的注释守卫一上线即红；「为什么这样做」的信息应从代码迁到 `docs/`，现在两边各一份。
- **判据**：`docs/design/dilee-consultant-p2-tool-catalog-2026-11-24.md` §7.2 与 `dilee-consultant-governance-2026-11-22.md` §8.2。

### D-6 实验脚本绕过候选集唯一出口

- **症状**：R-13 要求候选只从 `candidateOperations` 出，实验脚本却直接拼工具清单。
- **证据**：`gap-experiment/groups.mjs:5,45` 与 `run-one.mjs:9,22` 直接 import `TOOL_CAPABILITIES` / `AGENT_TOOLS`。
- **影响**：以后改候选过滤逻辑，实验与线上会分叉，漂移率口径失真。

### D-7 工单续跑标记不可达

- **症状**：`setResume` 只有一处调用，且传 `false`；没有任何路径把它置 `true`。
- **证据**：`git grep -n "setResume(" tools/ticket-agent/src` 只命中 `coordinator.ts:779`（`setResume(latest.id, false, ...)`）。
- **影响**：`git-workspace.ts:238` 的 `resume === true` 分支与它保留同名分支的能力永远走不到；提交 `0665123` 宣称的「接着上一轮干」不成立。
