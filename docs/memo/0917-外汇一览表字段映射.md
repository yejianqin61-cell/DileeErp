## 二、四个与老表不一样的地方（都是刻意的）

1. **加了「币种」列并按币种分段**。老表把 `$6,200` 与 `￥1,005` 写在同一列，甚至同一行的 `货款金额` 是人民币、`汇入总金额` 却是美元。本系统的红线是**绝不跨币种相加**。
2. **加了「其他到账」列**。老表只有「定金/货款」两列，而款项性质有四个取值。硬把「其他/没标注」塞进货款列就是编数据。
3. **每笔收款只出现一次**。老表 `DL260002` 两次出库的定金都写 `$620`（同一笔钱抄了两遍）。这里按规则归属：能追溯到出库的直接挂上，追溯不到的（典型是出货前收到的定金）挂在**该订单出货日期最早的那次出库**上。所以**按本表求「定金合计」是正确的，按老表求会重复计算**。
4. **期间按「收款（实际到账）日期」**（这是你选定的）：一行出库出现在本期表里，是因为它**在期间内确实收到了钱**。因此出货在 3 月、尾款 7 月到账的单子会出现在 **7 月**那一段。「欠尾款」是**截至期间末**的余额（含期间外的收款），所以它是时点值，不能跨期间相加。

## 三、需要你确认的三件事

1. **「跟单」与「银行手续费」两列现在恒空**（系统里没有任何字段记录它们，全库搜过）。你当时选的是「留空 + 表尾写清」。
   - 如果要让它们有值：跟单需要给销售订单加一个字段（下单时录），手续费需要给收款加一个字段，并且要定清楚**手续费算不算进「已收」**（这会影响欠尾款的口径）。跟我说一声我就加。
2. **定金从哪录**：定金是出货前收到的钱，那时系统里还没有应收（应收是成品出库过账时才生成的），所以定金只能在 **收支管理 → 收支流水** 里手工录一笔收入，填上「客户名 + 订单号 + 款项性质 = 定金」。
   - 出货后收的货款不用手工录：在「确认应收」时选款项性质（默认货款）即可。
   - 请确认财务愿意这样录定金；如果不愿意，另一条路是给销售订单加「预收款」字段，但那就不是资金流水了（钱没有落账）。
3. **「其他到账」这一列**要不要保留？它是为了不让「其他/未标注」的收款被塞进货款列而加的。如果你更希望它并进货款列（照老表两列的样子），告诉我，我改成合计口径并把口径写进表尾。

## 四、两个已知的限制

- **「按对账单一键确认应收」产生的到账不会出现在明细行里**：那种确认方式写的是**一条流水覆盖 N 张出库单**（对账单本身就是一张凭证），拆不出每张出库各收了多少。硬拆会让明细行的欠尾款变成编出来的数，所以这几笔会**逐类列在导出文件的表尾**（带笔数、金额、对账单号），并写明「不含在汇入总金额里」。
  - 想让它们也进明细，就得改成「一张对账单写 N 条流水」——那是记账口径的改动，需要你先拍板。
- **订单还没出货就先收到的钱**（定金）同样进不了明细（没有出库行可挂），也在表尾列出订单号与金额。
