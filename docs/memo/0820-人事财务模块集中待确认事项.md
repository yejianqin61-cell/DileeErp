# 人事财务模块集中待确认事项

> 本清单已完成本轮集中确认。结论已合并至 [人事财务模块设计](../design/hr-finance-module-design.md)；销售单价格、外加工费、预收预付、超额核销和会计口径将在后续开发设计中继续细化。

## 已确认前提

- 人事与财务合并设计；员工目录用于工资计算。
- 应收来源：成品出库和其他事项；应付来源：采购原料入库和其他事项。
- 应收、应付、收款与付款均支持分批和一次性处理。
- `order_no` 是业务身份证；涉及订单的应收应付必须可追溯到订单号。
- 生产模块输出车间员工计件/计时薪资来源；财务可在薪资台账独立调整，但不得反写生产日报。
- 所有业务数据遵循“进退皆可”、影响预览、上下游联动和全量审计。

## A. 员工目录与人事基础资料

### 1. 员工目录字段与唯一性
问题：员工目录至少是否维护员工编号、姓名、部门/岗位、入职日期、在职状态、联系电话、身份证/银行卡、备注？员工编号由系统生成还是手工录入？
建议：系统生成唯一员工编号；至少维护姓名、部门/岗位、入职日期、在职状态、联系电话、备注。身份证和银行卡作为敏感字段，只有财务/管理员可见，是否存储由你确认。
身份证，银行卡，啥鬼，不需要
### 2. 在职、离职与历史薪资
问题：员工离职是否只能设为离职/停用，继续保留历史生产日报、考勤、绩效和薪资台账？离职后是否禁止新建日报和薪资来源？
建议：采用；禁止物理删除，历史不变，离职生效后禁止新录入。
确认
### 3. 部门、岗位与员工类型
问题：部门和岗位是可维护字典吗？是否需要区分车间工人、办公室员工、管理人员等员工类型？
建议：部门、岗位、员工类型均作为可维护字典；车间工人可关联生产日报，其他人员不强行关联生产日报。
确认，这些都要支持增删改查
### 4. 考勤范围与录入
问题：V1.0 是否需要每日考勤？记录什么：出勤、请假、加班、迟到早退、缺勤、工时？由谁录入？
建议：先支持按员工和日期的手工考勤，使用可维护考勤类型与备注；不做考勤机、排班或自动导入。
确认
### 5. 绩效范围与录入
问题：绩效是按月、按季度还是按次记录？需要评分、等级、奖惩金额、评语哪些字段？
建议：先支持按员工+期间的人工绩效记录，评分/等级/奖惩金额/评语均可选；具体周期可维护。
都是按月
## B. 薪资台账

### 6. 薪资周期与生成方式
问题：工资按自然月、固定结算周期还是可自选起止日期？薪资台账是按周期从生产日报汇总后生成，还是由财务手动创建？
建议：按可选起止日期创建薪资周期，财务从生产日报汇总生成草稿台账；允许没有生产日报的办公室人员手动建立台账。
按月算
### 7. 薪资构成
问题：除生产计件/计时金额外，是否需要基本工资、加班、考勤扣款、绩效奖惩、补贴、社保、个税、其他调整及实发金额？
建议：预留以上构成，全部人工维护或汇总；V1.0 不自动计算社保、个税或考勤工资。
还有房补，这些就行了。要支持后期管理员自行增删改，灵活为上
### 8. 生产薪资来源与台账调整
问题：生产日报金额是否按员工+工资周期自动汇总为不可编辑“生产薪资来源”；财务是否在台账以独立调整行增删改，而不能直接改来源金额？
建议：采用。台账显示来源明细和人工调整明细，调整必须填原因并审计。
确认
### 9. 薪资状态与付款
问题：是否采用 `草稿 -> 已确认 -> 部分支付 -> 已支付 -> 已关闭`？工资付款是否支持分批，付款后允许通过工资付款冲销/补付更正？
建议：采用；已确认台账不直接覆盖金额，使用调整行；已付款不允许删除，使用冲销/补付。
确认
### 10. 考勤/绩效与薪资联动
问题：考勤和绩效是否自动带入薪资台账，还是只作为财务人工调整参考？
建议：V1.0 只展示为参考，由财务手动录入对应调整，避免在规则未稳定时自动计薪。
确认
## C. 应收与收款

### 11. 应收生成时点
问题：成品出库后是否自动生成应收草稿，还是由财务/销售手动根据成品出库创建应收？客户签收是否是应收确认门禁？
建议：成品出库生成可追溯应收草稿，财务确认后生效；签收日期和物流凭据保留为确认参考，不在 V1.0 强制阻塞，除非业务要求。
确认
### 12. 应收金额口径
问题：应收金额来自销售单约定、出库数量乘销售单价，还是由财务手动填写？是否有币种、税率、折扣、运费和其他费用？
建议：保留来源金额快照、币种、含税/未税、税率、折扣和其他费用；最终应收金额由财务确认并保留调整原因。
确认
### 13. 分批出库与应收
问题：一个订单分批成品出库时，是每次出库形成一条应收，还是多次出库汇总为同一订单应收？
建议：每笔出库先形成独立来源明细，财务可按订单/客户/期间汇总为应收单，兼顾分批追溯与结算便利。
确认
### 14. 其他应收
问题：其他应收可以有哪些类型，例如样品费、运费、赔偿、预收、杂项？是否必须选择客户及填写类型、原因、金额、日期和附件？
建议：建立可维护其他应收类型；必须选择相对方、类型、金额、发生日期、原因，附件可选。无法关联订单时必须明确标记“其他事项”。
确认，要满足用户可以自行灵活增删改，这是我们的设计哲学
### 15. 收款与核销
问题：一笔收款能否同时核销多笔应收？一笔应收能否被多次收款部分核销？是否记录收款日期、金额、币种、方式、银行流水号、收款人、附件？
建议：支持多对多分批核销；保留上述信息，核销总额不得超过应收未核销余额，超额作为预收或异常处理需确认。
确认
### 16. 应收状态与更正
问题：是否采用 `草稿 -> 已确认 -> 部分收款 -> 已收清 -> 已关闭`，并支持取消？错开应收、退款、坏账、折让、汇率差异如何处理？
建议：采用基础状态；已确认后用红字/冲销或独立调整更正，退款单独记录。坏账、折让、汇率差异是否纳入 V1.0请确认。
确认
## D. 应付与付款

### 17. 应付生成时点
问题：采购原料 QC 合格入库后是否自动生成应付来源草稿，财务确认后形成应付？是否仍以“实际入库数量 × 最终确认单价”为金额依据？
建议：采用，与采购/仓库设计一致；已报送来源不可重复生成应付。
确认
### 18. 分批入库与应付
问题：一张采购单分批入库时，是每次入库独立应付，还是按供应商/采购单/期间汇总？
建议：每笔入库保留独立应付来源，财务可按供应商、采购单、订单、期间汇总为应付单。
确认
### 19. 其他应付
问题：其他应付有哪些类型，例如外加工费、运费、维修、租金、杂项？是否必须选择相对方及填写类型、原因、金额、日期和附件？
建议：建立可维护其他应付类型；必须选择相对方、类型、金额、发生日期、原因，附件可选。外加工费的具体计量/结算规则可在后续细化。
确认，提供自行增删改的接口
### 20. 付款与核销
问题：一笔付款能否核销多笔应付？一笔应付能否分批付款？是否记录付款日期、金额、币种、方式、银行流水号、付款人、附件？
建议：支持多对多分批核销；保留上述信息，核销不得超过应付未核销余额，超额付款作为预付或异常处理需确认。
确认
### 21. 应付状态与更正
问题：是否采用 `草稿 -> 已确认 -> 部分付款 -> 已付清 -> 已关闭`，并支持取消？退供应商、退款、折让、价格差异和预付款如何处理？
建议：采用基础状态；仓库退供应商回冲来源，应付已确认/已付款后的更正使用冲销、退款或独立调整。价格差异沿用采购单价差异审计。
确认
## E. 共同规则、报表与权限

### 22. 订单号与其他事项边界
问题：是否规定凡是来源于销售出库、采购入库、生产或外加工的应收应付必须填 `order_no`；其他事项允许为空但必须填写业务类型、相对方和原因？
建议：采用，避免订单成本和回款无法追溯。
确认
### 23. 发票与对账
问题：应收应付是否维护发票号、开票/收票日期、发票金额、是否已开/已收、对账状态？是否统一使用 `attachment` 上传发票、对账单、银行回单和合同资料？
建议：支持附件且不强制；结构化发票/对账字段建议保留，具体必填性由财务确认。
确认
### 24. 告警与到期日
问题：应收应付是否维护到期日，并提供逾期、超额核销、来源差异、未关联订单四类告警？告警是否统一采用“待处理、已确认、已恢复”？
建议：采用；告警不阻塞保存，但超额核销必须阻止保存。
确认
### 25. 固定报表、导出与权限
问题：是否确认首批报表：员工目录、考勤、绩效、薪资台账/付款、应收与收款明细、应付与付款明细、应收账龄、应付账龄、订单收支追溯、财务告警；均支持日期、订单号、客户/供应商/员工、状态筛选与 Excel/CSV 导出？财务、人事、销售、采购、管理员是否按模块授权，审批人字段继续预留？
建议：确认；附件统一非必传，审批流暂不实现。
确认
