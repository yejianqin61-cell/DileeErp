## 2. 与现状的差距

### 2.1 已有基础、但字段口径不同

| 示例表 | 现状 | 差距 |
| --- | --- | --- |
| 销售对账明细表 | `GET /finance/receivable-sources` + 出库单 | 缺 **产品代码 / 规格型号 / 单位 / 税额 / 折扣 / 调整金额 / 含税单价 / 含税金额 / 汇率 / 本币五列**；当前应收来源只有 `quantity/unitPrice/taxRate/amount/currency` |
| 采购对账明细表 | `GET /finance/payable-entries` + 采购单/物料 | 缺 **产品代码(部分有) / 税额 / 折扣 / 调整金额 / 含税单价 / 含税金额**；当前应付只有 `quantity/unitPrice/taxRate/amount` |
| 销售对账汇总表 | 本轮新增的「应收对账」列表 | 缺 **调整金额 / 税额 / 开票金额 / 欠款** 列；当前是 应收快照/已收快照/系统余额/外部余额/差异 |
| 销售利润报表(毛利) | 无 | 完全缺失：**成本金额**没有任何数据来源（BOM 成本？采购成本？没有定义） |

### 2.2 完全缺失

| 示例表 | 说明 |
| --- | --- |
| 收支明细表 | 现金收支流水（按对方、币种、结算方式）。现有 `customer_payments` / `supplier_payments` 是**收付款单**，不是「收支流水」：没有「对方名称」统一字段，也没有把收入/支出放同一行两列的表达 |
| 收支汇总表 | 按**费用/收入项目**汇总。这 39 个项目属于「可配置类目」（宪法《Configurable Business Categories》），需要字典 + 明细上的项目字段，目前完全没有 |

## 3. 需要业务确认的问题

1. **这 6 份表的用途**：是「财务模块要做到的报表清单」，还是「导出格式要长得一样」，还是只是现状记录？
2. **收支明细表 / 收支汇总表**是否要做成新的「收支管理」子栏目（含可配置的收支项目字典）？
   它们的 39 个项目与现有的应收/应付/付款是什么关系——是同一笔付款的另一种视角，还是独立录入的流水？
3. **含税单价 / 税额 / 折扣 / 调整金额 / 汇率 / 本币** 这几个字段：
   - 是在销售单/采购单明细上补齐（主数据侧），还是在财务对账时人工填写？
   - 现模型只有 `taxRate`（税率）没有税额与含税单价，也没有汇率与折扣字段；
   - 「本币」= 公司本位币（CNY）？汇率取哪一天的？
4. **开票金额**：`ReceivableSource` 只有 `invoiceNo/invoiceDate`，没有发票金额。开票是财务在应收上手填，还是来自其它模块？
5. **「欠款」**：应等于 销售金额 + 调整 - 税额 - 已收？还是另有口径（例如含未开票）？
6. **销售利润报表的「成本金额」** 数据来源是什么？
7. **是否要求导出**成与示例一致的 `.xls`（含表头与列顺序），还是只要页面表格一致？
