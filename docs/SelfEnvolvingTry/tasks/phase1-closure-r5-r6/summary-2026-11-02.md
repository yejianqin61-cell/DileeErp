## 这些变更意味着什么？

门禁不再只相信 Agent 声称“测试通过”：它要求候选中的 `tool.ts` 和 `tool.test.ts` 同时被冻结并进入哈希；Validator 报告的字节哈希必须与证据记录一致；新离线容器会先执行该 Builder 测试，再运行宿主固定样例与权限探针。Builder 无法在交付副本上继续写入，网络和数据库凭据也不可用。

并行不再只由模拟数组断言：集成测试走实际 SDK 生命周期和 Cordis 的 `build_tool`、`validate_tool` 策略，激活轨迹带有能力、角色、开始与结束时间。验证器数量、对应能力、执行次序和 Builder 区间重叠均由门禁检查。

## 仍然开放的收口条件

本批次**没有**把脚本化模型适配器伪装成真实模型验收。以下条件必须在 R-2、R-3、R-4 的实链路完成后，再运行 R-5/R-6 的最终严格入口：

1. 真实模型从空候选目录分别写出两份实现、Builder 测试和 Validator 报告，且使用专用测试数据库的受限入口。
2. 两份实际候选均经 R-5 独立容器复跑后，才接入 R-6 的双候选整批放行。
3. 将单项失败、缺项、重复通知和资源清理实验与 R-7 的监督进程证据合并；随后由 R-8 的 `verify:phase1` 产生唯一阶段结论。

因此，阶段一文档状态保持“待实施/待验收”，本批次只能作为 R-5/R-6 的可复跑实现证据。
