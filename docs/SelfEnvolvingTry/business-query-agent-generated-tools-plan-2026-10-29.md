# 业务查询 Agent 自生成工具实施计划

> 日期：2026-10-29｜状态：待阶段验证｜依据：[自生成工具架构](business-query-agent-generated-tools-architecture-2026-10-29.md)

先验证两个会决定路线能否成立的条件：DeepSeekHarness 能否受控地运行多 Agent 构建；生成工具能否在不取得任意数据库和进程权限的情况下回答真实业务问题。通过后再接入自动发布与前端展示。业务模块、业务写操作和完整 ERP 自修改不在本计划内。

## 1. 需求

- **R-1 缺口识别** — 本次产品转向：Query Agent 在工具目录查不到所需能力时提交构建请求。
- **R-2 Harness 构建** — 本次产品转向：DeepSeekHarness 承担 Coding Agent，每个工具有 Builder 和 Validator。
- **R-3 多工具并行** — 本次产品转向：同一问题需要多个新工具时，并行构建与验证。
- **R-4 工具写入边界** — 本次产品转向：Coding Agent 只修改业务查询工具包。
- **R-5 工具权限与验证** — 本次产品转向及既有 V0 权限约束：新工具经对抗审查、测试和权限门禁。
- **R-6 快照发布与回滚** — 本次产品转向：Artifact Registry 记录版本，工具通过热切换上线。
- **R-7 查询等待与续跑** — 本次产品转向：构建期间 Query Agent 释放计算 run，完成后继续原问题。
- **R-8 持久心跳与恢复** — 本次产品转向：Coding Agent 工作状态可追踪，断线和重启可恢复。
- **R-9 前端工作态** — 本次产品转向：页面展示多 Agent 拓扑分发和 Coding Agent 运行状态；细节后续设计。

## 2. 逐项做法

### R-1 缺口识别

- **做法**：目录检索后产生结构化缺口。空结果、权限拒绝和模型拼错名称不触发构建。
- **涉及**：查询编排、工具目录。
- **测试入口**：现有查询编排 Interface。
- **验收**：[ ] 缺能力产生一次请求；[ ] 已有工具、空数据、越权和参数错误都不构建。
- **难点**：模型的“需要新工具”判断必须有可核对的目录证据。

### R-2 Harness 构建

- **做法**：锁定 Harness 版本，由独立 Coding worker 启动一个 Harness runtime；其根 Agent 统筹 Builder/Validator 本地子会话，并记录父会话、Activation、返工与产物。
- **涉及**：Coding Agent、构建作业。
- **测试入口**：构建作业 Interface。
- **验收**：[ ] 一项脱敏真实缺口产出可运行工具；[ ] 母 Agent 接收 Validator 反馈并决定返工；[ ] Validator 独立审查并写对抗用例；[ ] 插件与 Worker 拒绝跳过验证。
- **难点**：Harness SDK 与子 Agent 能力尚未在本仓库验证。

### R-3 多工具并行

- **做法**：一个请求拆成多个工具任务；各工具内部先编写后验证，整个批次一起发布。
- **涉及**：构建作业、发布器。
- **测试入口**：批次构建 Interface。
- **验收**：[ ] 两个工具并行构建；[ ] 任一失败时整批不激活；[ ] 重复通知不重复发布。
- **难点**：并发产物相对活动快照的冲突处理。

### R-4 工具写入边界

- **做法**：源码只读挂载，工具包与测试目录临时可写；发布器按路径白名单核对差异。
- **涉及**：构建沙箱、发布器。
- **测试入口**：越界写入检查。
- **验收**：[ ] 尝试改业务模块或配置会失败；[ ] 凭据不可读；[ ] 只允许工具包进入候选快照。
- **难点**：容器挂载、子进程和网络隔离在生产环境中的实际效果。

### R-5 工具权限与验证

- **做法**：生成工具使用受限只读数据入口；宿主在调用前后校验档位、范围和输出。
- **涉及**：工具执行、数据入口、Validator 门禁。
- **测试入口**：现有 Tool Executor Interface 加真实双角色样例。
- **验收**：[ ] 低档不能取得财务字段；[ ] 工具不能写库或越出声明的业务范围；[ ] 每个结果可追来源。
- **难点**：数据入口既要可扩展，又不能变成任意 Prisma/SQL 通道。

### R-6 快照发布与回滚

- **做法**：保存内容寻址的不可变包；先预载和健康检查，再原子切换活动指针。
- **涉及**：Artifact Registry、工具运行进程、发布器。
- **测试入口**：快照激活 Interface。
- **验收**：[ ] 模型 schema 与 executor 使用同一版本；[ ] 发布失败仍可调用旧版；[ ] 回滚恢复旧版。
- **难点**：活动查询与版本切换交错时的快照固定。

### R-7 查询等待与续跑

- **做法**：用户 run 进入等待工具状态并释放计算许可；发布后幂等领取续跑尝试。
- **涉及**：查询编排、状态管理、持久作业。
- **测试入口**：现有 run 状态与 SSE Interface。
- **验收**：[ ] 等待不占四个查询许可；[ ] 同一问题只回答一次；[ ] 取消和降权后不续跑。
- **难点**：现有单用户活动 run 索引和重启恢复语义要同步修改。

### R-8 持久心跳与恢复

- **做法**：构建 worker 续租作业；前端订阅持久事件，SSE 发连接心跳。
- **涉及**：构建作业、事件流。
- **测试入口**：作业租约与现有 SSE 重放 Interface。
- **验收**：[ ] worker 失联可检测；[ ] 刷新和 API 重启后能找回进度；[ ] 断线不重做构建。
- **难点**：长时间构建与用户问答超时的生命周期不同。

### R-9 前端工作态

- **做法**：先展示等待、每个 Builder/Validator 状态、成功和失败；拓扑交互另做界面设计。
- **涉及**：查询页、前端状态机。
- **测试入口**：现有查询页 reducer 与浏览器恢复流程。
- **验收**：[ ] 构建中用户看见持续状态；[ ] 刷新后状态一致；[ ] 错误可重试且不泄露内部日志。
- **难点**：现有界面把非终态一律当作“正在回答”。

## 3. 阶段与证据

### 阶段 1 — 验证 Harness 与安全数据入口

**覆盖**：R-2 Harness 构建、R-4 工具写入边界、R-5 工具权限与验证。

**目标**：用一个真实脱敏缺口，让 Builder 编写、Validator 审查和测试，工具在隔离进程中返回合规事实。

**任务**

- 打通一项缺口从 Harness 子 Agent 到工具包和测试报告的薄链路。
- 锁定 Harness 版本，实测 SDK、子 Agent、事件、取消与 Cordis 能力。
- 建立只读源码视图、工具包写入区和越界写入检查。
- 建立首版受限数据入口及工具运行进程。
- 用双角色和越订单样例验证字段、来源与拒写。

**证据**：真实脱敏问题得到正确 `QueryFact`；越界文件和数据访问被拒绝；留下版本与测试报告。

**本阶段不做**：自动发布和前端拓扑。

### 阶段 2 — 缺口请求能跨重启等待

**覆盖**：R-1 缺口识别、R-7 查询等待与续跑、R-8 持久心跳与恢复。

**目标**：Query Agent 遇到缺口后释放计算许可；API 重启后仍能找回构建任务，并在工具可用时继续原问题。

**任务**

- 打通目录缺口、持久构建请求、等待状态和续跑的薄链路。
- 排除空结果、误选 operation、参数错误和权限拒绝触发构建。
- 修改 run 约束和事件迁移，区分等待与活动计算。
- 增加构建作业租约、超时和幂等领取。
- 演练取消、降权、断线和 API 重启。

**证据**：等待期间查询许可归还；重启后只构建一次、只回答一次；权限变化阻止续跑。

**本阶段不做**：多工具并行和自动激活。

### 阶段 3 — 多工具批次自动发布

**覆盖**：R-3 多工具并行、R-5 工具权限与验证、R-6 快照发布与回滚。

**目标**：同一问题并行生成两个工具，其中一个覆盖跨单聚合；通过验证后以一个快照上线，失败可回滚。

**任务**

- 打通两个工具并行构建、各自验证、整批激活的薄链路。
- 扩展受限数据入口并验证一项跨单聚合，不依赖销售订单根。
- 建立不可变 Artifact Registry 和发布前路径、权限、测试门禁。
- 让模型 schema 与执行器固定到同一快照。
- 串行化激活并处理基线版本冲突。
- 演练预载失败、上线异常、紧急撤销和回滚。

**证据**：双工具问题完成；一个工具失败时目录不变；回滚后旧工具仍工作。

**本阶段不做**：修改 ERP 业务层或写入型工具。

### 阶段 4 — 用户看见多 Agent 工作

**覆盖**：R-8 持久心跳与恢复、R-9 前端工作态。

**目标**：用户在查询页看见 Builder、Validator、发布和续答进度，刷新页面后保持一致。

**任务**

- 打通从持久构建事件到页面工作态的薄链路。
- 展示并行工具任务和各自 Builder/Validator 状态。
- 展示失败原因、取消与重试入口。
- 检查键盘操作、状态播报和移动端布局。
- 用断线、刷新与重启流程核对事件重放。

**证据**：用户能完整观察一次双工具构建与续答；刷新和断线不丢状态。

**本阶段不做**：详细拓扑交互、源码 diff 编辑器或通用 ERP 自修改。
