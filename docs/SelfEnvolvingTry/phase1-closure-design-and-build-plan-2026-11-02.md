# 阶段一怎样继续推进并一次收口？

日期：2026-11-02｜版本：1.0｜状态：待实施｜类型：收口设计与施工计划

基线：工作区提交 `c4de0c52201ad32aea501a6c3b8a3b586a9358cb`。
依据：[阶段一施工计划](phase1-architecture-validation-build-plan-2026-10-31.md)、
[自生成工具总计划](business-query-agent-generated-tools-plan-2026-10-29.md)及本次代码评估。

本轮交付目标是一个能重复执行的阶段一验收入口：从规范化请求出发，由真实模型驱动母 Agent，
在 Linux 容器内生成、审查和返工两个工具，经宿主受限入口读取本地脱敏数据库，
最后由 ERP 独立门禁返回整批候选和完整证据。全部收口条件通过后，阶段一才标记完成。

本轮复用既有 SDK、Cordis 策略、受限数据入口和候选门禁，补齐真实运行链。
最大不确定项是完整 Harness 的受控模型出口，以及模型能否在预算内完成真实文件返工。
先验证这两项，再扩展批次与对抗实验。

范围终点是“待发布候选集合与独立验收报告”。
自动缺口识别、持久作业租约、查询等待续跑、Artifact Registry、活动目录切换及前端工作态属于后续阶段。
阶段一所需的容器隔离、数据库适配、独立重验、并行和清理证据均在本轮闭合。

## 2. 每项需求怎样实现和验证？

### R-1 本地数据基线可重复

- **做法**：从本地快照库一致性导出到专用测试库，冻结清单与校验值；仅在副本补充标记明确的边界样例。
- **涉及**：测试数据库准备、脱敏投影、业务样例与独立预期值。
- **测试入口**：现有候选纵切的数据库准备步骤，复用测试库身份校验。
- **验收**：逐项核对以下结果。
  - [ ] 原数据卷、快照库和当前业务库没有被迁移、清空或写入测试数据。
  - [ ] 同一导出和补充样例可重建相同数据校验值；预期值由独立数据库聚合得到。
  - [ ] 包装样例覆盖两个订单、同订单两名员工、多个日期、空结果和软删除；补充行可辨认。
- **难点**：原包装数据只有单员工；必须分开报告原始数据验证和补充样例验证。

### R-2 完整 Harness 受 Linux 边界约束

- **做法**：固定版本构建 Worker 镜像，容器运行 SDK 与完整 Harness；模型请求经唯一受限转发出口。
- **涉及**：Coding Worker 镜像、运行配置、模型转发、容器资源和进程监督。
- **测试入口**：现有批次运行入口及 Linux 隔离集成测试，使用真实 SDK 工厂。
- **验收**：逐项核对以下结果。
  - [ ] 真实模型完成一次母 Agent 到 Builder、Validator 的文件纵切，并保存精确版本与镜像摘要。
  - [ ] 源码只读、非授权目录不可写；容器不能取得数据库、用户令牌、部署凭据或模型上游密钥。
  - [ ] 模型服务可达；任意外网、数据库端口、遥测和非必要插件出口均不可达。
- **难点**：只关闭插件或只配置代理变量不能形成网络边界，运行时还需容器网络约束。

### R-3 实际生成与返工绑定真实修订

- **做法**：从空候选区生成实现、测试与报告；宿主冻结修订并计算哈希，Validator 审查该修订后反馈母 Agent。
- **涉及**：受控动作、候选冻结、Builder 续接、Validator 报告和修订记录。
- **测试入口**：既有返工纵切入口，增加真实模型模式和宿主固定的失败挑战。
- **验收**：逐项核对以下结果。
  - [ ] 实现和基础测试由本次模型生成；没有复制既有候选充当新生成结果。
  - [ ] 固定挑战使首版真实文件失败，Validator 报告具体失败，母 Agent 让原 Builder 修复。
  - [ ] 返工复用 Builder 会话但产生新 Activation；新文件哈希通过，旧哈希和报告重放被拒。
- **难点**：模型可能首版就正确；自然失败不能作为唯一返工覆盖方式。

### R-4 受限入口能安全读取实库

- **做法**：宿主复用现有角色解析与受限投影，使用专用只读账号查测试副本；离线候选经受控消息通道请求数据。
- **涉及**：宿主只读适配、角色读取、数据请求代理、结果和来源校验。
- **测试入口**：现有受限入口与候选执行入口，加入实库集成用例。
- **验收**：逐项核对以下结果。
  - [ ] 每次数据请求重查有效角色，使用创建时与当前档位较低者；停用或无有效角色拒绝。
  - [ ] 请求订单必须属于宿主授权范围；候选伪造档位、另一订单、工序或任意查询均被拒绝。
  - [ ] 日产量、员工累计与独立预期值一致；日期和小数保持口径，结果带可解析的实际来源。
  - [ ] 工资、单价、金额、自由备注均不输出；数据库写入被拒；超行数和超字节明确失败。
- **难点**：仅验证返回行等于候选自己请求的订单，不能证明该订单获得宿主授权。

### R-5 ERP 独立重验整个候选

- **做法**：ERP 宿主启动独立门禁进程，对冻结副本重新计算哈希，在新离线容器运行固定测试及权限用例。
- **涉及**：候选包、门禁运行器、受信测试、不可变副本和整批证据。
- **测试入口**：现有候选门禁与整批门禁，连接真实运行器；不新增公开业务接口。
- **验收**：逐项核对以下结果。
  - [ ] 生成实现、生成测试、Validator 报告和宿主测试结果均绑定同一能力、修订与源码基线。
  - [ ] 篡改、替换、缺文件、符号链接、错误基线、伪造通过及失败测试均不能返回通过候选。
  - [ ] 门禁独立复跑生成测试和宿主固定对抗集；仅有报告或回调返回成功不能放行。
  - [ ] 任一工具失败时返回整批失败；通过后的交付目录不可由构建容器继续修改。
- **难点**：内容黑名单只是辅助筛查；最终安全边界来自离线容器、宿主授权和固定对抗集。

### R-6 一个母 Agent 统筹双工具并行

- **做法**：每批次使用一个父会话和 Harness，母 Agent 声明两项能力并分别启动 Builder；沿用既有 Activation 管理。
- **涉及**：批次编排、父会话环境、能力目录、动作状态机、整批候选汇总。
- **测试入口**：既有批次入口贯穿真实 SDK、两个子会话和整批门禁。
- **验收**：逐项核对以下结果。
  - [ ] 同一个父会话统筹两个不同能力，两个 Builder 的实际 Activation 区间重叠。
  - [ ] 每个 Validator 只在对应构建完成后开始，审查被冻结的修订；两个工具可独立执行。
  - [ ] 成功返回两项候选和共同批次身份；单项失败、缺项和重复提交均不返回部分集合。
- **难点**：现有多 Harness 并行与既定母 Agent 语义不同；先收敛执行路径再扩展并发。

### R-7 失败可追溯且整树清理

- **做法**：宿主在运行时收集事件并监督整个批次容器，取消时关闭 SDK，再限时终止容器；失败保留证据。
- **涉及**：批次截止时间、容器监督、事件归档、attempt 目录与错误归一化。
- **测试入口**：既有生命周期和 Linux 集成测试，注入真实子进程、强制退出和资源限制。
- **验收**：逐项核对以下结果。
  - [ ] 同一截止时间覆盖启动、构建、等待、测试和门禁；清理另有有限宽限期。
  - [ ] 超时、主动取消、Harness 崩溃、Worker 被杀和资源耗尽后，没有归属该批次的容器或后代进程。
  - [ ] 失败前事件可读；能力、角色、会话、Activation、修订和轮次可关联，重复观察不触发重复提交。
  - [ ] 新 attempt 使用新目录，旧 attempt 证据不能参与新门禁；保留原始失败及清理错误。
- **难点**：被杀死的 Worker 不能自行清理，独立监督者必须持有容器身份和硬超时。

### R-8 阶段验收可一键复跑

- **做法**：增加专用收口入口，将离线回归、实库、真实模型、并行及失败实验汇成当前基线的验收清单。
- **涉及**：验收命令、本地证据目录、版本清单、持续回归与阶段报告。
- **测试入口**：现有 Worker 测试运行器与新增的阶段一验收命令；后者只组合既有入口。
- **验收**：逐项核对以下结果。
  - [ ] 必需实验全部执行且零跳过；缺模型、缺数据库或缺 Linux 时返回失败和具体原因。
  - [ ] 当前修订、镜像、依赖、数据集、配置和候选哈希均进入证据索引，不能混用历史通过记录。
  - [ ] 全部收口用例通过后独立重放一次候选门禁；报告逐项映射回原阶段一七项需求。
  - [ ] 最终报告只给出“通过”或“未通过”；有残留缺口时不更新阶段一为完成。
- **难点**：普通开发回归允许环境跳过，阶段收口入口必须采用更严格的失败规则。

### 2.1 整条链怎样连接？

阶段一入口接收受信的规范化构建样例，Query Agent 自动触发仍留在后续阶段。
入口先检查环境和数据集身份，再建立一个批次、一个 attempt 和一个固定父会话。

| 顺序 | 执行者 | 输入与交接 | 终点 |
| --- | --- | --- | --- |
| 1 | ERP 宿主 | 规范化请求、数据集校验值、源码提交 | 批次与受限授权上下文 |
| 2 | Linux Worker | 净化源码、窄工具契约、模型出口 | 一个母 Agent 及多能力声明 |
| 3 | Builder 与宿主 | 候选实现、基础测试；宿主冻结实际字节 | 真实修订哈希 |
| 4 | Validator 与固定测试运行器 | 冻结修订、独立用例、受限数据入口 | 审查报告与可信运行证据 |
| 5 | 母 Agent | 拒绝与测试摘要 | 原 Builder 返工，或请求整批提交 |
| 6 | ERP 独立门禁 | 当前候选集合、基线与结构化证据 | 整批通过或整批拒绝 |
| 7 | 宿主验收入口 | 门禁结果、事件、资源与清理记录 | 候选归档和阶段验收报告 |

### 2.2 本轮固定哪些设计边界？

下列决定落实既有架构；实现时先复用已有模块，不引入通用编排框架或额外 Agent 管理器。

1. 每批一个母 Agent。受控动作调用仍串行校验，但启动子 Activation 后立即返回，两个 Builder 可以重叠运行。
   各能力使用独立目录；宿主冻结候选并检查目录差异。目录和 preset 不宣称能隔离同进程内恶意子 Agent。
2. 统一父会话身份。父会话标识与策略插件环境由同一受信入口生成，不允许调用者分别填写。
   现有每能力启动独立 Harness 的入口退出正式验收路径；保留有价值的隔离和取消测试。
3. 使用最小模型转发。构建容器仅加入专用内部网络，网络上只有模型转发服务；不加入数据库网络。
   转发服务固定上游地址和请求路径，禁止任意地址和 CONNECT，只由转发服务持有上游模型密钥。
4. 将依赖装入锁定镜像。构建期间不安装依赖；停用 web、遥测、远程日志、插件管理和非必要后台组件。
   保存最终配置并运行实际出口探针，不能以配置文本代替出口证据。
5. 将测试与构建分开。候选测试在新建、默认断网的容器内运行，源码、工具副本和固定测试均只读。
   容器没有模型密钥、数据库连接串、Docker socket、宿主主目录或原始数据卷。
6. 通过标准输入输出交换受限数据消息。宿主生成的运行包装层提供数据读取能力，固定消息类型、数量与大小。
   宿主把会话与一次调用绑定到用户、授权订单和工序；候选不能通过消息替换身份或扩大授权范围。
7. 把信任放在宿主。构建区内的策略状态、Agent 报告及自写日志均视为待核实输入。
   宿主收集外部观察、冻结副本和固定测试结果；最终门禁重新验证，拒绝仅凭母 Agent 的通过声明。
8. 控制写入边界。只允许候选实现、清单和对应测试进入候选；Validator 可提交审查与对抗用例，不能替 Builder 修改实现。
   受控文件工具核验角色和路径，shell 运行测试转到只读执行容器；宿主复核差异和实现哈希。

模型转发是基础设施组件，不转发任意业务请求。
阶段一只把净化源码、工具契约、脱敏输入和必要错误摘要送给模型；原始数据库导出与对照映射留在宿主。
候选只能请求宿主已允许的数据操作；窄数据入口不够用时批次失败，由人扩入口后重验。

### 2.3 数据、候选和证据怎样保持一致？

数据集从本地快照一致性导出，导入名称明确含测试标识的专用数据库。
重新检查姓名、备注、连接信息等残留字段，对模型和候选可见内容作确定性脱敏。
补充多员工、跨日、软删除和两档角色样例时，只写测试副本；清单分别记录原始行与补充行数量。

宿主数据适配使用最小列权限的只读账号，不使用数据库所有者或开发连接回退。
双角色、撤权等变更由独立测试准备账号完成；候选和数据读取进程都不能取得该账号。
身份重查复用现有角色口径，测试中的员工别名不构成线上员工信息权限扩展。

每日分组按订单、工序、员工、日期汇总；员工累计按订单、工序、员工汇总，不从截断页推算。
金额和数量不用浮点计算；日期按业务日期输出，软删除和失效关联沿用业务过滤口径。
原始日报引用与累计来源集合均由宿主保留索引；最终来源不能只是无法解析的拼接标签。
同一销售订单有多个生产订单时，宿主合并同一员工的分组，来源保留全部生产订单和日报关联。
两档均返回批准的窄产量字段；候选不能把合法的高档结果误判为非法，宿主也不能随档位附带工资字段。
宿主在候选返回后再次校验结果结构、授权范围、字段、来源、行数和字节，不依赖候选自行投影。

双工具纵切固定为“员工每日产量”和“员工累计产量”，二者独立实现、独立验证。
它们复用同一受限汇总数据入口，属于原包装产量需求的能力拆分，不扩展到跨单聚合或新业务域。
原订单 A 汇总样例保留作回归，不能作为新候选预填进空工作区。

| 交接对象 | 必需内容 | 谁核对 |
| --- | --- | --- |
| 构建请求 | 请求、批次、attempt、源码基线、能力约束、预算 | ERP 宿主 |
| 授权上下文 | 调用身份、初始档位、当前角色、允许订单和工序 | 宿主数据入口 |
| 候选修订 | 能力标识、实现与测试文件、文件哈希、清单哈希 | 宿主冻结和枚举 |
| Validator 报告 | 能力、修订、会话、Activation、结论、失败与对抗用例 | 宿主解析并独立复跑 |
| 门禁证据 | 相同修订、数据集、固定用例版本、退出码、输出摘要 | ERP 独立进程 |
| 批次结果 | 精确预期能力集合、逐项证据、唯一提交身份 | 整批门禁 |
| 阶段报告 | 版本索引、实验清单、拒绝反例、清理结果、最终结论 | 收口入口 |

候选包内容限定为每能力的工具实现、测试、清单，以及单独的审查证据。
依赖仍使用批准的固定运行时；本轮仅支持两项明确批准的产量能力，不建设任意工具插件加载平台。
冻结时按稳定路径排序计算文件哈希；进入最终测试和交付的必须是同一份宿主只读副本。
实现与 Builder 基础测试组成构建修订，Validator 新增测试和报告单独计算证据哈希。
最终清单绑定构建修订和全部证据哈希；新增审查测试不伪装成 Builder 返工，修改实现必重新审查。

返工实验分两种模式：普通真实模型生成，以及显式故障挑战。
挑战由宿主在首版中注入一个受控缺陷，例如破坏工序参数传递；记录注入前后哈希及差异。
Validator 必须依据实际固定测试识别失败，母 Agent 决定修复，原 Builder 写出通过新修订。
报告将此标记为故障注入证据，不能把宿主改动归为模型自主犯错。

事件在接收时由宿主分配观察顺序，保留原始来源顺序与实际时间。
每次 Activation 关联能力、角色和修订轮次；不能给全批所有事件套用同一个外部轮次。
本地证据采用追加文件和最后的完整性索引；失败同样落盘，不依赖函数成功返回才生成进度。

### 2.4 预算、失败和回退怎样约束？

以下是首次实验的预算起点，不是已校准性能指标；调整后配置摘要必须变化并重新执行验收。

| 项目 | 初始限制 | 达到限制时 |
| --- | --- | --- |
| 同时构建 | 每批 2 项能力 | 拒绝超额请求 |
| 返工 | 每能力最多 1 次 | 终止本批，按新 attempt 重新实验 |
| 整批截止时间 | 20 分钟 | 终止构建与门禁并收口 |
| 单次测试 | 60 秒 | 标记失败并清理测试容器 |
| 清理宽限期 | 15 秒 | 强制终止并记录清理失败 |
| 数据输出 | 每组最多 100 行；每次结果最多 256 KiB | 明确拒绝，不返回不完整累计 |
| 模型调用 | 全批最多 80 次；输出 token 总预算 100,000 | 停止转发并使批次失败 |
| 运行资源 | 沿用容器限制起步，记录双 Builder 峰值 | 耗尽实验按失败路径退出 |

控制器分别为构建、测试和门禁容器分配批次标签。
独立监督进程持有硬截止时间和这些容器身份，Worker 被强杀后仍可终止全部归属资源。
监督进程在容器外运行；不把 Docker socket 暴露给任何 Agent 或候选。

所有失败都保留失败证据并禁止交付成功集合；重试从新 attempt 和空目录开始。
每个施工关口可撤回新增入口和实验配置，现有静态 Query Agent 无须切换。
数据回退只清理本轮记录在案的专用测试库、容器与网络，不对原数据卷执行清空或迁移。

## 3. 按什么顺序施工，怎样证明已经收口？

施工分为五个关口，依次执行；这是阶段一内部顺序，不是另开五个产品阶段。
工作量估计为 7—10 个工作日，假设一名实施者、模型凭据可用且数据权限准备顺利。
估计不代表完成日期；完成由本节的证据决定，任何必需实验失败都留在阶段一解决。

### 关口一：真实模型和本地数据能在受控边界相遇吗？

**覆盖**：R-1 本地数据基线可重复、R-2 完整 Harness 受 Linux 边界约束、R-4 受限入口能安全读取实库。

**目标**：真实模型经受限出口启动完整母子会话，一次候选调用经宿主入口读取专用测试库。

**任务**

- 打通真实 SDK、Linux Harness、模型转发和宿主实库读取的最小探针链。
- 建立专用测试库与只读账号，冻结原始数据、补充样例和独立预期值。
- 打包锁定 Worker 镜像并裁减插件，验证模型可达、非授权网络不可达。
- 绑定宿主身份与授权范围，验证候选消息不能改档位、换订单或提交任意查询。
- 保存环境清单、配置摘要、探针结果和测试副本重建记录。

**证据**：实际模型请求记录、父子会话、实库读取和全部边界探针通过；缺任一项即停止扩展。

**回退**：关闭实验网络与容器，保留失败记录；只重建专用副本，不修改数据来源。

**本关不做**：双工具批次和最终候选放行。

### 关口二：真实文件能被拒绝、返工并独立通过吗？

**覆盖**：R-3 实际生成与返工绑定真实修订、R-4 受限入口能安全读取实库、R-5 ERP 独立重验整个候选。

**目标**：一个空目录产出工具，故障挑战触发真实返工，新修订经 ERP 独立测试通过。

**任务**

- 打通单工具从空目录生成、冻结修订、Validator 审查到独立门禁的整条链。
- 收紧角色写入范围并将测试执行移到只读容器，绑定实际文件哈希和宿主运行结果。
- 注入首版缺陷，让 Validator 报告失败并由母 Agent 唤醒原 Builder 修复。
- 复跑实库正例与固定对抗集，验证来源、空值、日期、小数和双档输出。
- 重放旧报告并篡改冻结前后文件，确认宿主门禁拒绝错误修订。

**证据**：原 Builder 的两个 Activation、实际不同文件哈希、失败用例、修复差异和独立通过报告。

**回退**：撤回该 attempt 的候选资格，保留修订与失败证据，使用新 attempt 重跑。

**本关不做**：活动工具注册和线上权限规则扩展。

### 关口三：一个母 Agent 能交付完整的双工具批次吗？

**覆盖**：R-6 一个母 Agent 统筹双工具并行、R-5 ERP 独立重验整个候选、R-7 失败可追溯且整树清理。

**目标**：同一个母 Agent 并行启动两个 Builder；两项独立通过才返回整批候选。

**任务**

- 打通单父会话的双能力生成、逐项冻结验证和整批门禁。
- 统一父会话环境生成，复用按能力索引的状态机和独立候选目录。
- 将当前并行入口中的目录、取消与事件逻辑复用到正式批次路径。
- 记录两个 Builder 的实际运行区间及各自 Validator、修订和来源。
- 注入单能力失败、缺项、重复通知和重复提交，确认整批无部分候选。

**证据**：同一父会话的两个 Builder 区间重叠，双工具实库结果正确；反例全部拒绝。

**回退**：整批失效，关闭同批容器，不保留任何部分成功资格。

**本关不做**：多请求共享构建、跨单聚合和快照激活。

### 关口四：被中断的批次会完整停止吗？

**覆盖**：R-7 失败可追溯且整树清理，并强化 R-2 完整 Harness 受 Linux 边界约束。

**目标**：真实 Linux 失败实验结束后没有残留运行，失败前的证据仍可读取。

**任务**

- 打通运行中强杀 Worker 到独立监督者清理整批资源的失败链。
- 在实际测试里启动后代进程，分别触发截止时间、主动取消和 Harness 退出。
- 注入内存或 PID 上限失败，验证根因、清理宽限期和强制终止结果。
- 在事件接收时归档观察记录，验证失败记录、轮次关联和重复事件重放。
- 从失败批次发起新 attempt，拒绝旧目录、旧候选和旧证据混入。

**证据**：每类故障都有终态、原始错误和清理检查；批次标签下无存活容器或后代进程。

**回退**：由外部监督者终止实验资源，保留诊断资料，修复后重跑对应故障及完整批次。

**本关不做**：持久作业租约和自动恢复中断中的 Agent 会话。

### 关口五：本阶段能用一个入口给出收口结论吗？

**覆盖**：R-8 阶段验收可一键复跑，并汇总 R-1 本地数据基线可重复至 R-7 失败可追溯且整树清理。

**目标**：一次严格验收产生完整证据索引，并据此明确通过或未通过阶段一。

**任务**

- 组合全部已接通入口，运行当前提交的严格验收并输出机器可读清单。
- 执行 Worker 全量回归、类型检查、配置装载及受影响 API 权限与数据测试。
- 对通过候选在新容器独立重放门禁，复核字节集合与数据集基线一致。
- 汇总失败反例、资源检查与原阶段一需求映射，检查所有必需项目没有跳过。
- 更新阶段一文档状态、运行日志和后续阶段接口清单，仅在全通过时标记收口。

**证据**：下表全部通过，候选独立重放通过，且报告没有“阶段一后补”项。

**回退**：保留未通过结论与具体失败关口，阶段状态保持待验收，回到对应关口修复。

**本关不做**：用文档完成或测试数量代替阶段通过。

### 3.2 最终从哪个命令进入，交付什么？

现有快速入口继续使用：

```powershell
npm run test --workspace=@dilee/coding-worker
npm run typecheck --workspace=@dilee/coding-worker
```

本轮拟新增以下严格入口；截至本文件建立时尚未实现：

```powershell
npm run verify:phase1 --workspace=@dilee/coding-worker
```

严格入口先验证显式测试库、Linux、模型出口和专用账号，避免误用开发连接回退。
离线确定性检查可接入 Linux 回归；带模型成本的实验显式执行，缺凭据不能记为通过。
进程退出成功只在所有必需实验及清理完成后返回，任一跳过或失败均返回非零。

本地证据归档按批次和 attempt 保存，不作为 Artifact Registry。
归档包含规范化输入、版本索引、数据集摘要、候选文件、审查报告、宿主测试记录、事件和清理结果。
提交仓库的验收报告仅含脱敏摘要与哈希；原始会话和模型往返按本地敏感资料保存，不记录密钥。

| 原阶段一要求 | 本轮收口证据 |
| --- | --- |
| 同版 Harness 独立运行 | 固定镜像内完整 runtime 的真实模型纵切 |
| 母 Agent 统筹双子会话 | 单父会话的 Builder、Validator 及反馈决策 |
| 失败返工可追溯 | 实际文件、新旧哈希和原 Builder 的两轮 Activation |
| Cordis 与 Worker 强制规则 | 越序拒绝、预算、整批截止时间及全树清理 |
| 源码与数据只读隔离 | 模型出口白名单、文件探针、只读数据库和宿主范围授权 |
| 真实工具与独立门禁 | 实库正确性、来源、独立重跑及篡改拒绝 |
| 并行批次与可观察失败 | 双 Builder 重叠、整批拒绝、失败事件和新 attempt |

### 3.3 什么条件下可以写“阶段一已完成”？

只有最终验收清单全部通过、必需实验零跳过、候选独立重放通过且无资源残留时，才更新阶段一状态。
源码、依赖、配置、数据集或候选改变后，相关证据失效，必须重新执行受影响实验并重建最终索引。
任何阶段一需求尚缺运行证据，都保留“未通过”；不能转写成下一阶段待办来完成本阶段。

后续阶段只接收本轮已验证的请求契约、候选契约、门禁结果、事件格式和失败语义。
它们再建设自动缺口触发、持久作业、查询续跑、发布回滚和页面工作态。
